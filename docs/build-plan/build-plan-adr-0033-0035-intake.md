The crown-jewel PII gate (NFR-1, load-bearing at the de-id-touching waves), the EXTEND-NOT-REBUILD gate (NFR-2), the per-user-local + generic-labels posture (NFR-3/NFR-4), and the mock/fixture 0-live-spend posture (NFR-3) are checkpoint invariants on every wave (no test opens a network socket to a non-loopback host / makes a live model call / makes a `converse`/curation live call / reads a real key). `<wave-base>` is the merge-base of the build branch with `main`, computed DYNAMICALLY as `$(git merge-base HEAD origin/main)` in every executable checkpoint command (QA-F6 — so the gate does not go stale if `main` is rebased under the branch); the literal `12f769f` is the verified-as-of-2026-06-30 (S103) annotation, NOT the executable base. The branch's ADR/spec docs commits touch no code, so the numstat probe reads 0 from this base. `<7 frozen files>` = `scripts/plan/orchestrate.py scripts/plan/pipeline.py scripts/plan/assemble.py scripts/plan/generate_plan.py scripts/plan/adjudicate.py scripts/plan/adjust.py scripts/plan/track.py`.

**Full-suite gate (port-pinned, QA-F5).** Every wave's full-suite gate REQUIRES port 8765 FREE (the wave's entry criterion frees it) so `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES .venv/bin/python -m pytest -q` is unambiguously **0 failed** — that is the gate, and every per-wave "full suite green" below inherits this definition. If the operator's intake server holds 8765, the gate accepts a failure set of EXACTLY the two PINNED ids `tests/serve/test_bind.py::test_port_collision_exits_nonzero_fail_loud` + `tests/serve/test_server.py::test_main_reads_no_stdin` (the documented env delta) AND NOTHING ELSE — any other failing test, or a different-identity failure of these two, is a real regression that REDs the gate (a held-port run can never launder a regression as "2 env failures").

**Three-tier review (QA-F4, per `/execute-plan` + the CLAUDE.md PR lifecycle).** Each wave runs Tier-1 (the SE recipe-verification self-check) BEFORE the Tier-2 wave review specified per boundary below (QA always; Architect/Security per the activation map, over the whole-wave diff); Tier-3 (`/review-pr`, the 6-agent review) runs ONCE over the whole-build diff before the single `/merge` to `main`. No tier is skippable; `plan-integrity` gates each wave transition independently of (and in addition to) the three tiers.

**Router.py EXTEND-NOT-REBUILD posture (the one sanctioned exception):** for W1 (before T2 lands), `git diff --numstat $(git merge-base HEAD origin/main) -- scripts/plan/router.py` = 0 rows (numstat=0). From W2 onward (T2 has landed), router.py is SCOPED-ADDITIVE: the gate is `git diff $(git merge-base HEAD origin/main) -- scripts/plan/router.py` shows ONLY the sanctioned hunks (the repurposed `_age_band` exact-age deriver body, the new current-weight+trend deriver, the `_FIELD_DERIVATION` `training-age-band` mapping value + the new `bodyweight-band` entry, the `_RAW_TO_FIELD` `bodyweight-kg → bodyweight-band` entry, the `EXCLUDED_RAW_PII` `bodyweight-kg` member), with the `SUMMARY_FIELD_SET` tuple + `dispatch` + the other derivers byte-unchanged; PLUS the mechanical guard `git diff $(git merge-base HEAD origin/main) -- scripts/plan/router.py | grep '^-' | grep -E 'def dispatch|SUMMARY_FIELD_SET|EXCLUDED_RAW_PII'` returns 0 deleted lines touching `def dispatch` or the `SUMMARY_FIELD_SET`/`EXCLUDED_RAW_PII` members (additive-only; the human diff-hunk read is the backstop).
