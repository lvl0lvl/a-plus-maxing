# Build Plan: Local Scheduled Headless Subscription Runner — the Plan-Loop Cadence Runtime (ADR-0039)

Scope: the approved single-ADR spec (4 tasks — ADR-0039-T1..T4) that gives the built plan-evolution loop's CADENCE trigger its only viable host: a LOCAL scheduled headless Claude-Code SUBSCRIPTION runner, **disabled by default**, under a greenfield `scripts/runner/` tree. On the cadence it reads the operator's local gitignored store, de-identifies the raw intake IN the Python driver, builds a subscription-sub-agent `dispatch` + supplies the ADR-0027 `deid_client`, and calls the already-built `plan_loop.signal(root, trigger=CADENCE_TRIGGER, dispatch=..., deid_client=..., tailor_client=...)` as its SINGLE entry into the loop. The runner supplies the seams the standalone Python server cannot; it re-hosts nothing (the debounce, the fail-closed composition, and the cross-domain holds all stay inside the built loop). The ONLY tracked-file Modify in the whole spec is `.gitignore` — every other file is a Create under `scripts/runner/`.

## Overview / Governing Constraint

**The ONE thing that governs this build: the runner is a GREENFIELD driver that SUPPLIES the built seams and re-hosts nothing, while the raw-PII containment of the top-level subscription session stays in the Python driver.** Four properties are checkpoint invariants on every wave, none deferred to the last:

1. **EXTEND-NOT-REBUILD (greenfield driver, frozen engine + store byte-frozen).** The runner supplies `dispatch`/`deid_client`/`tailor_client` to `plan_loop.signal`; it re-hosts NONE of the debounce (`MIN_REGEN_INTERVAL_DAYS=7` + the sustained-signal window, [plan_loop.py:383-455](../../scripts/serve/plan_loop.py)), the fail-closed composition, or the cross-domain holds. Mechanically: a grep over the runner finds 0 occurrences of `_should_regenerate` / `compose_disposition` / `orchestrate.generate_plans` / `plan_driver.drive` / a re-declared `MIN_REGEN_INTERVAL_DAYS` (T1 AC-3), and the frozen engine + store glob stays byte-frozen — `git diff --numstat origin/main` = empty for `<frozen-glob>` (T1 AC-4, re-verified at the terminal). The runner touches NEITHER the frozen engine NOR the `scripts/serve/` server package. The runner's lock lives in a new `scripts/runner/store_lock.py`; its lock FILE lives under the already-gitignored `vault/store/`, so `scripts/store/*` is not edited.
2. **Raw-PII containment of the TOP-LEVEL subscription session.** The raw `store.read_all` intake read and the ADR-0027 `deid_in` de-identification MUST execute in the Python DRIVER layer (inside `plan_loop.signal → regenerate → run_orchestrated → deid_in`, [plan_loop.py:113-178](../../scripts/serve/plan_loop.py); [plan_orchestrator.py:127](../../scripts/plan/plan_orchestrator.py); [deid_in.py:39](../../scripts/plan/deid_in.py)), so raw store content NEVER enters the top-level subscription session's transmitted context — the subscription lane carries ONLY PII-free orchestration plus the de-identified summary. Mechanically: the crown-jewel non-egress wire-scan (0 raw-PII in any dispatch payload, T1 AC-5) + the local-store-only scan (the ONLY seam that receives raw store content is `deid_client.deidentify`, T1 AC-6). A naïve `claude -p "read the store and run the loop"` is DISQUALIFIED.
3. **DISABLED BY DEFAULT + operator-owned activation.** NO build, provisioning, or `init_instance` step loads the launchd/cron entry — ONLY the explicit, documented operator enable action arms the schedule (the PF-S63-02 guard-loosening sensitivity applied to a provisioning path). Mechanically: fresh-install → 0 active launchd/cron entries (T3 AC-1); importing/building the runner fires 0 `signal`/0 de-id/0 dispatch (T1 AC-7, T3 AC-2); the NAMED anti-implicit-activation guard REDs if a build/provision/`init_instance` path loads the schedule (T3 AC-8).
4. **0 live-API spend.** Every task is satisfiable with an injectable subscription-session factory + a fixture `dispatch(domain, prompt, summary)` + a fixture `deid_client`/`tailor_client` + fake keychain/env seams + scratch stores + synthetic PII-free fixtures. No test opens a socket or makes a live model/Agent-tool call; 0 real operator PII (0 real secret) enters the test tree. The runner ships DISABLED BY DEFAULT; the operator-present LIVE run — the not-metered probe (exactly the de-id-IN call metered, 0 metered dispatch), the OQ-6 acceptable-use decision, and the live sub-agent-dispatch confirmation — is the downstream operator-gated attestation AFTER this build, never a build task.
