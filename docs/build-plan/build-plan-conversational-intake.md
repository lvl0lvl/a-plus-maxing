# Build Plan: Conversational Intake Agent — Swappable Model Client + `/chat` Egress Seam + Extraction + Demographic Activation + Field-Set Extension

This plan executes one spec (`docs/spec/adr-0015-0019-conversational-intake-spec.md`, tier 7, ADR-0015 + ADR-0016 + ADR-0017 + ADR-0018 + ADR-0019) as two dependency-ordered waves, closing the long-standing core-capability gap (PF-S63-02 / PF-S87-01 / bead `71s4`): a real conversation produces a *usable plan* through the existing assembly pipeline, not just working chat plumbing. **Wave A — the model boundary + the conversation path** (the system's FIRST programmatic model client over a runtime-resolved key, the de-identified store-grounded question strategy, the plan-author re-wire through the one client, the `/chat` egress seam, and the conversation→de-identified-store extractor) and **Wave B — the form-side activation + the token vocabulary + the end-to-end usable-plan proof** (the demographic-form activation lighting the four orphan tokens, the `SUMMARY_FIELD_SET` extension that lets chat-extracted rich facts reach the planner, and the PF-S87-01 headline conversation→usable-plan integration gate). 8 tasks total (5 in Wave A, 3 in Wave B), all software — a new `scripts/model/` package (the single model boundary) + a new `scripts/serve/chat.py` / `scripts/serve/extract.py` over the unchanged loopback `scripts/serve/` server, plus token-extension edits to `scripts/serve/capture.py` / `scripts/plan/router.py` / `scripts/plan/generate_plan.py` and the `vault/design/templates/intake.py` form activation.

The build **reuses, never re-implements**, the live seams the data-in / data-out / intake-website waves already built. Reused byte-unchanged: `capture.persist_capture` (the de-identification gate, [scripts/serve/capture.py:189](../../scripts/serve/capture.py#L189) [VERIFIED]) and `store.append(item, reading, root)` (the NDJSON write + `(item,timepoint,source)` dedupe, [scripts/store/store.py:134](../../scripts/store/store.py#L134) [VERIFIED]) — the extractor adds only the dialogue→facts *producer* in front of these (ADR-0017 Alternative C). Reused unchanged: `assemble`'s four safety filters + the clearance gate + the per-domain translators + `record_plan` ([scripts/plan/generate_plan.py:60-62](../../scripts/plan/generate_plan.py#L60) [VERIFIED]) — ADR-0015 amends ONLY ADR-0006's dispatch *mechanism*, swapping the captured-envelope feed (`_author_callable`, [scripts/plan/generate_plan.py:65](../../scripts/plan/generate_plan.py#L65) [VERIFIED]) for a programmatic call through the one client. Reused unchanged: `router.summarize` (the 0-raw-PII derivation boundary, [scripts/plan/router.py:352](../../scripts/plan/router.py#L352) [VERIFIED]) and the content-upload transport (`route.route_upload` → `ingest.run`/`dna.land` [VERIFIED]) — the split moves the *rich sections* to chat, not the file uploads. The substrate is local Python 3.12+ + the stdlib `http.server` (the unchanged `ThreadingHTTPServer(("127.0.0.1", port), ...)`, `_LOOPBACK = "127.0.0.1"` at [scripts/serve/server.py:29](../../scripts/serve/server.py#L29) [VERIFIED]); the FIRST third-party dependency the build introduces is the commercial no-train model SDK, isolated behind `scripts/model/client.py` (an `rg` over `scripts/` for `anthropic`/`openai`/`.messages.create`/`httpx`/`requests` returns 0 today [VERIFIED]). Tooling is `pytest`, `rg`, `git`. Every script is built by SE; QA + Security + Architect review on every wave (the model boundary, the first egress, and the crown-jewel PII boundary are load-bearing on both waves); the design-reviewer is added on Wave B for the `/chat` panel + the activated demographic form; `plan-integrity` grounds every task's inputs against the LIVE tree and gates each checkpoint.

**The crown-jewel PII boundary (NFR-1, load-bearing).** Exactly three data classes cross exactly these boundaries: the **live conversation (raw)** MAY egress raw — but ONLY on the one `/chat` model call, on the no-train lane (ADR-0016); the **de-identified context** for the next ask (token names, bands/classes, booleans) MAY egress de-identified; the **persisted fact** crosses to the plan model only as a de-identified `SUMMARY_FIELD_SET` band/class through the unchanged `router.summarize` path. Nothing raw is EVER committed: the raw transcript is transient (in-memory for the live session, discarded per-turn after extraction — CONCERN-2), any residue lands ONLY on a gitignored surface (`vault/scaffold/filled/`, `vault/store/` are gitignored, [.gitignore:4-5](../../.gitignore#L4) [VERIFIED]), and the registered `block-pii-commit.sh` PreToolUse hook + the `pre-push-pii-scan.sh` backstop deny a committed filled-value path. The 0-shared-routine-edit invariant (ADR-0003-T2 — `scripts/ingest/ingest.py`/`adapter.py`/`scheduler.py` byte-unchanged) and the store-adversarial-test battery (`docs/checklists/store-adversarial-tests.md`) apply to any `scripts/store/` surface this build touches (ADR-0017/0019). **Public-repo secret discipline (NFR-3):** the no-train API key is resolved at RUNTIME from an injectable source (env var / macOS-keychain command), NEVER a tracked file — the repo is PUBLIC. The headline acceptance is exercisable against MOCKS/fixtures with NO live API (the model client is swapped for a fixture at the ADR-0015 seam); the **LIVE end-to-end run** (real conversation → real plan via the runtime keychain key) is the final, operator-present checkpoint, NOT a CI gate.

## Wave Schedule

Built from the spec's Kahn topological sort (8 nodes, 0 cycles, 6 ordered groups — spec Dependency Map lines 295-307). The single entry point is `ADR-0015-T1` (the model client, the boundary every model-touching task routes through). The spec's "Wave grouping for the build plan" (spec line 307) groups the 8 tasks into two waves by that DAG, and this plan adopts it verbatim: **Wave A** = the model boundary + the `/chat` transport + the extractor + the plan-author re-wire (the conversation path); **Wave B** = the demographic activation + the field-set extension + the end-to-end usable-plan proof (the form-side activation + the token vocabulary that lets the chat-extracted rich facts reach the planner, with `ADR-0017-T2` the terminal wave-closing integration gate that needs both waves' tokens).

Risk ordering applied within the topological constraints: the single model boundary (`ADR-0015-T1`) and the de-identified store-grounded strategy (`ADR-0015-T2`) and the gate-enforced extractor (`ADR-0017-T1`) all land BEFORE the `/chat` egress seam (`ADR-0016-T1`) that makes the first authorized outbound call — so the fail-closed contract, the single-egress-class bound, and the gate-at-write routing are all in place before any raw conversation egresses; the plan-author re-wire (`ADR-0015-T3`) lands in Wave A so the wired author path is proven (mock) before the Wave-B end-to-end rides it. In Wave B the demographic activation (`ADR-0018-T1`) precedes the field-set extension (`ADR-0019-T1`) — they share the `router.py`/`capture.py` token-extension surface and are serialized to avoid a merge collision — and both precede the terminal PF-S87-01 end-to-end (`ADR-0017-T2`).
