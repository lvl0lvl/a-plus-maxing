# Build Plan: Large-Change Hold-Until-Confirm via a Bounded Confirmation-Pointer (ADR-0040)

Scope: the approved single-ADR spec (4 tasks — ADR-0040-T1..T4) that resolves ADR-0036 OQ-4's hold-half (the TRUE large-change hold ADR-0036-T4 shipped only an ADVISORY for). A materially-large automated re-gen (`_change_magnitude(...) >= LARGE_CHANGE_THRESHOLD_DOMAINS`, `3` of the closed 4-set `PLAN_DOMAINS`) is still RECORDED through the ADR-0032-frozen write path, but it does NOT resolve as the standing plan and is NOT tailored/egressed until an explicit operator confirm. The hold is a bounded `(domain, plan_date) → decision` confirmation-pointer the standing-plan resolvers honor + a tailoring-seam gate — an ADDITIVE read-side + loop-layer change; the record WRITE path + inner engine stay byte-frozen.

## Overview / Governing Constraint

**The ONE constraint that governs this build: the safety boundary lives at the STANDING-PLAN RESOLVER and the TAILORING SEAM, never at the record write.** Concretely, four properties are checkpoint invariants on every wave, none deferred to the last:

1. **Frozen-spine byte-freeze (ADR-0032 AR-007).** The ADR-0032 Validation-named WRITE-path + engine glob stays byte-frozen: `git diff --numstat origin/main` = empty for `scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`, `scripts/plan/plan_driver.py`, `scripts/plan/plan_orchestrator.py`, `scripts/store/keying.py`, `scripts/store/store.py`. The ONLY `scripts/store/plan_schema.py` edit is `read_plan`'s read-side pre-filter (`resolve_plan`'s date-equality body / `record_plan` / `correct_plan` / `store.append` caller lines byte-unchanged — a targeted diff assertion, NOT a `numstat=0` on all of `plan_schema.py`). The one additive `plan-confirm::` stream is written through the UNCHANGED `store.append`/`store.correct` sinks.
2. **Fail-closed (no unconfirmed large re-gen ever stands or is tailored/egressed).** A held domain resolves `NO_PLAN_TODAY` (plan `None`), NOT the held plan and NOT a walk-back to the prior-dated plan; a decline / no-action leaves it held indefinitely. Only an explicit operator confirm promotes.
3. **0 live-API spend.** Every task is satisfiable with a fixture `dispatch` + fixture `tailor_client` + synthetic PII-free `plan::`/`plan-confirm::`/`biomarker::` fixtures. No test opens a socket or makes a live model/Agent-tool call; 0 real operator PII enters the test tree.
4. **Loop live-activation stays operator-gated (ADR-0039).** ADR-0040 changes what a fired re-gen DOES (hold vs stand), not whether it fires; the operator-present LIVE run (real key + real data + spend) is a downstream attestation AFTER this build, never a build task.

**Wave grouping (Kahn levels over the spec's verified-acyclic Dependency Map): four single-task waves.** The spec's Dependency Map is `T1→T2, T1→T3, T1→T4, T2→T3, T2→T4, T3→T4` — a transitively-closed total order (every task depends on ALL prior tasks). Kahn's algorithm yields exactly one task per level: **L1 = {T1}**, **L2 = {T2}**, **L3 = {T3}**, **L4 = {T4}**. No two tasks can co-occupy a wave (each carries an unmet dependency on the immediately-prior task), so four single-task waves is the FAITHFUL topological reading, not padding. Unlike the ADR-0036/0038 loop plan, ADR-0040 has no parallel side-chain (no horizon-style task rides alongside) — it is one strict serial chain across DISJOINT files (T1: `plan_confirm.py`; T2: `plan_schema.py`+`horizons.py`+`tailoring.py`; T3: `plan_loop.py`; T4: `confirm.py`+`server.py`), so no file is co-modified by two tasks (no BP-07 anywhere; the chain is a data-dependency chain, not a shared-file writer chain).

Each criterion is a SPECIFIC command / grep / numstat / count with an expected result and a verifier role. These gates are EXECUTED at `/execute-plan` time, not reasoned. The four governing invariants (frozen-spine numstat=0; fail-closed held→`NO_PLAN_TODAY`, never standing; 0-live-spend; loop-activation-operator-gated) are checkpoint invariants on every wave — no test opens a network socket or makes a live model/Agent-tool call. The store-adversarial obligation (`docs/checklists/store-adversarial-tests.md`) lives on ADR-0040-T1 (the ONLY store-surface task; T2/T3/T4 add no new `scripts/store/` write — the pre-filter READS `plan-confirm::`, the loop/confirm WRITE only through T1's `plan_confirm` API), and the suite-green gate re-runs the existing store-adversarial batteries across every change. `<frozen-glob>` below abbreviates `scripts/plan/orchestrate.py scripts/plan/pipeline.py scripts/plan/assemble.py scripts/plan/generate_plan.py scripts/plan/adjudicate.py scripts/plan/adjust.py scripts/plan/track.py scripts/plan/plan_driver.py scripts/plan/plan_orchestrator.py scripts/store/keying.py scripts/store/store.py` (the ADR-0032 Validation-named WRITE-path + engine glob).

**0-live-spend note (checkpoint invariant 3):** the 0-live-spend property is fixture-by-construction — every test uses a fixture `dispatch` / fixture `tailor_client` + synthetic PII-free streams, consistent with the existing offline 2274-test suite (which carries no network probe either), so no checkpoint needs a live-call assertion beyond confirming the fixture seams are fed. A network-blocking autouse conftest is tracked OPTIONAL hardening (a follow-up, NOT built in this plan; no new global fixture is added here).
