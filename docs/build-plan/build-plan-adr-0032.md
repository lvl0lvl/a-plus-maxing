Scope: the approved ADR-0032 spec (5 tasks T1..T5) that makes the now-live plan-generation engine DNA-aware on CURRENT science WITHOUT crossing the operator's raw genotypes to the no-train planner. ADR-0031 already lands the genotypes as durable FACTS (`dna-report` readings, `item`=gene+rsID, `value`=alleles); this build closes the gap with four NEW surfaces and ONE additive engine edit. **T1** stands up a NEW variant-keyed, ingestion-gated `vault/library/genetics/` section: the `### library/genetics/` schema in `vault/WIKI.md` + a `_template.md`, the `genetics` entity type in `scripts/lib/wiki-helpers.sh`, and the strict `check_genetics` battery in `scripts/wiki-ingest-lint.sh` (the variant-keyed schema + a W1 library-association operator-token scan reusing `scripts.guard.pii_scan.scan_text`/`DEFAULT_IDENTITY_CONFIG` via a python shell-out [SEC-ORD-01] + a W1 raw-genotype-in-trait-token guard [SEC-ORD-02]). **T2** adds the LOCAL genotype↔library matcher (`scripts/genetics/match.py` + the OQ-3 curated `variants.py`): reads the operator's `dna-report` genotype fact per curated variant via the per-item `store_read` surface, selects the per-genotype finding by the operator's LOCAL allele — pure, 0 egress, honest no-match. **T3** is the ONE additive plan-path edit (`scripts/plan/router.py`, the ADR-0019 `SUMMARY_FIELD_SET`-extension precedent): a de-identified `genetic-trait-classes` token + its local deriver, so the raw rsID+allele genotypes NEVER reach the planner. **T4** builds the care-assistant→DNA-research-agent hookup as a STUB (`scripts/genetics/research_query.py`): a GENERIC, operator-de-associated, ALLELE-AGNOSTIC per-variant query + a fail-closed de-association guard + a 0-spend stubbed dispatch — the live `aplus-research` run is the operator-gated OQ-1. **T5** is the end-to-end proof + the five ADR-0032 falsification probes as tests.
