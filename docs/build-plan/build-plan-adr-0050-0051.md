# Build Plan: Front-Door Plan Personalization (ADR-0050 + ADR-0051)

Scope: the approved single spec (`docs/spec/adr-0050-0051-plan-personalization-spec.md`, 3 tasks across two coupled ADRs) that makes the `/generate-plan` front door author each specialist from the operator's real, identity-stripped record instead of a coarse band-derived generic. It delivers: (1) repoint the front-door author input from `router.summarize`'s ~18-token band to ADR-0042's `assemble_context` identity-stripped FULL record, so the model author call reads the operator's real program/symptoms/supplement detail (ADR-0050-T1); (2) rewrite `_author_system_prompt` to be contract-driven — each specialist carries its own `design/specialist-plan-contracts.md` section — and genetics-aware, interpreting raw `GENE rsID = (C;C)`-shaped calls with an uncertainty directive for the un-vetted SNPs (ADR-0050-T2); and (3) reverse the ADR-0032/0042 raw-genotype carve-out, carrying the operator's FULL raw `dna-report` panel to the specialists identity-stripped through the assembler's existing `pii_scan` gate via a separate `dna-report`-source read path that keeps `router.py` frozen (ADR-0051-T1). The wave schedule is GROUNDED on the spec's Dependency Map (2 edges, 2 Kahn parallel groups, verified acyclic), File Manifest, and Test Strategy — this plan schedules them; it independently RE-DERIVES (does not transcribe) the waves, critical path, and per-wave file-disjointness against the live tree.

## Overview / Governing Constraints

**This build is a mock/fixture build at $0.** Fixture/spy model clients, synthetic-genotype store fixtures, no live SDK call and no spend. The operator-present LIVE run — real key, real data, real spend, first real-genome egress — is operator-gated and OUT of this plan's scope; it is recorded below as the Phase-1 and Phase-2 operator-verification checkpoints, NOT waves. The build rides three checkpoint invariants on EVERY wave, none deferred to the last:

1. **Frozen ADR-0032 six HARD byte-freeze for the ENTIRE build — NO sanctioned break.** Every one of the 3 tasks lands OUTSIDE the ADR-0032 frozen six. `<frozen-six>` = `scripts/store/store.py scripts/store/keying.py scripts/plan/pipeline.py scripts/plan/adjudicate.py scripts/plan/adjust.py scripts/plan/router.py`. The freeze is asserted at every wave boundary AND the terminal by `git diff --numstat 3ab1c3abb6c995fbaaadcb179735759e4a61d73d -- <frozen-six>` == EMPTY. **The numstat base is the durable fork-point SHA `3ab1c3ab`** (verified `git cat-file -t` == `commit`, frozen-six numstat EMPTY vs it at entry 2026-07-17), **NEVER the dynamic merge-base** (PF-S133-03): a merge-base drifts as `main` advances and silently changes what the probe forbids. `router.py` is load-bearing IN the six — ADR-0051-T1's whole mechanism (a separate `dna-report`-source read path, NOT the `_HEALTH_SUBSTANCE_ALLOWLIST` route) exists to keep `router.py` byte-frozen, which is why the spec foregrounds `router.py` in that task's frozen-surface probe (AC-4). The probe command is IDENTICAL across all three tasks (the same six files); the six stay byte-identical throughout.

2. **Identity-strip invariant at every checkpoint.** No operator name / DOB / contact / health-identifier reaches the model author call. The invariant is the reused `pii_scan.scan_operator_value` gate (`context_assembler.py:188`), fail-closed. It holds on the pre-existing carries (labs / medications / free-text, already the assembler's built behavior) and is verified at each boundary: Wave 1 authors each specialist against `assemble_context`'s `pii_scan`-stripped record (ADR-0050-T1 AC-1); Wave 2 proves the SAME strip holds on the NEW raw-genetics carry via a fail-closed RAISE probe with two sub-cases (ADR-0051-T1 AC-2, both mutation-gated): (a) an operator name/DOB/contact seeded into a `dna-report` field RAISES via `scan_operator_value` (`context_assembler.py:188`) — dropping the scan lets the operator name cross without raising → RED; (b) a nested-dict / non-scalar third-party MRN/provider-name RAISES via the `_is_flat_scalar` flat-scalar guard (`context_assembler.py:165`) — dropping the guard lets the nested third-party PII cross → RED. The security-sensitive ordering is that the strip is proven on the assembler-fed author input (Wave 1) BEFORE the raw genome is added to that same carry (Wave 2).

3. **0 live-API spend / 0 real operator PII / PUBLIC repo synthetic fixtures.** Every one of the 3 tasks is satisfiable with spy/fixture model clients and synthetic-genotype store fixtures; no test opens a live socket or makes a live model call (`anthropic` SDK intentionally ABSENT from `requirements.txt` and un-importable — verified 2026-07-17 — the 0-live-spend guard by construction). **NO task reads from or writes to `scripts/store/`** — the manifest touches `server.py`, `client.py`, `context_assembler.py`, and their tests only. **The store-adversarial blocking gate (`docs/checklists/store-adversarial-tests.md`) therefore does NOT trigger** — stated explicitly so no wave carries a phantom store-battery obligation.
