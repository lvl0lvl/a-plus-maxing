# Recipe: Clone-Init Step + Operator-Facing Clone README

> **This task is the fresh-clone independence boundary.** `init_instance.run()` is
> the one entry point a new operator runs after `git clone` to reach a fillable,
> PII-free local instance. Its three load-bearing properties are DATA-ISOLATION
> properties, not features: (crit 2) data entered after init lands OUTSIDE
> `git status` (untracked/gitignored, relying on the ADR-0005-T1 boundary); (crit 3)
> the instance generates a **dashboard** from the clone's OWN inputs alone, with
> **0 reads of any other operator's store** (0 cross-clone paths) — the plan half of
> spec crit-3 is DEFERRED (its generation path, `assemble.py`/ADR-0006-T2, does not
> exist until Wave 5; see the UPSTREAM FLAG and Deviation #2); (crit 5)
> `init_instance.run()` references **no network and no cross-clone path** (the
> cross-spec egress guard over the call observes 0 outbound; 0 reads outside the
> local clone root). These three are gated as falsifiable RED targets BEFORE any
> GREEN (Risk Pre-Check) — a clone-init that silently reads a sibling clone's store,
> or whose entered data lands tracked, or that touches the network, defeats the
> independence boundary this task exists to establish.
>
> **`init_instance.run` is a thin entry point, NOT a broadly-reused interface.** It
> CONSUMES the ADR-0002-T1 store (`store.append`/`store.read` + `keying.py`), the
> ADR-0004-T1 generation path (`render.emit`), the ADR-0005-T1 gitignore boundary,
> and the ADR-0001-T1 egress guard. It publishes no new shared signature any later
> task plans against (it is a leaf — ADR-0005-T2 has 0 outgoing dependency edges in
> the spec map). See Interface Contracts.

## Risk Pre-Check

The spec's "Risk Mitigations" field declares the ADR-0005 Negative (gitignored store + filled scaffolds carry no version-control backup/history — data loss if the working copy is lost) an **accepted, documented limitation** (Component Overview), NOT a defect to engineer away. Its mitigations are first-class criteria of this task: **criterion 2** keeps entered data untracked **by design** (the accepted trade-off), and **criterion 4** (the README) **states the no-VC-backup consequence** so the operator keeps a separate local backup. Because criterion 2 is the deliberate realization of the accepted trade-off, its falsifiable RED test is the gate — paired with the two adjacent data-isolation properties the ADR-0005 Validation Approach makes load-bearing (0 cross-clone paths, no network). These three must hold as falsifiable RED targets BEFORE any GREEN (a placeholder `assert True` / a pass-only test FAILS this gate):

- **Gate A — entered data lands untracked (crit 2; the accepted no-VC-backup trade-off, realized).** The RED test MUST, in a scratch clone carrying the ADR-0005-T1 `.gitignore` boundary, call `init_instance.run()`, then enter one reading via the store API, and assert the new store file is **untracked / gitignored** (`git status --porcelain` does NOT list it AND `git check-ignore <new store file>` exits 0). Falsifiable: a clone-init that wrote the reading to a tracked path, or under a clone that lacks the boundary, makes this red. This is the test that proves the accepted trade-off is realized, not a render bug.
- **Gate B — generate from local inputs alone, 0 cross-clone reads (crit 3, dashboard-scoped).** The RED test MUST run the crit-3 **dashboard** generation on the initialized clone with **no other operator's store present**, and assert (i) the dashboard renders from local inputs only, AND (ii) the generation performs **0 reads of any path outside the clone root** — in particular 0 reads of any other clone's `vault/store/`. The 0-cross-clone-read assertion is observed by a filesystem-read trace/audit over the generation call (e.g. plant a sibling-clone store directory OUTSIDE the clone root and assert the trace shows 0 opens of any path under it / any path not under the clone root). Falsifiable: a generation that opened a sibling clone's store, or any path outside the clone root, makes this red. The load-bearing isolation property (generates from the clone's OWN inputs alone, 0 cross-clone reads) is fully testable against the dashboard render; the **plan half of spec crit-3 is DEFERRED** to a post-ADR-0006-T2 integration checkpoint because no plan-generation path (`assemble.py`, Wave 5) exists at this Wave-4 task (UPSTREAM FLAG + Deviation #2).
- **Gate C — 0 egress + 0 reads outside the clone root (crit 5).** The RED test MUST wrap an `init_instance.run()` call in ONE zero-arg closure passed to the cross-spec egress guard `run(callable)` and assert it is **truthy** (0 outbound calls, including any child/subprocess egress), AND assert the call performs **0 reads outside the local clone root** (the filesystem-read trace over the `init_instance.run` call shows 0 opens of any path not under the clone root). Falsifiable: an `init_instance.run` that made an outbound call (guard returns falsy) or read a cross-clone/network-cached path makes this red. **Failing-capable check (build-plan Wave-4→5 boundary SEC-03, line 251):** the RED set MUST also inject a synthetic outbound call into one `init_instance.run` path and assert the egress guard returns FAIL (falsy) — proving the guard actually intercepts this new code path (subprocess- and async-spawned calls included), not merely that a clean run happens to make 0 calls. A guard that does NOT flip to FAIL on the injected call is a no-go.
