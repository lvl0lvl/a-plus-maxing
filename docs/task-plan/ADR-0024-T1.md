# Recipe: Multi-Agent Whole-Plan Safety Review

This task builds the multi-agent whole-plan SAFETY review
(`scripts/plan/safety_review.py`): a `/review-pr`-style multi-lens safety
review over the WHOLE assembled plan. It dispatches ≥2 independent safety
lenses (`medical-safety-reviewer`, `health-edge-case-reviewer`, the
`medical-liaison` as a whole-plan reviewer — all present in `.claude/agents/`)
over the COMPOSED multi-domain plan, synthesizes + blind-triages their
findings, and routes each legitimate finding into the shared revise loop. It
reads the reconciler hold set carried on the `run_generation` result to EXCLUDE
already-adjudicated per-finding holds (no double-gate, no gap). The lens
dispatches are MOCKED in tests (0 live spend).

This review WRAPS — it does NOT replace — the inner per-finding `adjudicate`
gate. The inner gate (`scripts/plan/adjudicate.py`, driven through
`run_generation`'s `adjudicator` hook) SURVIVES verbatim as the per-finding
layer: it adjudicates INDIVIDUAL held findings one at a time (one additive-AE,
one cross-domain conflict, one Rx-BPMH at a time, each built by a dedicated
`safety_finding` builder in `orchestrate.py`). This new tier is the ADDITIVE
whole-plan layer that catches EMERGENT cross-domain issues no single held
finding represents — cumulative stimulant/hepatic load summed across the
workout + nutrition + supplement + peptide domains, or a contraindication
visible only when the four domains are read together — issues for which the
reconciler raises 0 holds and the per-finding gate therefore never sees. The
two cover disjoint failure classes (per-finding vs whole-plan); neither makes
the other redundant.

`safety_review.py` is built as the CALLABLE that the orchestrator's
`gate_dispatch=` seam targets (the SAFETY gate, parallel to ADR-0023's quality
gate). This task builds the callable + its mock-tested behavior; the WIRING of
the gate into the orchestrator's loop control flow (calling it post-assembly,
re-running it each revise pass, treating a safety finding as BLOCKING/terminal)
is ADR-0022-T2's job (the revise-loop owner), NOT this task. This task does NOT
modify `plan_orchestrator.py` (see Deviations — scope-boundary confirmation).
