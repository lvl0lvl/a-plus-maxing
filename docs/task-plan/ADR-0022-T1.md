# Recipe: Programmatic Subscription Orchestrator Wrapping the Inner Engine

This task builds the orchestrator CORE: a programmatic drive layer
(`scripts/plan/plan_orchestrator.py`) that takes the de-identified summary
emitted by the Wave-1 `deid_in` boundary, dispatches the plan-domain
specialists programmatically (the runtime surface superseding the S68
interactive session), and drives the existing `pipeline.run_generation` seam
(compute → reconcile → adjudicate → record). It WRAPS the inner engine
verbatim — it re-authors nothing in `orchestrate`/`pipeline`/`assemble`/
`generate_plan`/`adjudicate`/`router`. On a `deid_in` honest-no-plan sentinel
(`{"deidentified": False, ...}`) it HALTS to honest no-plan and dispatches
nothing. The revise loop (ADR-0022-T2) and the dispatch-cap (ADR-0022-T3) are
LATER tasks and are explicitly OUT of scope here.

This task ALSO owns the orchestrator's control surface, so it must expose — as
part of the core — an injectable GATE-DISPATCH SEAM (a `gate_dispatch=`
callable, default a NO-OP that dispatches nothing). The Wave-3 quality judge
(ADR-0023-T1) and safety review (ADR-0024-T1) wire their real gates into THIS
seam; ADR-0020-T2 spies it for the outage gate-idle (0-dispatch) assertion. This
task builds ONLY the seam (the injectable hook + its no-op default), NOT the
gates themselves — the gates are Wave-3 and OUT of scope. (Note: `gate_dispatch`
is a DISTINCT concept from `run_generation`'s existing `gates=` per-domain
safety-inputs dict — do NOT conflate them. `gates=` carries
`clearance_granted`/`red_s_lea_screen` to `compute_plan`; `gate_dispatch=` is
the post-generation judge/safety-review dispatch hook this task adds.)

## Risk Pre-Check
