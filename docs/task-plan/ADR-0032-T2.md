# Recipe: Local Genotype↔Library Matcher + the OQ-3 Curated Variant Set — Pure/Local, 0 Egress, Non-Tautological A≠B Match, Honest No-Match, Read-Only

A NEW local-genetics package `scripts/genetics/` (`test ! -e scripts/genetics` → ABSENT [VERIFIED]) of two production
modules:

1. **`scripts/genetics/variants.py` — the OQ-3 curated planning-relevant set + the excluded set + the item-key deriver.**
   `PLANNING_RELEVANT_VARIANTS` is EXACTLY the operator-curated OQ-3 set (ACTN3 rs1815739, CYP1A2 rs762551, MTHFR
   rs1801131, MTHFR rs1801133, FADS2 rs1535, LCT/MCM6 rs4988235, MTNR1B rs10830963, FTO rs9939609, SOD2 rs4880, ADIPOQ
   rs17300539); `EXCLUDED_VARIANTS` carries APOE/DRD2/BDNF (sensitive / non-actionable — NEVER auto-matched, NEVER
   auto-queried; ADR-0032 Non-goals + OQ-3); the two are disjoint. `variant_item(gene, rsid)` derives the `dna-report`
   item key `"<GENE> <rsID>"` (space-joined, e.g. `"MTNR1B rs10830963"`) — the durable-FACT key ADR-0031 stores
   ([`client.py:311-317`](../../../../scripts/model/client.py)). No I/O, no SDK.
2. **`scripts/genetics/match.py` — the LOCAL genotype↔library matcher.** `match_genotypes(store_read, *, library_root)`
   iterates ONLY `PLANNING_RELEVANT_VARIANTS`; for each curated variant it reads the operator's genotype FACT via the
   injected per-item `store_read("<GENE> <rsID>")` surface and filters `source == "dna-report"`
   (the cross-item source filter precedent [`status.py:69`](../../../../scripts/ingest/status.py):
   `[r for r in store_read if r.get("source") == "dna-report"]`); finds that variant's `vault/library/genetics/` page
   under `library_root` BY `gene`+`rsid` frontmatter (not the filename — the pinned T1↔T2 format contract); and selects
   the per-genotype finding from the page's `## Genotype Findings` section by the operator's LOCAL allele (normalizing
   allele orientation, so a stored `(G;C)` matches a page key `(C;G)`). It returns one resolved match per variant that
   resolves — `{gene, rsid, genotype, trait_class, implication, page}` — where `trait_class` is the coarse hyphenated
   de-id token T3 collects. `unmatched_planning_variants(store_read, *, library_root)` returns the research-gap list:
   the curated variants the operator carries a genotype for but whose library finding does NOT resolve (page absent, OR
   no `## Genotype Findings` entry for the operator's genotype) — reported honestly, NEVER a fabricated finding.

`match.py`/`variants.py` are a PURE, LOCAL, READ-ONLY orchestration: they call the INJECTED `store_read` callable (the
`store.read` surface, pre-bound to the instance root by the caller per the e3b contract,
[`router.py:540-558`](../../../../scripts/plan/router.py)), parse fixture/real genetics pages off `library_root` with a
small private parser, and import NO outbound HTTP client and NO model-client SDK (`anthropic` never appears) and call NO
`store.append`/`store.correct` (the crown-jewel 0-egress-by-construction posture — the operator's raw genotypes stay
100% LOCAL; the matcher is the LOCAL genotype↔implication step ADR-0032 keeps off every egress lane). The package
mirrors how ADR-0031's local-extract front module lives in `scripts/ingest/` — a NEW `scripts/genetics/` package, NOT an
engine edit, so the frozen plan engine + store stay numstat=0 (NFR-2). It is a Wave-1 entry point (no inbound edges):
T3's `router._genetic_trait_classes_token` calls `match.match_genotypes` and collects each match's `trait_class`; T4's
`research_query` imports `variants.EXCLUDED_VARIANTS`/`PLANNING_RELEVANT_VARIANTS`. There is no Python page-parser to
reuse (`scripts/lib/wiki-helpers.sh` is the bash INGESTION gate, T1's surface, not importable here) — `match.py` parses
the pinned-format page itself; the fail-closed honesty is INHERENT — an unresolved variant is a reported gap, never a
fabricated trait.

## Interface Contracts

This task CREATES two interfaces consumed by ADR-0032-T3 and ADR-0032-T4: the `match.match_genotypes` /
`match.unmatched_planning_variants` matcher and the `variants` curated set. It MODIFIES no shared interface (it CALLS
the INJECTED `store_read` callable and PARSES fixture/real genetics pages; it edits no `store.py`, no `router.py`, no
engine file).

- **`match.match_genotypes(store_read, *, library_root)` (CREATED, consumed by T3).**
  - Signature: `match_genotypes(store_read, *, library_root) -> list[dict]`. In: `store_read` (Callable — the per-item
    `store.read` surface, `store_read(item) -> list[reading]`, pre-bound to the instance root by the caller per the e3b
    contract, [`router.py:540-558`](../../../../scripts/plan/router.py)); `library_root` (str | Path — the
    `vault/library/genetics/` root). Out: a list of resolved matches, one per CURATED variant the operator carries a
    `dna-report` genotype for AND whose library page + per-genotype finding resolve — each `{gene, rsid, genotype,
    trait_class, implication, page}`. T3's `router._genetic_trait_classes_token` calls `match.match_genotypes(store_read,
    library_root=...)` and collects each match's `trait_class` into the `;`-joined `genetic-trait-classes` token.
  - **Crown-jewel local / 0-egress (NFR-1c):** the match is LOCAL and read-only — the operator's raw genotypes never
    leave the machine and never reach the planner (T3's deriver collects only the coarse `trait_class`, never the
    `genotype`). `match.py`/`variants.py` import no outbound client / SDK and call no `store.append`/`store.correct`.
  - **Non-tautological selection (AC-2):** the returned `trait_class`/`implication` is the operator's-allele lookup
    against the page's `## Genotype Findings` (a distinct genotype yields a distinct finding), never a code constant.
  - **Orientation normalization (AC-5):** the operator's allele orientation is normalized before the per-genotype
    lookup (`(G;C)` ≡ `(C;G)`), so a stored value matches the page key regardless of allele order.
  - **Read-surface discipline (AC-7):** `store_read` is called ONLY with curated-variant item keys (`"<GENE> <rsID>"`);
    a non-`dna-report` reading under a curated item is filtered out (`source == "dna-report"`, the [`status.py:69`]
    (../../../../scripts/ingest/status.py) precedent).

  consumed by T4 + by `match.py`).**
