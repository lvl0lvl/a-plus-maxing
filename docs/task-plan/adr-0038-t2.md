## Risk Pre-Check

The spec task block carries non-empty Risk Mitigations. This section is BLOCKING: the RED phase must include a test/command for each before any production change.

**Risk 1 — ADR-0038 Alternative C rejection (no periodization rewrite of the flat schema).**
- Negative consequence: a schema/writer edit to `plan_schema.py` to carry week/month structure would be the rejected high-blast-radius periodization rewrite, breaking the date-equality "today" resolution and every existing plan consumer.
- Gate condition: a verification asserting `plan_schema.py` is UNCHANGED — `git diff --numstat <wave-base>..HEAD -- scripts/store/plan_schema.py` → 0 changed lines (AC-3). A subjective "we didn't mean to edit it" does not satisfy the gate; the numstat command is the gate.

**Risk 2 — ADR-0038 Validation "enrichment rides D2 with zero schema change".**
- Negative consequence: if the horizon extras did NOT ride the open-on-extras seam, either an enriched plan would fail validation (forcing a schema edit) or a flat plan would stop validating (breaking the graceful floor).
- Gate condition: paired tests that (a) a `plan::<domain>` value carrying the horizon extras validates through `record_plan` (AC-1) AND (b) a flat `plan::<domain>` value WITHOUT them still validates through `record_plan` (AC-2), both with no edit to `plan_schema.py`. Neither may be a placeholder `assert True` — each seeds a real plan value through `record_plan` and asserts no raise.

## Interface Contracts

This task defines an interface consumed by ADR-0038-T3 (per the spec dependency map: ADR-0038-T3 depends on ADR-0038-T1 + ADR-0038-T2 and reads the `week_expectation` extra + the plan-value extras):

- **Horizon-extra key convention** (a module constant in `scripts/plan/horizons.py` naming the three keys `phase`, `week_intent`, `week_expectation`): the canonical set of keys enriched onto `plan::<domain>` values via the ADR-0010 D2 open-on-extras seam. These keys are permitted by omission from every domain's required/optional dict in `plan_schema` and carry no schema declaration.
- **Read-back accessor** (in `scripts/plan/horizons.py`): given a resolved `plan::<domain>` value, surfaces the horizon extras for the week/month framing; returns absent/empty (no raise) when the extras are absent.
- **Behavioral contract:** the convention rides the D2 seam with zero schema change — an enriched plan and a flat plan both validate through `record_plan`; an unknown/typo'd extra is ignored, not rejected. ADR-0038-T3's date-range classifier reads `week_expectation` off these values as the declared per-week expectation.
- **Change control:** ADR-0038-T3 MUST NOT rename or redefine this key convention without Architect review — it is the read contract T3 consumes.
