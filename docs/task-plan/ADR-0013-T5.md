# Recipe: Egress TEST Over the Request-Handler Dispatch (0 Outbound, Egress-Free by Construction)

This task produces a TEST: `tests/serve/test_serve_no_egress.py`, which PROVES the
upload→ingest→re-render request path is egress-free. It builds a fixture upload request, runs the
handler's upload→ingest→re-render dispatch over a `tmp_path` store INSIDE a zero-arg closure,
passes that closure to the already-audited OS-level egress guard `egress_guard.run`, and asserts
truthy (sockets blocked; the store-write side-effects persist on disk so the assertion is
meaningful, not vacuous). It is failing-capable: an INJECTED outbound call into the dispatch drives
the guard to FAIL (falsy). This is the ADR-0013 Confirmation-2 + Falsification-2 checks, the
ADR-0001 "0 outbound calls carrying store content" boundary realized on the new network surface.

**The guard is the test harness, NOT a per-request production wrapper.** `egress_guard.run` FORKS a
child that applies the OS sandbox, runs the operation, and `os._exit`s with a status code — `run`
returns only a bool to the parent ([scripts/guard/egress_guard.py:82,102-119](../../scripts/guard/egress_guard.py#L82)).
The re-rendered HTML response produced INSIDE the child therefore never returns to the parent
request handler, so the guard CANNOT wrap the production request (which must return a response).
The PRODUCTION server is egress-free BY CONSTRUCTION (it makes no outbound calls) — also proven by
a grep test that `scripts/serve/` imports no `socket.create_connection` / `urllib` / `http.client`
/ HTTP client. The production re-render re-reads the disk store in the PARENT after the
(guarded-in-test) ingest. The TDD Steps follow the standard RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

Active. Each gate maps to a concrete `pytest` test or an `rg` assertion.

- **Risk ADR-0013 Negative-1 / ADR-0001 no-egress** (the new listening socket is a leak surface; it must be proven egress-free by test on the real request path). Mitigation: criteria 1-3 — the failing-capable 0-egress proof + the egress-free-by-construction grep. **Gate (triple, each falsifiable):**
  - **Half A — egress-clean over the REAL request dispatch:** a RED test runs a REAL POST `/upload` of a synthetic `export.xml` (the production stage → route → re-render dispatch, over a `tmp_path` store) INSIDE ONE zero-arg closure, passes it to `egress_guard.run`, and asserts the result is truthy (0 outbound calls across the whole dispatch) AND that the store-write side-effects persist on disk (so the truthy result is meaningful, not a closure that did nothing). A test asserting 0 egress over a no-op (rather than over a real dispatch) fails this gate.
  - **Half B — failing-capable:** a RED test wraps a dispatch that makes ONE injected outbound call and asserts `egress_guard.run` returns falsy (FAIL). **Falsifiable:** the guard is failing-capable by construction (OS-level, `ADR-0001-T1`) — it must flip to FAIL on the injected call, proving it intercepts the request code path (subprocess/async-spawned calls included). A guard that does NOT flip to FAIL is a no-go.
  - **Half C — production egress-free by construction (NOT a production wrap):** a RED test asserts `rg` over `scripts/serve/` finds 0 outbound HTTP clients (`socket.create_connection`, `urllib.request`, `http.client`, `requests`, `httpx`). The production server makes no outbound calls — it is egress-free by construction, NOT by being wrapped in `egress_guard.run` (which it cannot be: the guard forks a child whose re-rendered response never returns to the parent handler). Asserting an `egress_guard.run` wrap in production `server.py` would be WRONG — escalate if a reviewer asks for it.
