# Recipe: Egress Guard Over the Request-Handler Dispatch (0 Outbound, Loopback-Proven)

This task produces CODE: the extension of `scripts/serve/server.py` that wraps the
request-handler dispatch in the already-audited OS-level egress guard `egress_guard.run`,
so any outbound network call during request handling fails the no-network sandbox. It PROVES
the upload→ingest→re-render request path is egress-free (0 outbound calls) AND failing-capable
(an INJECTED outbound call drives the guard to FAIL) — the ADR-0013 Confirmation-2 + Falsification-2
checks, the ADR-0001 "0 outbound calls carrying store content" boundary realized on the new
network surface. This is the load-bearing Wave-A safety gate: the request path is proven
egress-free BEFORE any operator PII is captured through it (Wave B). The TDD Steps follow the
standard RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

Active. Each gate maps to a concrete `pytest` test or an `rg` assertion.

- **Risk ADR-0013 Negative-1 / ADR-0001 no-egress** (the new listening socket is a leak surface; it must be proven egress-free by test on the real request path). Mitigation: criteria 1-2 — the failing-capable 0-egress proof. **Gate (dual, both falsifiable):**
  - **Half A — egress-clean over the REAL request path:** a RED test wraps a REAL POST `/upload` of a synthetic `export.xml` (the production stage → extract → route → re-render dispatch) in ONE zero-arg closure and passes it to `egress_guard.run`, asserting the result is truthy (0 outbound calls across the whole dispatch). A test asserting 0 egress over a no-op (rather than over a real dispatch) fails this gate — it must exercise the production request path.
  - **Half B — failing-capable:** a RED test wraps a dispatch that makes ONE injected outbound call and asserts `egress_guard.run` returns falsy (FAIL). **Falsifiable:** the guard is failing-capable by construction (OS-level, `ADR-0001-T1`) — it must flip to FAIL on the injected call, proving it intercepts the new request code path (subprocess/async-spawned calls included). A guard that does NOT flip to FAIL is a no-go.
  - **Half C — production wrap (not test-only):** a RED test asserts `rg` over `scripts/serve/server.py` finds the `egress_guard.run` wrap — the PRODUCTION request-handler dispatch runs the request path under the sandbox, not merely the test. A wrap present only in the test fails this gate.
