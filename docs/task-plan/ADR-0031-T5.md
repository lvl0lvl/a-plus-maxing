# Recipe: SPA Honest-Partial Note on the Review Panel — No Silent "No New Data" (Clinical-Light-LOCKED Conformance; QA-1 Partial+Empty Fold-In; Inline-Asset Clean)

A Wave-3 leaf task: surface T4's honest partial/too-large signal on the EXISTING operator-approved Clinical-Light-LOCKED SPA review panel. Today, when an unrecognized-format upload returns the extracted-readings JSON review payload, the inline JS populates `#review-panel` and the operator confirms what lands ([app_view.html:485-489] the panel, [:759-765] `showReview`, [:766-796] `up(f)`). T4 (Wave 2) extends the server `/upload` payload from `{"readings": [...]}` to `{"readings": [...], "partial": bool, "notes": [...]}` so a document too large/dense to fully extract carries an honest signal. The SPA does NOT consume `partial`/`notes` today (`grep -c "partial\|notes\|extraction-note" vault/design/templates/app_view.html` → **0** in the upload flow) — so a partial extraction with 0 surfaced readings currently falls through to `showReview([])`, which RE-SHOWS the awaiting `.empty` div ([:763] `aw.style.display=readings.length?'none':''` → `''` when `readings.length==0`). That is the exact silent "no new data" failure ADR-0031 forbids: the operator is told nothing was found when in fact the document was too large/dense to fully read.

This task does ONE thing in TWO parts, both in the SPA design source `vault/design/templates/app_view.html` (which `app_shell.render` reads VERBATIM via `_VIEW.read_text()` [app_shell.py:104], so the served GET `/` body via `generate.run("app")` → `server.py:_render_intake` carries the edits):

1. **A partial-extraction note on the review panel.** Add a note element inside the existing locked `#review-panel` (`#panel-build`/`ws-docs`) that displays the `notes` when the `/upload` payload's `partial` is true — a note in the EXISTING Clinical-Light panel idiom (the locked `.empty` / `.upload-status` / `data-awaiting` convention already in the file), NOT a redesign, NOT a new surface. Its DEFAULT rendered state is honest-empty: default-hidden, no fabricated note baked into the HTML as if an extraction ran.

2. **The `partial`/`notes` inline-JS branch + the QA-1 awaiting-state gate.** Thread `partial` + `notes` from T4's JSON `/upload` payload through the upload-response flow into `showReview`, and gate the awaiting-state display on the PARTIAL SIGNAL, not just `readings.length`. **FOLD-IN QA-1 (load-bearing): `partial==True` + `readings==[]` → the SPA shows the note AND HIDES the awaiting/empty state** — the operator is told "this document was too large or dense to fully extract", NEVER a silent "nothing found". A genuinely-empty extraction (0 findings, not partial) still shows the honest awaiting state; a partial extraction WITH readings shows BOTH the readings AND the note.

The byte-frozen ingest engine (`scripts/ingest/{ingest,adapter}.py`) + every `scripts/plan/*.py` + the `keying.py`/`store.py` sink stay numstat=0 (EXTEND-NOT-REBUILD, NFR-3) — T5 touches ONLY `app_view.html` (markup + inline JS) + `tests/serve/test_app_shell.py`. T5 adds 0 new browser outbound class: the note consumes T4's existing `/upload` payload; no new `fetch()` target. The build is the rendered-SPA-HTML string + the standalone `app_shell.render` / the real `generate.run("app")` emit — MOCK/fixture-tested at 0 live spend (no live API, no key, no non-loopback socket).
