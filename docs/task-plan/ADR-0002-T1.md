A test that only checks the happy path (a complete reading appends) fails this gate — the raise-and-0-new-lines assertion is required. This gate is satisfied in Cycle 2 RED (the `store.append` cycle).

This gate is satisfied in Cycle 1 (the gitignore + keying cycle). The no-repo-backup consequence of N4 is carried as a documented limitation (spec Proceed disposition), not a task here — do not add backup logic (scope creep).

  - Appends one NDJSON line for `reading` to the item's per-item file under the store root, idempotently: a reading whose dedupe identity is already present writes 0 new lines.

- **Function:** `store.read(item)` in `scripts/store/store.py`
  - Returns the item's readings as a sequence ordered by timepoint (non-descending), whole-file scan, all appended timepoints present.

## Deviations

**DEV-1: Package-discovery files needed for imports, not in the 5-file manifest.**
The spec's file manifest for this task lists exactly five files (`scripts/store/keying.py`, `scripts/store/store.py`, `.gitignore`, `tests/store/test_keying.py`, `tests/store/test_store.py`). This is the first Python package and first `pytest` suite in the repository: there is no `scripts/__init__.py` / `scripts/store/__init__.py`, no `tests/` directory, no `conftest.py`, and no pytest config (`pyproject.toml` / `pytest.ini`) at the repo root. For `tests/store/test_store.py` to import `scripts.store.store` (and for `store.py` to import `keying`), pytest discovery needs the project root on `sys.path` so the flat `scripts/`-as-namespace import path (`from scripts.store import store`) resolves. None of the enablers is in the spec manifest.

- **What changed (pinned):** the executor creates ONE concrete discovery file beyond the 5 manifest files — a **repo-root `conftest.py` that puts the project root on `sys.path`**. This is the pinned choice (not "one of several"): it is the lowest-footprint enabler and matches the flat `scripts/`-as-namespace layout the recipe's imports use (`from scripts.store import store`), so the executor makes no undocumented architecture decision mid-build. It does NOT introduce `__init__.py` markers or a `pyproject.toml` pytest stanza — `conftest.py` alone resolves the import path for both the `scripts/` package imports and the `tests/` collection.
- **Why:** without it, AC-7's `pytest tests/store/test_store.py tests/store/test_keying.py` cannot collect/import the modules — the criterion is unsatisfiable as written against an empty repo. This is mechanically necessary, not feature scope.
