# Recipe: Bounded Confirmation-Pointer Stream + Shared Caller-Side Pre-Filter (Store Surface)

> Wave-1 entry-point task. It creates the bounded `plan-confirm::<domain>` pointer stream
> (`mark_pending` / `set_decision` / `decision_for`) and the shared caller-side pre-filter
> (`filter_confirmed`) that every downstream task consumes: T2's read-side skip imports
> `filter_confirmed`, T3's loop writes `mark_pending`, T4's confirm act flips `set_decision`.
> This IS a store-surface task — the four-part store-adversarial battery (bead `pka`) is a
> BLOCKING Tier-1 gate, category (d) run RED under two named mutations. The pointer is bounded
> to `(domain, plan_date) -> decision`; a widened value leaks plan content (the ADR-0038
> relaxation's audited cost). The record WRITE path stays byte-frozen: the pointer is appended
> through the UNCHANGED `store.append` / `store.correct` sinks under a distinct item namespace.

## Risk Pre-Check

**BLOCKING GATE — store-surface task (bead `pka`) + a new stream relaxing ADR-0038.** Do not proceed to GREEN until a real (non-`assert True`) test exists for every risk below. A placeholder test fails this gate.

- **Risk (ADR-0040 Consequences-Negative-1 — a bounded new stream relaxes ADR-0038's zero-new-stream rule):** an unbounded pointer value would smuggle plan content into a schema-relaxing stream (a one-way door).
  - Gate condition: RED must include a test that a WRITTEN pointer value's keys are a subset of `{"decision"}` AND a source-grep of `scripts/store/plan_confirm.py` finds 0 `plan::`-content field names (`exercises`/`meals`/`items`/`compound`), count == 0 (covered by AC-4).
- **Risk (S37–S41 store-keying escape pattern, bead `pka`):** the builder + Tier-2 systematically under-test store cross-stream / dedupe / correction-path cases; five consecutive waves shipped a store-keying escape caught only at Tier-3.
  - Gate condition: RED must include all four adversarial categories as real tests — (a) cross-stream namespace-disjoint, (b) same-timepoint dedupe (two distinct-source writes persist, identical re-write no-op), (c) dedupe-key boundary + correction-path (re-`set_decision` appends 0 lines, superseded pending never current, never-stored `set_decision` fails loud, cross-stream correction isolated), (d) mutation — a NAMED battery test must go RED when `_PREFIX_CONFIRM` is removed (cross-read) OR the store dedupe key is widened to include `value` via `monkeypatch.setattr(keying, "DEDUPE_FIELDS", keying.LINE_FIELDS)` (correction stops superseding), then reverts (covered by AC-5). Patching `keying._DEDUPE_EXCLUDED` is INERT — `DEDUPE_FIELDS` is import-frozen from it and `dedupe_key` reads `DEDUPE_FIELDS`, so only patching `DEDUPE_FIELDS` bites. A battery green under these two mutations is tautological and FAILS this gate.

## Interface Contracts

This task CREATES the `plan_confirm` API — the shared seam every downstream ADR-0040 task consumes:

- `plan_confirm.mark_pending(domain, plan_date, root) -> None` — appends one `plan-confirm::<domain>` `pending` pointer at timepoint `plan_date` via `store.append`. Consumed by **ADR-0040-T3** (the loop writes it on the large-change branch, before `regenerate` returns).
- `plan_confirm.set_decision(domain, plan_date, decision, root) -> None` — supersedes the stored pointer's value via `store.correct`; raises `ValueError` on a never-stored `(domain, plan_date)`. Consumed by **ADR-0040-T4** (the confirm/decline operator act flips `pending` → `confirmed`/`declined`).
- `plan_confirm.decision_for(domain, plan_date, root) -> str | None` — the current decision for a `(domain, plan_date)`, or `None` when no pointer. Consumed internally by `filter_confirmed`; available to **ADR-0040-T4**.
- `plan_confirm.filter_confirmed(readings, domain, root) -> list` — returns `readings` minus any whose `timepoint` carries a non-`confirmed` (i.e. `pending`/`declined`) pointer; a no-pointer or `confirmed` reading is kept unchanged. Consumed by **ADR-0040-T2** (the caller-side pre-filter `read_plan` / `window_block` / `tailor` apply before the pure resolve).
- Behavioral invariants: the pointer value is bounded to `{"decision": <token>}` (0 plan-content fields); the stream is written through the UNCHANGED `store.append`/`store.correct` sinks (record WRITE path byte-frozen); the module imports `scripts.store.store` ONLY (no `plan_schema` cycle).
- Change control: ADR-0040-T2/T3/T4 MUST NOT change these signatures without Architect review (the build plan assigns Architect to this wave for exactly this seam).
