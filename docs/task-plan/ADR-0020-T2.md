# Recipe: De-Id-Boundary Whole-Run Outage → Fail-Closed Halt

When the de-id API boundary is DOWN / unreachable for a WHOLE run (not a single failed
call), the engine HALTS to the honest no-plan state: 0 plans recorded, the existing
maintained artifact untouched, and the downstream gates (judge ADR-0023, safety review
ADR-0024) issue 0 dispatches. It does NOT silently degrade to the deterministic
`router.summarize` gate as a coarse de-id-IN substitute — never relax de-id fidelity on a
crown-jewel boundary (ADR-0020 OQ-4, disposition #3 fail-closed-halt). This asserts the
orchestrator's halt-before-dispatch behavior on a de-id-boundary outage.

**De-id-IN boundary is already fail-closed (grounded):** `scripts/plan/deid_in.py`
collapses ANY exception from the de-id call to the SINGLE honest-no-plan sentinel
`{"deidentified": False, "reason": DEID_CALL_FAILED}` (`except Exception` →
`DEID_CALL_FAILED`, verified at `deid_in.py:63-72`). A whole-run outage is byte-identical to
a per-call failure AT THE `deid_in` BOUNDARY — no signal distinguishes them there. So this
task does NOT add a "distinct outage reason" to `deid_in`: the orchestrator treats the
existing `DEID_CALL_FAILED` sentinel as the halt trigger (which is all AC-1 / AC-3 / AC-4
need). The work is entirely in the orchestrator's halt-before-dispatch control flow over the
existing sentinel; `deid_in.py` is NOT modified by this task.

**Build-plan wave attestation (v1-build):** this is build-plan Wave 2 (`docs/build-plan/build-plan-plan-gen-engine.md` §Wave 2). The prior wave's checkpoint Go/No-Go (Wave 1 → Wave 2: T0-SCANSCOPE + ADR-0020-T1 ACs run-and-observed green; 0-leak gates green) must have passed before this task builds. ADR-0020-T1 is merged (commits `20944cf` + `fdad236`).

**INTRA-WAVE DEPENDENCY (load-bearing — see UPSTREAM FLAG below):** AC-4's gate-idle assertion (judge dispatch = 0 AND safety-review dispatch = 0 on outage) requires the orchestrator's `gate_dispatch=` seam to exist, and that seam is built by **ADR-0022-T1 — the SAME Wave 2** (0022-T1 fix M1/3.1: the injectable no-op gate-dispatch hook). ADR-0020-T2 MUST build AFTER ADR-0022-T1. The Entry State requires 0022-T1 complete. AC-4 is satisfied by injecting a recording spy into 0022-T1's `gate_dispatch=` seam and asserting it fires 0 times on outage — the real Wave-3 gate modules are absent and the spy stands in for them; it does NOT need the real judge/safety modules (those are Wave 3). See the UPSTREAM FLAG (non-blocking) for the satisfiability analysis.

## Risk Pre-Check

This task carries risk mitigations in the spec (ADR-0020 Consequence-Negative-4 / OQ-4; ADR-0025 Falsification-2; ADR-0020 OQ-4 gate-idle). The gate: before GREEN, a failing-capable test must exist for EACH risk. A placeholder (`assert True`) fails this gate.

- **Risk R1 — whole-run de-id outage would let the engine silently degrade de-id fidelity (ADR-0020 Consequence-Negative-4 / OQ-4):** Gate — a test injects the de-id boundary as unreachable for the whole run (a `_FixtureBackend(deidentify_result=ModelCallError(...))` / a client whose `deidentify` raises `ModelCallError`) and asserts the orchestrator records 0 plans and surfaces the honest no-plan state. The test must turn RED if the engine recorded any `plan::<domain>` after an injected outage (a degrade-to-`summarize` or a fabricated summary would record a plan). Covers AC-1.
- **Risk R2 — the engine must NOT fall back to `router.summarize` as a degraded de-id-IN on outage:** Gate — a test spies/mocks the `router.summarize` call site and asserts 0 calls to `summarize` AS A DE-ID-IN SUBSTITUTE on the outage path (the persisted-side `summarize` is a distinct legitimate use; the assertion targets the de-id-IN-substitute call, i.e. the orchestrator never routes the raw intake through `summarize` to keep going). The test must turn RED on a boundary that degraded to `summarize` to continue the run. Covers AC-2.
- **Risk R3 — a boundary outage must not trigger a partial / stale re-emit (ADR-0025 Falsification-2):** Gate — a test seeds an existing maintained-HTML artifact, injects the outage, and asserts the artifact's bytes are IDENTICAL pre- and post-outage (no partial re-emit, no clobber). The test must turn RED if the outage path rewrote / truncated / partially re-emitted the artifact. Covers AC-3.
- **Risk R4 (gate-idle, the missing negative assertion — E2E-placement discipline, ADR-0020 OQ-4) — on outage the downstream gates must issue 0 dispatches:** Gate — a test injects a recording spy into the orchestrator's `gate_dispatch=` seam (the injectable hook ADR-0022-T1 built; the judge AND safety-review both dispatch through this one seam, so a single recording spy counts all gate dispatches) and asserts the spy's dispatch count = 0 after an injected outage. The test must turn RED if the orchestrator dispatched any gate on a non-summary (e.g. it reached the `gate_dispatch` seam despite the outage halt). Covers AC-4. This is the negative-assertion gate: "data does NOT land where it should not" (CLAUDE.md E2E-placement discipline) — the gate-dispatch seam is IDLE on outage, asserted, not merely "a plan is absent". **Wave-4 re-assertion note:** this asserts the seam is idle against the Wave-2 NO-OP gate_dispatch default; re-assert AC-4 at the Wave-4 checkpoint when ADR-0022-T2 wires the REAL gate dispatch into the seam, so the gate-idle-on-outage property holds against the WIRED path, not only the Wave-2 no-op seam.

No risk is deferred. Every gate references a falsifiable test, not a subjective assessment.
