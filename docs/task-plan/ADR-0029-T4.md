# Recipe: Not-Naive Intake Elicitation on the SPA Surface (Sentinel Bands = Gap; Fresh Operator Asked; Never Vacuous `intake_complete`)

A **test-only PROOF task** (0 production change). It creates `tests/serve/test_intake_elicitation.py` to
PIN — on the SPA-served `/chat` surface — that a fresh operator (the four chat-band tokens at their
`not-discussed` sentinel) is ASKED the genuine gap and that those sentinels read as a GAP, never a vacuous
`domain_done` / `intake_complete` (PF-S87-01). It binds the ALREADY-BUILT `/chat` mechanism
(`chat.plan_next_turn` / `_missing_fields` / `domain_done` / `intake_complete` / `record_only` /
`_DOMAIN_TOKENS`, the served `/chat` route, the `router._ALWAYS_SET_DERIVED` sentinels) — it adds, mints,
or modifies NO production code.

**GROUNDING FINDING (load-bearing — read before RED).** The built mechanism ALREADY satisfies not-naive,
confirmed against the live tree (`main @ 1fec2d4`, 2026-06-26): a fresh operator's `router.summarize`
output carries the four `_ALWAYS_SET_DERIVED` chat tokens (`dietary-pattern-class` /
`supplement-stack-class` / `peptide-use-class` / `training-volume-band`) ALL at the `_NOT_DISCUSSED =
"not-discussed"` sentinel (`router.py:230,361,386,410,443`), and `chat._DOMAIN_TOKENS` maps
`nutrition`/`supplements`/`peptides` to the EMPTY tuple (`chat.py:39-56`), so `plan_next_turn` over a
fresh operator returns `target_domain="goals"`, `missing_fields=(the 4 goals tokens)`,
`record_only=("nutrition","peptides","supplements")`, `domain_done=False`, `intake_complete=False`. This
task therefore PROVES a built property; it does NOT drive new code. The TDD RED phase here means the
NEGATIVE CONTROL is demonstrated FAILING-CAPABLE (it goes RED on a deliberately-naive mechanism), not that
the not-naive assertions fail first (they pass against the built mechanism — that passing IS the proof). A
failing-capable control is mandatory: a test that passes with or without the not-naive behavior proves
nothing (PF-S87-01). See **Deviations** for the GREEN-at-RED framing.

The SPA-served `/chat` route (the surface T1 stands up) is the surface this elicitation runs on; T4 POSTs
to `/chat` DIRECTLY (it does NOT consume T3's SPA chat-composer fetch markup), so its only precondition is
that the SPA surface is SERVED (T1), not that the composer is wired (T3). The byte-frozen inner engine +
the `/chat` mechanism stay numstat=0; the ONLY file this task writes is the new test. The build is
MOCK/FIXTURE-tested at 0 live spend (the mock backend injected at the ADR-0015 `ModelClient(backend=...)`
seam).

## Risk Pre-Check

This task carries the spec's ADR-0029-T4 Risk Mitigations field. Before proceeding to RED, verify a test
exists (or the RED phase adds one) for EACH gate below. A placeholder test (`assert True`) fails this
gate. The gate conditions reference live tests/commands, not subjective assessments.

- **Risk — a tautological elicitation proof (PF-S87-01, the headline of this task).** A test that passes
  with OR without the not-naive behavior proves nothing. Gate: a FAILING-CAPABLE negative control exists
  whose assertion FLIPS to FAIL if the sentinel were treated as captured — (a) an all-sentinel session
  (`covered_domains={nutrition,supplements,peptides}`, summary carrying the four `not-discussed`
  sentinels) asserts `domain_done is False`; this assertion would FAIL if the strategy counted the present
  sentinel tokens as a planner-feeding done (the vacuous-`domain_done` bug); (b) the COMPLEMENTARY
  gaps-filled case asserts `intake_complete is True` AND the three sentinel domains REMAIN in
  `record_only` — proving the verdicts distinguish complete from incomplete (not constant-False), and that
  the present sentinels are NOT counted as captured (they'd drop out of `record_only` if they were). The
  RED step DEMONSTRATES the control is failing-capable via a transient mutation-oracle (Step 1b), 0
  commit. (T4 crit 4; PF-S87-01.)
- **Risk — a sentinel band vacuously satisfies `domain_done` / `intake_complete` (PF-S87-01 / design
  CONCERN-1).** A chat-covered domain whose token is at its `not-discussed`/`none`/`moderate` sentinel
  must report RECORD-ONLY (captured-for-record, not-planned), NEVER `domain_done` from the sentinel. Gate:
  a fresh-operator served-`/chat` drive asserts the sentinel domains resolve to `progress["record_only"]`
  and NEVER `domain_done`; a grounding guard asserts `chat._DOMAIN_TOKENS[d] == ()` for each record-only
  domain so the proof RE-GROUNDS (reds) if a future ADR-0019 batch mints those tokens rather than silently
  testing a now-minted domain. (T4 crit 2,3.)
- **Risk — the elicitation control surface leaks raw operator PII (crown-jewel, ADR-0029 PII-boundary).**
  The returned `TurnIntent` / the served-`/chat` `progress` it projects must carry 0 raw operator string —
  token NAMES (`missing_fields`), domain NAMES (`target_domain`/`record_only`), and booleans
  (`domain_done`/`intake_complete`) ONLY. Gate: a drive that SEEDS an identifiable raw value into a `/chat`
  turn asserts that value does NOT appear anywhere in `progress`, AND every `progress` value is a domain
  name (∈ `CHAT_DOMAINS`), a token name (∈ `SUMMARY_FIELD_SET`), a boolean, or None. (T4 crit 5; NFR-1.)
- **Risk — scope creep into production (test-only, 0 production change).** Gate (a SHELL gate run in
  REGRESSION + at the Wave-2 checkpoint, NOT a RED-first pytest test — `<wave-base>` is a `git merge-base`
  unresolvable inside pytest): `git diff --numstat <wave-base>..HEAD` lists EXACTLY ONE file —
