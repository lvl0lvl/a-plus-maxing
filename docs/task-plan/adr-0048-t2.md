# ADR-0048-T2 — App-mediated OAuth authorization-code flow + localhost PKCE callback + the D7 wire-scan

## Goal

Build `scripts/serve/oauth_callback.py` — the one-shot `127.0.0.1` OAuth callback listener (PKCE
code-challenge/verifier + `state`/CSRF + code→token exchange behind a fail-closed no-follow-redirect
opener) — and a `server.py` connect-start route that spins up the listener and opens the vendor
authorize URL. On a matching callback the exchanged token is written through the **ADR-0048-T3
per-source write class** into the SAME `a-plus-maxing-<source>-oauth` item `oauth_pull`'s reader
reads. The load-bearing deliverable is the **D7 crown-jewel wire-scan** — the OAuth sibling of the
ADR-0049-T1 D2 scan: driving auth→callback→exchange under a recording network seam proves 0 store
bytes in any outbound request, 0 no-train-model-lane calls, and the vendor's own authorize/token
endpoint as the ONLY outbound host — each family per-family RED-gated by a self-invalidating mutation
(the D2 gold standard).

## Consumer-contract grounding (PF-S141-02 — enumerate the seam this task WIRES ONTO, at grounding time)

This task WRITES via a consumer seam. Per PF-S141-02 (the ADR-0049-T1 REJECT lesson: a wired-onto
seam's FULL contract must be enumerated at grounding, not just its signature), the ADR-0048-T3
per-source write class the callback consumes is `IntakeRequestHandler._save_tracker_token`
(`server.py:1017`), whose write core is **`secret_store.set_secret(oauth_pull._oauth_service_name(source), token)`**
(`server.py:1087`) reached ONLY AFTER: (a) exact-membership source validation
`source in oauth_pull._MANIFESTS` (`:1074`, fail-closed 400 "unknown source" — this closes the
service-name-injection surface: an unvalidated source could write an arbitrary keyring item), and
(b) `token.strip()` non-empty (`:1077`). **Contract the callback MUST honor:** it writes the exchanged
token through `secret_store.set_secret(oauth_pull._oauth_service_name(source), token)` for a `source`
it has FIRST validated `in oauth_pull._MANIFESTS` and a stripped-non-empty `token` — so the token
lands in the exact item `oauth_pull`'s default `credential_reader` reads, and no unvalidated source
can inject a keyring item. The write NEVER logs/echoes the token (NFR-3). `set_secret` raises
`secret_store.KeyStoreError` on a failed write (including the clear-fail case where the write
SUCCEEDED but stale fallback residue could not be cleared — so a failure path must NOT assert
"unstored" as certainty). To avoid duplicating the validation, EXTRACT the shared write path
(source-validate → strip → `set_secret`) into a helper both `_save_tracker_token` and the callback
call, OR the callback calls the same `secret_store.set_secret(oauth_pull._oauth_service_name(source), token)`
after the identical `_MANIFESTS` membership + strip guards (SE's discretion — the CONTRACT is that
both paths write through the same validated derivation site; do not add a second unvalidated writer).

## Design (what the SE builds — no literal code here; this is the contract)

### `scripts/serve/oauth_callback.py` (CREATE)

- **The PKCE authorize URL builder:** given a `source` (validated `in _MANIFESTS`) + the vendor
  config (client_id from `alpha_config`, authorize endpoint), mint a `state` (CSRF nonce) + a PKCE
  `code_verifier`/`code_challenge` (S256), and build the authorize URL carrying the challenge + state
  + the `127.0.0.1:<ephemeral>` redirect_uri. The verifier + state + source are held in memory for the
  one-shot callback match (never persisted).
- **The one-shot `127.0.0.1` listener:** binds `127.0.0.1` on an ephemeral port (assert the bind
  address is loopback, never `0.0.0.0`/`""` — AC-2), accepts EXACTLY one callback, then tears down
  (a second request to the port is refused / the socket closed — AC-5).
- **The callback handler:** on the callback, REJECT a mismatched `state` (0 token writes — AC-3);
  on a match, run the code→token EXCHANGE.
- **The code→token exchange (fail-closed, AC-1/AC-4):** POST the code + `code_verifier` to the
  vendor's token endpoint through a host-locked opener that MIRRORS `oauth_pull._NoFollowRedirect`
  (build an opener with a `redirect_request`→`None` handler; the exchange refuses to follow ANY 3xx
  and host-locks the token endpoint) — so a token endpoint returning a 3xx-to-another-host aborts the
  exchange with 0 credential bytes reaching the redirect target + 0 token writes (AC-4). PKCE
  protects the EXCHANGE: a fixture token endpoint receiving a missing/mismatched `code_verifier`
  rejects → 0 token writes (AC-1).
- **The write (the PF-S141-02 consumer contract):** on a successful exchange, write the token through
  `secret_store.set_secret(oauth_pull._oauth_service_name(source), token)` after the SAME
  `source in oauth_pull._MANIFESTS` + `token.strip()` non-empty guards `_save_tracker_token` applies
  (extract the shared write path or call the identical derivation — one validated writer, per the
  grounding note). Never log/echo the token. `KeyStoreError` → a fail-closed error that does not
  assert "unstored" as certainty.
- The network + the model lane are NEVER touched on this path except the vendor authorize/token host;
  the module reads no store (structural — imports no `scripts.store` symbol; mirror the D2 guarantee).

## Acceptance Criteria (executable RED/GREEN checks)

Each AC either REDs on feature-absence, or — for a negative/no-leak assertion — is validated by an
in-suite `pytest.raises` meta-assertion (the D2/AR-005 discipline). All env via `monkeypatch`; hermetic,
$0 (fixture vendor endpoints via injected seams — no live network; the model lane fake; no live key).

1. **PKCE exchange + write via the ADR-0048-T3 class (AC-1).** A matching callback (correct `state`)
   drives the code→token exchange carrying the `code_verifier` for the issued challenge → the fixture
   token endpoint accepts → the token is written via `secret_store.set_secret(oauth_pull._oauth_service_name(source), token)`
   (assert the exact item + value written, `secret_store` dict-mocked). **Falsifier:** a fixture token
   endpoint receiving a MISSING or MISMATCHED `code_verifier` rejects the exchange → **0 token writes**
   (assert the mock `set_secret` never called).
2. **Loopback-only bind (AC-2).** The listener's bind address is asserted `127.0.0.1` — never
   `0.0.0.0`/`""` (0 non-loopback binds). Falsifier: a mutant binding `0.0.0.0` REDs the assertion.
3. **`state`/CSRF mismatch (AC-3).** A callback whose `state` differs from the issued value → **0
   token writes** (the exchange never runs). Falsifier: the matching-state case DOES write (proves the
   0-write is the mismatch rejection, not a dead path).
4. **No cross-host redirect on the exchange (AC-4).** A fixture token endpoint returning a
   3xx-to-another-host → the exchange ABORTS with **0 credential bytes reaching the redirect target**
   (a recording seam on the redirect host asserts 0 bytes) AND **0 token writes**. The opener mirrors
   `oauth_pull._NoFollowRedirect` (`redirect_request`→`None`). Falsifier (in-suite meta-assertion): a
   mutant opener that DOES follow the 3xx → the redirect-host recorder sees credential bytes →
   `pytest.raises(AssertionError)` the scan REDs.
5. **One-shot listener (AC-5).** After accepting exactly one callback the listener tears down: a
   second request to the ephemeral port is refused / the socket closed (assert
   `ConnectionRefusedError`/closed). Falsifier: a mutant that re-accepts → the second request succeeds
   → the one-shot assertion REDs.
6. **D7 crown-jewel wire-scan (AC-6, load-bearing — the D2 gold-standard shape).** Drive
   auth→callback→exchange under a RECORDING network seam capturing the ACTUAL outbound requests (the
   bytes sent, not seam-inbound args), with a store-content sentinel seeded into the store + a
   model-lane call-counting fake. Assert the CLEAN direction FIRST: (a) **0 bytes of store content**
   in any outbound request body/header (the sentinel appears 0 times; the module performs 0 store
   reads — a module-level `store.read/read_all/items` spy + a structural no-`scripts.store`-import AST
   check); (b) **0 calls to the no-train model lane** (`_ClaudeNoTrainBackend` fake call-count 0);
   (c) the **ONLY outbound host** is the vendor's own authorize/token endpoint. Then RED-gate EACH
   family with a self-invalidating mutation, each wrapped in `pytest.raises(AssertionError)` so a scan
   that CANNOT go RED fails the meta-assertion: a stub adding a store-content byte to the outbound leg
   MUST RED the store-content assertion; a fixture token endpoint returning a 302-to-attacker-host
   MUST RED the vendor-only-host assertion (asserting 0 credential bytes reach the redirect target +
   the exchange aborts — this is AC-4's mutation, shared); a stub opening a no-train model-lane call
   on the auth/callback path MUST RED the model-lane assertion. **The test is invalid, and itself
   fails, if any mutation does not RED its family.**
7. **Frozen-six untouched (AC-7).** Re-run the Entry State 8 frozen-six `git diff --numstat` on the
   FINAL tree; it prints nothing (the callback lands in `scripts/serve/`, the route in the existing
   `server.py` connect-start region — both outside the six).
