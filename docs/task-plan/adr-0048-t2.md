# ADR-0048-T2 — App-mediated OAuth authorization-code flow + localhost PKCE callback + the D7 wire-scan

## Goal

Build `scripts/serve/oauth_callback.py` — the one-shot `127.0.0.1` OAuth-2.0 authorization-code
callback (PKCE code-challenge/verifier + `state`/CSRF + a code→token exchange behind a fail-closed
no-follow-redirect opener) — and a `server.py` connect-start route that spins up the listener and
opens the vendor authorize URL. On a matching callback the exchanged **refresh_token** (in the
per-vendor shape the reader consumes — see the consumer contract) is written through the ADR-0048-T3
per-source write path into the SAME `a-plus-maxing-<source>-oauth` item `oauth_pull`'s reader reads.
The load-bearing deliverable is the **D7 crown-jewel wire-scan** — the OAuth sibling of the ADR-0049-T1
D2 scan, captured at the TRUE HTTP wire (`opener.open(request)`): driving auth→callback→exchange
proves 0 store bytes in any outbound request, 0 no-train-model-lane calls, and the vendor's own
authorize/token endpoint as the ONLY outbound host contacted — each family per-family RED-gated by a
self-invalidating mutation on the REAL opener (the D2 gold standard).

## Consumer-contract grounding (PF-S141-02 — enumerate the FULL contract of the seam this task WIRES ONTO, incl. the DOWNSTREAM READER's value-format)

The ADR-0049-T1 REJECT taught: a wired-onto seam's FULL contract must be enumerated at grounding —
its write-site gates AND its downstream reader's value-format — and the E2E must drive the PRODUCTION
consumer, never a fixture. This task writes an item with exactly ONE downstream consumer; both halves:

**(A) The write-site (`_save_tracker_token`, `server.py:1017`).** Write core:
`secret_store.set_secret(oauth_pull._oauth_service_name(source), token)` (`:1087`), reached ONLY after
exact-membership `source in oauth_pull._MANIFESTS` (`:1074`, fail-closed 400 — closes service-name
injection: an unvalidated source could write an arbitrary keyring item) + `token.strip()` non-empty
(`:1077`). `set_secret` raises `secret_store.KeyStoreError` (`secret_store/__init__.py:87`) on a failed
write INCLUDING the clear-fail case where the write SUCCEEDED but stale fallback residue could not be
cleared — so a failure path must NOT assert "unstored" as certainty. **MANDATE (resolves QA SHOULD-FIX
4 / the extract-vs-duplicate ambiguity): EXTRACT the shared write path** (source-membership-validate →
strip-non-empty → `set_secret(_oauth_service_name(source), token)` → KeyStoreError-fail-closed) into
ONE helper (e.g. `oauth_callback.store_oauth_credential(source, value)` or a `server.py` shared method)
that BOTH `_save_tracker_token` AND the callback call — one validated writer, no second unvalidated
path. Refactoring `_save_tracker_token` to call the helper is IN SCOPE (its existing
`test_credential_writes.py` gate/injection/500 tests then cover the shared helper unchanged — verify
they stay green).

**(B) The downstream READER's value-format (`oauth_pull.access_token`, `scripts/ingest/oauth_pull.py:330`
— the ONLY consumer of the item; the LOAD-BEARING half F1 caught).** Live signature
`access_token(source, *, credential_reader=None, credential_writer=None, http=None)` (`:330`) →
`_parse_credentials(payload)` (`:368`→`:304-316`) → `body = {"grant_type": "refresh_token",
"refresh_token": creds["refresh_token"], ...}` (`:370`), forwarding `client_id`/`client_secret` into
the grant IFF the parsed blob carries them (`:372-375`). So the stored value MUST be the OAuth
**`refresh_token`** (NOT the access token — the reader's sole use is as the `refresh_token` in a
refresh grant; storing the access token yields a credential dead on the first live tick → vendor 400 →
`TrackerPullError`), in the shape governed by the vendor's CLIENT TYPE.

**The CANONICAL client-type record is `scripts/serve/alpha_config.py` (ADR-0048-T1's dedicated
artifact — AR-001/002 grounding).** `DEFAULT_CLIENT_TYPES` (`:60-65`) =
`{whoop: CONFIDENTIAL, google: PKCE_PUBLIC, oura: PAT, garmin: EXCLUDED_FROM_ONE_CLICK}`;
`AlphaConfig.client_type(vendor)` (`:107`) returns the type or `ClientType.MANUAL` when unmapped.
Read the client type at build time — **do NOT hardcode any vendor's type in recipe prose.** By type:
- **CONFIDENTIAL** (whoop): store the blob `{"refresh_token", "client_id", "client_secret"}`
  `_parse_credentials` consumes (the refresh grant forwards the secret);
- **PKCE_PUBLIC** (google): store the bare `refresh_token` (no secret — a PKCE-public client refreshes
  without one; `VendorCredential.client_secret` is `None`);
- **PAT / EXCLUDED_FROM_ONE_CLICK** (oura / garmin): NOT authorization-code-servable — the connect-start
  route rejects them (AR-004).

**Key-space mapping (AR-003 — the two artifacts use different keys):** the SOURCE key space is
`oauth_pull._MANIFESTS` (`{whoop, oura, garmin, google-health}` — what `_oauth_service_name(source)` +
the reader use); the CLIENT-TYPE/CLIENT-ID key space is `alpha_config` vendor names (`{whoop, oura,
garmin, google}`). They differ ONLY on Google (`google-health` source ↔ `google` vendor). The build
uses an EXPLICIT source→vendor map `{whoop→whoop, oura→oura, garmin→garmin, google-health→google}`;
the write uses the SOURCE key (`_oauth_service_name(source)`), the client-type/`client_id` lookup uses
the mapped VENDOR key (`config.client_type(vendor)`, `config.vendors[vendor].client_id`). A source
whose mapped vendor is `MANUAL`/absent is not servable.

**Cross-artifact conflict (bead — flagged, not resolved here):** `oauth_pull.py:141-142` (the
`_GOOGLE_HEALTH` comment) says Google's refresh grant *requires* `client_id`/`client_secret` — which
CONTRADICTS `alpha_config`'s `google: PKCE_PUBLIC`. This task DEFERS to `alpha_config` as the canonical
client-type record for the mock build (stores Google as a bare `PKCE_PUBLIC` refresh token); the
reconciliation (which client model Google actually uses) is a LIVE-run correctness bead
(`a-plus-maxing-*`, filed S141) that must land before the LIVE Google connect (`m8ia`).

**The `source` used in the write is the in-memory source validated at connect-start** (held with the
verifier+state for the one-shot match), NEVER re-parsed from the attacker-influenceable callback
request (Sec clarity add — the callback request carries only `code`+`state`; `source` is server-side).

## Design (what the SE builds — no literal code here; this is the contract)

### `scripts/serve/oauth_callback.py` (CREATE)

- **PKCE + state generation (Sec MEDIUM-2 — CSPRNG mandated):** mint the `state` (CSRF nonce) + the
  PKCE `code_verifier` from `secrets.token_urlsafe(≥32)` (verifier length ≥ 43 chars, RFC 7636); the
  `code_challenge` is `base64url(SHA256(code_verifier))` (S256). The verifier+state+source are held
  in memory for the one-shot callback match (never persisted, never logged).
- **The authorize-URL builder:** given a SOURCE (in the servable set), map source→vendor
  (`{whoop→whoop, oura→oura, garmin→garmin, google-health→google}`), read `config.client_type(vendor)`
  — servable ONLY when `CONFIDENTIAL` or `PKCE_PUBLIC` (contract §B; NOT `PAT`/`EXCLUDED`/`MANUAL`) —
  and build the authorize URL carrying the challenge + state + the `127.0.0.1:<ephemeral>` redirect_uri
  using `config.vendors[vendor].client_id`. The client type governs whether a `client_secret`
  participates in the exchange + is persisted (CONFIDENTIAL: yes; PKCE_PUBLIC: no). **Empty/missing
  config (AR-006):** if `config.vendors` has no entry for the mapped vendor (unset `APLUS_ALPHA_CONFIG`
  → empty config, or a config missing that vendor), respond with a clean handled error (constant
  message, 400), bind NO listener, open NO browser — never emit an authorize URL with a `None`/empty
  `client_id`.
- **The one-shot `127.0.0.1` listener:** binds a LOOPBACK address on an ephemeral port; after
  accepting EXACTLY one request (ANY request — a state-mismatched/malformed first callback ALSO
  consumes the one-shot, Sec LOW-1: fail-closed, smaller window) it tears down deterministically (the
  accept-loop terminates + the listening socket closes + the server thread joins).
- **The callback handler:** REJECT a mismatched `state` (0 token writes — AC-3); on a match run the
  exchange. The browser response + any stderr on EVERY path (success + error) echoes NONE of the
  auth `code`, `code_verifier`, or `client_secret` (Sec MEDIUM-3; extend `oauth_pull`'s NFR-3
  constant-message discipline to all three secret classes).
- **The code→token EXCHANGE (fail-closed, AC-1/AC-4 — an INJECTABLE opener seam, QA MUST-FIX-1 / Arch
  F4):** POST the `code` + `code_verifier` (+ `client_id`/`client_secret` for a confidential client)
  to the vendor token endpoint through an **injectable opener** (an `opener=`/`http=` param or a
  monkeypatchable module attr, mirroring `oauth_pull.access_token(..., http=None)` resolved at call
  time) whose DEFAULT is a build_opener over a `redirect_request`→`None` handler that MIRRORS
  `oauth_pull._NoFollowRedirect` + host-locks the token endpoint — so the exchange **never contacts a
  redirect host** (a 3xx raises/fails-closed exactly like `oauth_pull._http`), and a token endpoint
  returning a 3xx-to-another-host aborts with **0 connections to the redirect host** + 0 token writes
  (AC-4). PKCE protects the EXCHANGE: the token request carries the `code_verifier` for the issued
  challenge; a fixture endpoint validating `S256(code_verifier) == code_challenge` rejects a
  missing/mismatched verifier → 0 token writes (AC-1).
- **The write (contract §A/§B):** on a successful exchange, PARSE the response into the per-CLIENT-TYPE
  stored shape (`PKCE_PUBLIC` → the bare `refresh_token`; `CONFIDENTIAL` → the
  `{refresh_token, client_id, client_secret}` blob) and write it via the EXTRACTED shared write helper
  (source-membership-validate → strip → `set_secret(_oauth_service_name(source), value)`) for the
  in-memory validated SOURCE key. Never log/echo the value. `KeyStoreError` → fail-closed, not asserting
  "unstored" as certainty.
- The module reads NO store (structural — imports no `scripts.store` symbol; the D2 guarantee) + opens
  NO no-train model lane; the ONLY outbound hosts are the vendor authorize/token endpoints.

## Acceptance Criteria (executable RED/GREEN checks)

Each AC either REDs on feature-absence, or — for a negative/no-leak assertion — is validated by an
in-suite `pytest.raises` meta-assertion (the D2/AR-005 discipline). All env via `monkeypatch`; hermetic,
$0. **The exchange + authorize legs run through the REAL injectable opener against REAL `127.0.0.1`
loopback fixture servers** (the authorize endpoint, the token endpoint, and a redirect/attacker host),
each fixture recording the FULL received request (URL + headers + body); NO substituted exchange seam
that bypasses the real no-follow opener (Sec MEDIUM-1 / QA MUST-FIX-1).

1. **PKCE exchange + write the refresh_token via the ADR-0048-T3 write path (AC-1).** A matching
   callback drives the exchange carrying the `code_verifier` for the issued challenge → a fixture token
   endpoint that VALIDATES `S256(verifier)==challenge` (QA SHOULD-FIX 6) accepts + returns a token
   response → the **refresh_token** (in the per-vendor shape) is written via the shared helper
   (`set_secret(_oauth_service_name(source), <value>)`; assert the exact item + value). **Reader
   round-trip (Arch F1 — drive the PRODUCTION consumer):** the written value, fed to
   `oauth_pull._parse_credentials` (and/or `oauth_pull.access_token(source, http=<fixture>)`), yields a
   usable refresh grant (a `refresh_token` grant body; for a confidential vendor the `client_id`/
   `client_secret` are forwarded) — proving the stored value satisfies the reader, not an author-chosen
   scalar. **Falsifier:** a fixture endpoint receiving a MISSING/MISMATCHED `code_verifier` rejects →
   **0 token writes**; and storing the ACCESS token instead of the refresh token → the reader
   round-trip REDs (the value the reader needs is absent).
2. **Loopback-only bind (AC-2).** Assert the LISTENER'S REAL bound address (`server_address[0]` /
   `getsockname()[0]`, not a config value — QA SHOULD-FIX 7) is loopback (`127.0.0.1`/`::1`), never
   `0.0.0.0`/`""`/a routable address (Sec LOW-2). Falsifier: a mutant binding `0.0.0.0` REDs.
3. **`state`/CSRF mismatch (AC-3).** A callback whose `state` ≠ the issued value → **0 token writes**
   (the exchange never runs). Falsifier: the matching-state case DOES write (the path is live).
4. **The redirect host is NEVER CONTACTED on the exchange (AC-4 — Sec HIGH-1: assert the real control,
   not "0 bytes").** A fixture token endpoint returning a 3xx-to-another-host → the exchange
   ABORTS/fails-closed AND the redirect/attacker-host fixture records **0 connections** (connection-count
   == 0 at its socket — the `_NoFollowRedirect` guarantee "the redirect target is never contacted") AND
   **0 token writes**. Falsifier (in-suite meta-assertion): a mutant opener that swaps ONLY
   `redirect_request` (None→returns-a-Request) on the REAL exchange path → urllib `.open()`s the
   attacker host → the attacker fixture's connection-count > 0 → `pytest.raises(AssertionError)` the
   scan REDs. (A byte-content assertion is INSUFFICIENT: a 302/303 drops the POST body so 0 bytes leak
   even when following — the connection-count is the RED-capable check across 302/303/307/308 + both
   header-auth and body-auth vendors.)
5. **One-shot listener (AC-5).** After accepting exactly one request (any request, incl. a rejected
   one) the listener tears down; assert the DETERMINISTIC post-condition (the accept-loop terminated /
   the server thread joined / the listening socket is closed — QA SHOULD-FIX 5), with a
   second-request-refused check as a SECONDARY (not the load-bearing racy `ConnectionRefusedError`).
   Falsifier: a mutant that re-accepts → the socket stays open → the one-shot assertion REDs.
6. **D7 crown-jewel wire-scan (AC-6, load-bearing — the D2 gold-standard shape, captured at
   `opener.open(request)`).** Drive auth→callback→exchange through the REAL injectable opener against
   loopback fixtures, recording each FULL outbound request (`request.full_url` + `request.headers` +
   `request.data` — serialize ALL of it, `json.dumps(recorded, default=str)`, NOT an enumerated
   subset), covering BOTH the authorize-URL leg AND the exchange POST. A store-content sentinel seeded
   into the store + a model-lane call-counting fake. Assert the CLEAN direction FIRST:
   (a) **0 bytes of store content** in any recorded outbound request (the sentinel appears 0 times) AND
   the module performs **0 store reads** (a module-level `store.read/read_all/items` spy == 0) AND
   imports no `scripts.store` symbol (AST structural check);
   (b) **0 calls to the no-train model lane** (`_ClaudeNoTrainBackend` fake call-count 0);
   (c) the **ONLY outbound host** contacted is the vendor's own authorize/token endpoint.
   RED-gate EACH sub-guarantee with a self-invalidating mutation, each wrapped in
   `pytest.raises(AssertionError)` so a scan that CANNOT go RED fails the meta-assertion:
   - a stub adding a store-content byte to an outbound request MUST RED (a)'s content assertion;
   - **a stub opening a `store.read(...)` on the callback path MUST RED (a)'s store-read spy** (the
     DISTINCT store-READ mutant — Arch F3 / QA MUST-FIX 2 — the store-content-append mutant does NOT
     exercise the spy, mirror `test_metered_dispatch.py:473`);
   - a fixture token endpoint returning a 302-to-attacker-host MUST RED (c)'s vendor-only-host
     assertion (the attacker fixture's connection-count > 0 — shared with AC-4);
   - a stub opening a no-train model-lane call on the auth/callback path MUST RED (b)'s model-lane
     assertion.
   **The test is invalid, and itself fails, if any mutation does not RED its sub-guarantee.**
7. **Connect-start route coverage (AC-7 — QA MUST-FIX 3: a new attacker-facing state-changing POST).**
   In a live-socket `build_server(0)` test (the `test_credential_writes.py` pattern) with an injected
   `AlphaConfig` fixture carrying synthetic `client_id`(+`client_secret` for whoop) for the vendors
   under test: (a) a `text/plain` AND a no-Content-Type POST to `/settings/connect` → **415 BEFORE any
   listener bind or browser-open** (a negative assertion: no ephemeral port bound + the browser-open
   shim uncalled + no listener thread spawned — the `_save_tracker_token:1032` before-any-side-effect
   parity); (b) each NON-servable source → clean 400, no listener/browser side effect: `garmin`
