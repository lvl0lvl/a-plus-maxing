# Recipe: Operator-Confirm-Before-Land — `/upload` Surfaces Extracted Readings, `POST /confirm-extraction` Lands Only the Confirmed Subset via the Unchanged `store.append`

The Wave-3 task. T2 (Wave 2) extended `route_upload` so an unrecognized-format upload routes through the no-train
`client.extract_readings` and RETURNS the extracted readings WITHOUT landing them (the discriminated return). T3 wires the
server end of that contract: the `POST /upload` handler surfaces the extracted readings as a JSON review payload (it lands 0),
and a NEW `POST /confirm-extraction` route lands ONLY the operator-confirmed subset through a NEW `scripts/serve/confirm.py`
`land_confirmed` — a CALLER of the UNCHANGED `ingest.manual_entry`/`store.append` sink (NOT a second sink, NOT a second gate,
NOT a second dedupe key; the operator-confirm IS the gate), the SAME disposes-after-gate pattern as `capture.persist_capture`
([capture.py:230]). This task does THREE things:

1. **Create the sink-caller `confirm.land_confirmed`.** `scripts/serve/confirm.py` exposes `land_confirmed(readings, *, root)`
   — it lands each operator-confirmed reading through the UNCHANGED `ingest.manual_entry` ([ingest.py:61]) → `_store_reading`
   ([ingest.py:21,36]) → `store.append` ([store.py:134]). It makes 0 model call, adds 0 direct NDJSON write, and references
   no keying/dedupe of its own (the dedupe + the uniform missing-field rejection are INHERITED from `store.append`/
   `keying.is_conformant` [keying.py:11,35]). A confirmed reading missing any Line-Field-Set field lands nothing.
2. **Surface the `/upload` discriminated result, lands 0 (the confirm-gate precondition).** `scripts/serve/server.py`'s
   `do_POST` `/upload` branch ([server.py:145-214]) routes T2's discriminated `route_upload` return — a landed-source string
   re-renders the app shell as today ([server.py:214]); an extracted-readings payload is surfaced as a JSON review payload via
   the existing `_write_json` ([server.py:353]), NOT landed. The instance `self.client` ([server.py:125,241]) is threaded into
   the `route.route_upload(file_part…)` call ([server.py:180], today called WITHOUT a client) so T2's extraction branch can run.
3. **Add the `POST /confirm-extraction` route.** A new `do_POST` branch ([server.py:138]) reads the operator-confirmed subset
   from the JSON body and lands it through `confirm.land_confirmed`, writing a JSON receipt via `_write_json`; it mirrors the
   `/chat` catch-and-degrade thread-survival posture ([server.py:243-267]). The route table gains EXACTLY `POST
   /confirm-extraction` → `{GET /, GET /settings/key, POST /upload, POST /chat, POST /settings/key, POST /confirm-extraction}`;
   the `_LOOPBACK="127.0.0.1"` bind ([server.py:30]) is byte-unchanged; 0 new bind/port; 0 new outbound class.

The byte-frozen INNER ENGINE (`scripts/ingest/{ingest,adapter}.py` + every `scripts/plan/*.py` incl. `scripts/plan/deid_in.py`)
+ the Line-Field-Set + `store.append` stay numstat=0 (EXTEND-NOT-REBUILD, NFR-4); T3 touches only `scripts/serve/confirm.py`
(new) + `scripts/serve/server.py` + `tests/serve/test_extract_confirm.py` (new). The build is MOCK/FIXTURE-tested at 0 live
spend (a mock no-train backend injected at the ADR-0015 seam via `build_server(client=…)` + temp store roots; no live API, no
key, no non-loopback socket).
