# Recipe: End-to-End Conversation → Usable Plan Through the SPA-Served Path (Compose ADR-0017-T2; Non-Tautological; Mock-Tested)

This task produces a TEST FILE only — NO production file. It is the terminal Wave-3 integration
gate and the headline acceptance the whole ADR-0029 intake slice exists to satisfy (PF-S63-02 /
PF-S87-01 / bead `71s4`): a real-or-fixture conversation produces a USABLE PLAN through the
SPA-SERVED path, not just working chat plumbing and not the honest no-plan state. It REALIZES the
ADR-0017-T2 recipe (the `tests/plan/test_conversation_to_plan_e2e.py` that recipe specified was
never written — `test ! -f` returns 0 [VERIFIED]) through the surface T1 stands up and T3 wires:
the loopback server now serves the SPA body (T1's GET `/` re-point) and the `Upload Documents`
`/chat` composer T3 wires drives the same built `/chat` route. The E2E binds the built `/chat`
per-turn dispatch (`chat.dispatch_turn` / `plan_next_turn`) + the gate-enforced extractor +
`persist_capture` + `summarize` + the wired programmatic author path (`generate_plan` /
`compute_plan`) into ONE end-to-end proof. It is testable WITHOUT the live API — the model client
is a FIXTURE/MOCK injected at the ADR-0015 `ModelClient(backend=...)` seam returning scripted
`converse` turns + extraction proposals AND a scripted `author` envelope; the run is deterministic
+ CI-runnable with no network, no key. The LIVE end-to-end run (real conversation → real plan via
the runtime keychain key) is the FINAL operator-present checkpoint, documented as a docstring-noted
`@pytest.mark.skipif`-on-absent-key variant, NOT a CI gate. The TWO load-bearing test properties:
**(a)** the headline E2E goes RED if it produces the honest no-plan state (`recorded == False`)
instead of a USABLE plan — a tautological "a plan object is non-None" assertion is forbidden; it
asserts `recorded == True` AND content-traceability (a de-identified value the fixture conversation
supplied appears in the rendered plan), with a failing-capable negative control proving it
distinguishes a usable plan from the no-plan state; **(b)** it is mock-testable (no live API). The
TDD Steps follow RED/GREEN/REFACTOR/REGRESSION, GREEN here meaning "the binding test passes against
the already-built mechanism" — this task wires no new production code; if the E2E goes RED for a
real mechanism gap, that routes back to the owning Wave-1/2 task, not a fix authored here.

CONCERN-1 / record-only loop-termination is NOT in this recipe's scope — ADR-0029 split that proof
into ADR-0029-T4 (the not-naive elicitation task). T5's ACs are the usable-plan E2E (AC-1), the
failing-capable negative control (AC-2), mock-tested (AC-3), the operator-gated live variant
(AC-4), the post-conversation PII 0-leak (AC-5), and the pytest-passes close (AC-6) — six ACs, no
elicitation/CONCERN-1 assertion.
