# Recipe: Wire the SPA `Upload Documents` Surface — Demographic Form → `/upload` + Chat Composer → `/chat` + Honest Ingestion-State

This task produces CODE: it WIRES the served SPA's `Upload Documents` surface to the already-built
intake backend, REALIZING the ADR-0018 form/chat split on the new front-end. Today the operator-approved
`Upload Documents` screen is inert markup: the "About you" demographic inputs carry 0 `name=` and POST
nothing ([prototype/app.html:363-366](../../../prototype/app.html#L363) — birth-year input `:363`, sex
select `:364`, a 7-pound-range bodyweight select `:365`, equipment select `:366`), the chat composer is a
dead `Send →` button with 0 `fetch` ([prototype/app.html:467](../../../prototype/app.html#L467)), and the
document-cards/statusbar render FABRICATED ingestion counts ("12,480 readings · ✓ ingested",
"2 of 4 categories · parsing labs…", [app.html:370,379](../../../prototype/app.html#L370)). T3 makes this
surface live in the T1-created render-view module `vault/design/templates/app_shell.py`:

1. **The demographic "About you" form gets real capture.** Each demographic input POSTs into a
   `<form action="/upload">` with the four `name=` attributes the BUILT capture gate reads —
   `date-of-birth`, `sex-for-dosing`, `bodyweight-band`, `equipment-access-class`. The `<select>`
   `<option value=>` tokens are BUILT FROM the gate enum constants (`SEX_OPTIONS` /
   `BODYWEIGHT_BANDS` / `EQUIPMENT_ACCESS_CLASSES`, [capture.py:117-119](../../../scripts/serve/capture.py#L117))
   so markup and gate cannot drift. For `bodyweight-band` the `value=` is the kg gate token (so
   `persist_capture` still validates) and the DISPLAY LABEL is the pounds range (so the operator reads
   pounds) — the 6-band 1:1 map, NOT the prototype's 7 pound-ranges (the 7→6 cardinality mismatch removed).
2. **The chat composer fetches `/chat`.** The dead `Send →` button becomes inline same-origin JS that
   POSTs the turn to the BUILT `/chat` route ([server.py:126](../../../scripts/serve/server.py#L126),
   dispatch [server.py:235](../../../scripts/serve/server.py#L235)) and renders the returned turn-list +
   the per-turn `{reply, receipt, progress, degraded}` receipt
   ([chat.dispatch_turn](../../../scripts/serve/chat.py#L304) return shape, server write
   [server.py:252](../../../scripts/serve/server.py#L252)).
3. **The ingestion-state renders the REAL load-state.** The document-cards + statusbar render the injected
   `ingest.status.resolve` load-state ([scripts/ingest/status.py:51](../../../scripts/ingest/status.py#L51),
   injected into the `"app"` view by T1's `generate.py` extension) — 0 fabricated counts.

This is EXTEND-NOT-REBUILD: only `vault/design/templates/app_shell.py` (the T1-created SPA module) + its
test `tests/serve/test_app_shell.py` change on the production side. The built capture seam
(`persist_capture`, `WIRED_TOKENS`, `_DOB_FIELD`, `_BOUNDED_ENUMS`, the gate enums), the built `/chat`
route + `chat.dispatch_turn`, and the `ingest.status.resolve` seam are REUSED VERBATIM — `persist_capture`
is NOT modified, no new `scripts/store/` write is added, and the byte-frozen inner plan engine
(`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track,router}.py`) + the
`deid_in` de-id-IN boundary stay numstat=0. The build is MOCK/FIXTURE-tested at 0 live spend.
