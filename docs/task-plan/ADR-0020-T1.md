# Recipe: Model-Backed De-Id-IN Boundary Over the No-Train Backend

The crown-jewel egress boundary. A model-backed de-identification boundary takes raw
operator plan-intake PII and emits the de-identified summary the plan pipeline consumes,
routed through the injected `ModelClient` on its no-train backend, fail-closed to the honest
no-plan state on any model failure (never a leak, never a passthrough of raw). This
boundary supersedes `router.summarize` as the SOLE de-id-IN on the plan path; `summarize`
SURVIVES UNCHANGED as the persisted-side de-id.

**[AMENDED 2026-06-24 — de-id-seam spec defect fix]** The de-id seam is a NEW
`ModelClient.deidentify(raw_intake) -> de_identified_summary` method on
`scripts/model/client.py`, NOT `author`. `author(domain, summary)` CONSUMES an
already-de-identified summary — it cannot ingest raw and emit a de-identified summary, so it
is the wrong seam for de-id IN. The no-train guarantee binds to the no-train BACKEND
(`_ClaudeNoTrainBackend`) AND to `deid_in` constructing NO second client / opening no SDK
path (both falsifiable) — NOT a `router.Dispatch` lane (no no-train lane lives on
`ModelClient`). This task adds `deidentify` to `client.py` (the ALLOWED model-boundary
extension ADR-0020 sanctions), then creates the boundary module + its mock-tested suite
(0 live-API spend). EXTEND-NOT-REBUILD: it reuses the wired `ModelClient` seam and does NOT
re-author the INNER ENGINE (`orchestrate`/`pipeline`/`assemble`/`generate_plan`/`adjudicate`/`adjust`/`track`)
or `router.py`; `client.py` is the extended boundary, NOT frozen.

## Risk Pre-Check

This task carries risk mitigations in the spec (ADR-0020 Consequence-Negative-1, Consequence-Negative-4, Constraint ADR-0001, Constraint ADR-0016). The gate: before GREEN, a failing-capable test must exist for EACH risk. A placeholder (`assert True`) fails this gate.

- **Risk R1 — raw plan-intake PII transits the API before de-id (ADR-0020 Consequence-Negative-1 / Constraints ADR-0001 + ADR-0016):** **[AMENDED 2026-06-24]** Gate — a test asserts the de-id call runs on the no-train BACKEND (the injected `ModelClient` over a no-train backend) AND that `deid_in` uses the INJECTED client only — it constructs no second `ModelClient` and opens no SDK path. Falsifiable two ways: a `deid_in` that instantiated its own client turns the "only the injected client is used" assertion RED (spy `ModelClient.__init__` / pass a sentinel client and assert it is the exact object the de-id call went through); a `deid_in` that called a training-eligible backend turns the no-train-backend assertion RED. This REPLACES the prior `router.Dispatch`-lane assertion (no no-train lane lives on `ModelClient`; binding the guarantee to a router lane was tautological). Covers AC-1.
- **Risk R2 — per-call de-id failure could yield a fabricated/partial/leaking summary (ADR-0020 Consequence-Negative-4):** Gate — a test injects a `ModelCallError` from the mock client's `deidentify` and asserts `deid_in` returns the honest no-plan state (the `DEID_CALL_FAILED` sentinel mirroring `AUTHOR_CALL_FAILED`), NOT a fabricated summary and NOT a passthrough of the raw input. The test must be able to turn RED on a boundary that returns raw-on-error. Covers AC-2.
- **Risk R3 (crown-jewel) — raw PII leaks past the boundary or onto a tracked file:** Gate — a test seeds a known synthetic raw-PII token (a synthetic legal name + a synthetic lab value) into the raw intake, runs the boundary (the mock `deidentify` returns a de-identified fixture; the probe oracle is over the EMITTED summary, not the mock's input), and asserts `pii_scan.scan_text` over the emitted summary returns 0 AND nothing raw was written under a tracked path. The probe must FAIL on an absent/passthrough boundary (a `deid_in` that echoed `raw_intake` instead of the `deidentify` output turns this RED). Covers AC-1+AC-5 (and supports the Validation-Approach raw-PII-leak probe).
- **Risk R4 — the persisted-side `router.summarize` gate must stay intact (ADR-0001 persisted-store-de-identified invariant):** Gate — a regression assertion that this task edits 0 lines of `scripts/plan/router.py` (the boundary uses it, does not rewrite it) AND a post-run scan of the store-read summary returns 0 raw-PII hits. Covers AC-3.

No risk is deferred. Every gate references a falsifiable test, not a subjective assessment.

## Interface Contracts

This task creates / extends two shared interfaces consumed by downstream tasks:

- **New model-boundary method:** `ModelClient.deidentify(raw_intake) -> de_identified_summary` in `scripts/model/client.py` (the de-id-IN seam; the third published method alongside `converse`/`author`). **[AMENDED 2026-06-24]** Takes the raw operator plan-intake, routes through `_call(self.backend.deidentify, raw_intake)` on the injected backend (default `_ClaudeNoTrainBackend`, whose live method is `NotImplementedError` until the operator checkpoint), shape-checks the result, raises `ModelCallError` on an empty/malformed result (the fail-closed contract `author`/`converse` share). This is the model-surface extension ADR-0020 sanctions; it does NOT change `converse`/`author`. Change control: a future de-id consumer reuses this method; it does not re-author the client.
- **The boundary function:** `deid_in(raw_intake, client)` in `scripts/plan/deid_in.py`.
  - **Signature/behavior:** takes the raw operator plan-intake and an INJECTED model client (`scripts/model/client.py`'s `ModelClient`, or a `_FixedEnvelopeClient`-style mock in tests); calls `client.deidentify(raw_intake)` and returns the de-identified summary object the orchestrator consumes (a `SUMMARY_FIELD_SET`-shaped de-identified mapping, the same de-identified-summary contract the inner engine already consumes from `router.summarize`). Uses ONLY the injected client (constructs no second `ModelClient`, opens no SDK path). On a `ModelCallError`, returns the honest no-plan state (the de-id-IN sentinel below), never a fabricated/partial summary and never the raw input. Writes nothing to a tracked path.
  - **Honest-no-plan return shape (de-id-IN, [AMENDED 2026-06-24] — Architect CONCERN-2):** the de-id-IN honest-no-plan return is a small sentinel mirroring the VOCABULARY of `AUTHOR_CALL_FAILED`, NOT `generate_plan`'s full per-domain `{ "domain", "section": None, "reason", "meta" }` record (that record shape is per-DOMAIN, produced DOWNSTREAM of de-id-IN by `generate_plans`; `deid_in` is UPSTREAM of any per-domain dispatch, so it carries no domain/section). The de-id-IN sentinel is `{ "deidentified": False, "reason": DEID_CALL_FAILED }` (a non-summary marker the orchestrator treats as "no de-identified summary → halt to honest no-plan, dispatch nothing"), with `DEID_CALL_FAILED = "deid-call-failed"` a module constant mirroring `AUTHOR_CALL_FAILED = "author-call-failed"`. The downstream ADR-0022-T1 orchestrator branches on this sentinel (a falsy/`deidentified: False` summary → record 0 plans), and ADR-0020-T2 reuses the SAME sentinel vocabulary for the whole-run-outage halt (a distinct `reason`, same shape).
  - **Dependent tasks:** **ADR-0022-T1** (the orchestrator dispatches plan-domain specialists over the de-identified summary THIS boundary emits — the boundary's output is the orchestrator's input contract, and the orchestrator must branch on the de-id-IN honest-no-plan sentinel above) and **ADR-0020-T2** (adds the whole-run-outage branch to this same module/function; it extends `deid_in`'s contract with a distinct system-level halt reusing the sentinel shape, without touching the per-call contract this task fixes).
  - **Change control:** dependent tasks MUST NOT change this interface (the `deid_in` signature, the de-identified-summary return contract, the de-id-IN honest-no-plan sentinel shape, or the honest-no-plan-on-`ModelCallError` behavior) without Architect review.
