# Recipe: Upload Route → Ingest Dispatch + Intake Re-Render (Intake-Only)

This task produces CODE: the `scripts/serve/route.py` upload-routing seam + the POST `/upload`
handler wiring in `scripts/serve/server.py`. The POST handler stages the upload (`ADR-0013-T2`),
then routes the staged file (zip or xml) into the UNCHANGED `ingest.run` (wearable) or `dna.land`
(DNA) seam, and re-renders the wizard via `generate.run('intake')`. The route does NOT extract —
an Apple-Health zip is passed AS A ZIP into `ingest.run` via the zip-aware `healthkit` adapter
(`ADR-0013-T3`), which extracts `export.xml` itself; the route adds NO extraction logic (ADR-0013's
`complements ADR-0012` edge: "this server still adds no extraction logic"). The source-detection
REUSES the CLI's `_EXT_SOURCE` / `_detect_source` logic, content-disambiguating a `.zip`
(Apple-Health-export shape → healthkit; 23andMe shape → dna). The server serves NO generated
artifact live — intake-only (ADR-0013 Falsification 3). The shared ingest routines
(`ingest.py`/`adapter.py`/`scheduler.py`/`dna.py`) are BYTE-UNCHANGED by this task (ADR-0013 "new
front door"; ADR-0003 0-shared-routine-edit); `healthkit.py` is the adapter that changed in
`ADR-0013-T3`, not here. The TDD Steps follow the standard RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

Active. Each gate maps to a concrete `pytest` test, an HTTP status assertion, a `git diff --numstat`, or an `rg` assertion.

- **Risk ADR-0013 Falsification-3** (serving a generated artifact re-crosses the artifact-delivery axis ADR-0004/NG-4 prohibit). Mitigation: criterion 5 — the intake-only assertion. **Gate (intake-only, falsifiable):** a RED test must assert a GET for a dashboard/report artifact path returns 404 (no artifact route) AND `rg` over `scripts/serve/` finds 0 `dashboard`/`report` artifact-serving route. **Falsifiable RED:** the assertion turns RED if an artifact-serving route is added. **Negative-control failing-capability proof:** the RED includes a one-time negative-control — temporarily add a `do_GET` branch returning a dashboard artifact, confirm the 404 assertion FAILS (the path now 200s), then remove it and confirm the 404 returns. This proves the intake-only gate is failing-capable.
- **Risk ADR-0003 0-shared-routine-edit / ADR-0013 "new front door."** Mitigation: criterion 6 — the shared ingest routines are byte-unchanged. **Gate (falsifiable 0-edit):** `git diff --numstat <pre-task> -- scripts/ingest/ingest.py scripts/ingest/adapter.py scripts/ingest/scheduler.py scripts/ingest/dna.py` reports 0 changed lines. **Negative-control failing-capability proof:** add a transient scratch comment to `ingest.py`, confirm the `git diff --numstat`=0 assertion FAILS, revert, confirm it returns to 0.
- **Risk ADR-0013 reuse, not re-implement** (the source-detection reuses the CLI map). Mitigation: criterion 4. **Gate:** a RED test asserts `rg` over `scripts/serve/` finds 0 SECOND extension→source map definition — `route.py` references the CLI's `_EXT_SOURCE` / `_detect_source` (or a thin content-branch over it), not a re-derived rule set.

## Interface Contracts

This task PUBLISHES the route + the POST `/upload` handler consumed by `ADR-0013-T5` (the egress TEST runs this request dispatch inside `egress_guard.run`) and `ADR-0014-T1` (the form submits to the same handler).

- **Handler:** the POST `/upload` route on the `ADR-0013-T1` handler — stage → route → re-render (an Apple-Health zip is extracted inside the `ADR-0013-T3` zip-aware adapter, not the handler). **Invariant (load-bearing for criterion 5):** the handler serves NO generated artifact live; the route table is intake-only. **Dependent tasks:** `ADR-0013-T5` (the egress TEST runs this dispatch inside `egress_guard.run`; the guard is the test harness, not a production wrapper), `ADR-0014-T1` (the form-submit POST on the same handler). **Change control:** no artifact-serving route may be added without re-opening ADR-0013 against ADR-0004/NG-4.
