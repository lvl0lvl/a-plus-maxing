# ADR-0047-T3 — Route `oauth_pull` credential defaults through `secret_store`

## Goal

Refactor the two per-source OAuth credential seams in `scripts/ingest/oauth_pull.py`
— `_read_oauth_credential` and `_write_oauth_credential` — so their bodies delegate to
the merged `scripts.secret_store` abstraction (ADR-0047-T1) instead of a direct macOS
`security` shell-out, WITHOUT changing any public signature, the injectable seam
parameter names (`credential_reader` / `credential_writer`), the payload normalization,
the non-fatal-but-loud rotation-write-back semantics, or the fail-closed error contract.

This is the third and last consumer refactor of ADR-0047 (after ADR-0047-T2 routed
`key_source` + `auth_isolation`). It is FILE-DISJOINT from T2. **ARTIFACT dependency:
ADR-0047-T1 only** (the `secret_store` abstraction is the sole import). R2 INLINES the exact
strip pattern, so T3 is buildable on T1 alone — the `key_source._keychain_runner` precedent
it cites is a convenience, not a code dependency. **Sequencing note (AR-002):** this session
builds T3 after T2 merged (Entry State 1 pins branch-point `bf8a1e73`), so the cited precedent
is live; but `depends_on: [ADR-0047-T1]` in the frontmatter is the correct DAG edge (spec puts
T2 ∥ T3 parallel). If a scheduler runs T3 before T2, use R2's inlined pattern (do not require

## The refactor (grounded against the live tree — decomposition, NO literal code)

### R1 — add the abstraction import
Add `from scripts import secret_store` to the imports.

### R2 — `_read_oauth_credential(source)` → `secret_store.get_secret`
Replace the `security find-generic-password -w -s <service>` shell-out body with a
read through `secret_store.get_secret(_oauth_service_name(source))`.

- **PRESERVE THE STRIP (load-bearing — this is the ADR-0047-T2 F1 lesson):** the current
  body does `payload = completed.stdout.strip(); return payload or None`. `secret_store.get_secret`
  returns the stored value VERBATIM (no strip). So the new body MUST strip and collapse a
  blank/whitespace-only value to None — mirror `key_source._keychain_runner`'s merged fix
  (`value = secret_store.get_secret(...); if not value: return None; return value.strip() or None`).
  A dropped strip would let a padded/whitespace-only credential flow to `_parse_credentials`
  (a padded refresh token → a 401 refresh; a whitespace-only payload → a truthy garbage
  credential that bypasses the fail-closed "no token" guard). The default-read strip test
  (AC-4b below) pins this.
- None-on-absent is preserved (get_secret is None-on-absent; the absence path stays the
  caller's fail-closed trigger).
- The account binding moves inside `secret_store` (`getpass.getuser()`), matching the write.

### R3 — `_write_oauth_credential(source, payload)` → `secret_store.set_secret` (NON-FATAL warn, NOT raise)
Replace the `security add-generic-password -U -A -a <user> -s <service> -w <payload>`
shell-out with `secret_store.set_secret(_oauth_service_name(source), payload)`.

- **PRESERVE the non-fatal-but-loud semantics (this is NOT key_source's raise-translate):**
  the current writer WARNS to stderr on failure and does NOT raise (a rotation-write failure
  must not abort a tick whose access token already works — Security's guidance, per the
  docstring). Wrap the call: `try: secret_store.set_secret(...) except secret_store.KeyStoreError: <warn to stderr, do NOT raise>`. Do NOT translate to a raise; do NOT add a new exception class.
- **SOFTEN the warn message (Phase-4 CONVERGENT finding — arch W1 + qa S2 + sec MEDIUM):**
  `secret_store.set_secret` raises `KeyStoreError` on TWO conditions the writer cannot tell
  apart — `_STORE_FAIL_MSG` (keyring unavailable AND fallback write failed → token persisted
  NOWHERE → "stranded, re-run authorize" is accurate) and `_CLEAR_FAIL_MSG` (keyring write
  SUCCEEDED, only stale fallback residue could not be cleared → token IS persisted →
  "stranded / next tick fails closed / re-run the authorize flow" is FALSE and points at the
  wrong cause). The current message asserts the stranded case as a CERTAINTY. Reword so it does
  NOT assert stranding as fact — e.g. "tracker-pull: FAILED to write the rotated {source} refresh
  token back to the secret store (keychain item {service}); the rotated token may NOT have
  persisted — if the next tick fails auth, re-run the authorize flow." This: drops the false
  certainty ("stranded" / "will fail closed") — AR-003; names the `secret_store` while KEEPING the
  `"keychain"` substring the migrated test asserts (AR-005 — post-abstraction a rotation write can
  land in the file-fallback tier, so bare "the keychain" over-claims); keeps `{source}` + the
  service-item name; NEVER the payload (NFR-3). T3-analog of the T2 F2 disposition, softened (not
  just documented) because THIS message names a specific wrong remediation. The migrated test pins
  the softening NON-VACUOUSLY (TDD RED note): `"stranded"`/`"will fail closed"` ABSENT, `"keychain"`
  + `{source}` present.
- **SEC-04 downgrade — accepted + documented (sec MEDIUM):** catching `_CLEAR_FAIL_MSG` here
  turns T1's deliberately fail-loud stale-residue clear into a swallowed warn on the tracker
  path (unlike key_source, which raises). Accepted bounded erosion: a rotated-away refresh token
  is dead, and if the keyring is later unavailable `get_secret` serves the stale fallback value →
  a 401 → fail-closed. Note this one-liner in the `_write_oauth_credential` docstring (the writer
  stays warn-not-raise per the non-fatal contract). The migrated RED test cannot distinguish the
  two `KeyStoreError` conditions — note that in the test so the conflation is not read as intended.
- **`-A` allow-all-ACL supersession (the ADR-0047-T2 F3 lesson):** the current docstring
  documents `-A` (allow-all ACL so the backgrounded pull's later read is not blocked on a
  prompt). `secret_store` → `keyring.set_password` grants no ACL. Add a one-line docstring
  note that `-A` is intentionally superseded by the abstraction and the backgrounded-read
  behavior is deferred to the operator-present live run (bead `a-plus-maxing-m8ia`, already
  extended for the key_source path in ADR-0047-T2). Do NOT restore `-A` here (a live-gated
  design call).
