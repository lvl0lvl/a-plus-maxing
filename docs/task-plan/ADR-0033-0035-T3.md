# Recipe: Safety-Signal Routing — Exercise-Safety / PHQ-2 / Apnea → Referral, Allergies → Hard-Limits, Never a Plan Input (+ the read-only 0-egress `referral.py` collation surface)

A Wave-3 task EXTENDING `scripts/serve/capture.py` (a NEW safety/allergy routing region, DISTINCT
from T1's W1 rich-domain region and T2's W2 DOB/weight region) and CREATING ONE NEW module
`scripts/serve/referral.py` (`test ! -e scripts/serve/referral.py` → ABSENT [VERIFIED]). It is the
CROWN-JEWEL safety boundary of ADR-0034: the three safety screens (exercise-safety / PHQ-2 / apnea)
become referral/gate signals that NEVER reach the no-train planner, and food/drug allergies route to
the existing de-identified `hard-limits` token. T3 wires three things:

1. **Capture safety region — the `safety-screen::<name>` answered markers + the `referral::<name>`
   positive flags.** Capturing each of the three safety-screen answers writes a `safety-screen::exercise-safety`
   / `safety-screen::phq2` / `safety-screen::apnea` store item (the gate's PRESENCE signal — written
   regardless of the answer value) via the UNCHANGED `store.append`; a POSITIVE answer ALSO writes a
   `referral::<name>` flag, a NEGATIVE answer writes none (the safety-bypass falsification — a positive
   answer never silently drops its referral). The marker carries a de-identified answered-state /
   positivity signal, NOT raw free-text PII (the `::` item-name shape mirrors the existing frozen
   `dvq::queue` item, [queue_schema.py:11](../../../scripts/store/queue_schema.py) [VERIFIED]).
2. **Capture allergy region — food/drug allergies → `hard-limits`.** The allergy field(s) route to the
   EXISTING de-identified `hard-limits` token ([router.py:36](../../../scripts/plan/router.py) — a
   `SUMMARY_FIELD_SET` member; [capture.py:54](../../../scripts/serve/capture.py) — a `WIRED_TOKEN`)
   via the UNCHANGED `store.append`, NEVER into the liaison-curated `rx-interaction-classes` token (a
   drug allergy is a hard contraindication, not a drug-interaction class).
3. **`referral.py` — the read-only/0-egress intake-referral collation surface.** `collate(...)` READS
   the `safety-screen::*` / `referral::*` store items (via `store.read`, [store.py:214](../../../scripts/store/store.py))
   and returns the positive safety-screen referral flags for the doctor-visit / My-Info display. It is
   READ-ONLY: it imports NO outbound HTTP client / NO model SDK, and calls NO `store.append` /
   `store.correct` (0 egress, 0 write). It is the INTAKE-time serve-layer collation — DISTINCT from
   the FROZEN plan-time medical-liaison `orchestrate.collate_doctor_visit_queue`
   ([orchestrate.py:684](../../../scripts/plan/orchestrate.py)) / `queue_schema.py` `dvq::queue`, which
   T3 does NOT touch.

The crown jewel: NO `safety-screen::*` / `referral::*` item is a `SUMMARY_FIELD_SET` member, so
`summarize` (which iterates ONLY `SUMMARY_FIELD_SET`, [router.py:675](../../../scripts/plan/router.py)
[VERIFIED]) never reads them, and the `dispatch` whitelist
([router.py:777-781](../../../scripts/plan/router.py) [VERIFIED]) REJECTS one injected into a payload
(`set(payload) ⊆ SUMMARY_FIELD_SET`). The exercise-safety load-suppression rides the engine's EXISTING
default-deny `clearance_granted` gate ([generate_plan.py:141-153](../../../scripts/plan/generate_plan.py)
[VERIFIED] — `clearance_granted` defaults False, `exercise.pop("load", None)` drops every load
prescription), so T3 makes NO `_DOMAIN_GATES` / frozen-engine edit; the enforced effect of a positive
exercise-safety answer is the distinct `referral::exercise-safety` flag + the recorded
`safety-screen::exercise-safety` contraindication marker. The ACTIVE forbid-clearance veto (a positive
contraindication must FORBID a future clinician-clearance grant) is a DOCUMENTED deferred
forward-constraint — no clearance-grant path exists in V1.

The build is FIXTURE/MOCK-tested at 0 live spend: every test runs against a tmp store root via an
injected `store.append` / `store.read` over `tmp_path`; no live API, no key, no `converse` / curation
call, no network socket. T3 writes via the UNCHANGED `store.append` (no new store surface), the frozen
plan engine + store modules byte-unchanged.
