# Recipe: First-Cut Adapters (HealthKit + Oura), Garmin 0-Edit Extensibility Proof, Whoop Stub

This task produces CODE: four per-source adapters (`scripts/ingest/adapters/healthkit.py`,
`oura.py`, `garmin.py`, `whoop.py`) and their tests (`tests/ingest/test_adapters.py`). Each
adapter IMPLEMENTS the frozen `ADR-0003-T1` adapter interface — `source_tag` (zero-arg
source-identity accessor) + `read_readings(export_file)` (one-arg, returns an iterable of
Line-Field-Set readings) — and is run through the UNCHANGED `ingest.run`. This task defines
NO new shared interface; it implements an existing one (see Interface Contracts). The two
0-edit `git diff --numstat` proofs (Garmin extensibility, criterion 3; simulated
format-rename re-validation, criterion 6) are the load-bearing extensibility evidence: each
diffs `scripts/ingest/ingest.py` + `scripts/ingest/adapter.py` against its OWN distinct
baseline and must report 0 changed lines. They are falsifiable-capable because the
`ADR-0003-T1` interface "names NO per-source export field" invariant means all per-source
format specifics live INSIDE each adapter's `read_readings` mapping — a routine edit would
turn either diff RED. The TDD Steps follow the standard RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

This task carries risk mitigations in the spec → Risk Pre-Check is active. Each gate maps to a concrete `pytest` test (or a `git diff --numstat` / `rg` assertion run inside a test) that must exist in the RED phase and fails if the mitigation is absent. A placeholder (`assert True`) fails each gate.

- **Risk ADR-0003 N1** (a per-source adapter's export-format change breaks the adapter and can break idempotency-key derivation, silently duplicating/dropping readings). Mitigation: criterion 6's simulated export-format field-rename re-validation re-derives the dedupe key with 0 shared-routine edits. **Gate (format-rename 0-edit, falsifiable, DISTINCT committed-tree baseline):** a RED test (Cycle 4) must (a) capture a `pre-format-rename` baseline ref of `scripts/ingest/ingest.py` + `scripts/ingest/adapter.py` that is DISTINCT from the Cycle-2 `pre-garmin` baseline (a different point in the commit/stage history — after Garmin is functional, before the simulated rename) and that references a COMMITTED tree (a tag/commit, or an explicit `git stash create` object) with both paths in their FINAL committed state at capture, so the diff is against a FIXED git object rather than the non-deterministic working index, (b) simulate an export-format field rename affecting ONE adapter's sample export, (c) re-run that adapter's `read_readings` → `ingest.run` and assert the readings still land and dedupe correctly (the dedupe key is re-derived through the adapter's `read_readings` mapping, NOT through a shared-routine edit), and (d) assert `git diff --numstat <pre-format-rename> -- scripts/ingest/ingest.py scripts/ingest/adapter.py` emits 0 ROWS (empty output) for the two paths — `git diff --numstat` emits NO row for an unchanged path, so "both paths unchanged" is an EMPTY numstat (row count 0 / empty stdout), NOT a literal "0" token to search for. **Falsifiable RED:** the diff assertion turns RED if accommodating the renamed field required ANY edit to `ingest.py` or `adapter.py` (i.e. if the format specifics were NOT fully inside the adapter's `read_readings`) — that edit makes numstat emit a row (`N M <path>`), so the row count becomes non-zero. This is the `ADR-0003-T1` "interface names no per-source export field" invariant under test — if it held, the rename is absorbed entirely inside the adapter and the diff is 0; if it were violated, the rename forces a routine edit and the diff is non-zero. The DISTINCT-baseline requirement is load-bearing: a format-rename diff taken against the same `pre-garmin` ref would conflate the Garmin addition with the rename and could pass on a stale baseline — it must be its own point.
- **Risk ADR-0003 N2** (first cut wires only a subset; unwired sources narrow to manual entry). Mitigation: criterion 5 documents Whoop as the pluggable-but-unwired scaffold that falls back to manual entry (`ingest.manual_entry`, `ADR-0003-T1`) until wired. **Gate (Whoop-unwired, falsifiable within this task's scope):** a RED test (Cycle 3) must assert BOTH (a) `scripts/ingest/adapters/whoop.py` is importable and conforms to the `ADR-0003-T1` adapter interface (the registered/scaffold half — `source_tag` accessor + `read_readings(export_file)` present), AND (b) the wired-adapter set this task exposes/declares does NOT include Whoop, expressed as the spec's `rg "whoop" scripts/ingest/scheduler.py` returning 0 invocation references. **Note (cross-task ordering — see Deviations UPSTREAM FLAG):** `scripts/ingest/scheduler.py` is `ADR-0003-T3`'s deliverable and does not exist at this task's entry point; `rg` over a MISSING file errors (exit 2) rather than cleanly returning 0 matches, so the literal command cannot be the in-task RED assertion at T2-time. The T2-ownable, falsifiable assertion is: the Whoop adapter is importable+conformant (scaffold present) AND this task introduces NO wiring that would import/invoke Whoop in any scheduler entry point — the `rg "whoop" scripts/ingest/scheduler.py = 0` command is verified at the Wave 4→5 boundary AFTER `ADR-0003-T3` creates `scheduler.py`. **Falsifiable RED:** the conformance assertion turns RED if `whoop.py` is absent or does not implement the interface; the no-wiring assertion turns RED if this task ever adds a Whoop reference to a scheduler/wired-set entry point.
