## Interface Contracts

This task CREATES the horizon read-layer module `scripts/plan/horizons.py` — the read/query contract that **ADR-0038-T2** (D2 extras-seam enrichment) and **ADR-0038-T3** (date-range week/month query + latest-in-window selection + expectation-vs-actual classifier) consume and extend (per the spec dependency map and the build-plan Agent Assignment Matrix, which routes T1 through Architect code review as the read-layer composition contract).

- **Module:** `scripts/plan/horizons.py` — a pure read/query composition over `goal_schema` + `calendar_schema` + `plan_schema` (`store.read` / `store.items`). Writes no store stream, defines no `::`-prefixed key.
- **Behavioral contract:**
  - Milestone progress is DELEGATED to `goal_schema.resolve_goal` — the horizon layer never computes `_percent` itself (single progress site). Return shape carries the resolved goal dict (`label`, `percent`, `baseline`, `current`, `target`, `unit`, `on_date`).
  - The next dated cadence is DELEGATED to `calendar_schema.read_events` over the four `EVENT_CATEGORIES`; returns the next cadence `{category, label, date}` on/after the render date, or an honest absence.
  - Cadence/tracking is gated on `plan_schema.TRACKED_DOMAINS` — `peptides` yields none.
  - An open-ended (deadline-less) goal degrades to rolling maintenance cycles; the output fabricates no target-date.
- **Change control:** ADR-0038-T2/T3 MUST NOT change this read-layer contract (function surface, single-progress-site delegation, no-new-stream invariant) without Architect review. T2 layers D2-extras enrichment onto the SAME module; T3 adds the date-range query + classifier onto the SAME module — neither introduces a store write or a second progress derivation.
