# Recipe: Extend `SUMMARY_FIELD_SET` with De-Identified Chat-Sourced Tokens (Per-Token Coarseness Proof; Tripwires Green)

This task produces CODE: it widens the closed `SUMMARY_FIELD_SET`
([scripts/plan/router.py:18-36](../../scripts/plan/router.py#L18)) with new de-identified
nutrition / supplement / peptide / training-detail tokens so the chat-extracted rich-section
facts (Wave-A extractor → `persist_capture` → store) reach `compute_plan`'s domain translators
`_to_nutrition_plan` / `_to_supplements_plan` / `_to_peptides_plan` / the workout meta
([scripts/plan/generate_plan.py:130-228](../../scripts/plan/generate_plan.py#L130)). Every new token
is **kind-2 (raw-backed-derived)** (ADR-0019 §3.2, non-negotiable): a raw input lands in a
named-excluded store item and `summarize` derives the band/class via `_RAW_TO_FIELD` →
`_FIELD_DERIVATION` ([router.py:80-85,301-305](../../scripts/plan/router.py#L80)).

**THE CRITICAL AC (criterion 2): a per-token output-scan COARSENESS PROOF for EACH new token.**
On the raw-backed-derived path `summarize` runs the derivation with NO 8j6 `scan_text` call
([router.py:405-412](../../scripts/plan/router.py#L405) — contrast the pass-through `else` at
[L416-430](../../scripts/plan/router.py#L416), which DOES run the 8j6 gate). So a new token's
de-identification is NOT enforced by the 8j6 gate — it is the DERIVATION's COARSENESS, and that
coarseness MUST be proven by an INDEPENDENT per-token output scan: a crafted raw value seeded at
the token's source store item → assert the EMITTED token carries 0 of that raw value
(non-reversibility). The test docstring states explicitly that the 8j6 gate does NOT run on this
path. A new token added to NEITHER `SUMMARY_FIELD_SET` NOR a derivation reads through `summarize`'s
else-branch under its own raw name — exactly the leak the module-load tripwires red on
([router.py:312-313](../../scripts/plan/router.py#L312)). This is a STORE-SURFACE task — the new
token raw-source writes land in `scripts/store/`, so `docs/checklists/store-adversarial-tests.md`
is binding. The TDD Steps follow the standard RED/GREEN/REFACTOR/REGRESSION cycle.
