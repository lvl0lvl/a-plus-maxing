# ADR-0048-T3 — Extend the server credential-write class to N per-source OAuth tokens

## Goal

Extend `scripts/serve/server.py`'s single-key credential-write class (`_save_key` /
`_key_status`, the POST/GET `/settings/key` pair) to N per-source OAuth tokens: a new
per-source WRITE route (source + token → written through `scripts.secret_store` into the
SAME service item `oauth_pull`'s default `credential_reader` reads) and a per-source
STATUS route (connected booleans only, never a value) — carrying the ADR-0013 posture
(loopback-only, 16-KiB body ceiling, the SEC-001 `application/json` CSRF gate
415-BEFORE-write) onto the new secret-write surface. The existing single-key
`/settings/key` routes are preserved byte-unchanged.

**Wave-3 serialization (build-ORDER constraint, not a dep edge):** this task and
ADR-0049-T1 both modify `server.py` in NON-OVERLAPPING regions. THIS task touches ONLY
the handler class (new handler methods + the `do_GET`/`do_POST` route dispatch + the
route-table docstrings). It does NOT touch `build_server` (`server.py:~1024`, ADR-0049-T1's
server.py region — the `loop_dispatch` injection + the ADR-0048-T1 shared-key bridge
invocation at server start) — and NOT `main()`, which lives in `scripts/serve/__main__.py`
(AR-007: outside this task's single-file manifest entirely). The Wave-3→4 checkpoint
verifies the two `server.py` regions disjoint.

## The extension (grounded live — decomposition, NO literal code)

### R1 — route dispatch + route-table docstrings
Add two routes to the handler: **GET `/settings/trackers`** → `_tracker_status` and
**POST `/settings/tracker`** → `_save_tracker_token`, wired in `do_GET`/`do_POST`
alongside the existing `/settings/key` entries. Update BOTH route-table docstrings
(~16 and ~138-141) to list the new routes (the T2/T3 stale-doc lesson: the route table
is prose that must match the dispatch). **Pre-existing staleness (Phase-4 qa SF-3):**
both tables ALREADY omit GET `/conversation` and POST `/plan-loop` (dispatched live at
~186-188 / ~216-218). COMPLETE the tables in passing — adding those two pre-existing
routes is sanctioned doc-only scope (2 routes × 2 tables = 4 additions, judge-verified),
LIMITED to exactly these two routes (AR-011 — do not touch any other doc content) within
the same docstring edit (the consistency mandate), NOT scope creep; state it in the PR.
Dispatch mechanics (AR-009/AR-010): the new GET matches the QUERY-STRIPPED `path`
variable (like the `/settings/key` GET at ~:183, so `?v=2` cache-busting works); the new
POST branch goes among the explicit `if self.path == …` branches BEFORE the
`if self.path != "/upload"` FALLTHROUGH (~:219) — placed after it, the branch is dead
code (a non-`/upload` path already 404s). Any other POST/GET still 404s.

### R2 — `_tracker_status` (GET, status only, never a value)
Report `{sources: {<source>: bool, …}}` over the WIRED source set — presence =
`oauth_pull._read_oauth_credential(source) is not None` (AR-004: the reader's EFFECTIVE
presence, NOT raw `get_secret` truthiness — a whitespace/newline-only stored value must
report `false`, matching what the pull will actually see; raw truthiness would report
"connected" while the reader returns None. This also matches `_key_status`'s
resolve-based semantics, and routes the status through `_oauth_service_name`
automatically — one derivation site for read AND status, resolving the AR-001 drift).
The wired set is single-sourced from `oauth_pull`'s manifest keys, read at REQUEST time
via a function-local import (house style; request-time reading is what makes the SF-1
monkeypatch falsifier work and keeps the set data-driven) — NOT a hand-copied list.
Response carries ONLY booleans — never a token value, mirroring `_key_status`'s
"reports ONLY whether a key is present" contract.

### R3 — `_save_tracker_token` (POST — the new secret-write surface)
The gate order is the contract (each gate fires BEFORE any body-read/write that
follows). It preserves `_save_key`'s relative order EXACTLY for the shared gates, with
ONE new gate — source validation — inserted between shape and token (AR-006: a superset,
not a byte-mirror; `_save_key` has no source concept):
1. **CSRF (SEC-001 / AC-5):** `Content-Type` not `application/json` → 415, BEFORE the
   body is read — byte-mirroring `_save_key`'s gate INCLUDING its exact normalization
   (sec LOW-5): `(headers.get("Content-Type") or "").split(";", 1)[0].strip().lower()`,
   so `application/json; charset=utf-8` passes and a naive `!=` false-415 is avoided.
   (A cross-site CORS-simple `text/plain` POST is refused; a genuine `application/json`
   cross-site POST forces a preflight the server never answers.)
2. **Body ceiling (AC-2):** Content-Length parse failure → 400; length >
   `_SETTINGS_MAX_BYTES` (the SAME 16-KiB constant — no new constant) → 413.
3. **Parse + shape (BUG-001 posture):** malformed JSON / non-UTF-8 → 400; non-dict
   body → 400; read the fields via `body.get("source")` / `body.get("token")` —
   NEVER subscript (AR-003: `body["source"]` on an ABSENT key is an uncaught
   `KeyError` dropping the request thread; `.get` makes missing → None → the non-str
   400, mirroring `_save_key`'s `body.get("api_key")`); non-str `source` or non-str
   `token` (including None-from-absent) → 400 (isinstance-guarded).
4. **Source validation (fail-closed; sec LOW-1):** `source` not in the wired set → 400,
   as EXACT membership — NO case-folding, NO unicode normalization (a case/homoglyph
   variant simply misses the set → 400, which is the fail-closed behavior wanted). Pass
   the SAME validated string VERBATIM to the service-name derivation — never a
   normalized/derived variant (a `.lower()`-then-derive-from-RAW would write a different
   item than it validated). This closes the service-name-injection surface (an
   unvalidated source would let a request write an arbitrary
   `a-plus-maxing-<anything>-oauth` keyring item).
5. **Token normalization:** strip; empty/blank → 400 (mirror `_save_key`'s
   empty-reject; parity with `key_source.store` and the T2-F1 strip discipline — the
   stored item is clean, and the reader's own strip is defense-in-parity, not the only
   normalizer).
6. **Write:** `secret_store.set_secret(<service>, token)` — the service string is the
   SAME item `oauth_pull`'s default reader reads (`a-plus-maxing-<source>-oauth`).
   `except secret_store.KeyStoreError` → 500 with a CONSTANT message that (a) never
   carries the token value (NFR-3) and (b) does NOT assert the token is unstored as a
   certainty (the T2-F2 clear-fail lesson: `set_secret` also raises when the write
   SUCCEEDED but stale fallback residue could not be cleared).
   **Concurrency posture (sec LOW-4, acknowledged not patched):** `secret_store`'s
   FALLBACK tier does a whole-dict read-modify-write, so concurrent per-source writes
   (ThreadingHTTPServer = a thread per request) can lose a sibling source's update
   last-writer-wins — a pre-existing T1 property this surface newly exposes to
   browser-driven concurrency. Data-integrity only (re-save fixes; keyring primary is
   per-service, no race). The fix is T1-owned (bead `a-plus-maxing-7n31`) — do NOT add
   a lock in the handler.
7. **Responses:** 200 `{ok: true, connected: true}`; every ERROR body mirrors
   `_save_key`'s shape `{ok: false, error: <constant>}` (arch F3) — no token value on
   ANY surface. **UI contract (AR-013):** the Wave-5 UI branches on the HTTP STATUS
   CODE (400/413/415/500); the `error` string is a non-contractual constant (human
   diagnostic, not an API field to parse).

The write path goes DIRECTLY through `secret_store` (no `key_source`-style translation
class — `key_source.KeyStoreError` is the api-key path's class; this surface catches the
sibling `secret_store.KeyStoreError` itself).

### R4 — service-string parity contract (arch F1: MANDATED, not optional)
The write must land in the EXACT service item `oauth_pull._read_oauth_credential`
reads. REUSE `oauth_pull._oauth_service_name` (the same request-time function-local-import
approach R2 uses for the wired set — AR-008) — do NOT derive the literal in server.py.
Rationale: the AC-3 round-trip pins parity for the tested source only; a TRANSFORMING
derivation (e.g. sanitizing the hyphen in `google-health` → `google_health`) would pass
a whoop-only round-trip while breaking that source. One derivation site eliminates the
drift class; the hyphenated synthetic-source falsifier test (TDD list, qa SF-1)
backstops it.

**Downstream consumption contract (AR-012 — for the Wave-4 ADR-0048-T2 recipe author):**
this task exposes NO standalone writer function — `_save_tracker_token` is a request-handler
method coupled to the request object. The spec's "T2 writes via the ADR-0048-T3 per-source
write class" is satisfied by EITHER (a) the callback POSTing the loopback
`/settings/tracker` route, or (b) reusing
`secret_store.set_secret(oauth_pull._oauth_service_name(source), token)` directly (the
same parity this R4 mandates). The T2 recipe must PIN which — do not inherit the
ambiguity silently (also arch F4).

### R5 — the single-key class is preserved byte-unchanged
NO edit to `_save_key`, `_key_status`, or the `/settings/key` dispatch entries. The
existing `tests/serve/test_settings_key.py` suite is the regression pin (AC-1's
"preserved unchanged" half).
