# Recipe: Complete Standing-Plan Reader Set Skips an Unconfirmed Reading (Read-Side Pre-Filter)

One-line summary: make every direct standing-plan reader honor T1's `plan-confirm::` pointer by applying `plan_confirm.filter_confirmed(...)` to the store readings BEFORE the pure resolve — `read_plan`'s single AR-007 edit (transitively covering the byte-frozen `track.py`/`maintained.py`), `horizons.window_block`'s direct-scan (the AR-002 separate falsifier), and `tailoring.tailor`'s emit-gate — so a held large re-gen resolves `NO_PLAN_TODAY` (never the held plan, never a walk-back) while `resolve_plan`'s date-equality body, the WRITE path, the engine, and the `care_team_rollup.resolve_rollup` freshness read-model all stay byte-frozen.

## Interface Contracts

This task **modifies the behavioral contract of a shared reader** consumed by downstream tasks (spec Dependency Map: `T2 → T3`, `T2 → T4`).

- **Consumed (from ADR-0040-T1, unchanged here):** `plan_confirm.filter_confirmed(readings, domain, root) -> list` — returns the readings minus any whose `timepoint` carries a `pending`/`declined` pointer; keeps no-pointer and `confirmed` readings. T2 MUST NOT change this signature.
- **Modified — `plan_schema.read_plan(domain, on_date, root) -> dict`** (signature UNCHANGED): now resolves a held (`pending`/`declined`-pointer) reading to `state == NO_PLAN_TODAY` (`plan is None`), NOT the held plan and NOT a walk-back to the prior-dated plan; a no-pointer / `confirmed` reading resolves EXACTLY as pre-ADR. `resolve_plan(readings, on_date)`'s signature AND body stay byte-unchanged (the filter is caller-side). The same skip semantics extend to `horizons.window_block` and `tailoring.tailor`.
- **Behavioral invariant downstream tasks rely on:**
  - **ADR-0040-T3** — the loop marks every promoted domain `pending`; those domains MUST then read `NO_PLAN_TODAY` through this skip (T3's end-to-end held→`NO_PLAN_TODAY` / 0-window-surfacing probes consume exactly this contract).
  - **ADR-0040-T4** — the operator confirm flips the pointer to `confirmed`; `read_plan` then STANDS the plan because `filter_confirmed` keeps `confirmed` readings. T4's "confirm promotes" (the reader no longer skips) IS this contract honoring `confirmed`.
- **Change control:** dependent tasks (T3, T4) MUST NOT change `read_plan`'s pre-filter placement or `filter_confirmed`'s drop-semantics without Architect review. The `resolve_plan`-body-byte-unchanged constraint is a frozen-spine invariant (AR-007) and is not renegotiable at this layer.
