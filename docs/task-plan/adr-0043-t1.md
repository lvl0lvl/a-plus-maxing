# Recipe: Care Agent Decompose→Brief — Rewrite `_care_messages` to the Orchestration System Prompt

> Wave-2 task, the FIRST wave carrying Tier-2 work (build-plan Wave Schedule). It is the
> highest-leverage first step of the care-agent Orchestrator: it turns the care agent from a
> reply-only chatbot into the Orchestrator that DECOMPOSES the operator's goals + assembled
> state into N per-specialist briefs. It MODIFIES `scripts/serve/care_chat.py` — SUPERSEDES the
> reply-only `{task:"care-conversation"}` `_care_messages` context (203-219) with the
> orchestration decompose→brief system prompt, and adds the brief-builder control flow
> `decompose(goals, assembled_state, active_domains) -> [brief, ...]` where each brief carries
> that specialist's ADR-0042 assembled record (the FULL record — the per-specialist slice is
> deferred, disposition #10), NOT a coarse `router.summarize` band. It CREATES
> `tests/serve/test_orchestrator_brief.py`.
>
> ADDITIVE, not a rip-and-replace (AC-5 — "the orchestration is additive to the existing
> agent"). `_care_profile` (166-200) and the capture call site (286-289,
> `extract.persist_extraction` → `capture.persist_capture`) stay BYTE-UNCHANGED. The existing
> conversational context (profile / `extractable_fields` / persistence-note / weight / age /
> glossary) is PRESERVED and the orchestration decompose→brief system prompt + the `briefs`
> list are LAYERED ON — so the 11 existing `test_care_chat.py` conversational tests and the
> `test_plan_loop*.py` / `/care-chat`-route tests that drive `respond` stay GREEN (REGRESSION).
> The `active_domains` set is an INJECTED input (the front-door wiring of the real
> `activation.active_domains` source is ADR-0043-T3 + ADR-0046-T1) — this task does NOT bake in
> a second activation gate and does NOT compute the active set (`scripts/plan/activation.py` is
> absent until Wave 3, grounded).
>
> PF-S130-01 (MANDATORY): `_care_messages` is a REWRITE of an existing production function.
> The suite MUST carry a PRODUCTION-PATH integration test that drives the REAL `care_chat.respond`
> path (not `_care_messages` in isolation) with an input that DISTINGUISHES the orchestration
> output from the old reply-only behavior AND goes RED on a revert of the rewrite. A test that
> passes whether or not the rewrite happened is tautological (the exact Wave-1 gap Tier-3 caught).
>
> DE-ID posture (no new exposure): each brief carries the ADR-0042 `assemble_context` record,
> which is identity-stripped + genetics-carved BY CONSTRUCTION (the crown-jewel seam already
> Security-reviewed at ADR-0042-T1). The briefs the care model sees are STRICTLY de-id-safer than
> the raw `_care_profile` the private care agent already reads — so this task adds no crown-jewel
> exposure (why the build-plan matrix routes 0043-T1 to QA, with Architect added here for the
> `decompose` interface contract). FROZEN SPINE: `care_chat.py` is a serve-layer module, NOT a
> frozen-spine file and NOT under any byte-guard (grounded: no `tests/**` frozen set lists
> `scripts/serve/care_chat.py`), so this task needs NO frozen-guard carve-out; the `<always-frozen>`
> HARD six stay byte-frozen (invariant 1).
