# Recipe: Universal-Extraction Front Door — `route_upload` Routes an Unrecognized Format Through `client.extract_readings` (Not the Named Adapters; Readings Do NOT Auto-Land; OQ-5 Residue)

The Wave-2 task. Today `route_upload(staged_path, *, root=None, dna_root=None)` ([route.py:58]) maps a browser-staged file
to a source by REUSING the CLI's `_EXT_SOURCE`/`_detect_source` ([route.py:87], the `.zip` content-branch at [route.py:84-85])
and dispatches into the UNCHANGED `ingest.run` (wearable) / `dna.land` (DNA) seam ([route.py:90,92]) — it "adds NO extraction
logic" ([route.py:14-18]) and returns the routed source string ([route.py:93]). An unrecognized extension hits the
`_detect_source` `SystemExit` dead-end ([`scripts/ingest/__main__.py:46`], `_EXT_SOURCE` at [:39]). This task adds a NEW
FRONT-DOOR BRANCH onto the existing router — it does NOT rebuild the engine:

1. **A `client=None` param + an unrecognized-format extraction branch.** `route_upload` gains a keyword-only `client=None`
   parameter. When `_detect_source` would `SystemExit` (an extension the named-adapter map does not cover) AND a `client` is
   injected, the staged file is routed through the no-train lane — `client.extract_readings(file_content, media_type)` (the
   surface ADR-0030-T1 builds) — reading the file content from the gitignored staged path ONLY. With NO client injected, the
   unrecognized-format `SystemExit` is PRESERVED (today's no-client contract is byte-unchanged for any caller that passes no
   client). The named-adapter / `.zip`-content-branch / `dna.land` dispatch ([route.py:84-92]) is unchanged.
2. **A discriminated return — extracted readings do NOT auto-land.** The recognized-format path RETURNS the landed source as
   today (a string); the extraction path RETURNS the extracted readings as an awaiting-confirm payload (NOT a source string) —
   distinguishable by the caller (T3's `/upload` handler surfaces the readings; the named/dna result re-renders). The extraction
   path makes 0 `store.append` and 0 `dna.land` calls — the store is empty after the route (the readings await the operator
   confirm step T3 builds).
3. **CROWN-JEWEL file-egress + OQ-5 residue + EXTEND-NOT-REBUILD.** The file content reaches ONLY the injected
   `client.extract_readings` (no other sink receives it); `scripts/serve/` adds no outbound-client / SDK import (the two standing
   structural guards stay green); the raw file is written to NO tracked path (held in memory / the gitignored staged path,
   discarded by the server's `TemporaryDirectory`); and the byte-frozen engine (`scripts/ingest/ingest.py`,
   `scripts/ingest/adapter.py`, every `scripts/plan/*.py` incl. `scripts/plan/deid_in.py`) stays numstat=0.

T2 touches ONLY `scripts/serve/route.py` (the branch + the param + the discriminated return) and `tests/serve/test_route.py`
(the new probes). The build is MOCK-tested at 0 live spend — a fixture/mock `client` records its `extract_readings` calls; no
live API, no key, no network socket.
