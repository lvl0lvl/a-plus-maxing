## Interface Contracts

This task DEFINES the shared secret-store interface consumed by ADR-0047-T2 and ADR-0047-T3 (spec Dependency Map `:305-306`, `:321`). Dependent tasks MUST NOT change this interface without Architect review.

- **`get_secret(service: str) -> str | None`** — returns the stored secret for `service`, or `None` when no secret is stored (mirrors `key_source._keychain_runner`'s None-on-absent contract). Reads the OS-native `keyring` backend via the injected backend seam. Keyring is "unavailable" for an operation when the backend raises/prompts/blocks on THAT operation, and unavailability is **SYMMETRIC** — a locked/prompting/raising backend raises on both `get` and `set`. `get_secret` reads the file/env fallback IFF the keyring raises on the GET; on an AVAILABLE keyring that merely misses (secret absent) it returns `None` WITHOUT reading the fallback (no stale resurrection — SEC-04). Performs **0 fallback reads when keyring is available** (present OR absent direction).
- **`set_secret(service: str, value: str) -> None`** — stores `value` under `service` via the `keyring` backend (username `getpass.getuser()`); when the backend is unavailable OR raises/prompts (symmetric), persists to the file/env fallback tier (the ADR-0047×ADR-0039 unattended rotating-vendor write-back seam). No empty-value guard (the consumer owns that). **Total-failure contract (A-4):** when the keyring is unavailable AND the fallback write also fails, `set_secret` propagates a `KeyStoreError`-class error FAIL-LOUD (constant message, no secret value — mirroring `key_source.py:131`), never a silent no-op.
- **`delete_secret(service: str) -> None`** — removes any stored secret for `service` from **BOTH tiers unconditionally** (keyring AND the file/env fallback — not only the tier that happened to serve it, closing the SEC-04 stale-fallback window); idempotent (no error when absent in either tier).
- **Consumed by (dependent task IDs):** **ADR-0047-T2** — `key_source.resolve`/`store` default seams route onto `get_secret`/`set_secret` for service `a-plus-maxing-api-key`; `auth_isolation.build_subscription_env`'s `keychain_reader` default for service `a-plus-maxing-oauth-token`. **ADR-0047-T3** — `oauth_pull`'s `credential_reader`/`credential_writer` defaults for service `a-plus-maxing-<source>-oauth`. **ADR-0048-T4** — the My Info "Connections & Keys" per-source DISCONNECT path (AC-2, spec:223), routed through ADR-0048-T3's per-source handler class, calls `delete_secret` to remove a per-source credential (`a-plus-maxing-<source>-oauth`).
- **Seam names T2/T3 preserve (this abstraction is ADDITIVE, forces NO consumer-seam rename — Risk-N3):** `keychain_runner`/`keychain_writer` (`key_source.py`@65/135), `keychain_reader` (`auth_isolation.py`@87), `credential_reader`/`credential_writer` (`oauth_pull.py`@320/382). Those consumer seam PARAMETER names stay UNCHANGED when their DEFAULTS are re-pointed onto this trio; the `get_secret` None-on-absent + `credential_reader`/`keychain_runner` None-on-absent parity is what keeps T2's env-first precedence (T2 AC-5) and T3's `_key_def_count()==0` (Risk-N3) intact. The abstraction imports NO consumer and defines NO `def .*key` symbol under `scripts/ingest/`.
- **Internal test-affordance seams (NOT a downstream contract):** the injectable keyring-backend seam, the keyring-availability indirection, AND the injectable fallback-file-PATH seam (F-E — DEFAULT = the real instance-local constant, injected to `tmp_path` in tests) are internal to `scripts/secret_store/` — T2/T3 consume only the public trio, not these. (Documenting them here as a contract would be a TP-10 phantom contract; they are described in TDD/GREEN only.)
