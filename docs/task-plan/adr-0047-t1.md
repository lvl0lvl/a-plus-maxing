## Risk Pre-Check

**BLOCKING GATE — an at-rest credential surface (the fallback tier) + a frozen-spine foundation.** Do NOT proceed to a cycle's GREEN until a real (non-`assert True`), RED-capable test exists for every risk that cycle lands. A test that passes with OR without the mitigation is tautological and FAILS this gate. **Per-cycle gate (reconciles the 2-cycle sequencing — F-G):** the gate binds each risk test to ITS cycle's GREEN. Cycle-1 risks (per-OS matrix, unattended-no-prompt, fallback-engagement, symmetric recoverability, no-resurrection, write-through-clear, delete-fail-loud-under-unavailability, honest at-rest transform, no-secret-leak, file mode at creation, env-prefix, dep) are RED-capable BEFORE Cycle-1 GREEN; Cycle-2 risks (gitignore PLACEMENT, complete threat-model docstring, frozen-six) are RED-capable BEFORE Cycle-2 GREEN. Cycle-1 fallback-file CREATION is safe to precede the Cycle-2 gitignore line because **every Cycle-1 fallback write targets an INJECTED `tmp_path`** (the fallback-path seam, below) — never the real instance-local location — and the `block-pii-commit`/`pre-push-pii-scan` hooks backstop any stray real-path write from ever reaching the tree. Risk Mitigations are drawn from the spec ADR-0047-T1 block (`:100`) + OQ-2/OQ-4 (`:26,28`).

- **Risk (OQ-2 — fallback weaker-at-rest; ADR-0047 Consequence-Negative "fallback weaker-at-rest"):** the file/env fallback is weaker than the OS keyring at rest (its key material is env-var-extractable), so it must engage ONLY when keyring is genuinely unavailable, protect what little it honestly can, never leak the secret value, and document its threat model — not silent.
  - Gate condition — **"unavailable" is SYMMETRIC + per-operation; fallback engages IFF unavailable (AC-3 + AC-8 + AC-9):** a locked/prompting/raising backend raises on BOTH `get` and `set`. `test_fallback_engages_iff_keyring_unavailable` (AC-3) — keyring available + secret present → `get_secret` returns via keyring with **0 fallback reads** (fallback-seam spy records 0); keyring symmetrically unavailable → the fallback serves. `test_raising_backend_routes_to_fallback` (AC-8) — a symmetric raising/prompting backend routes `set` to the fallback AND `get` recovers the value from it (recoverability holds ONLY under symmetric unavailability). `test_available_miss_no_fallback_resurrection` (AC-9) — an AVAILABLE keyring that simply MISSES (secret absent) → `None` + **0 fallback reads** (no stale-fallback resurrection — SEC-04). RED-capable: a fallback read while keyring is available (present OR absent direction) flips it RED; a `get` that ignores the fallback under symmetric unavailability returns None → RED.
  - Gate condition — **fallback lifecycle: write-through-clear on a keyring-available set/delete (AC-15 — F2):** a keyring-available `set_secret`/`delete_secret` CLEARS any stale fallback FILE residue for the service. `test_fallback_write_through_clear` — set-during-outage (v1→fallback) → keyring recovers → available set-v2 CLEARS the fallback → a LATER outage `get` returns `None`, never stale v1 (closes the orphan-after-recovery corner + the SEC-04 stale-serve window). RED-capable: a swallowed keyring-delete failure → RED; a surviving fallback residue → RED.
