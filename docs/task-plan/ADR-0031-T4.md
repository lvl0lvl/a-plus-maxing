# Recipe: Wire the Local-Extract-First Front Step into `route._extract_unrecognized` + Surface the Honest-Partial Signal via `/upload`

The Wave-2 task. Wave 1 built two new local-extract front modules: T1's
`pdf_extract.extract_text(pdf_path) -> str` (local `pdftotext`/`marker` subprocess, 0 network,
fail-loud `PdfExtractError`) and T2's `extract_chunked.extract_all(text, client) ->
{"readings", "complete", "note"}` (chunk → `client.extract_readings(chunk, "text/plain")` per
chunk → aggregate + dedupe via the UNCHANGED `keying` → the honest partial/too-large signal).
T4 WIRES them into the served upload path. It does NOT rebuild the engine — it is two
NEW-FRONT-STEP edits onto the ADR-0030 router + server, plus the test-side frozen-set extension
the build plan requires. Today an unrecognized-format upload (a `.pdf` included) reaches
`route._extract_unrecognized(path, client)`, which reads `path.read_bytes()` and hands the raw
binary + a derived media type to `client.extract_readings` ([route.py:143-145]) — a raw
base64 `document` block off-device. ADR-0031 TIGHTENS that for a PDF: the raw binary stays LOCAL.

This task does TWO production things plus the test reconciliation:

1. **Branch `route._extract_unrecognized` on PDF — local-extract-first.** For a PDF
   (`media_type == "application/pdf"`) the staged file is local-extracted to TEXT via
   `pdf_extract.extract_text(path)` (the raw binary reaches ONLY the local subprocess), then
   chunk-structured via `extract_chunked.extract_all(text, client)` (the model receives only
   `text/plain` chunks). The route RETURNS `{"extracted_readings": readings,
   "extraction_complete": bool, "extraction_note": note|None}` — the awaiting-confirm payload
   carrying the honest signal. A NON-PDF unrecognized format keeps the UNCHANGED ADR-0030
   raw-content path (`client.extract_readings(file_content, media_type)`, return shape
   `{"extracted_readings": list}`) — `pdf_extract.extract_text` is NOT called. The raw PDF
   bytes reach NO non-no-train endpoint and NO `client.extract_readings` call (crown-jewel).

2. **Surface the honest-partial signal in the server `/upload` review payload + FOLD-IN F1.**
   The `/upload` handler collects `extraction_complete`/`extraction_note` across staged files
   and surfaces `{"readings": extracted, "partial": <any incomplete>, "notes": [...]}`. **F1
   (load-bearing): the honest-partial signal surfaces even when `extracted == []` but
   `partial == True` — the handler must NOT fall through to the silent "no new data" HTML
   re-render in that case.** A complete extraction keeps `partial: false`/`notes` empty. A
   total local-extraction failure (`PdfExtractError`, T1's fail-loud raise) degrades the thread
   like the existing `ModelCallError` (no dropped connection, no fabricated reading).

3. **EXTEND the test-side frozen set + reconcile the ADR-0030 `.pdf` fixtures (integration).**
   T4 EXTENDS `_FROZEN_ENGINE_PATHS` in `tests/serve/test_route.py` with `scripts/store/keying.py`
   + `scripts/store/store.py` (the frozen-set extension the build plan + spec crit 7 require).
   AND — because T4 re-routes `.pdf` away from the raw-content path — it MUST reconcile every
   earlier-phase test that POSTs/routes a `.pdf` through the ADR-0030 raw-content path, or the
   full suite goes RED (see the SPEC DEFECT note below). This is an integration obligation
   (CLAUDE.md § Call Chain Review Rule / "E2E tests from an earlier phase MUST be updated when a
   later phase changes the expected behavior"), not scope creep.

**SPEC DEFECT (surfaced, must be reconciled in this PR).** The T4 File Manifest lists only
`scripts/serve/route.py` + `tests/serve/test_route.py` + `scripts/serve/server.py` +
`tests/serve/test_server.py`. But T4's `.pdf` reroute breaks the `.pdf` fixtures in TWO
manifest-omitted test files — `tests/serve/test_extract_confirm.py` (3 `.pdf` POSTs, ADR-0030-T3)
and `tests/serve/test_universal_ingestion_e2e.py` (7 `report.pdf` POSTs, ADR-0030-T5, including
the crown-jewel `token in received` probe that asserts the RAW bytes reach the model — the exact
behavior ADR-0031 FORBIDS for a PDF). These earlier-phase tests exercise the GENERIC unrecognized
→ raw-content → model → confirm → land mechanism, which ADR-0031 PRESERVES for NON-PDF formats.
The reconciliation is to repoint their `.pdf`/`report.pdf` fixtures at a NON-PDF unrecognized
extension (one `_detect_source` SystemExits on AND `mimetypes.guess_type` does not classify as
`application/pdf` — e.g. `.bin` → `application/octet-stream`); every existing assertion then
stays VALID and GREEN against the ADR-0031-preserved non-PDF branch (crit 3 regression). This
recipe adds both files to the T4 touch list with that justification; the spec/build-plan
File-Manifest omission is flagged for the wave reviewers.

The build is MOCK/FIXTURE-tested at 0 live spend: a recording-mock `client` records its
`extract_readings` calls; `pdf_extract.extract_text` is STUBBED in the route/server tests (no
real `pdftotext`/`marker` run in T4 — the real-`pdftotext` round-trip is T1's + the T6 E2E's);
no live API, no key, no network socket.
