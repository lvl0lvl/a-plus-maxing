## Risk Pre-Check

This task carries risk mitigations in the spec, so the report is GATED on covering them. For a non-code spike the gate is a content assertion (the report must contain the covering text), not a `pytest` test.

- **Risk ADR-0001 N2** (split-path complexity; a mis-routed dispatch sends PII to a training-eligible path; no enforcement mechanism built yet). Gate: the report's "No-Raw-Reading-To-Model Rule" + "Egress Guard Mechanism" + "Recommendation" sections must, between them, design the data-in enforcement mechanism that `ADR-0001-T1` implements — i.e. name the egress-capture mechanism AND the no-raw-reading-to-model rule that convert N2 from unmitigated to mechanism-backed for the data-in facet. A section that merely restates the risk without naming a concrete mechanism fails this gate (the non-code analogue of a placeholder `assert True`).
- **Risk ADR-0001 N1** (bounded retention). Gate: the report must record the data-in egress guarantee that bounds the data-in surface to 0 (retention applies only to the deferred plan-reasoning path, which is out of scope here). This is satisfied by the "Egress Guard Mechanism" section stating the 0-outbound-call guarantee for the store-read / ingest / generation operations; the report must state explicitly that N1 retention is out of the data-in scope, not silently omit it.

The RED-equivalent step below turns both gates into concrete `rg` content assertions so coverage is mechanically checkable, not a subjective read.
