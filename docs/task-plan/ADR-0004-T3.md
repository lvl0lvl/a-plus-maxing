# Recipe: On-Demand + Unattended (Cron) Generation Entry Point

> **This task PUBLISHES a thin entry point (`generate.run`), it does NOT publish a
> broadly-reused interface.** It CONSUMES the V1 render interface `render.emit(template,
> store_read)` from ADR-0004-T1 (which RETURNS the path it wrote) and exposes one
> on-demand + unattended-cron entry mode over it. The load-bearing constraints are NG-4
> (no live server / 0 listening socket during the call — crit 3) and the single-render-path
> property (cron + on-demand route through the same `render.emit` — crit 5), so the
> unattended artifact is structurally identical to the on-demand one.

## Risk Pre-Check

The spec lists risk mitigations for this task; the Risk Pre-Check is active. Every gate below is a falsifiable RED target — an `assert True` / boolean / no-op placeholder FAILS the gate.

- **Risk: ADR-0004 Falsification — a running server/daemon to generate or open the file is an NG-4 breach (no-live-server decision).** Spec assigns criterion 3.
  - **Gate (crit 3 — 0 listening socket / 0 server process during the call):** a RED test MUST observe socket binding ACROSS the whole `generate.run(artifact_name)` call and assert the count of sockets BOUND-TO-LISTEN during the call == **0** (no server process / no listening socket opened). The observation wraps the real `generate.run` invocation (e.g. a socket-bind interceptor or an enumeration of listening sockets attributable to the call), not a no-op. A test that asserts 0 over a stub, or only checks the process exited, FAILS this gate — the 0-listening-socket count must be measured over the production `generate.run` path. **POSITIVE CONTROL (mandatory — closes the blind-observer tautology):** the SAME socket-observation mechanism MUST additionally be run over a deliberately socket-binding callable (a one-line probe that binds + listens) and assert that run reports a NON-ZERO count — proving the observer discriminates 0-from-nonzero. Without this, a mis-wired interceptor (wrong namespace, or an enumeration that returns empty for an unrelated reason) reports 0 and passes green regardless; the gate must FAIL if the observer is blind. This is the NG-4 go/no-go (build plan line 120).
- **Risk: ADR-0004 Negative — no live server → snapshot only; a stale artifact silently misrepresents the store until re-run (accepted, documented limitation).** Spec assigns criterion 5 (the mitigation: every artifact is a FRESH render of the store at generation time, so re-running reflects new readings).
  - **Gate (crit 5 — cron + on-demand route through ONE `render.emit`):** a RED test MUST assert that BOTH entry modes (the on-demand invocation and the unattended/cron invocation) call the SAME `render.emit` render function. The MANDATORY proof is a SPY on `render.emit`: assert both entry modes (cron + on-demand) drive exactly ONE shared `render.emit` invocation per run via the spy. Structural-identity of the two modes' produced artifacts (the unattended artifact == the on-demand artifact in template/component structure for the same store state) is a CORROBORATING/secondary check ONLY — NOT an acceptable standalone substitute, because two INDEPENDENT render paths that happen to produce structurally-identical output for a fixture would pass it while violating the single-render-path property this gate enforces. A test that exercises only one mode, that lets the two modes diverge onto different render paths, or that relies on structural-identity ALONE without the emit-spy, FAILS this gate — both modes must demonstrably route through the single `render.emit` call, which is what keeps the snapshot fresh and the two artifacts structurally identical.

These gates are first-class RED targets, scheduled in Cycle 1 below — not optional add-ons.

## TDD Steps

Two cycles. Rationale (per `tdd-planning.md` "When to Split": 6 ACs exceed the 3-AC threshold, and AC-4 — the produced file opening offline — depends on a file already produced by Cycle 1's `generate.run`, a natural dependency order). **Cycle 1** establishes the entry point itself: the on-demand write+exit-0 (crit 1), the unattended stdin-closed run (crit 2), the NG-4 0-listening-socket gate (crit 3), and the single-render-path property (crit 5) — the entry-point behavior and the two load-bearing risk gates land first. **Cycle 2** verifies the produced file opens offline with 0 outbound (crit 4), reusing the file `generate.run` already wrote. Total = 8 steps (2 cycles × 4), well under the 10-step guardrail. Each cycle runs the full RED/GREEN/REFACTOR/REGRESSION sequence.

### Cycle 1: Entry Point — On-Demand Write+Exit, Unattended, NG-4 0-Socket, Same Render Path (AC-1, AC-2, AC-3, AC-5)

#### Step 1: RED — Write Failing Tests

Call `/write-tests` for `tests/generate/test_generate.py` targeting:
- **AC-1 (on-demand write + exit 0):** call `generate.run(artifact_name)` over a fixture store read and assert (a) it returns / exits with code 0, AND (b) the named artifact file EXISTS on disk after the call returns (the file `render.emit` wrote, located via the path `render.emit` returned and `generate.run` surfaces). Structural-identity of the two modes' produced artifacts for the same store state (the unattended artifact's template/component structure == the on-demand artifact's) is a CORROBORATING/secondary assertion ONLY — NOT a standalone substitute (two independent render paths could coincidentally match a fixture and pass it while violating single-render-path). ## Interface Contracts

This task **CONSUMES** the ADR-0004-T1 render interface and **publishes a thin entry point — NOT a broadly-reused interface**.

- **Consumes:** `render.emit(template, store_read)` in `scripts/generate/render.py` (published by ADR-0004-T1). `generate.run` calls `emit`, which writes ONE self-contained HTML file and RETURNS the path it wrote; `generate.run` captures that returned path to locate the produced file (crit 1) and routes both entry modes through this single `emit` (crit 5). This task MUST NOT change the `render.emit` signature, its path-return contract, or its PII no-egress / refuse-external-asset boundary (per the ADR-0004-T1 change-control note — that requires Architect review).
- **Publishes:** `generate.run(artifact_name)` in `scripts/generate/generate.py` — a thin on-demand + unattended-cron entry point that invokes `render.emit` and exits 0. This is the operator/cron-invocable entry point, NOT a shared library interface that other build tasks plan against. No downstream task in the spec's dependency map consumes `generate.run` as an interface (ADR-0004-T3 has no outgoing interface edges — it is an isolated cron-entry leaf per the build plan's critical-path analysis). Therefore this section publishes no signature for downstream coordination — it does not create or modify a broadly-reused shared interface.
