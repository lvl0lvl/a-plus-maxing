# Recipe: The Four-Tier Deterministic Executor + Escalation Predicate (FAIL-CLOSED, CREATE-only)

> Wave-5 task (build-plan Wave 5 = {ADR-0046-T2, ADR-0045-T2}). **Entry: Wave 4 checkpoint
> passed (MERGED to `main` @ `1cd134c2`).** CREATE `scripts/plan/tiered_executor.py` — a NEW
> module that reads ADR-0045-T1's compiled `monitoring_config` and routes a day's monitoring
> events into four escalation tiers, **fail-closed by direction** (an unclassifiable or
> multi-tier event escalates to the HIGHER tier, never guesses down). It is the zero-slack
> critical-path node on the monitoring loop (`0045-T1 → 0045-T2 → 0045-T3`); ADR-0045-T3
> (Wave 6) hosts it in the ADR-0039 runner.
>
> The load-bearing property is **DETERMINISM ON A NO-EVENT DAY**: when no `monitoring_signal`
> crosses a material threshold, the executor makes **0 model calls + 0 de-id-IN calls + 0
> front-door re-entries** (AC-1). ANY model / de-id-IN call on a no-event day → RED. This is
> measured by call-counting an injected fixture `dispatch` + a fixture de-id client + a spy on
> the front-door entry — never inferred.
>
> **This module CALLS four existing seams and EDITS no existing file.** Its ONLY store write is the
> EXISTING `plan_confirm.mark_pending` on the Tier-4 path (Ruling 1 / Option B) — it rides the frozen
> `plan-confirm::` stream under keying's unchanged `(item, timepoint, source)` identity, defines NO
> new store key/stream, and calls no other `store.append`/`store.correct`, so NO new store-adversarial
> surface opens (it READS the compiled config + the confirm-hold decisions and performs that one
> sanctioned pointer write):
> - **Tier-2 (material in-domain)** routes the re-plan THROUGH the composed gate + per-domain
>   safety floor (`plan_orchestrator.run_orchestrated`(loop_enabled) → `plan_driver.drive` →
>   `gate_dispatch.compose_disposition`), the SAME composition ADR-0043-T3's Leg-1 uses — and
>   **NEVER the bare `adjust.adjust_plan` leg** (finding-A parity, PF-S133-02: `adjust.py`'s own
>   docstring confirms it applies ONLY the per-domain floor and does NOT re-run the composed
>   gate nor the cross-domain reconciliation — the exact safety gap Tier-2 must not open).
> - **Tier-3 (cross-domain seam)** calls ADR-0043-T2's reconciler (`orchestrate.reconcile` /
>   the `cross_domain_seams` pass), 0 auto-applied at Tier-1.
> - **Tier-4 (safety-threshold)** HOLDS by the executor calling the EXISTING
>   `plan_confirm.mark_pending(domain, plan_date, root)` DIRECTLY for the safety-affected domain(s)
>   (Ruling 1 / Option B), **magnitude-INDEPENDENT** — NOT via the composition's magnitude-gated
>   ADR-0040 hold, which is SKIPPED on a blocked run / sub-majority change (so Option A fails OPEN for
>   exactly the safety events Tier-4 exists to close). The `pending` pointer makes
>   `plan_model.read_plan_version`/`_standing_versions` resolve the change NOT-standing and
>   `plan_confirm.decision_for == DECISION_PENDING` positively, **0 auto-advance** past the
>   human/medical-liaison gate.
> - **Tier-1 (bounded in-domain deterministic)** auto-applies with 0 model calls; the *model
>   recording* of a Tier-1 auto-apply is ADR-0045-T3's disposition #22 (Wave 6), not this task.
>
> **PF-S130-01 (the CRUX):** every tier-routing decision is a PRODUCTION-PATH test whose input
> DISTINGUISHES the routed tier from the others AND that REDs when the routing is reverted (a
> test that passes with OR without the correct routing is a gate gap). **PF-S131-01:** every
> `monitoring_signal` / `adjustment_rule` fixture is `monitoring_compiler.compile_config`'s REAL
> compiled output — never a hand-built stand-in. **PF-S132-02:** every mutation/revert
> falsifier (Step 2.5) runs in an ISOLATED git worktree, never a mutate-and-restore of the
> shared main checkout. Every fixture is SYNTHETIC — 0 live-API spend, 0 real operator PII
> (PUBLIC repo).
