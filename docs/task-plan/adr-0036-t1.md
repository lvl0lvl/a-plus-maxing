# Recipe: Serve-Trigger → Driver Front-Door Binding + Anti-Degradation Guard (BUILD PREREQUISITE)

> This is the Wave-1 gating safety prerequisite. It binds the automated loop's serve trigger to
> the FULL-COMPOSITION front door (`run_orchestrated` → `plan_driver.drive` → composed
> `gate_dispatch` + `orchestrate.generate_plans`) and forbids the screened-only
> `_do_generate_plan` path AND `adjust.py` on the loop path. Finding-A safety-parity FAILS
> outright if any trigger reaches the screened-only route — the anti-degradation guard is the
> load-bearing deliverable, not a nicety. No downstream loop/tailoring task starts until this
> checkpoint RAN green.

## Risk Pre-Check

**BLOCKING GATE — this is a crown-jewel safety task.** Do not proceed to GREEN until a real (non-`assert True`) test exists for every risk below. A placeholder test fails this gate.

- **Risk (ADR-0036 finding-A safety gap):** an automated trigger reaching the screened-only `_do_generate_plan` path — or `adjust.py` per-domain — skips the ADR-0028 composed `gate_dispatch` (judge + safety lenses + fail-closed `safety_passed is True` + liaison adjudication) AND the five `orchestrate` cross-domain holds, so every evolved plan after the first records un-reconciled.
  - Gate condition: RED must include a spy-backed test that the loop path records **0** `server._do_generate_plan` calls, **0** direct `orchestrate.generate_plans` calls that bypass `plan_driver.drive`, and **0** `adjust.adjust_plan` calls, AND a positive test that the loop DID enter `plan_driver.drive` + `compose_disposition` + the `orchestrate` reconciler (covered by AC-2, AC-3, AC-4).
- **Risk (ADR-0036 Validation "held-domain persistence"):** a re-gen that inherits a prior plan's clearance instead of re-deriving it silently un-holds a still-unsafe domain.
  - Gate condition: RED must include a test that a domain HELD by the new-data composition (additive-AE/conflict/Rx-BPMH → `recorded: False, plan: None`) is NOT recorded on the re-gen (covered by AC-5).
- **Risk (PF-S63-02 / INV-CORE-CAPABILITY):** verifying a hand-configured module instead of driving the assembled system through the real entry point encodes a broken/unwired state as "passing."
  - Gate condition: RED must drive the loop through the REAL serve `/plan-loop` route (bound server + `http.client` POST), not by importing `plan_loop.regenerate` in isolation, and assert a NEW dated all-domain plan set results (covered by AC-1, AC-2).

## Interface Contracts

This task defines the loop→front-door binding interface consumed by ADR-0036-T2, ADR-0036-T3, ADR-0036-T4, and ADR-0037-T1:

- Function: `plan_loop.regenerate(root, *, dispatch, deid_client, plan_date=None, trigger=None) -> dict`
- Expected behavior: drives `run_orchestrated` → `plan_driver.drive` → composed `gate_dispatch` + the five `orchestrate` cross-domain holds, producing a NEW dated plan for all `PLAN_DOMAINS` that passed the full safety composition; returns the `run_orchestrated` result (or its honest-no-plan / `SAFETY_BLOCKED` shape). Never calls `_do_generate_plan` or `adjust.adjust_plan`; never bypasses `plan_driver.drive`; records nothing itself and opens no new store stream.
- Serve surface: a `/plan-loop` POST route in `scripts/serve/server.py`'s `do_POST` chain, distinct from `/generate-plan`.
- Downstream consumers: ADR-0036-T2 wraps `regenerate` with the shared debounce gate; ADR-0036-T3's re-summarize path re-enters it; ADR-0036-T4 attaches the post-promote rationale/confirmation/tailoring-hook/adherence seams to it; ADR-0037-T1's tailoring pass fills the T4 post-promote hook.
- Change control: dependent tasks MUST NOT change this signature or the front-door binding without Architect review (the build plan assigns Architect to the wave review of this task for exactly this seam).
