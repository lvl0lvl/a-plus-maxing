A Wave-2 task (parallel with T4; depends on T2 — the deriver calls T2's matcher). It is the ONE additive plan-path edit ADR-0032
names: a de-identified `genetic-trait-classes` token added to the closed `SUMMARY_FIELD_SET` ([router.py:20-47]) plus its local
deriver `_genetic_trait_classes_token` — which calls T2's `scripts.genetics.match.match_genotypes(store_read, library_root=…)`,
collects each match's coarse `trait_class`, and emits a `;`-joined, sorted, deduped scalar — wired into `summarize` through a
dedicated always-set branch that MIRRORS `_rx_interaction_classes_token` ([router.py:167-207,586-591]). The planner consumes the
coarse trait classes through the EXISTING `router.summarize` / `ModelClient.author` seam; the raw rsID+allele genotypes NEVER cross
to the no-train planner (the crown jewel, NFR-1).

The deriver takes a `genetics_library_root` argument and `summarize` gains an OPTIONAL `genetics_library_root=None` param —
ADDITIVE, defaulting so the three frozen no-arg callers (`scripts/serve/chat.py:363,365`, `scripts/plan/generate_plan.py:356`,
`scripts/plan/orchestrate.py:537`) need NO edit (the ADR-0015 consumer-direction claim). The load-bearing FIX-1/CQ-1 pin: `None`
resolves to a MODULE-LEVEL `GENETICS_LIBRARY_DEFAULT_ROOT = Path("vault/library/genetics")` — the REAL production library,
mirroring `store.DEFAULT_ROOT = Path("vault/store")` ([store.py:23]) — so the frozen production no-arg `summarize(store_read)` call
IS DNA-aware WITHOUT a caller edit. `None` resolves to the live library; it does NOT disable the feature. This closes the
integration-verification crack the always-set AC alone cannot (a feature shipping INERT in production — `None` → `""` always —
would pass every green gate; CQ-1 is the criterion that goes RED on that).

It is an **ADDITIVE** change (the ADR-0019 `SUMMARY_FIELD_SET`-extension precedent). The ONLY plan-path change is the new field
member + `_genetic_trait_classes_token` + the `GENETIC_TRAIT_CLASS_FIELD`/`GENETICS_LIBRARY_DEFAULT_ROOT` constants + the
`summarize` always-set branch + the optional param + the `scripts.genetics.match` import. `dispatch`, the existing derivers
(`_age_band`, `_issue_class`, `_trend_token`, `_recent_trend_direction`, `_rx_interaction_classes_token`, the four chat-sourced
derivers), and the existing `SUMMARY_FIELD_SET` / `EXCLUDED_RAW_PII` / `_ALWAYS_SET_DERIVED` / `_RAW_TO_FIELD` members are

lives in T2's NEW `scripts/genetics/` package, never in the frozen engine.
