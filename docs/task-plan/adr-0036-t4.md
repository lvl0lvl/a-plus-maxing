## Risk Pre-Check

This task HAS risk mitigations in the spec — Risk Pre-Check is REQUIRED. Each gate condition below must be satisfied by a concrete test in RED (a `assert True` placeholder fails this gate):

- **Risk — ADR-0036 OQ-4 (silent swap of a materially different plan):** a large re-generation must surface for operator confirmation rather than swap the standing plan silently. Gate: a test asserts a change over the pinned threshold routes to the confirmation surface and does NOT swap the standing plan (0 large-change silent swaps), while a below-threshold change swaps without a prompt (AC-2), and a deterministic test reads the threshold as a fixed value (AC-3).
- **Risk — ADR-0036 Decision (automated tailoring invocation):** the loop must invoke the tailoring pass directly after `record_plan` on the automated (non-operator) re-gen. Gate: a spy test asserts the post-promote tailoring-hook seam fires exactly once per re-gen with the promoted plan + render target, as a pass-through until ADR-0037-T1 fills it (AC-4).
- **Risk — ADR-0036 OQ-5 (the `plan-track::` adherence claim left dangling):** adherence must reach the re-gen as a SEPARATE, additional input, never the trigger's carrier. Gate: a test asserts the trend re-derivation (T3 AC-1) still succeeds with `resolve_plan_progress` returning `has_tracking=False` — adherence absent does not block the trend-driven re-gen (AC-5).
- **Risk — ADR-0038 no-new-store-schema rule:** the rationale/adherence path introduces no stored stream. Gate: a store-scan test asserts 0 new `::`-prefixed item ids are written by the rationale/adherence path (AC-6).

## Interface Contracts

This task defines the following interface, consumed by **ADR-0037-T1**:

- **Post-promote tailoring-hook seam** (in `scripts/serve/plan_loop.py`): a single call fired exactly once per re-gen AFTER the front-door promote, receiving the promoted plan set + the render target (the `reemit_maintained` root/artifact target). In this task it is a **pass-through** — it invokes but produces no tailored content and performs no egress.
- **Expected behavior:** ADR-0037-T1 fills the seam with the care-lane tailoring pass (`promote → tailoring pass → reemit_maintained`) on the automated re-gen path; ADR-0037-T1's acceptance (its AC-5) verifies the seam actually invokes the pass, so the pass-through here is a hard dependency, not a decoration.
- **Change control:** ADR-0037-T1 MUST NOT change the seam's call shape (promoted plan + render target, once per re-gen) without Architect review; a later edit changing the seam triggers a contract-update notice to the Architect (per the build plan's multi-agent coordination flag).

The large-change confirmation branch added to `scripts/serve/confirm.py` is an internal serve-layer surface consumed only by `plan_loop.py` within this task — it is not a cross-task shared interface.
