# ADR-0049-T3 — Per-tester cumulative monthly spend cap

## Goal

Build `scripts/runner/spend_cap.py` — a `SpendCap` maintaining a cumulative monthly per-tester count in
a gitignored instance-local JSON (keyed by `getpass.getuser()` + `YYYY-MM`), with a **serialized,
atomic, fail-closed** refusal past the per-tester monthly ceiling — and wire it into the ADR-0049-T1
metered dispatch factory as an injectable consult-before-dispatch seam (a create-then-modify of
`build_dispatch`). The cap is a NEW cumulative-monthly invariant that COMPOSES with (does not replace)
the per-run `dispatch_budget.DEFAULT_DISPATCH_CAP`. The ADR-0049-T1 D2 egress wire-scan STAYS green:
the cap reads its own ledger file (never `scripts.store`) and adds 0 field to the outbound payload.

## The three load-bearing contracts the Phase-4 review pinned (read before building)

**(C1) Exception propagation — `SpendCapExceeded` SUBCLASSES `DispatchCapExceeded` (Arch F1, BLOCKING /
PF-S141-02).** The metered dispatch, once armed, is consumed by `run_orchestrated` (`plan_orchestrator.py`).
The ONLY cap-halt handler on its outer `try` (`:231`) is `except DispatchCapExceeded as exceeded`
(`:314`) → `_honest_no_plan(exceeded.reason, dispatch_count=exceeded.count)`, and the GATE path
`:282 except DispatchCapExceeded: raise` deliberately re-raises past the `:284 except Exception` so a
budget refusal reaches `:314`. A **mirror-not-subclass** `SpendCapExceeded` would be UNCAUGHT → the
armed plan run CRASHES (never honest-no-plan). Therefore `SpendCapExceeded` MUST be
`class SpendCapExceeded(dispatch_budget.DispatchCapExceeded)` (import from `dispatch_budget`; do NOT
modify `dispatch_budget`) carrying a DISTINCT reason token (`SPEND_CAP_EXCEEDED`, so `:314`'s
honest-no-plan is distinguishable from the per-run `DISPATCH_CAP_EXCEEDED`). `.count` = the PERSISTED
current count (the ceiling), NOT ceiling+1 (see C2). The `dispatch_count` field overload at `:314`
(it would carry the monthly count for a spend refusal) is a known cosmetic residual the reason token
disambiguates.

**(C2) Fail-closed = CHECK-then-increment over a PERSISTED ledger (QA MF-1 ≡ Arch F4).** The cited
`DispatchBudget.charge` (`dispatch_budget.py:83-90`) is increment-THEN-check — safe ONLY because its
count is in-memory + discarded per run. A PERSISTED ledger MUST be check-then-increment: read the
current `(tester, month)` count; if `count + 1 > ceiling` raise `SpendCapExceeded` carrying `count`
(the persisted current) WITHOUT writing; else increment + persist. A persist-then-check build would
drift the stored count upward on every refused retry (real over-spend) — do NOT mirror
`DispatchBudget`'s ORDERING (mirror only its named-constant + raising shape).

**(C3) Serialized + atomic + fail-closed-on-corruption (Security H1 BLOCKING + M2).** The armed metered
loop runs under `ThreadingHTTPServer` (`server.py:1232` → concurrent `/plan-loop` requests on separate
threads in ONE process). A lock-free read-modify-write is a TOCTOU → lost increments → the cap
under-counts → **fail-OPEN**. The project already met + solved this EXACT class for the metered pass:
`scripts/serve/confirm.py:47-68` `_confirm_lock_for` — a process-wide **`threading.Lock`** registry
keyed by root, chosen at `confirm.py:53` explicitly *"`threading.Lock` (not `fcntl.flock`) is the right
tool — the contention is intra-process threads"*. That is the DIRECT analog: the armed loop's
concurrent charges are same-process `ThreadingHTTPServer` threads, each of which MUST be counted
(serialize + wait, NEVER skip). The charge critical section (read → check → increment → persist) MUST
be serialized under a **`threading.Lock` registry keyed by `ledger_path`** (mirror `_confirm_lock_for`).
Do NOT reach for `store_lock.cadence_lock` (`fcntl.flock` `LOCK_EX|LOCK_NB`): its skip-on-contention
`LOCK_NB` yields-False semantics DROP a charge (wrong for a cap — a skipped charge is an uncounted
dispatch), and `flock` is process-level so it does not cleanly serialize same-process threads. `flock`
(blocking `LOCK_EX`, NOT `LOCK_NB`) is warranted ONLY if a future CROSS-process CLI charger shares the
instance ledger — a beaded follow-on, not this task. The WRITE MUST be atomic (mirror
`secret_store._write_fallback_file` `__init__.py:137-170`: `mkstemp` → `fchmod(0o600)` → `fsync` →
`os.replace` at `:170`) — NOT a bare `open('w')` (torn-write-unsafe: a
crash mid-write empties the ledger → every tester's count resets to 0 → cap silently disabled). A
present-but-**corrupt/unreadable/non-dict** ledger → **fail CLOSED** (raise `SpendCapExceeded` — for a
spend control, refusing when the count cannot be verified is the safe direction; recovery = the
operator deletes the ledger; DIVERGES from `secret_store`'s fail-open-to-empty read, which is safe for
a secret but unsafe for a cap). A MISSING ledger → count 0 (first run — correct, nobody has spent).

## Design (what the SE builds — no literal code here; this is the contract)

### `scripts/runner/spend_cap.py` (CREATE)

- `DEFAULT_MONTHLY_CAP` (a named module-level constant, sensible alpha ceiling; NOT a literal at the
  check site) + `SPEND_CAP_EXCEEDED` reason token.
- `class SpendCapExceeded(dispatch_budget.DispatchCapExceeded)` (C1) — carries `.reason=SPEND_CAP_EXCEEDED`
  + `.count` (the persisted current count). **Define its OWN `__init__(self, count)`** that sets
  `self.count = count` and `self.reason = SPEND_CAP_EXCEEDED` (+ `self.cap = None` for base-attr parity);
  do NOT call `DispatchCapExceeded.__init__` and do NOT set `.reason` before it — the parent
  `__init__(count, cap)` SETS `self.reason = DISPATCH_CAP_EXCEEDED` (`dispatch_budget.py:54`), which would
  CLOBBER the distinct token C1 depends on (AR-3). AC-2b's `reason == SPEND_CAP_EXCEEDED` assertion guards
  this, but the override is the fix.
- `class SpendCap` — PRE-BOUND consult (SF-4): `__init__(self, *, ledger_path=None, ceiling=DEFAULT_MONTHLY_CAP, tester=None, clock=None)`
  (all default to production: `ledger_path`→the gitignored instance path, `tester`→`getpass.getuser()`,
  `clock`→the real clock; INJECTABLE for tests — a tmp `ledger_path`, a low `ceiling`, a synthetic
  `tester`, a fake `clock` for the AC-3 rollover). `charge(self)` (argless): under the C3 lock, read
  the ledger, take the current `(tester, month=clock().strftime("%Y-%m"))` count; if `count+1 > ceiling`
  raise `SpendCapExceeded(count)` WITHOUT writing (C2 check-then-increment); else increment + atomically
  persist (C3). Corrupt/unreadable/non-dict ledger → fail CLOSED (raise). Missing ledger → count 0.
  Reads/writes ONLY the ledger file — NEVER `scripts.store` (AC-5).

### `scripts/runner/metered_dispatch.py` (MODIFY)

- `build_dispatch(client, *, spend_cap=None)`: `spend_cap is not None` → the `dispatch` closure calls
  `spend_cap.charge()` BEFORE `client.author(name, context)` (a `SpendCapExceeded` propagates
  fail-closed — the outbound call is never issued). `spend_cap is None` → NO consult (backward-compat —

  real `spend_cap` (the D5 ceiling) AND the `run_orchestrated` catch is satisfied because
  `SpendCapExceeded` subclasses `DispatchCapExceeded` (`:314` surfaces honest-no-plan). Adds 0 outbound
  field + 0 `scripts.store` read.

## Acceptance Criteria (executable RED/GREEN checks)

1. **Gitignored ledger + owner-only (AC-1).** `git check-ignore .spend-cap-ledger.json` (the PRODUCTION
   default repo-root path — NOT a tmp path, which repo `.gitignore` does not cover) exits 0; the ledger
   is created 0o600 (assert `stat.S_IMODE == 0o600`, precedent `test_secret_store.py:305-307` — a
   world-readable ledger REDs). The `SpendCap` production default `ledger_path` IS this path (`.gitignore`
   gets the matching line, AC + Design).
2. **Cap enforcement + fail-closed persist, non-vacuous (AC-2, C2).** Ceiling not reached → `charge`
   increments; ceiling reached → the next `charge` raises `SpendCapExceeded`. **Persist assertions
   (MF-1):** after a refused charge, re-open the ledger → the persisted `(tester, month)` count == ceiling
   (NOT ceiling+1); TWO consecutive past-ceiling charges both raise AND the ledger never exceeds ceiling
   (idempotent refusal); `exc.value.count == ceiling`. Falsifiers: (a) a mutant dropping the
   `count+1 > ceiling` check → the extra dispatch proceeds → RED; (b) a **persist-then-check** mutant
   (increment+persist, THEN raise) → the re-read ledger shows ceiling+1 → RED.
3. **`build_dispatch` refusal E2E via the PRODUCTION consumer (AC-2b, Arch F1/F2).** Drive
   `run_orchestrated(...)` (the production consumer, NOT `_dispatch_domains` directly) with a
   cap-injected metered dispatch (`build_dispatch(client, spend_cap=<SpendCap over a tmp ledger at the
   ceiling>)`) → the run surfaces the HONEST-NO-PLAN halt (`reason == SPEND_CAP_EXCEEDED`, 0 plans),
   NOT an uncaught exception/crash. Falsifier: make `SpendCapExceeded` NOT subclass `DispatchCapExceeded`
   → `run_orchestrated` raises uncaught → the test REDs (proving the subclass is load-bearing for
   fail-closed propagation).
4. **Monthly rollover (AC-3).** With an injected `clock`, a prior-month entry does not count against the
   current month (charge the ceiling in month M, then charge in M+1 → proceeds). Falsifier: a mutant
   keying the ledger without the month → the prior-month count blocks M+1 → RED.
5. **Per-tester isolation + composition (AC-4).** Tester-A at the ceiling does NOT refuse tester-B.
   Composition with `DispatchBudget` at the seam, TWO configs (SF-5): (a) monthly-ceiling < per-run-cap
   → `SpendCapExceeded` fires; (b) per-run-cap < monthly-ceiling → `DispatchCapExceeded` fires FIRST
   (`budget.charge()` at `:380` precedes the closure's `spend_cap.charge()` — assert `DispatchCapExceeded`,
   not `SpendCapExceeded`). Drive `_dispatch_domains(..., DispatchBudget(cap=K))` with
   `build_dispatch(client, spend_cap=cap)` in both.
6. **Concurrency — the charge is serialized (AC-4b, Security H1).** **N≥8** concurrent `charge()` threads
   against a ledger with `ceiling` set to 1 (i.e. the first charge succeeds, all others must refuse) →
   **EXACTLY ONE succeeds** (the load-bearing assertion), the other N−1 each raise `SpendCapExceeded`; the
   final persisted count == 1. Falsifier: a lock-free mutant → >1 succeeds → RED (proving the lock is
   load-bearing). **Determinism (AR-1 — the falsifier MUST reliably RED, else the TDD FALSIFIER gate
   flakes):** align all threads at the ledger-read with a `threading.Barrier(N)` in the INJECTED `clock`
   (or a test-injected read-hook) so every thread reads the pre-write ledger before any persists — this
   widens the lock-free mutant's lost-update window to certainty while the locked GREEN still serializes.
   The barrier MUST fire at the READ, NOT inside the charge lock (a barrier under the lock would deadlock
   the CORRECT impl — the lock serializes, so thread 2 never reaches the barrier). This is why `charge`
   computes the month key from `clock()` BEFORE acquiring the charge lock (the month is invariant across
   the microsecond critical section): a barrier-blocking `clock` then aligns entry without touching the
   lock. NOTE: assert on the success-count (exactly one), NOT on `count > ceiling` — a lost-update RMW may
   still leave `count==1`, so "exactly one succeeds" is the assertion that reliably REDs the mutant.
7. **Corrupt/torn ledger fail-closed (AC-4c, Security M2).** A present-but-corrupt (non-JSON / non-dict)
   ledger → `charge` raises `SpendCapExceeded` (fail-closed, not reset-to-0), carrying `count=0` (the
   count is unreadable on this path — a sentinel, so `:318`'s `dispatch_count=exceeded.count` is defined
   once armed; the load-bearing behavior AC-4c asserts is the exception TYPE + fail-closed direction).
   A simulated torn write (via the atomic-rename path) leaves the PRIOR count intact (the temp file is
   not `os.replace`d on a mid-write failure). Falsifier: a bare-`open('w')` (non-atomic) mutant → a torn
   write empties the ledger → the prior-count assertion REDs.
8. **D2 wire-scan stays green after the cap wiring (AC-5, load-bearing).** Drive the metered dispatch
   WITH a real `spend_cap` injected via `_drive_metered(lambda c: metered_dispatch.build_dispatch(c, spend_cap=cap), summary, monkeypatch)`
   (SF-3 — importing the harness helpers; `test_metered_dispatch.py` stays byte-unchanged) over a tmp
   ledger below the ceiling → `_assert_clean_metered_egress` passes: 0 outbound field outside the
   summary + the module-level `store.read/read_all/items` spy == 0 (the cap reads its ledger, not the
   store). A NEW `spend_cap`-scoped AST no-`scripts.store`-import check in `test_spend_cap.py` (MF-2 —
   mirror the `ast.walk` + relative-import resolution, `package_parts=["scripts","runner"]`, parsing

   ADR-0049-T1 D2 tests (no cap) still pass byte-unchanged.
