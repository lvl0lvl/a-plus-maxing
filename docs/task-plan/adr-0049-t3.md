# ADR-0049-T3 — Per-tester cumulative monthly spend cap

## Goal

Build `scripts/runner/spend_cap.py` — the cumulative monthly per-tester ledger (a gitignored
instance-local JSON, keyed by `getpass.getuser()` + `YYYY-MM`) with a fail-closed refusal past the
per-tester monthly ceiling — and wire it into the ADR-0049-T1 metered dispatch factory as an
injectable consult-before-dispatch seam (a create-then-modify of `metered_dispatch.build_dispatch`).
The cap is a NEW cumulative-monthly invariant that COMPOSES with (does not replace) the existing
per-run `dispatch_budget.DEFAULT_DISPATCH_CAP` — two independent ceilings. The ADR-0049-T1 D2
egress wire-scan STAYS green: the cap consult reads its own ledger file (never `scripts.store`) and
adds 0 field to the outbound payload.

## Consumer-contract grounding (PF-S141-02 — the seam this task WIRES ONTO)

The wired-onto seam is `metered_dispatch.build_dispatch(client)` (`scripts/runner/metered_dispatch.py:37`),
whose `dispatch(name, prompt, context)` closure calls `normalize_author_output(client.author(name, context))`
and reads no store. The cap wiring INSERTS a `spend_cap.charge(...)` consult BEFORE `client.author(...)`
so a refusal fail-closes BEFORE the outbound (metered) call is issued. **Backward-compatibility (the
D2-stays-green contract, AC-5):** the consult is an INJECTABLE seam — `build_dispatch(client, *, spend_cap=None)`;
`spend_cap=None` → NO consult (the existing ADR-0049-T1 D2 tests call `build_dispatch(client)` with no
cap → unchanged → the D2 scan stays green byte-for-byte). A provided `spend_cap` → consult before each
dispatch. **Production note:** the metered loop is NOT armed in production today (the ADR-0049-T1 REJECT
reverted the arming; the arming precondition is the metered judge/lens surface, bead `a-plus-maxing-23xr`);
this task builds the cap + the seam so the loop-arming task (whenever `23xr` lands) passes a real
`spend_cap` — the recipe pins that the arming MUST inject the cap (documented in `build_dispatch`'s
docstring so the future wiring cannot silently skip it).

The per-run `DispatchBudget` (`scripts/plan/dispatch_budget.py:60`, `DEFAULT_DISPATCH_CAP=64`, `.charge()`
raising `DispatchCapExceeded` at `:77`) is a SEPARATE in-memory per-run ceiling — the monthly `spend_cap`
is a persisted cumulative cross-run ceiling; they are independent (AC-4). Do NOT touch `dispatch_budget`.

## Design (what the SE builds — no literal code here; this is the contract)

### `scripts/runner/spend_cap.py` (CREATE)

- A named module-level `DEFAULT_MONTHLY_CAP` (mirror `dispatch_budget.DEFAULT_DISPATCH_CAP`'s named-constant
  pattern — NOT a hard-coded literal at the check site; a sensible alpha ceiling, e.g. a few hundred).
- A `SpendCapExceeded` exception class (mirror `DispatchCapExceeded`) — fail-closed refusal past the ceiling.
- The LEDGER: a gitignored instance-local JSON (e.g. `.spend-cap-ledger.json` at the repo/instance root),
  a mapping `{tester: {month: count}}`. Written with owner-only perms (mirror `secret_store`'s at-rest
  posture). Read-modify-write per charge (a small file; per-instance single-writer — no cross-process
  lock needed at alpha scale, matching `secret_store`'s posture; note it if a future multi-process
  concern arises).
- `charge(*, tester=None, now=None, ceiling=DEFAULT_MONTHLY_CAP, ledger_path=None)`: resolve `tester`
  (default `getpass.getuser()`), `now` (default the real clock — INJECTABLE for the AC-3 rollover test,
  NOT a hard-coded `datetime.now()` at the use site), the month key (`now.strftime("%Y-%m")`), and
  `ledger_path` (default the instance path — INJECTABLE for the AC-1/AC-4 tests). Read the ledger, take
  the current-(tester, month) count; if `count + 1 > ceiling` raise `SpendCapExceeded` (carrying the
  count reached) — fail-closed, the ledger is NOT incremented past the ceiling; else increment + persist.
  Prior-month entries for the same tester are NOT counted against the current month (rollover, AC-3).
  Reads/writes ONLY the ledger file — NEVER `scripts.store` (AC-5).

### `scripts/runner/metered_dispatch.py` (MODIFY — the injectable consult seam)

- `build_dispatch(client, *, spend_cap=None)`: when `spend_cap is not None`, the `dispatch` closure calls
  `spend_cap.charge()` (or `spend_cap(...)` — a `Callable`/object consult seam) BEFORE `client.author(name, context)`
  — a `SpendCapExceeded` propagates fail-closed (the outbound metered call is never issued). When
  `spend_cap is None`, NO consult (backward-compatible — the existing D2 tests pass no cap → unchanged).
  The consult adds 0 field to the outbound payload + performs 0 `scripts.store` read (it reads the ledger
  file only). Update the `build_dispatch` docstring: the loop-arming task MUST inject a real `spend_cap`
  (the D5 per-tester ceiling; the metered loop is not armed today — bead `23xr`).

## Acceptance Criteria (executable RED/GREEN checks)

1. **Gitignored ledger (AC-1).** The ledger persists OUTSIDE `scripts/store/` at a gitignored
   instance-local path; `git check-ignore <ledger-path>` exits 0 (assert the exit code). The ledger
   file is created with owner-only perms (assert the mode, mirror the secret_store test).
2. **Cap enforcement, non-vacuous (AC-2).** With the ceiling not reached, `charge` proceeds (the count
   increments); with the ceiling reached, the next `charge` for that tester raises `SpendCapExceeded`
   (fail-closed) — and via `build_dispatch(client, spend_cap=<real cap over a tmp ledger>)`, the
   (ceiling+1)th dispatch is REFUSED (the outbound `client.author` never called for it). **Falsifier:**
   a test that lets ≥1 dispatch PAST the ceiling flips RED (drive ceiling+1 dispatches with a
   ceiling-2 cap → the last raises; a mutant that drops the `count+1 > ceiling` check → the extra
   dispatch proceeds → the test REDs).
3. **Monthly rollover (AC-3).** With an INJECTED `now`, a ledger entry from the PRIOR month does not
   count against the current month's ceiling (charge the ceiling in month M via injected `now`, then
   charge in month M+1 → proceeds, not refused). Falsifier: a mutant keying the ledger without the
   month → the prior-month count blocks the new month → REDs.
4. **Per-tester isolation + composition (AC-4).** One tester reaching the ceiling does NOT refuse
   another tester's dispatch (charge tester-A to the ceiling; tester-B's charge proceeds). The monthly
   cap composes with the per-run `DispatchBudget` — they are INDEPENDENT: a run under the per-run cap
   can still be monthly-refused, and vice versa (a test asserting both ceilings fire independently).
5. **D2 wire-scan stays green after the cap wiring (AC-5, load-bearing).** Drive the metered dispatch
   WITH a real `spend_cap` injected (over a tmp ledger, ceiling not reached) through the ADR-0049-T1 D2
   harness (`_drive_metered` + `_assert_clean_metered_egress` + the module-level `store.read/read_all/items`
   spy) → the outbound payload has 0 field outside the summary + the cap consult performs **0
   `scripts.store` read** (the store spy == 0) + `spend_cap` imports no `scripts.store` symbol (AST
   check). Confirm the EXISTING ADR-0049-T1 D2 tests (with no cap) still pass byte-unchanged. Falsifier:
   a mutant making the cap consult read `scripts.store` → the store spy REDs.
6. **Frozen-six + suite (AC-6).** `git diff --numstat 3ab1c3abb6c995fbaaadcb179735759e4a61d73d -- <six>`
   prints nothing; `pytest tests/runner/test_spend_cap.py tests/runner/test_metered_dispatch.py -q`
   passes; the full baseline stays green (no NEW failure vs entry).
