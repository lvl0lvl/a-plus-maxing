# Recipe: Loop Marker-Before-Exposure + Tailoring-Seam Gate; Debounce Counts the Held Re-Gen (ADR-0040-T3)

Build-plan wave: **Wave 3** (single-task wave, on the fully-serial critical path `ADR-0040-T1 → T2 → T3 → T4`). Prior-wave attestation: the **Wave 2 → Wave 3** checkpoint Go/No-Go MUST have RAN green (executed, not reasoned) before this task builds — `read_plan` skips a held reading → `NO_PLAN_TODAY` (not a walk-back, `resolve_plan` body byte-unchanged), `window_block` skips in both windows (AR-002), `tailor`'s emit-gate skips, a no-pointer reading stands (the falsifiable pair), the frozen-spine glob numstat=0 with the `read_plan`-only hunk, and the `resolve_rollup` freshness paired control. **What this task does, in one sentence, and the test that verifies it:** on the large-change branch of `regenerate`, write a `pending` confirmation pointer for every promoted domain BEFORE the function returns and exclude those held domains from the post-promote tailoring seam, so the held re-gen resolves `NO_PLAN_TODAY` end-to-end and is never tailored/egressed — verified by `tests/serve/test_plan_loop_hold.py` driving a large re-gen through the fixture-dispatch serve path and asserting the marker-before-exposure order, held→`NO_PLAN_TODAY`, 0 window surfacing, the held-domains-absent tailoring spy, and the debounce still counting the held re-gen.

## Risk Pre-Check

This task HAS risk mitigations in the spec — Risk Pre-Check is REQUIRED. This is the crown-jewel fail-closed surface (silent-swap-then-render leak + the debounce storm). Each gate below MUST be satisfied by a concrete RED test before GREEN (an `assert True` placeholder fails this gate):

- **Risk — silent-swap-then-render leak on the raw-egress surface (ADR-0040 Decision §4):** an unconfirmed materially-large swap must be neither standing nor tailored/egressed. Gate: (a) the **marker-before-exposure TEMPORAL probe** — a spy asserts every `plan_confirm.mark_pending(domain, plan_date, root)` for a promoted domain happens-BEFORE `regenerate` returns, and no read that resolves the HELD (`plan_date`) reading is interposed between the frozen promote and the last marker write (AC-1); (b) the **tailoring-seam gate probe** — the held domains are ABSENT from `_post_promote_tailoring`'s `promoted` argument (spy-asserted) and 0 tailored artifact is produced for a held domain (AC-4).
- **Risk — the transient window between promote and marker (ADR-0040 transient-window negative / OQ-4):** closed by call ORDER, not by the resolver failing closed. Gate: AC-1's order-assertion. **Do NOT reintroduce a fail-closed-on-unmarked-reading claim** — AC-1 is the TEMPORAL guarantee only; an interrupted marker-write leaves NO pointer, so that reading is indistinguishable from a normal plan and STANDS (per T2 AC-5 backward-compat). This was corrected in the spec.
- **Risk — pending-over-pending re-gen storm (ADR-0040 Consequences-Negative-3 / AR-003):** the debounce must COUNT the held re-gen (it is the ONE reader excluded from the pointer skip). Gate: the **debounce-counts-held probe** — after the large re-gen `_last_regen_date` reflects the held re-gen's date and no second large re-gen fires within `MIN_REGEN_INTERVAL_DAYS`; its RED is the mutation control (repoint `_last_regen_date` at `read_plan` → the held re-gen stops counting → a second re-gen fires → RED) (AC-5). `_last_regen_date` stays byte-unchanged.
- **Risk — frozen-spine drift (ADR-0032 EXTEND-NOT-REBUILD / AR-007):** the hold is an ADDITIVE loop-layer change only. Gate: the **frozen-spine numstat probe** — `git diff --numstat origin/main -- <frozen-glob>` = 0 changed lines, AND `_last_regen_date` / `_prior_standing_plan` / `_change_magnitude` are byte-unchanged (the `scripts/serve/plan_loop.py` diff touches only `regenerate`'s post-promote branch + the `plan_confirm` import) (AC-6).

## TDD Steps

Six testable ACs (1–6; AC-7 is the whole-file pytest run verified at each REGRESSION) on ONE atomic behavior (hold = readers skip AND tailoring skips), split into two RED-first cycles so no cycle leaves a leaky intermediate its own tests would catch. Cycle 1 = the pending marker + its read-side consequences (`mark_pending`). Cycle 2 = the tailoring-seam gate (`promoted` minus held). All probes run against a fixture `dispatch` + fixture `tailor_client` + synthetic PII-free seeds (0 live spend).

**Builder note (load-bearing, OQ-3 "held as a unit"):** `_change_magnitude` counts only domains whose CONTENT changed, but the hold marks EVERY promoted domain `pending` (the whole majority-swap is held as a unit per OQ-3), so a promoted-but-content-unchanged domain ALSO reads `NO_PLAN_TODAY` during the hold. This is intended and faithful to OQ-3 — iterate `promoted` (not the changed subset) for `mark_pending`, and the held set = `set(promoted)`.

**Builder note (AC-1 order-assertion vs `_change_magnitude`'s `resolve_plan`):** `_change_magnitude` legitimately calls `plan_schema.resolve_plan` via `_prior_standing_plan`, but only on readings dated STRICTLY `< plan_date`, so it resolves the PRIOR standing plan and can never surface the just-promoted held (`plan_date`) reading — it is NOT an exposure of the held reading. The AC-1 order-assertion therefore scopes "interposed read" to a read that would resolve the HELD `plan_date` reading (of which there are none on the synchronous path); do NOT write a naive "0 `resolve_plan` calls total" assertion — it would false-RED forever because `_change_magnitude` calls `resolve_plan` by design and is byte-unchanged.

## Interface Contracts

This task establishes contracts consumed by **ADR-0040-T4**, and consumes contracts from T1 + T2:

- **Consumes (T1):** `plan_confirm.mark_pending(domain, plan_date, root)` — appends the `pending` `plan-confirm::<domain>` pointer at `timepoint=plan_date`. T3 calls it; it does not re-implement it.
- **Consumes (T2):** `read_plan` / `horizons.window_block` / `tailoring.tailor` honor the pointer (drop a `pending`/`declined` reading). T3's end-to-end held→`NO_PLAN_TODAY` / 0-window-surfacing probes rest on this.
- **Defines — marker-write placement contract (consumed by T4):** after a large-change (`_change_magnitude(...) >= LARGE_CHANGE_THRESHOLD_DOMAINS`) re-gen, a `pending` pointer keyed `(domain, plan_date)` EXISTS for every promoted domain, written before `regenerate` returns. T4's `confirm_plan_change` flips exactly this pointer via `plan_confirm.set_decision(domain, plan_date, decision, root)`; T4 MUST NOT change the `(domain, plan_date)` marker key shape without Architect review.
- **Defines — deferred-tailoring seam contract (consumed by T4):** a held domain is EXCLUDED from `_post_promote_tailoring`'s `promoted_plan` during the hold (not tailored/egressed). T4's confirm fires the deferred `_post_promote_tailoring` once for the now-confirmed domain (idempotent per `(plan, date)`, ADR-0037). The `_post_promote_tailoring` call shape (promoted plan + render target, once per re-gen) is UNCHANGED — only which domains populate `promoted_plan` narrows during a hold.
- **Debounce-untouched invariant:** `_last_regen_date` stays byte-unchanged (reads `plan::` via `resolve_plan` directly, NOT `read_plan`), so it keeps counting the held re-gen — a T4 or later edit repointing it at `read_plan` would break the AR-003 storm suppression and requires Architect review.
