# Recipe: Step-Harness `plan_step.py` (Memo-Cache Serialization Format + Determinism Audit)

The skill's PER-ROUND drive. The `/generate-plan` skill cannot hold a live `plan_driver.drive`
generator object across Agent-tool dispatches (a generator cannot pause for the Agent tool), so the
harness is the pause boundary: skill → harness → driver. `step(serialized_state | None)` constructs/
resumes the driver from the SERIALIZED memo-cache state, advances it EXACTLY ONE yield, and returns
`(pending_request, serialized_memo_cache_state)`. Re-calling `step` with the prior serialized state +
the just-fulfilled envelope appended re-drives to the NEXT yield (or completion). There is NO held
generator object across calls — the state IS the serialized memo cache, because the inner engine is a
PURE FUNCTION of `(authors, summary, gates, cached-hook-responses)` (ADR-0028 OQ-5), so re-driving from
the same cache is deterministically reproducible.

This task RESOLVES OQ-5's residual: it PINS the memo-cache serialization FORMAT (a lossless `json`
round-trip with keys matching exactly T2's two documented shapes) and the DETERMINISM AUDIT (two
replays from the same serialized state reproduce the same `(kind, key)` sequence to the next miss). The
harness DRIVES — it does NOT compose a disposition (`compose_gate_dispatch` is the ONE composition site,
in `plan_driver`) and does NOT re-derive the adjudication RELEASE (`outcome == "cleared"` + the
CRITICAL/H1-H2 non-overridable check stay in the inner engine's `adjudicate`). The no-fork crown jewel
holds at the harness.

`plan_step.py` is a Create-only new artifact; the byte-frozen INNER ENGINE
(`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track,router}.py`) stays
numstat=0. The harness drives the T1 typed-request protocol + serializes the T2 memo cache (both
upstream inputs). All fixture-driven, 0 live spend.

**Build dependency vs runtime order (load-bearing):** the harness drives a FIXTURE consumer (a fixture
`dispatch` + fixture GATE raw verdicts + fixture REAUTHOR/ADJUDICATOR envelopes) in tests, never a live
raw intake. The value-scan over the GATE/ADJUDICATOR/REAUTHOR yield payloads is ADR-0028-T4's add to
this file (the first-ever scan over those DERIVED artifacts); T3 builds the drive mechanism, T4 attaches
the crown-jewel scan at the same harness boundary. The SE/Security verifier confirms at execute time
that the build's drivers are fed ONLY fixtures (no live de-id-IN or live Agent-tool dispatch introduced
into the build path).

## Risk Pre-Check

This task carries the spec's ADR-0028-T3 Risk Mitigations field. Before proceeding to RED, verify a test
exists (or the RED phase adds one) for EACH; a placeholder test (`assert True`) fails this gate. The gate
conditions reference live tests, not subjective assessments.

- **Risk — the step-harness is a new runnable artifact with its own resumable-state / idempotent-replay
  correctness burden (ADR-0028 Consequence-Negative-3).** Gate (AC-2, the serialization-format probe):
  the serialized memo-cache state round-trips losslessly — `json.loads(json.dumps(state)) == state` — AND
  every cache key matches one of the two documented shapes (`reauthor:(domain, constraint)` /
  `adjudicator:(held-domain, hold-class, finding_id)`). A format that loses data on round-trip, or a key
  off the two shapes, goes RED.
- **Risk — non-deterministic replay (the same serialized state produces a different yield sequence on
  re-drive, breaking the no-held-generator drive).** Gate (AC-4, the determinism audit): two independent
  replay runs over the SAME serialized cache state reproduce the IDENTICAL `(kind, key)` sequence up to
  the next cache-miss. A test that runs the harness twice from the same state and asserts the `(kind,
  key)` sequences are equal up to the next miss; a non-deterministic replay goes RED.
- **Risk — a held generator object leaks across `step` calls (the harness keeps a live `drive` frame
  rather than re-driving from serialized state — the OQ-5 mechanism is then unsound).** Gate (AC-3, the
  appended-envelope re-call): a full round-sequence (AUTHOR → GATE → … → promote) drives to a promoted
  plan with ≥1 `plan::` row PURELY through repeated `step` calls — no generator object is held across
  calls (the only state passed between calls is the serialized memo cache + the appended envelope).
- **Risk — forked safety loop / re-derived release at the harness (the no-fork crown jewel; a
  harness-level copy of the loop or the release is the forked-loop failure class).** Gate (AC-5, the
  no-fork grep): a grep over `scripts/plan/plan_step.py` for a disposition-composition site (the
  `{accept` 3-key build OR a `disposition.get("safety_passed") is True` / bare `safety_passed is True`
  EXECUTABLE gate expression) OR a re-derivation of the adjudication release (`outcome == "cleared"`, the
  CRITICAL/H1-H2 check) finds 0 executable copies — the harness drives, it does not compose or release.
  (Apply the executable-not-token discipline from ADR-0026-T1's QA-2: a bare token surviving in a
  docstring/comment is not a fork; the probe targets the executable gate expression / a `while True:`
  loop header, stripping comments/docstrings before counting.)
- **Risk — charge double-counting through the harness (a replayed cache-HIT round charges the budget
  again — the T2 replay-safety property must hold OBSERVED THROUGH the harness drive).** Gate (AC-6, the
  charge-on-miss-only-through-the-harness probe): driving a bounce + held-finding fixture through repeated
  `step` calls charges `budget.count` exactly once per cache-MISS (no charge on the replayed cache-HIT
  rounds the harness re-drives) — equal to the synchronous-reference count (the T2 AC-7 property observed
  through the harness). An over-count goes RED.
- **Risk — frozen inner engine re-authored (EXTEND-NOT-REBUILD).** Gate (a SHELL gate, `<base>` =
  `git merge-base HEAD feature/reauthor-adjudicator-replay-memo`, unresolvable inside pytest): `git diff
  --numstat <base>..HEAD` on the 8 inner-engine files → 0 changed lines. A STANDING INVARIANT verified in
  REGRESSION + at the Wave-3 checkpoint, not a RED-first test (the harness is a new Create-only file; the
  inner engine is byte-unchanged before any code lands).

    state + the just-fulfilled envelope APPENDED re-drives to the NEXT yield (or completion). There is NO
    held generator object across calls — the serialized memo cache + the appended envelope are the ONLY
    state passed between calls (the inner engine being a pure function of `(authors, summary, gates,
    cached-hook-responses)` makes the re-drive deterministically reproducible — OQ-5).
  - **The memo-cache serialization FORMAT (the pinned OQ-5 residual).** The serialized state is a lossless
    `json` round-trip (`json.loads(json.dumps(state)) == state`); every cache key matches exactly one of
    the two documented T2 shapes — `reauthor:(domain, constraint)` (a 2-tuple key) /
    `adjudicator:(held-domain, hold-class, finding_id)` (a 3-tuple key). ADR-0028-T2's memo-cache callables
    EMIT exactly these key shapes; a downstream task changing the key shape MUST coordinate with this
    serialization (Architect review per Core Rule 10).
  - **No-fork at the harness (a STANDING invariant).** The harness DRIVES — it does NOT compose the
    disposition (`compose_gate_dispatch` is the ONE composition site, in `plan_driver`) and does NOT
    re-derive the adjudication release (`outcome == "cleared"` + the CRITICAL/H1-H2 check stay in
    `orchestrate.adjudicate`). Verified by the harness no-fork grep (AC-5).
  - **Charge-on-miss-only (PRESERVED through the harness).** The harness's re-drive charges `budget.count`
    once per cache-MISS, never on a replayed cache-HIT it re-traverses — the T2 AC-7 property observed
    through the harness (AC-6).
  - The harness stays INDEPENDENTLY DRIVABLE by a fixture consumer (no live client, no skill — AC-7).
  - **Change control:** ADR-0028-T4 (drives the harness + adds the value-scan over the yield payloads)
    and ADR-0028-T5 (drives the orchestrator/harness fixture seam) MUST NOT change this drive-protocol
    (the one-yield-advance + serialize/resume boundary, the serialization FORMAT, the two memo-key shapes,
    the no-fork constraint) without Architect review (Core Rule 10).
