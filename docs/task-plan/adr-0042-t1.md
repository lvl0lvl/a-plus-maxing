# Recipe: The Context Assembler — Identity-Stripped Full Record with the Genetics Carve-Out (CROWN-JEWEL)

> Wave-1 entry-point task (Dependencies: None). It CREATES the Context Assembler —
> `assemble_context(store_read, ...) -> specialist_input` — that feeds each dispatched
> specialist the operator's FULL record with ONLY pure identity stripped, REPLACING
> `router.summarize`'s coarse 18-token collapse on the plan path. This redraws the
> crown-jewel PII boundary: on the plan path the assembled context flows
> `assemble_context` → `client.author(domain, summary)` (`generate_plan.py:362`), and
> `author` INLINES the summary to the model with NO second de-id pass and NO downstream
> field-set whitelist (`router.dispatch`'s whitelist is NOT on this path). So the strip
> inside `assemble_context` is the SOLE control — any gap is a direct model leak on a
> PUBLIC repo (a one-way door). The AC-4 identity-leak probe and the AC-5 genetics carve-out
> must therefore be COMPLETE, DEPTH-PROOF, mutation-RED-capable falsifiers, not
> confirmations — a de-id-bypass mutation must turn each RED against the GREEN
> implementation (observe RED, revert), mirroring the store-adversarial mutation rigor of
> ADR-0040-T1.
>
> CONSTRUCTION — ALLOWLIST, not denylist (Security-F1). The read-set is an EXPLICIT
> health-substance ALLOWLIST that MIRRORS `_care_profile` (`care_chat.py:166-200`): the
> de-id-safe base is `router.summarize` (identity-safe BY CONSTRUCTION — its output keys are
> `SUMMARY_FIELD_SET`, pinned disjoint from `EXCLUDED_RAW_PII` by the `router.py:668`
> tripwire, so NO identity / contact / health-identifier class ever appears; genetics crosses
> ONLY as the coarse `genetic-trait-classes` token), then ENRICHED with an EXPLICIT enumerated
> allowlist of raw health-substance free-text classes (mirroring `_CARE_HEALTH_DETAIL`,
> `care_chat.py:126`). An UNLISTED class STRUCTURALLY CANNOT be read into the payload —
> the correct crown-jewel fail-closed posture (a future-unknown class fails closed, never
> leaks by default). This designs NO new de-id scheme — it reuses `summarize` + the
> `_care_profile` allowlist precedent (the parked-de-id constraint holds).
>
> DE-ID PARKED: only pure identity + the health-identifier classes are excluded (by NOT being
> on the allowlist); ALL health substance FLOWS uncollapsed; the ONE preserved
> de-id-by-construction is the genetics crown jewel — raw rsID+allele genotypes are NEVER read
> into the context, genetics reaches it ONLY as the derived coarse `genetic-trait-classes`
> token via the projecting wrapper `router._genetic_trait_classes_token` (raw
> `match.match_genotypes` is NOT an implementation option — its return carries the raw
> `"genotype": <allele>`). FLAT-SCALAR return (Security-F2): `specialist_input` is a FLAT
> mapping of scalar / list-of-scalar values — NO nested dict at any key — so identity or a
> genotype cannot hide at a nested leaf; the shared scan is additionally RECURSIVE
> (defense-in-depth) and a nested-sentinel reach test proves it reaches every leaf.
>
> FROZEN SPINE: the `:356` swap in `generate_plan.py` supersedes the plan-path USE of
> `router.summarize`; `router.py` ITSELF is byte-frozen (`numstat` == 0), and the frozen
> FIVE (`store.py`/`keying.py`/`pipeline.py`/`adjudicate.py`/`adjust.py`) stay byte-frozen —
> the full 6-file `<always-frozen>` glob of the Wave-1 checkpoint. The ONLY edits are the
> new module + the one-line `:356` swap + the new test.

## Risk Pre-Check

**BLOCKING GATE — the crown-jewel PII-boundary redraw + the SOLE-control seam.** This task moves the load-bearing PII seam onto the direct `assemble_context → client.author` path (`generate_plan.py:356→362`), with NO downstream de-id pass or field-set whitelist behind it. Do NOT proceed to GREEN until a real (non-`assert True`) RED-capable test exists for every risk below. A placeholder test, or a falsifier that cannot reach a nested leaf, fails this gate.

- **Risk (ADR-0042 Consequences-Negative-1 — redraws the crown-jewel PII boundary; Security-F1 denylist leak):** replacing the 18-token collapse with a full-record read widens what reaches the specialist; a read-set built as a DENYLIST (`EXCLUDED_RAW_PII` minus a hand-picked identity set) LEAKS any class in neither the strip nor the derivations — concretely the 3 health-identifier classes (`medical-record-number`/`insurance-id`/`provider-name`), which the operator-identity value gate does NOT catch (Security executed: 0 `pii_scan` hits) — a one-way door on a PUBLIC repo.
  - Gate condition: RED must include **AC-4 primary** — seed SYNTHETIC values for ALL 10 identity/identifier classes of `EXCLUDED_RAW_PII` (`legal-name`, `date-of-birth`, `government-id`, `email-address`, `phone-number`, `postal-address`, `geolocation`, `medical-record-number`, `insurance-id`, `provider-name`) + a synthetic operator name registered in a tmp `identity_config`; flatten every value in the returned `specialist_input` (RECURSIVE scan) and assert, FOR EACH of the 10, that its class is not a payload key AND its synthetic value appears in 0 values (count == 0). The read-set is an EXPLICIT ALLOWLIST (a class not on the allowlist is structurally unreadable), so the falsifier cannot drift below the full exclusion set.
