## Risk Pre-Check

- **Tautology risk (the load-bearing one):** a plain mock (`_MockAuthorClient`) returns pre-built rich envelopes WITHOUT building the prompt, so the composition count would discriminate on T2's floor but NOT on T1's `_contract_section` map — a §5-§10 domain records from the canned envelope even if T1 never mapped it. MITIGATION: a `_ContractGroundedClient` subclass calls `client._author_system_prompt(domain)` FIRST (exercising `_contract_section`; an un-mapped domain raises `ValueError` → the server's `_author_rich` `except`→None drops it), so the ≥10 count genuinely requires BOTH T1 and T2. RED-capability PROVEN by a run-it probe: dropping §5-§10 from the map → 4 authored, not 10.
- **$0 (no live SDK):** the grounded client builds the pure-string prompt but returns a canned envelope — no model API call.
- **Frozen / no-edit:** T3 creates a test file only; server.py / care_chat.py / the frozen ADR-0032 six stay byte-unchanged (asserted in-test).
