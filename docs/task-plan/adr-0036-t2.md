# Recipe: Debounce + Three-Trigger Convergence (Derived State, No New Store Stream)

A Wave-2 loop task (parallel with ADR-0038-T2 on the disjoint `scripts/plan/horizons.py`; depends on ADR-0036-T1). T1 established the serve-trigger→driver front-door binding: the `regenerate(...)` entry in `scripts/serve/plan_loop.py` that drives `run_orchestrated` → `plan_driver.drive` → the composed `gate_dispatch` + the five `orchestrate` holds, producing a NEW dated plan for all `PLAN_DOMAINS`. T2 wraps that stable `regenerate` seam with a **shared debounce gate** and wires the three real trigger surfaces (wearable/lab `biomarker::` write-events + care-chat free-text) through the ONE gate so no trigger reaches `regenerate` un-debounced.

The debounce is the bound on the per-trigger cost (ADR-0036 Consequences-Negative-1): a whole-plan front-door re-gen is materially more expensive than a per-domain patch, so a re-gen fires only when BOTH (a) at least the pinned **minimum re-generation interval** has elapsed since the last re-gen AND (b) a **sustained** directional signal exists over the pinned window of the `biomarker::` series — never on a single reading. The free-text trigger is additionally rate-limited. Absent any signal in the window, the cadence trigger holds and surfaces a log-prompt, never re-generates. The debounce state introduces **zero new store stream** (OQ-5): the last-re-gen date is DERIVED from the dated `plan::` history via a `plan_schema` read, and the window is a query over the existing `biomarker::` series — no `loop::`/`debounce::`/`regen-marker::` item, no `store.append` of a marker.

This task pins OQ-1's concrete numbers as binary acceptance criteria (min interval, window n/span, directional-consistency bar, free-text rate limit) as module-level constants a deterministic unit test reads. Every test is fixture-driven at 0 live spend (fixture `dispatch`, seeded `biomarker::`/`plan::` fixtures) — no network, no key, no live model/Agent call.

- **PER-TRIGGER COST BOUND — the debounce bounds re-gen frequency (ADR-0036 Consequences-Negative-1).** A whole-plan front-door re-gen every trigger is materially more expensive than a per-domain patch; the min-interval + sustained-window + free-text rate limit are the mechanical bound. Gate: **AC-1** (single reading → 0 re-gen), **AC-4** (the parameters are pinned fixed numbers a deterministic test reads), **AC-6** (a second cross-kind trigger inside the window is dropped by the shared gate). - **SINGLE-READING vs SUSTAINED — the falsifiable pair (ADR-0036 Validation "debounce: single reading → NO re-gen").** The load-bearing paired control, driven through the SERVE entry point. Gate: **AC-1** (a single new `biomarker::` reading inside the window → count of new dated `plan::` sets == 0) AND **AC-2** (a sustained signal over the window ≥ the pinned n across the pinned span meeting the directional bar → count == 1). A gate that fired on both reds AC-1; a gate that fired on neither reds AC-2 — the pair cannot both pass unless the gate genuinely discriminates single from sustained.
- **ABSENT-DATA HOLD (ADR-0036 Validation "absent-data").** A cadence trigger with no new signal in the window must hold + prompt, never re-generate. Gate: **AC-3** (count of new dated `plan::` sets == 0 AND the returned payload carries a log-prompt flag). A gate that re-generated on empty signal reds AC-3.
- **NO NEW STORE STREAM — derived state (OQ-5 / ADR-0038 no-new-store-schema rule).** The debounce state is DERIVED, not stored. Gate: **AC-5** — a grep over `scripts/serve/plan_loop.py` + a store scan finds 0 new `::`-prefixed item ids (no `loop::`/`debounce::`/`regen-marker::`) and 0 `store.append` of a debounce/last-re-gen record; the last-re-gen date is read from the dated `plan::` history and the window from the `biomarker::` series. ## Interface Contracts

This task exposes the shared debounced entry consumed by the three trigger sites T2 modifies (and relied on by the Wave-2 convergence contract the reviewer validates):

- **Function:** `plan_loop.signal(root, *, trigger, dispatch, deid_client, plan_date=None)` (name/exact params at the SE's discretion within this contract) — the ONE debounced entry every trigger kind calls.
- **Behavior:** runs the shared debounce predicate over DERIVED state (last-re-gen date from the dated `plan::` history; sustained-signal window over the `biomarker::` series); on pass, invokes T1's `regenerate(...)` exactly once and returns its re-gen receipt; on a cadence trigger with no window signal, returns a hold+prompt payload carrying a `log-prompt` flag with 0 new plans; on a debounced drop (inside window / inside min interval / over the free-text rate limit), returns a no-op receipt with 0 new plans. It NEVER bypasses `regenerate` (the T1 front-door binding stays the sole path to the driver) and NEVER writes a store record.
- **Consumers:** `scripts/serve/route.py` (`route_upload`), `scripts/serve/confirm.py` (`land_confirmed`), `scripts/serve/care_chat.py` (`respond`). Downstream ADR-0036-T3 re-enters the re-summarize path and ADR-0036-T4 adds the post-promote seams through `regenerate`, NOT by re-shaping this gate.
- **Change control:** the debounce predicate + the single-entry convergence are the Wave-2 contract; dependent tasks MUST NOT change this interface without Architect review (a later edit that re-shapes it triggers a contract-update notice).

The debounce parameters are exposed as module-level constants (min-interval, window `n`/span, directional bar, free-text rate limit) that the AC-4 deterministic test reads by name.
