This task produces a TEST FILE only — NO production file. It is the terminal Wave-B integration
gate, the headline acceptance the whole conversational-intake set exists to satisfy (PF-S63-02 /
PF-S87-01 / bead `71s4`): a real-or-fixture conversation produces a USABLE PLAN through the
existing assembly pipeline, not just working chat plumbing and not the honest no-plan state. It
BINDS the Wave-A `/chat` dispatch (ADR-0016-T1) + the gate-enforced extractor (ADR-0017-T1) + the
wired programmatic author path (ADR-0015-T3) + the Wave-B demographic tokens (ADR-0018-T1) + the

extraction proposals; the run is deterministic + CI-runnable with no network. The LIVE end-to-end
run (real conversation → real plan via the runtime keychain key) is the FINAL operator-present
checkpoint, documented as a docstring-noted variant, NOT a CI gate. It carries the CONCERN-1
loop-termination proof end-to-end (a chat-covered domain whose token is NOT minted terminates
record-only, never `intake_complete` with a silent gap). The TWO load-bearing test properties:
**(a)** the headline E2E goes RED if it produces the honest no-plan state instead of a USABLE

traces to the fixture conversation's facts); **(b)** it is mock-testable (no live API). The TDD

test passes against the already-built Wave-A+B mechanism" — this task wires no new production
code; if the E2E goes RED for a real mechanism gap, that is a Wave-A/B defect to route back, not
a fix to author here.
