# Recipe: Unattended Scheduler Run (Delta-Since-Last-Run)

This task produces CODE: the unattended-run entry point `scripts/ingest/scheduler.py`
(`scheduler.run()`) and its tests (`tests/ingest/test_scheduler.py`). `scheduler.run()`
invokes the UNCHANGED `ADR-0003-T1` `ingest.run` over the `ADR-0003-T2` WIRED adapter set
(HealthKit, Oura, Garmin), appends only readings new since the last run, completes with
exit 0 and 0 operator prompts (stdin closed), excludes the Whoop unwired scaffold, and emits
0 outbound network calls (verified by the `ADR-0001-T1` `egress_guard.run` over a real
`scheduler.run()`). The scheduler runs a DATA-DRIVEN wired-adapter set — NOT a hardcoded
per-adapter call list — so adding a further wired adapter changes 0 lines in `scheduler.py`
(criterion 6, `git diff --numstat <committed-pre-add>` = 0 ROWS / empty output). **This task
publishes a THIN entry point (`scheduler.run`), not a broadly-reused interface** (see
Interface Contracts). **This is also where `ADR-0003-T2`'s DEFERRED literal command
`rg "whoop" scripts/ingest/scheduler.py` = 0 lands** — `scheduler.py` is created HERE, so the
T2 cross-task-ordering deferral is discharged in this recipe (criterion 4). The TDD Steps
follow the standard RED/GREEN/REFACTOR/REGRESSION cycle from `tdd-planning.md`.

## Risk Pre-Check

This task carries risk mitigations in the spec → Risk Pre-Check is active. Each gate maps to a concrete `pytest` test (or an `rg` / `git diff --numstat` / `egress_guard` assertion run inside a test) that must exist in the RED phase and fails if the mitigation is absent. A placeholder (`assert True`) fails each gate.

- **Risk ADR-0003 N1** (a per-source adapter's export-format change breaks the adapter and can break idempotency-key derivation, silently duplicating/dropping readings — here, during an UNATTENDED run where no operator catches it). Mitigation: criteria 2 and 3 assert delta-only and 0-duplicate unattended behavior, which fail if a format change corrupts the dedupe key during a `scheduler.run()`. **Gate (delta-only + 0-duplicate, both falsifiable):**
  - **Crit-2 delta-only:** a RED test must run a first `scheduler.run()` over an export, then a second `scheduler.run()` over an export that GAINED new-timepoint readings, and assert the item-file line-count DELTA equals EXACTLY the new-timepoint reading count (an exact delta, so an over-append — re-appending already-stored timepoints — or an under-append turns the test red). **Real RED (failing-capable on its own delta logic):** the RED author confirms the delta assertion turns RED against a deliberately-broken probe that makes the second run append ALL the export's readings unconditionally (re-appending the already-stored timepoints → delta = full export count, NOT the new-timepoint delta → assertion FAILS), then removes the probe. This proves the delta gate catches a corrupted-dedupe regression, not merely that the second run happens to append the right number.
  - **Crit-3 idempotent (0 lines on no-new):** a RED test must run a `scheduler.run()` over an export with NO new readings since the last run and assert the item-file line-count delta is EXACTLY 0 (idempotent unattended re-run). **Falsifiable RED:** this assertion turns RED if the no-new run appends any line (a corrupted/missing dedupe path would re-append already-stored readings).
- **Constraint D1→D3** (no egress; the unattended run writes only to the local store and makes 0 outbound network calls). Mitigation: criterion 5, carried by the `ADR-0001-T1` egress guard over a REAL `scheduler.run()`. **Gate (dynamic egress, falsifiable):** a RED test must wrap a REAL `scheduler.run()` invocation in ONE zero-arg closure and pass it to `egress_guard.run`, asserting the result is truthy (0 outbound network calls observed across the whole `scheduler.run()` invocation, including any child process). A test that asserts 0 egress over a no-op (rather than over a real `scheduler.run()`) fails this gate — it must exercise the production scheduler path. **Falsifiable RED:** this assertion turns RED if `scheduler.run()` makes (or spawns a child that makes) any outbound call — the guard is failing-capable by construction (`ADR-0001-T1`, across both egress directions + fail-closed).

These delta (crit-2), idempotent (crit-3), Whoop-not-invoked (crit-4), and 0-edit-on-adapter-add (crit-6) gates are all first-class, failing-capable RED targets — they are written to be able to turn red BEFORE the GREEN scheduler exists, per the cycle below. A scheduler that satisfies only the happy-path criterion 1 (exits 0) while silently failing the delta or idempotency check fails this Risk Pre-Check.
