## Risk Pre-Check

This is a raw-egress crown-jewel task; the Risk Pre-Check is BLOCKING. Every risk below MUST have a red-on-violation test in RED before production code is written. A placeholder (`assert True`) fails this gate.

- **Risk R-D (ADR-0037 finding D — shadow-prescribe a HELD domain):** the pass emitting tailored content for a domain the safety composition HELD is a plan-around-the-safety-gate. Gate: a test seeds a domain HELD (an additive-AE / conflict / Rx-BPMH hold so its record is `recorded: False, plan: None`) and asserts 0 tailored sections for that domain (AC-2). The emit-gate MUST read the recorded/held state, never re-derive the safety decision.
- **Risk R-§4 (ADR-0037 §4 — presentation failure fails OPEN):** if the presentation model call fails and the domain is emitted with the safety posture skipped, or the run crashes, the fail-closed posture is broken. Gate: a test injects a `ModelCallError`/empty return on the presentation call and asserts the affected domain renders its un-tailored, de-identified, safety-cleared recorded plan and the run does not crash (AC-3).
- **Risk R-egress (ADR-0021/0025 — a second store stream / second name-bearing writer):** the pass opening a store stream or a second name-bearing writer puts raw PII on a tracked/de-id surface. Gate: a grep-style test asserts `scripts/plan/tailoring.py` has 0 `store.append`/store-key definitions and renders ONLY through `reemit_maintained` (AC-4).
- **Risk R-idem (ADR-0036 constraint — non-idempotent re-run under the loop):** the loop re-runs the pass each re-gen; a non-idempotent pass leaves duplicate/stale tailored sections. Gate: a test fires the pass twice for the same `(plan, date)` and asserts 0 duplicate/stale tailored sections, reusing `_preserve_prior_content` (AC-6).

## Interface Contracts

This task creates the tailoring-pass placement/lifecycle contract that ADR-0037-T2 and ADR-0037-T3 extend (per the spec dependency map: ADR-0037-T2/T3 depend on ADR-0037-T1). Two interfaces are defined:

- **Tailoring pass entry — `tailoring.tailor`.** Signature (abstract; the executor owns internal structure): `tailor(root, *, client, plan_results_or_promoted, care_profile_read, plan_date, out_dir=None, ...) -> Path` — takes the store root, a presentation model client, the promoted/recorded plan state (the `generate_plans` per-domain records, or read via `plan_schema.resolve_plan`), a reader for `care_chat._care_profile`, and the plan date; returns the maintained artifact path. Behavioral contract: emits a tailored section for a domain ONLY when a recorded `plan::<domain>` exists AND the domain is in no hold set; degrades any domain to its un-tailored recorded plan on presentation failure; renders ONLY through `reemit_maintained`; opens no store stream. ADR-0037-T2 (dosing-token reject + interaction screen) and ADR-0037-T3 (load-time tripwire + wire-scan) extend this pass — dependent tasks MUST NOT change this signature or the emit-gate/degrade contract without Architect review.
- **`reemit_maintained` tailored-section injector.** `reemit_maintained` gains a keyword parameter carrying a `{domain: tailored-section}` mapping (default none → unchanged v0 behavior). Behavioral contract: the mapping is injected into the assembled HTML via the existing `_assemble_maintained` path, reusing `_assert_contained` + `reinsert_out` + `_preserve_prior_content`; it adds no store key and no second writer, and preserves the format-then-fill order and the realpath-containment precondition. Dependent tasks consuming the maintained artifact MUST NOT bypass this injector to write tailored content.
