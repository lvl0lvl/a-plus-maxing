- **CROWN-JEWEL BOTH LEGS — the load-bearing probe (NFR-1 / ADR-0035 Falsification).** A clarifying
  request carrying raw operator identity, OR a meds-curation request carrying operator identity / a
  name↔med linkage, OR a raw drug string persisting as a planner token / reaching the `dispatch`
  payload, is the PII-boundary breach this ADR set forbids. Gate (NON-TAUTOLOGICAL, BY pii_scan
  EXECUTION over the RECORDED requests): (a) `pii_scan.scan_text_full` over the clarifying-review
  `converse` request (`backend.calls`) → 0 identity hits AND a seeded-substring scan finds 0 full-DOB /
  0 legal name / 0 raw drug string (it carries ONLY the de-id `summarize` profile); (b) `pii_scan.scan_text_full`
  over the meds-curation request → 0 operator-identity hits AND 0 name↔med linkage (the drug name MAY
  appear, the operator identity MUST NOT); (c) the persisted `rx-interaction-classes` (after confirm) +
  the `dispatch` payload carry 0 raw drug string (a seeded-substring scan). **NEGATIVE CONTROL (QA-F3,
  prove-it-can-RED at THIS wave):** with an operator-identity token (legal name / full DOB) INJECTED
  into the de-id profile fed to EITHER request, the `pii_scan` probe goes RED — so the both-legs green
  is non-vacuous (not passed-because-the-mock-request-was-empty), proven at the wave where the egress
  code lands + Security reviews it. A substring grep alone is non-authoritative — the `pii_scan`
  EXECUTION (count > 0 vs 0) over the recorded request is the probe. The OS-egress-guard LIVE form is
  ADR-0035 OQ-1, deferred.
- **THE MEDS CURATION IS A DISTINCT NAMED EGRESS (AC3 / OQ-3).** The curation injected into a
  `chat._model_messages` / `converse` 0-store-content intake turn is the un-named-egress breach. Gate:
  the curation request is built by `care_review`'s OWN curation-message builder, NOT `chat._model_messages`
  — verified by asserting the curation request's message structure is NOT a `_model_messages(...)` output
  (e.g. it carries the drug-name curation content, not the `_deidentified_view` JSON token/domain-names
  shape) AND the chat `_model_messages` 0-store-content contract is byte-intact (a source-assert that
  `care_review` does not import/call `chat._model_messages` for the curation, + the existing
  `test_chat.py` no-egress probe stays green). FAILING-CAPABLE: routing the curation through
  `_model_messages` reds the "built outside `_model_messages`" assertion.
- **CONFIRM-WHEN-UNSURE — 0 unconfirmed class writes (AC4 / the rejected ADR-0035 Alternative C).** An
  uncertain classification auto-applied as an `rx-interaction-classes` token is the auto-apply
  false-clean. Gate: an uncertain meds classification surfaces a confirm question AND writes 0
  `rx-interaction-classes` store items until the operator confirms — verified by `store.read("rx-interaction-classes",
  root=tmp)` being EMPTY after an uncertain-classification review (a recording mock returning an
  uncertain proposal) AND a confirm question present in the review result; only a CONFIRMED token
  persists (a follow-up confirm → `store.read` non-empty). FAILING-CAPABLE: an auto-write of the
  unconfirmed token reds the 0-write assertion.
- **NO-KEY HONEST DEGRADE — 0 spend (AC5 / NFR-3).** A keyless final save making a model call is the
  0-spend breach. Gate: with `_key_available()` False (an injected `key_resolver` raising
  `KeyUnavailableError`, OR `care_review` passed `key_available=False`), the review makes 0 `converse`
  calls + 0 curation calls (the recording backend's `calls` list is EMPTY) and returns an HONEST
  deferred state (a `deferred`/`reason` field, not a silent empty / a fabricated question). FAILING-CAPABLE:
  a model call on the keyless path reds the 0-calls assertion; a silent empty (no deferred flag) reds
  the honest-state assertion.
- **MATERIAL-EDIT RE-TRIGGER (AC6 / ADR-0035 material-edit re-review).** A material My-Info edit that
  silently skips the review is the stale-curation breach. Gate: a SECOND `/upload` form-capture editing
  a medication / a safety-screen answer (the profile staying complete + a key available) re-fires the
  review + re-curates over the changed profile — verified by asserting the recording backend records a
  SECOND clarifying request + a SECOND curation request after the edit. FAILING-CAPABLE: a trigger that
