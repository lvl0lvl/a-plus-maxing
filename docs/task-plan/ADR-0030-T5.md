# Recipe: End-to-End Universal Ingestion — Synthetic Upload → Extract → Confirm → Land + the Four ADR-0030 Falsification Probes (Non-Tautological; Mock-Tested; 0 Live Spend)

This task produces a TEST FILE only — NO production file. It is the terminal Wave-4 integration gate and the
headline acceptance the whole ADR-0030 universal-ingestion slice exists to satisfy: a synthetic any-format upload
produces an operator-CONFIRMED LANDED reading through the SERVED `/upload` → `/confirm-extraction` path — not just a
working extraction call and not the honest no-data state. It creates the NEW `tests/serve/test_universal_ingestion_e2e.py`
(`test ! -e` returns 0 today [VERIFIED]) and composes the full backend chain into ONE end-to-end proof: a synthetic
fixture file → `route_upload`'s unrecognized-format branch (T2) → the mock `client.extract_readings` (the no-train lane,
T1) → the `POST /upload` review payload (T3) → `POST /confirm-extraction` → `confirm.land_confirmed` → the UNCHANGED
`store.append` sink (T3). It is testable WITHOUT the live API — the model client is a FIXTURE/MOCK injected at the
ADR-0015 `ModelClient(backend=...)` seam returning scripted Line-Field-Set readings (and, for the fail-closed probe,
raising); the run is deterministic + CI-runnable with no network, no key. The operator-present LIVE run (real key + real
file + real spend, the OS-egress-guard LIVE form of the crown-jewel probe) is OQ-1, the operator-gated checkpoint AFTER
this build, NOT a CI gate.

The TWO load-bearing test properties: **(a)** the headline E2E goes RED if it produces the honest no-data state
(the store stays empty / readings are a hardcoded constant / the empty-extraction lands a fabricated reading) instead of
a USABLE landed reading — a tautological "the store is non-empty" assertion is forbidden; it asserts the LANDED store
readings TRACE to the FIXTURE's extracted `(item, value)` (a DIFFERENT fixture → DIFFERENT landed readings), with a
failing-capable negative control proving it distinguishes a landed reading from the no-data state; **(b)** it is
mock-testable (no live API, no key). The TDD Steps follow RED/GREEN/REFACTOR/REGRESSION, GREEN here meaning "the binding
test passes against the already-built mechanism" — this task wires NO new production code; if the E2E goes RED for a real
mechanism gap, that routes back to the owning Wave-1/2/3 task (T1 the extract method / T2 the route front door / T3 the
confirm route), not a fix authored here.

T5's nine ACs are the non-tautological headline land (AC-1), the failing-capable negative control incl. the
empty-extraction honest-no-data outcome (AC-2), the crown-jewel file-egress probe (AC-3), the confirm-gate probe (AC-4),
the fail-closed probe (AC-5), the OQ-5 residue probe (AC-6), the EXTEND-NOT-REBUILD frozen-engine numstat checkpoint
(AC-7), the mock-tested 0-live-spend proof (AC-8), and the pytest-passes close (AC-9). T5 depends on T3 and drives the
served routes DIRECTLY (it does NOT depend on T4's SPA markup — T4 is the parallel Wave-4 task; the two share no file).

  reading — the headline failure mode this whole set exists to close).** Mitigation: AC-1 (the headline land) + AC-2 (the
