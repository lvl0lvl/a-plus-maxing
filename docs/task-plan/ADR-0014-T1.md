# Recipe: Web-Form Capture — By-Data-Class Persistence (Steps 2-6, Field-Map-Grounded)

This task produces CODE: the `scripts/serve/capture.py` by-data-class persistence seam, the
interactive Step-2..6 form markup in `vault/design/templates/intake.py`, and the form-submit
POST wiring on the `ADR-0013-T1`/`T4` handler in `scripts/serve/server.py`. It turns the
read-only Step-2..6 wizard shell into a capture flow: each submitted field is routed BY ITS
DATA CLASS (ADR-0014) — a de-identified `SUMMARY_FIELD_SET` token writes to the store via
`store.append`, item named EXACTLY as the token, tagged `source: "intake"`; raw/rich context
and the no-consumer fields write to the GITIGNORED `vault/scaffold/filled/` operator record;
raw PII is NEVER written into a `SUMMARY_FIELD_SET` store item (the `router.summarize` 8j6 gate
RAISES on it). Captured input reaches a specialist ONLY through `router.summarize`'s closed
field-set gate — there is no capture-to-`assemble` bypass. Step 6 is a HANDOFF state (the
operator runs `/generate-plan` — the agent path), NOT in-app generation. The form POSTs its
fields as multipart `fields` (already parsed by `stage_uploads`, `ADR-0013-T2`); the new
`capture.py` seam REUSES `store.append` + a scaffold writer, never re-implementing the store
write. The shared ingest routines + the three published seams (`store.append`,
`router.summarize`, `generate.run`) are reused UNCHANGED (ADR-0003-T2 0-shared-routine-edit;
`ingest.py`/`adapter.py`/`scheduler.py` byte-unchanged). The TDD Steps follow the standard
RED/GREEN/REFACTOR/REGRESSION cycle.

## Interface Contracts

- **Function:** `persist_capture(fields, *, root=None, scaffold_root=None, identity_config=None)` in `scripts/serve/capture.py` — **NAMED CONTRACT:** routes each submitted form field by its data class (per the Grounded Field Map), writing a wired de-identified token to the store via the UNCHANGED `store.append(token, reading, root=root)` tagged `source:"intake"`, and a record-only/raw value to the gitignored `vault/scaffold/filled/` (`scaffold_root`). **Invariants (load-bearing):** (a) the item name for a store write is EXACTLY a `SUMMARY_FIELD_SET` token (criterion 1); (b) a raw/record-only value NEVER reaches a `SUMMARY_FIELD_SET` store item (criterion 2); (c) `rx-interaction-classes` is written ONLY from supplied de-identified class tokens — 0 raw-name→class lookup (criterion 6); (d) it CALLS `store.append`, never re-implements the NDJSON write (the `pka` battery's basis). **Breaks if:** a future field is added without classifying it against the field-set/excluded split (the ADR-0014 standing discipline; the Feedback Protocol's unclassified-field HALT) — re-run the round-trip + fresh-clone-scan + the `summarize`-gate-raises checks (ADR-0014 review trigger).
- **Handler:** the form-submit POST on the `ADR-0013-T1`/`T4` POST `/upload` handler — stage → `persist_capture(staged["fields"])` → re-render. **Invariant (load-bearing for criterion 5):** the handler performs 0 in-app generation; the Step-6 submit is a `/generate-plan` HANDOFF; the route table stays intake-only {GET `/`, POST `/upload`}. **Change control:** no in-app generation call and no artifact-serving route may be added without re-opening ADR-0013/ADR-0014 against the artifact-delivery boundary (ADR-0004/NG-4).
