## Risk Pre-Check

This task carries risk mitigations (crown-jewel shadow-prescribe safety gates) — this section is BLOCKING. Implementation does not proceed to GREEN until a RED test exists for each. A placeholder (`assert True`) fails this gate.

- **ADR-0037 finding D — dose an investigational compound (§2 dosing-token reject) → AC-1.** Gate: a test must assert that a dosing token in a compound domain's tailored output causes REJECT (the domain degrades to its un-tailored recorded plan), with the count of compound-domain tailored sections carrying a dosing token == 0. The RED phase must include this test.
- **ADR-0037 §3 — deterministic drug×supplement×peptide interaction screen → AC-2 + AC-3 (paired control).** Gate: a test must assert BOTH that an intersecting (known) meds×supplements×peptides set surfaces "see your doctor" AND that a non-intersecting (safe) set surfaces no referral — `fires-on-known == True AND fires-on-safe == False`. A rule that fires on both or neither FAILS this gate (a non-paired assertion does not satisfy it).
- **ADR-0037 §3/§4 — the screen is split off the presentation model call → AC-4.** Gate: a test must inject a failing presentation call and assert the screen's verdict is unchanged (deterministic, independent of the presentation call).
- **ADR-0037 §3 — fail-closed, never silent drop → AC-5.** Gate: a test must assert that on an interaction match with a suppressed/empty presentation the referral still surfaces (never dropped).
