# Recipe: Loopback-Only HTTP Server Skeleton + `python -m scripts.serve` Entry

This task produces CODE: the `scripts/serve/` package marker, the `python -m scripts.serve`
entry (`__main__.py`), and the stdlib `http.server` request-handler skeleton (`server.py`)
that binds `127.0.0.1` ONLY and serves the existing intake wizard at GET `/`. It PUBLISHES the
server + the GET `/` route consumed by `ADR-0013-T2` (the multipart reader stages uploads for
it) and `ADR-0013-T4` (the POST `/upload` route wires into it). The server is GLUE — GET `/`
re-renders the existing wizard via `generate.run('intake')`; it adds 0 wizard markup. The bind
is `127.0.0.1` and NEVER `0.0.0.0`/`""` (ADR-0013 Confirmation 1, the first network surface the
system has ever opened). The TDD Steps follow the standard RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

This task carries risk mitigations in the spec → Risk Pre-Check is active. Each gate maps to a concrete `pytest` test that must exist in the RED phase and fails if the mitigation is absent. A placeholder (`assert True`) fails each gate.

- **Risk ADR-0013 Negative-1** (a listening socket is a new local leak surface; it must be loopback-bound by test). Mitigation: criterion 1 — the structural loopback-bind assertion. **Gate (loopback-bind, falsifiable):** a RED test must assert the server's bind address is `127.0.0.1` and NOT `0.0.0.0`/`""`/a routable interface — inspecting the constructed server's `server_address` (or the address passed to the `HTTPServer`/`socketserver` constructor). **Falsifiable RED:** the assertion turns RED if the bind is changed to `0.0.0.0` or `""`. **Negative-control failing-capability proof:** the RED includes a one-time negative-control — temporarily construct the server with `0.0.0.0`, confirm the bind assertion FAILS, then revert to `127.0.0.1` and confirm it passes. This proves the bind gate is failing-capable, not a constant-true assertion.
- **Risk ADR-0013 Negative-3** (an operator who walks away holds an open port; the ephemeral/operator-stopped lifecycle mitigates it). Mitigation: criterion 4 — clean operator-stop. **Gate:** a RED test must start the server in-process and stop it (signal / context exit / `shutdown`), asserting the listener is closed afterward (a subsequent bind to the same port succeeds, or the server's socket is closed). A server with no clean-stop path fails this gate.
- **Port-collision fail-loud (OQ-2).** Mitigation: criterion 3. **Gate:** a RED test must pre-bind the default port, then invoke `python -m scripts.serve`'s `main` and assert it exits non-zero with a fail-loud message (not a silent rebind to another port, not a stack trace swallow). A server that silently picks another port fails this gate (the operator must be told the URL changed).

## Interface Contracts

This task PUBLISHES the server factory + the GET `/` route + the handler class, consumed by `ADR-0013-T2`/`T4`, so the contract is load-bearing.

- **Factory:** `build_server(port)` (or equivalent) in `scripts/serve/server.py` — **NAMED CONTRACT (frozen at this task):** constructs an `HTTPServer` bound to `("127.0.0.1", port)` ONLY, with the published handler class. **Invariant (load-bearing for criterion 1):** the bind address is `127.0.0.1`, NEVER `0.0.0.0`/`""`/a routable interface. **Breaks if:** any later task changes the bind — then `ADR-0013-T1` criterion 1 (and the ADR-0013 Falsification 1 off-machine-unreachable guarantee) fails.
- **Handler:** the `BaseHTTPRequestHandler` subclass — `do_GET` serves the wizard at `/` (HTTP 200 + the `generate.run('intake')` body); a non-`/` GET returns 404. `ADR-0013-T4` adds `do_POST` for `/upload` to THIS handler; `ADR-0014-T1` adds the form-submit POST. **Change control:** `ADR-0013-T2`/`T4`/`T5` and `ADR-0014-T1` extend the handler but MUST NOT change the bind or the GET `/` route without Architect review.
- **Entry:** `main(argv=None)` in `scripts/serve/__main__.py` — the `python -m scripts.serve` operator entry; loopback-binds, fail-loud on collision, operator-stops. **Dependent tasks:** `ADR-0013-T4` (POST route on the same handler), `ADR-0013-T5` (wraps the request dispatch in `egress_guard.run`).
