## Risk Pre-Check

This task has risk mitigations in the spec → Risk Pre-Check is active. For a non-code spike the "gate condition: a test must exist" maps (per tdd-planning.md non-code handling) to: a verification CHECK must exist that fails if the mitigation content is absent from the report. A check that would pass on an empty report (the non-code analogue of `assert True`) fails this gate.

- **Risk ADR-0002 N2** — NDJSON enforces no schema; a malformed line is not rejected by the substrate. Mitigation: the spike fixes the exact field set so that the keying/validation discipline `ADR-0002-T1` (criterion 5: reject a reading missing any field) and `ADR-0003-T1` enforce has a concrete definition to enforce against.
  - Gate: the "Line Field Set" section must enumerate named JSON fields (item id, timepoint, source tag, value field(s)), verified by Verification step V4 (an `rg` for the field-name list, not a bare section-header match). An empty or header-only "Line Field Set" section fails V4.
- **Risk ADR-0003 N3** — the dedupe key cannot be finalized independently of the D2 (item, timepoint) keying; a later D2-keying change re-opens the dedupe design (circular dependency). Mitigation: resolving BOTH keys in this one spike removes the circularity — the dedupe tuple is fixed as a subset of the same line field set in the same report.
  - Gate: the "Dedupe Key (ADR-0003 OQ-2)" section must state a field tuple AND that tuple must be a proven subset of the "Line Field Set" fields, verified by Verification step V5 (the explicit subset assertion). A dedupe tuple naming a field absent from the Line Field Set fails V5.
