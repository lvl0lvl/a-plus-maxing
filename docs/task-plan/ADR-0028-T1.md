# Recipe: Typed Discriminated-Union Request Protocol + AUTHOR/GATE Direct-Yield Inversion

The Wave-1 entry task and the wire-shape break the rest of ADR-0028 builds on. Today `plan_driver.drive`
inverts only the AUTHOR dispatch: it yields a BARE author-tuple `yield (tuple(domains), summary, gates)`
([plan_driver.py:122](../../../../scripts/plan/plan_driver.py)) (revise re-yield at [:162]) and the GATE
is still a SYNCHRONOUS Python call in `drive`'s own frame — `_safe_gate(gate_dispatch, result)`
([plan_driver.py:129]). This task does TWO things, atomically (a CLEAN wire-shape break, not additive):

1. **The typed protocol.** Replace the bare author-tuple yield with a typed discriminated-union request
   — a `namedtuple`/dataclass `(kind, payload)` with `kind ∈ {AUTHOR, GATE, REAUTHOR, ADJUDICATOR}`. T1
   introduces the protocol + the AUTHOR + GATE kinds; REAUTHOR/ADJUDICATOR are reserved tokens T2 fills.
   The AUTHOR yield carries the `(domains, summary, gates)` payload the bare tuple carries today.
2. **The GATE direct-yield inversion.** The synchronous `_safe_gate(gate_dispatch, result)` becomes a
   YIELDED `GATE` request carrying the assembled plan + the judge + the lens roster. The consumer
   dispatches judge + each lens and `.send()`s the RAW verdicts back; `drive` STILL calls
   `compose_gate_dispatch` to map them into the 3-key disposition AND applies the fail-closed
   `safety_passed is True` surface gate ([plan_driver.py:133]). Composition stays in ONE place
   (`gate_dispatch.compose_gate_dispatch`), the surface gate in ONE place (`plan_driver.drive`) — the
   no-fork crown jewel ADR-0026 bought, inherited verbatim.

The wire-shape break is ATOMIC: `run_orchestrated`'s consumer unpack
(`req_domains, req_summary, req_gates = request`, [plan_orchestrator.py:253]) and EVERY generator-driving
test migrate to the typed-request shape in THIS task — a partial migration leaves two yield shapes in the
tree (the failure class this task exists to prevent). The byte-frozen INNER ENGINE
(`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track,router}.py`) stays
numstat=0 (EXTEND-NOT-REBUILD); only `plan_driver.py` + `plan_orchestrator.py` + (at the raw-verdict
boundary only, IF required) `gate_dispatch.py` + the generator-driving test files change. The build is
MOCK/FIXTURE-tested at 0 live spend.

This task CHANGES the shared interface consumed by ADR-0028-T2, T3, T4, T5: the `plan_driver.drive`
yield protocol. It is a CLEAN wire-shape break (not additive) of the protocol ADR-0026-T1 created. It
PRESERVES `run_orchestrated`'s public signature + return shapes verbatim (only the internal consumer loop
migrates from a bare-tuple unpack to a per-`kind` switch).

- **`plan_driver.drive` typed-request drive-protocol (the shared control-inversion contract — CHANGED,
  consumed downstream).**
  - The driver YIELDS a typed discriminated-union request — a `namedtuple`/dataclass `(kind, payload)`
    with `kind ∈ {AUTHOR, GATE, REAUTHOR, ADJUDICATOR}`. T1 emits `AUTHOR` + `GATE`; `REAUTHOR` /
    `ADJUDICATOR` are reserved tokens T2 fills. A bare tuple is NEVER yielded.
  - **AUTHOR request:** `payload` carries `(domains, summary, gates)` — the domains to author and the
    de-identified summary to author over. The CONSUMER dispatches each domain's specialist (its
    `dispatch` seam) and `.send()`s the captured `{domain: envelope}` authors fragment back.
  - **GATE request:** `payload` carries the assembled plan + the judge + the lens roster (RAW INPUTS, NOT
    a finished disposition). The CONSUMER dispatches the judge + each lens and `.send()`s the RAW verdicts
    back. `drive` then calls `compose_gate_dispatch` over those raw verdicts (the ONE composition site,
    `gate_dispatch.compose_gate_dispatch`) and applies the fail-closed `safety_passed is True` surface
    gate (the ONE surface gate, in `plan_driver.drive`) — non-True → terminal `SAFETY_BLOCKED`.
  - **The 3-key disposition the driver READS** is unchanged: `{accept: bool, safety_passed: bool,
    revise_domains: list}` — `safety_passed is True` the only surface path; `revise_domains` names only
    run-set domains. Composition is in EXACTLY 1 definition (`compose_gate_dispatch`); the driver consumes
    it, no consumer/harness/skill re-derives it (the no-fork crown jewel).
  - **Fail-closed:** an unrecognized `kind` (Negative-1) and a malformed/raised GATE `.send()`-back
    (OQ-3) both fail closed — the unknown kind → 0 plans surfaced; the malformed GATE → terminal
    `SAFETY_BLOCKED`, 0 plans.
  - The driver stays INDEPENDENTLY DRIVABLE by a fixture consumer (the test/API mode) — no live client,
    no skill (AC-9 suite green via the existing fixture drivers).
  - **Change control:** dependent tasks (T2 fills REAUTHOR/ADJUDICATOR via throw/replay; T3's harness
    serializes + advances the protocol; T4's skill drives it; T5 exercises the replay legs) MUST NOT
    change this drive-protocol (the typed-request shape, the per-class fulfilment, the GATE-carries-raw-
    inputs contract, the 3-key disposition read, the single composition/surface-gate sites) without
    Architect review (Core Rule 10).
- **`run_orchestrated(...)` — signature + return shapes UNCHANGED.** The signature (`raw_intake,
  deid_client, dispatch, store_read, root, *, plan_date, domains, on_date, gates, gate_dispatch,
  reauthor, adjudicator, dispatch_cap, revise_cap`) and the return shapes (the `run_generation` result +
  `dispatch_count` on success; the `_honest_no_plan` shape on each halt) are preserved verbatim. The
  backward-compat suite-green gate (AC-7 + AC-9) is the oracle that this contract did not drift.
