## Interface Contracts

This task exposes the runner-internal concurrency primitive; it has NO in-DAG downstream consumer (T4 is a Wave-2 LEAF — no sibling task consumes it, per the Dependency Map), so no Architect change-control gate binds a sibling. The contract is documented for future maintainers + the deferred LIVE run.

- **`store_lock.cadence_lock(root)`** (in `scripts/runner/store_lock.py`):
  - **Shape:** a context manager over `<root>/.cadence-runner.lock` using `fcntl.flock(LOCK_EX | LOCK_NB)`. Yields an ACQUIRED outcome on a free lock and a BUSY/deferred outcome on a held lock (one shape — a sentinel or a typed `CadenceLockBusy`, never both). Releases the lock in a `finally` on EVERY exit (normal, busy, or exception) so a crashed critical section frees the lock (the crash-release the re-fire rests on).
  - **Behavior:** serializes runner↔RUNNER ticks on the read→regenerate→promote critical section; does NOT lock against the server (runner↔server is accept-stale-snapshot, resting on the frozen `_write_atomic`→`os.replace` atomic-per-file). Appends NO store record, defines NO store key, adds NO `::`-prefixed item id — the lock lives OUTSIDE the frozen store.
- **`cadence_runner.run(...)`** (in `scripts/runner/cadence_runner.py`, MODIFIED, public signature UNCHANGED): its single `plan_loop.signal(CADENCE_TRIGGER)` critical section now runs inside `cadence_lock(root)`; a busy lock returns a deferred receipt (0 re-gen, 0 `signal` call) — catch-up on the next tick.
- **Crash-semantics invariant (documented, not a new API):** the debounce marker is the DERIVED latest `plan::` date (`plan_loop._last_regen_date` over `PLAN_DOMAINS`), NOT a stored marker — so a pre-promote crash writes no `plan::` reading and does not advance the marker / consume the weekly window; the runner adds NO separate marker (AC-4/AC-6).
