# Recipe: Chunk + Aggregate + Dedupe Extraction with the Honest-Partial Signal — Text-Path Only, Reuses `keying`, Mock-Tested, 0 Live Spend

A NEW local-extract-front module `scripts/ingest/extract_chunked.py` (`grep -c "extract_chunked" scripts/ingest`
→ 0 [VERIFIED ABSENT]) that takes already-extracted document TEXT plus an injected model client and:

1. **Splits the text into bounded, line-boundary chunks with overlap.** The text is chunked into pieces each ≤
   `_CHUNK_CHARS`, split on line boundaries (so a Line-Field-Set finding is never cut mid-line), with `_CHUNK_OVERLAP`
   characters of carry-over between consecutive chunks (so a finding straddling a chunk boundary appears in BOTH chunks —
   captured, then deduped — which is what makes "0 findings dropped across boundaries" hold). The three split constants
   (`_CHUNK_CHARS`/`_CHUNK_OVERLAP`/`_MAX_CHUNKS`) are OQ-2 build-time-tunable values, NAMED here as module constants so
   each is one machine-diffable value, NOT a call-site literal (NFR-7).
2. **Calls the injected client's `extract_readings(chunk, "text/plain")` once per chunk — the crown-jewel text path.**
   `extract_chunked` NEVER constructs a raw-binary / `document` block; it only ever hands the model a `text/plain` chunk.
   The injected client is the ADR-0030-T1 `ModelClient.extract_readings(file_content, media_type)` surface
   ([`client.py:97-126`](../../../../scripts/model/client.py)) — backend-injectable, so the build is mock-tested at the
   ADR-0015 seam at 0 live spend.
3. **Aggregates the UNION of every chunk's readings and dedupes them through the UNCHANGED `keying`.** All per-chunk
   readings are collected, then collapsed to one reading per `(item, timepoint, source)` identity using
   `keying.dedupe_key` ([`keying.py:19`](../../../../scripts/store/keying.py)) — the SAME dedup idiom the store sink
   already uses ([`store.py:131`](../../../../scripts/store/store.py): `list({keying.dedupe_key(r): r for r in
   readings}.values())`); each reading is checked with `keying.is_conformant`
   ([`keying.py:35`](../../../../scripts/store/keying.py)) before its `dedupe_key` is taken, honoring the documented
   precondition `dedupe_key` requires (it raises `KeyError` on a non-conformant reading — the same guard
   `confirm.land_confirmed` runs before landing, [`confirm.py:44`](../../../../scripts/serve/confirm.py)). NO second
   dedupe key is defined here (the single-source-of-truth reuse, AC-7).
4. **Returns `{"readings": [...], "complete": bool, "note": str|None}` — the HONEST partial/too-large signal.** When the
   text splits into more chunks than `_MAX_CHUNKS`, `extract_chunked` processes the first `_MAX_CHUNKS` chunks, returns
   the readings it DID extract, and sets `complete=False` + a non-empty `note` describing the too-large/over-budget
   condition — NEVER a silent empty list / "no new data" (the exact S99 failure this replaces). Within budget it returns
   `complete=True`, `note=None`.

`extract_chunked` is a PURE `(text, injected client) -> dict` orchestration: it imports `keying` (REUSED, no second
key) and imports NO model-client SDK (`anthropic` never appears — the client is injected). It is the second of the two
new local-extraction front modules in `scripts/ingest/` (T1's `pdf_extract.py` is the first); placing it in
`scripts/ingest/` keeps the serve layer subprocess-/orchestration-free and keeps the frozen-set numstat freeze on
`ingest.py`/`adapter.py` (specific files) intact — a NEW file in `scripts/ingest/` is allowed (spec Ledger note,
Module placement). It is a Wave-1 entry point (no inbound edges): T4 wires `route._extract_unrecognized` to call
`extract_chunked.extract_all(text, client)`. The fail-closed contract is INHERITED — a chunk-level `ModelCallError`
([`client.py:25`](../../../../scripts/model/client.py)) propagates out of `extract_all` unswallowed; it is never
converted into a fabricated reading or a false `complete`.

subjective assessment.

  variant that handed the client a `document`/raw-binary block, or any media type other than `"text/plain"`, would
  reopen the raw-binary egress ADR-0031 closes. Gate: a recording mock captures every `client.extract_readings` call's
  `(content, media_type)`; the test asserts EVERY recorded `media_type == "text/plain"` AND every recorded `content` is a
  `str` chunk of the input text (a `text/plain` chunk, never a constructed binary/`document` block). FAILING-CAPABLE: an

  T4 crit 2 / T6 crit 3, where the binary actually exists. The OS-egress-guard LIVE form is OQ-1, deferred.)

  AC. A too-large document that returned a silent `[]`/`complete=True` is the regression. Gate (NON-TAUTOLOGICAL): an

## Interface Contracts

This task CREATES one interface consumed by ADR-0031-T4: the `extract_chunked.extract_all` chunk-aggregate orchestration.
It MODIFIES no shared interface (it CALLS the frozen `ModelClient.extract_readings` surface and REUSES the frozen
`keying` key).

- **`extract_chunked.extract_all(text, client, *, chunk_chars=_CHUNK_CHARS, overlap=_CHUNK_OVERLAP,
  max_chunks=_MAX_CHUNKS)` (CREATED, consumed by T4).**
  - Signature: `extract_all(text, client, *, chunk_chars=_CHUNK_CHARS, overlap=_CHUNK_OVERLAP, max_chunks=_MAX_CHUNKS)
    -> dict`. In: already-extracted document `text` (str) + an injected `client` exposing
    `extract_readings(content, media_type) -> list` (the ADR-0030-T1 `ModelClient.extract_readings` surface). Out:
    `{"readings": list, "complete": bool, "note": str | None}`. T4 calls `extract_chunked.extract_all(text, client)` from
    `route._extract_unrecognized` over the locally extracted PDF text (T1's `pdf_extract.extract_text` output) with the
    served `self.client`.
  - **Crown-jewel text-path (NFR-1):** every `client.extract_readings` call carries media_type `"text/plain"`; no
    raw-binary / `document` block is ever constructed here. The raw PDF binary never reaches this module (T4 hands it
    only the extracted text).
  - **Honest-completeness contract (NFR-2):** a too-large document (chunk count > `max_chunks`) returns `complete=False`
    + a non-empty `note` AND the readings it DID extract (the first `max_chunks` chunks) — NEVER a silent empty list. A
    within-budget document returns `complete=True`, `note=None`. The load-bearing AC: no silent truncation / "no new
    data".
  - **Fail-closed contract (NFR-4):** a chunk-level `ModelCallError` propagates out of `extract_all` unswallowed — never
    converted into a fabricated reading or a false `complete`.
  - **Single-sink / reuse contract (NFR-3):** aggregation dedupes via `keying.dedupe_key` (one reading per `(item,
    timepoint, source)`), guarded by `keying.is_conformant`; NO second dedupe identity is defined; the module imports no
    model-client SDK (the client is injected).
  - **Pinned-interface / discretionary-internals (NFR-7):** the `extract_all` signature, the return-dict keys
    (`readings`/`complete`/`note`), the `"text/plain"` media type, and the union+dedupe+honest-signal contracts are
    PINNED. The exact `_CHUNK_CHARS`/`_CHUNK_OVERLAP`/`_MAX_CHUNKS` values, the chunk-split algorithm internals, and the
    exact `note` wording are implementer discretion (OQ-2).
  - **Change control:** T4 (which calls `extract_all`) MUST NOT change the signature, the return-dict keys, the
    `"text/plain"` contract, the honest-completeness shape, or the fail-closed/reuse contracts without Architect review at
    the T4 route seam.
- **Frozen surfaces (PRESERVED, called/reused not edited).** `ModelClient.extract_readings`
  ([`client.py:97-126`](../../../../scripts/model/client.py)) + `ModelCallError` ([:25]) are called/raised, byte-unchanged
