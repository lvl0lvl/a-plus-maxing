# Recipe: The No-Train `extract_readings` Method (Mirror `deidentify`/`converse`; Fail-Closed; Runtime Key; Content-Block File→Model Mechanism; Mock-Tested; 0 Live Spend)

The Wave-1 entry task and the no-train extraction primitive every downstream ADR-0030 task dispatches to. Today the no-train
model boundary `scripts/model/client.py` exposes three methods — `converse` ([client.py:251] live), `deidentify` ([client.py:297]
live), `author` ([client.py:291] the `NotImplementedError` stub) — over an injectable backend seam (`ModelClient(backend=None)`,
[client.py:44]); there is NO `extract_readings` method (`grep -c "def extract_readings" scripts/model/client.py` → 0, the new
surface). This task adds ONE new method to that boundary, mirroring the LIVE `deidentify`/`converse` shape:

1. **`ModelClient.extract_readings(file_content, media_type)` — the public fail-closed wrapper.** Mirrors `ModelClient.deidentify`
   ([client.py:78-95]): delegates to the backend, then validates the return is a `list` whose every reading carries the full
   Line-Field-Set (`item`, `timepoint`, `source`, `value` per `keying.LINE_FIELDS`, [keying.py:11]; reuse the existing
   `keying.is_conformant` field-presence check, [keying.py:35], NOT a second copy). A non-`list` return, a `list` carrying a
   field-short reading, or any backend exception RAISES `ModelCallError` — never a fabricated or partial readings payload.
2. **`_ClaudeNoTrainBackend.extract_readings` — the live no-train call.** Mirrors `_ClaudeNoTrainBackend.deidentify`
   ([client.py:297-334]): lazy `_client()` ([client.py:244]) with a runtime `key_source.resolve()` key, a bounded
   retry-with-timeout loop capped at `_EXTRACT_MAX_ATTEMPTS`, and a fail-closed `ModelCallError("extract_readings call failed")
   from None` on bound exhaustion — the raw SDK exception (carrying raw file bytes + the resolved key) is SUPPRESSED, never
   interpolated, never chained. The no-train `messages.create` carries the uploaded file as the media-typed content block per the
   spec's pinned mechanism table (a base64 `document` source for `application/pdf`, a base64 `image` source for an image media
   type, a `text` block for a text media type) plus a JSON-schema `output_config.format` constraining the returned readings to the
   Line-Field-Set array.
3. **The `_extract_*` prompt/parse helpers + `_EXTRACT_MAX_ATTEMPTS`/`_EXTRACT_TIMEOUT_SECONDS` bound constants** — the
   `_deid_prompt`/`_parse_deid_summary` ([client.py:129,153]) + `_DEID_MAX_ATTEMPTS`/`_DEID_TIMEOUT_SECONDS` ([client.py:216,220])
   analogues, named here so the bound is one machine-diffable value, not a call-site literal.

The method is **named `extract_readings` (NOT bare `extract`)** to avoid the literal collision with the existing serve-layer
`scripts/serve/extract.py` / `extract_facts` (the ADR-0017 conversation-proposal validator, a DIFFERENT layer + capability;
RGC-4 in the spec ledger). `converse`, `deidentify`, `author`, every other `ModelClient.*` wrapper, `_call` ([client.py:105]),
and `_client` stay byte-unchanged (EXTEND-NOT-REBUILD). The build is MOCK/FIXTURE-tested at the ADR-0015 seam at 0 live spend
(`_FakeAnthropic`/`_patch_backend_client`, [test_client.py:405,460]) — no live API, no key, no network; the operator-present
LIVE run (real key + real file + real spend) is OQ-1, the operator-gated checkpoint AFTER the build, in no wave.

## Risk Pre-Check

This task carries the spec's ADR-0030-T1 Risk Mitigations field + the build plan's Wave-1 hard constraints. Before proceeding to
RED, verify a test exists (or the RED phase adds one) for EACH; a placeholder test (`assert True`) fails this gate. The gate
conditions reference live tests/commands, not subjective assessments.

- **CROWN-JEWEL SEC — fail-closed carries no raw-file/key (NFR-1 / NFR-3 / ADR-0030 Falsification — key-never-committed).** The
  no-train extract call is the FIRST extension of the no-train lane onto the ingestion axis — whole raw FILES egress. A failure
  that interpolated the raw file bytes or the resolved key into the `ModelCallError` message, OR chained the raw SDK exception as
  `__cause__`, leaks them into a caller's `logger.exception()` / `traceback.print_exc()` (PUBLIC repo). Gate: (a) the raised
  `ModelCallError` carries a CONSTANT message — `str(exc)` + `repr(exc.args)` over a forced-failure path whose SDK exception
  EMBEDS a synthetic raw-file token + a synthetic key token carry 0 occurrences of either (AC-6); (b) `exc.__cause__ is None` AND
  the fully-rendered `traceback.format_exception(...)` carries 0 occurrences of either token (the `from None` lock, AC-6a). The
  synthetic key token is BUILT AT RUNTIME (no `sk-ant-…` literal in the source — the tree-wide `test_no_api_key_literal_in_tracked
  _tree` gate flags any key-shaped literal). Both probes are FAILING-CAPABLE: a variant interpolating `{exc!r}` into the message,
  or reverting `from None` to `from <exc>`, MUST turn the probe RED (verify the revert reds it, then restore).
- **FAIL-CLOSED — 0 fabricated readings (NFR-3 / ADR-0030 fidelity-ceiling).** A failed / empty / malformed / errored / timed-out
  extraction that returned a fabricated or partial readings payload is the fidelity-ceiling breach ADR-0030 forbids. Gate: each of
  `None`, `{}`, a non-list body, a `RuntimeError`, a `TimeoutExpired` injected at the patched SDK / the mock backend raises
  `ModelCallError` with 0 readings returned (AC-3); the backend invokes `messages.create` at most `_EXTRACT_MAX_ATTEMPTS` times
  before the fail-closed raise — `len(fake.calls) == _EXTRACT_MAX_ATTEMPTS` (AC-3a, never unbounded).
- **NON-TAUTOLOGICAL — the method returns the model's parse, not a constant (NFR / ADR-0030 Validation).** A method that returned a
  hardcoded readings constant would pass a single-fixture test vacuously. Gate: fixture A → readings A and a DIFFERENT fixture B →
  readings B with B ≠ A, each returned reading tracing to its fixture (AC-2); at the live backend, a different scripted SDK
  envelope → different parsed readings (Cycle-2 live non-tautological note).
- **RUNTIME KEY, no tracked file (NFR-1 / ADR-0030 Negative — key-never-committed).** A key read at module load or from a tracked
  file is the public-repo key-leak failure. Gate: a fake-`anthropic`-module test asserts the SDK client was handed the

- **FILE→MODEL content-block mechanism (NFR-7 — interface-pinned).** The pinned mechanism (a `document` base64 source for

## Interface Contracts

This task CREATES one interface consumed by ADR-0030-T2, T3, T5: the `ModelClient.extract_readings(file_content, media_type) ->
list[Line-Field-Set readings]` no-train extraction method. It PRESERVES the published `converse`/`deidentify`/`author` surface +
the `_call`/`_client` internals verbatim.

- **`ModelClient.extract_readings(file_content, media_type)` (CREATED, consumed downstream).**
  - Signature: `extract_readings(self, file_content, media_type) -> list` — the uploaded file content (bytes for document/image
    media types, decodable bytes/str for text) + its media type in; a `list` of readings out, each a `dict` carrying the full
    Line-Field-Set (`item`, `timepoint`, `source`, `value` per `keying.LINE_FIELDS`). Backend-injectable (`ModelClient(backend=
    ...)`) — T2's `route_upload(client=...)` dispatches to it; T5's E2E injects a mock backend at this seam.
  - **Fail-closed contract (NFR-3):** a non-`list` return, a `list` carrying a reading that fails `keying.is_conformant` (a missing
    Line-Field-Set field), or any backend exception (errored / timed-out) RAISES `ModelCallError` — never a fabricated or partial
    readings payload. The `ModelCallError` message is CONSTANT and the chain is `from None` (no raw file bytes or resolved key on
    `str` / `.args` / the rendered traceback — the crown-jewel SEC lock, NFR-1).
  - **Pinned file→model mechanism (NFR-7):** the no-train `messages.create` carries the file as the media-typed content block (a
    base64 `document` source for `application/pdf`, a base64 `image` source for an image media type, a `text` block for a text
    media type) + a JSON-schema `output_config.format` constraining the readings array. The content-block shape + the return type
    are PINNED; the exact SDK request JSON, the structured-output schema's internal field ordering, and the retry/timeout constant
    VALUES are implementer discretion.
  - **Empty-list / no-data seam (cross-task, document the decision):** AC-3's enumerated failure modes are `None`, `{}`, a non-list
    body, `RuntimeError`, `TimeoutExpired` — the empty list `[]` is not among them. T1 implements the AC-3 fail-closed boundary
    faithfully (a zero-reading result fails closed as no-usable-readings, consistent with the `deidentify` mirror). The store-empty
    honest-no-data outcome (T5 crit 2) is preserved either way at T3/T5 — a zero-reading extraction surfaces 0 readings for confirm
    and lands nothing. **For reviewers:** if a downstream task (T3 UX) needs a blank document to surface an empty review panel (a
    returned `[]`) rather than a fail-closed degraded response, that is a T3/T5 contract decision flagged here, NOT a T1 change.
  - **Change control:** dependent tasks (T2 dispatches to this method; T3 surfaces/lands its return; T5 drives it via a mock) MUST
    NOT change this method's signature, the Line-Field-Set return shape, the fail-closed contract, or the pinned content-block
    mechanism without Architect review at the T2 front-door seam.
- **Frozen surface (PRESERVED).** `converse`, `deidentify`, `author`, every other `ModelClient.*` wrapper, `_call`, and `_client`
  are byte-unchanged (AC-8). The single model-client SDK import stays inside `scripts/model/` (the crown-jewel structural guard,
