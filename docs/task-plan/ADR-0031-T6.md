# Recipe: End-to-End PDF Ingestion — Synthetic PDF → LOCAL Extract → Chunk → Confirm → Land + the ADR-0031 Falsification Probes (Non-Tautological; Mock/Fixture-Tested; 0 Live Spend)

This task produces a TEST FILE only — NO production file. It is the terminal Wave-3 integration gate and the
headline acceptance the whole ADR-0031 local-extraction-first slice exists to satisfy: a synthetic PDF upload produces
an operator-CONFIRMED LANDED reading through the SERVED `/upload` → `/confirm-extraction` path, with the raw binary
proven to stay LOCAL (the model receives extracted TEXT only) — not just a working extraction call and not the honest
no-data state. It creates the NEW `tests/serve/test_pdf_ingestion_e2e.py` (`test ! -e` returns 0 today [VERIFIED]) and
composes the full local-extract-first chain into ONE end-to-end proof: a synthetic fixture PDF → `route.route_upload`'s
PDF branch (T4) → `pdf_extract.extract_text` LOCAL extraction (T1; stubbed for the always-runs form, real `pdftotext`
for the `skipif`-gated form) → `extract_chunked.extract_all` chunk + aggregate + dedupe + honest-partial signal (T2) →
the mock `client.extract_readings(chunk, "text/plain")` (the no-train TEXT lane, never a `document` block) → the
`POST /upload` review payload `{"readings", "partial", "notes"}` (T4) → `POST /confirm-extraction` →
`confirm.land_confirmed` → the UNCHANGED `store.append` sink. It is testable WITHOUT the live API — the model client is
a FIXTURE/MOCK injected at the ADR-0015 `ModelClient(backend=...)` seam returning scripted Line-Field-Set readings (and,
for the fail-closed probe, raising); `marker` is never really run (no low-text trigger; stubbed if reached); the run is
deterministic + CI-runnable with no network, no key. The operator-present LIVE run (real key + the real 42-page
genetics/SNP report + real spend, the OS-egress-guard LIVE form of the raw-binary-egress + local-extractor-network
probes) is OQ-1, the operator-gated checkpoint AFTER this build, NOT a CI gate.

The TWO load-bearing test properties: **(a)** the headline E2E goes RED if it produces the honest no-data state
(the store stays empty / readings are a hardcoded constant / a failed extraction lands a fabricated reading) instead of
a USABLE landed reading — a tautological "the store is non-empty" assertion is forbidden; it asserts the LANDED store
readings TRACE to the FIXTURE's scripted `(item, value)` (a DIFFERENT fixture → DIFFERENT landed readings), with a
failing-capable negative control proving it distinguishes a landed reading from the no-data state; **(b)** it is
mock/fixture-testable (no live API, no key, no real heavy `marker`, 0 spend). The TDD Steps follow
RED/GREEN/REFACTOR/REGRESSION, GREEN here meaning "the binding test passes against the already-built mechanism" — this
task wires NO new production code; if the E2E goes RED for a real mechanism gap, that routes back to the owning
Wave-1/2 task (T1 the local extractor / T2 the chunk-aggregate / T3 the genetics prompt / T4 the route+server wiring),
not a fix authored here.

T6's nine ACs are the non-tautological headline land (AC-1: stubbed-always + real-`pdftotext`-`skipif`), the
failing-capable negative control (AC-2), the crown-jewel raw-binary-egress probe (AC-3), the completeness /
no-silent-truncation probe (AC-4), the genetics genotype-fact land cross-checking T3 (AC-5), the confirm-gate +
local-extractor-network probe (AC-6), the EXTEND-NOT-REBUILD numstat over the EXTENDED frozen set (AC-7), the
mock-tested 0-live-spend proof (AC-8), and the pytest-passes close (AC-9). T6 depends on T4 (the wired local-extract
route + the server `/upload`+`/confirm-extraction` path it drives directly) and T3 (the genetics genotype-fact prompt
it cross-checks); it does NOT depend on T5's SPA markup (T5 is the parallel Wave-3 task — the two share no file).

**FOLD-IN QA-2 — the canonical six are 5-per-test + 1-hook-verified (do NOT claim all six are per-test here).** The
ADR-0031 "six falsification probes" are, canonically: raw-binary-egress, local-extractor-network, extend-not-rebuild,
completeness/no-silent-truncation, confirm-gate, key-never-committed. **FIVE of those six are per-test IN this file**
(raw-binary-egress AC-3, local-extractor-network AC-6, extend-not-rebuild AC-7, completeness/no-silent-truncation AC-4,
confirm-gate AC-6). **The SIXTH — key-never-committed — is NOT a per-test AC**: it is the repo-wide release gate
carried by the `block-pii-commit`/`pre-push` hooks (grep every tracked file + git history on a fresh clone for the
API-key value; threshold 0), re-run at release, documented in the test-module docstring + the Non-AC note — NOT
asserted as a per-test here. The recipe additionally names a fail-closed/no-fabrication probe and a non-tautology
(genetics A≠B) probe as failing-capable per-tests (NFR-4 + AC-2/AC-5 family); see the spec-defect note in Report on the
two distinct probe enumerations.
