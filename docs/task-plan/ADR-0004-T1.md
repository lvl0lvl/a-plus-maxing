## Risk Pre-Check

The spec lists risk mitigations for this task; the Risk Pre-Check is active. Every gate below is a falsifiable RED target — a `assert True` / boolean / no-op placeholder FAILS the gate.

- **Risk: ADR-0004 Negative (generation constrained by the store read model + the PII no-egress boundary — no freedom to fetch remote data or assets).** Spec assigns criteria 5 and 6.
  - **Gate (crit 5 — egress-0-call):** a RED test MUST wrap a real `render.emit` call in ONE zero-arg closure under the ADR-0001-T1 egress guard (`egress_guard.run`) and assert `run` is **truthy** (0 outbound calls observed across the whole `emit` invocation) — i.e. the render path makes 0 network calls and reads only the store. A test that asserts 0 calls over a no-op (rather than over a real `emit`) fails this gate; it must exercise the production render path.
  - **Gate (crit 6 — raise-on-external-asset):** a RED test MUST construct an `emit` input whose template/component would reference an asset resolving to an **external URL** (a non-`data:`, non-fragment `src=`/`href=`/`url(`) and assert `render.emit` **raises** (refuses to emit a network-dependent file) — the engine never writes a file with a non-inlined external asset. A test that only checks the happy inlined-asset path fails this gate; the raise direction is required.
- **Constraint D1→ADR-0004 (PII no-egress at render: 0 PII egress at render).** Spec assigns criteria 1 and 5.
  - **Gate (crit 1 — 0 external asset references + offline render):** a RED test MUST assert that `rg` over the emitted file for `src=`/`href=`/`url(` pointing at any non-`data:`, non-fragment URL returns **0**, AND that an offline open of the file observes **0** outbound requests. The offline-open assertion REUSES the SAME ADR-0001-T0 capture mechanism the Entry State already gates on (the syscall/socket interceptor OR offline-namespace run named in the ADR-0001-T0 Recommendation — the harness the entry criterion requires be invocable), applied over the file-OPEN (not over `emit`): the file is opened under that capture and the captured outbound-request count is asserted == 0. A boolean "renders OK" check fails this gate; the external-reference count and the captured offline-open outbound count must both be measured and asserted == 0.
- **Accessibility / color-vision-safety MEASURED-VALUE gate (crit 3 — Wave 3→4 go/no-go checkpoint, build plan lines 93 + 237).** This is the load-bearing gate. **The concrete reference values the membership + color-distance halves assert against do NOT exist upstream** — `vault/design/artifact-design-protocol.md`'s Color Palette is TBD (it names the good/watch/concern roles + the WCAG-AA / print-safe / never-red-only constraints, with ZERO hex values; line 44–48), and no color-distance metric or numeric threshold is stated in the spec (crit 3 says only "a *stated* threshold"), build plan, ADR, or design source. Per the design source's own line-24 mandate ("make a defensible choice … and propose a permanent rule via a `decisions/` entry"), the executor RESOLVES these at GREEN and RECORDS them in an INDEPENDENT `vault/decisions/` entry (see the UPSTREAM FLAG and the Cycle-3 GREEN step). The RED test `test_contrast_and_colorblind` MUST:
  - Compute and assert a **measured AA contrast ratio** as a NUMBER — a computed ratio ≥ 4.5 for normal text / ≥ 3.0 for large text, derived from the emitted file's inline styles (the test computes the ratio from the foreground/background luminances; it prints/returns the computed ratio, never `assert True`). The 4.5 / 3.0 figures are pinned upstream (WCAG-AA); they are the only crit-3 numbers that do NOT come from the vault/decisions record.
  - Compute and assert a **measured color-distance NUMBER** for every adjacent-series color pair, above the RECORDED threshold **under the RECORDED color-vision simulation**. The metric and the numeric threshold are NOT stated upstream, so they are fixed in the same `vault/decisions/` entry as a load-bearing RED target the way contrast is pinned to 4.5/3.0: the metric is a **CIEDE2000 ΔE** computed under a **named deuteranopia + protanopia color-vision simulation** (the simulation name + the ΔE numeric floor are both recorded in the entry). The test applies the named simulation to each adjacent pair, computes the CIEDE2000 ΔE, and asserts that COMPUTED ΔE exceeds the RECORDED numeric floor read from the `vault/decisions/` entry (a computed number vs a recorded number — FALSIFIABLE on drift if the production palette regresses below the recorded floor); it prints/returns each computed ΔE, never a boolean.
  - Assert every series/category color in the rendered output is a MEMBER of the palette RECORDED in the `vault/decisions/` entry — the literal good/watch/concern hex set read from that entry, NOT re-read from `component_set.py`. (Reading the expected set from the production module would make the assertion a tautology, since the executor authors the palette in `component_set.py`; reading it from the independently-recorded decision makes the test FAIL if the production palette drifts from the recorded decision.) Also assert the design is never red-only (no semantic state distinguished by red alone).
  - Assert an `@media print` stylesheet block is PRESENT in the emitted file.
  - **Gate condition:** any of the four assertions reporting a non-numeric / `assert True` / boolean stub instead of a computed value FAILS this gate (a placeholder cannot pass the Wave 3→4 checkpoint silently — build plan lines 93, 237). The contrast ratio and the per-adjacent-pair CIEDE2000 ΔE MUST be computed numeric values, and the membership + ΔE-floor expected values MUST be read from the `vault/decisions/` entry (the recorded palette + threshold), not from `component_set.py`.

These gates are first-class RED targets, scheduled in the cycles below — not optional add-ons.

## Interface Contracts

This task **publishes** the V1 render interface in `scripts/generate/render.py` + the `vault/design/templates/component_set.py` template component library, consumed by four downstream tasks. These are load-bearing — the dependent tasks plan against these exact surfaces.

- **Function:** `emit(template, store_read)` in `scripts/generate/render.py`
  - **Signature:** `render.emit(template, store_read)` — `template` is the named component-set-assembling template (the dashboard or report template object/identifier); `store_read` is the store read model (the data returned by the cross-spec `store.read(item)` / `keying.py` read model). Writes one self-contained HTML file to disk and **RETURNS the path of the file it wrote** (the destination is `emit`-owned; callers do not pass an output-path argument — `emit` chooses the path and returns it). This is the defined way ADR-0004-T3's `generate.run(artifact_name)` (its crit-1 "file exists on disk after the call returns") and this task's own `wc -c` / `rg` / structural-diff tests LOCATE the written file: they capture the returned path and assert on it.
  - **Behavioral contract:** renders `template` against `store_read` into ONE self-contained local HTML file with everything inlined (inline CSS, inline SVG), and returns that file's path — 0 external asset references (no non-`data:`, non-fragment `src=`/`href=`/`url(`), each emitted file < 500000 bytes, the output opens offline with 0 outbound requests, and two generations of the same artifact type from the same `store_read` produce byte-identical structure (data-masked diff == 0). On the refuse-external-asset path it RAISES and returns nothing (writes no file).
  - **PII no-egress boundary (D1→ADR-0004):** `emit` reads operator data ONLY through the `store_read` argument (sourced from `store.read` / `keying.py`); it makes 0 outbound network calls and fetches no remote data or asset — verified by the cross-spec egress guard (`egress_guard.run`) over an `emit` call observing 0 outbound calls (criterion 5).
  - **Refuse-external-asset invariant (criterion 6):** `emit` RAISES when a referenced asset would resolve to an external URL — it refuses to emit a network-dependent file rather than writing one. Callers must inline every asset (as `data:` / fragment) before `emit`.
  - **Dependent tasks (consume `render.emit`):** **ADR-0004-T2** (extends `render.py` for the matrix/projection render under the ADR-0004-T0 cap — modifies this file, must preserve the signature + boundary), **ADR-0004-T3** (the on-demand + cron entry point `generate.run` invokes `render.emit`; both entry modes route through this one function), **ADR-0006-T2** (the assembled plan is rendered through this generation path), **ADR-0007-T2** (the loop-schema views render through this engine + component library).

- **Module:** `vault/design/templates/component_set.py`
  - **Contract:** the shared inline-CSS/SVG component library — the single definition of the reusable rendered components and the colorblind-safe semantic palette (the artifact-design-protocol good/watch/concern set, never red-only; AA-contrast foreground/background pairs; adjacent-series colors above the deuteranopia/protanopia distance threshold; an `@media print` block). - **Load-bearing invariants (with break conditions):** the three invariants downstream tasks plan against, each with an explicit "breaks if":
  - **Inline-only (refuse-external-asset).** Every asset is inlined as `data:` / fragment; `emit` raises on any non-`data:`/non-fragment reference. **Breaks if** any consumer references a non-`data:`/non-fragment asset → `emit` raises (no file written) and that consumer's render fails.

- **Change control:** Dependent tasks MUST NOT change the `render.emit(template, store_read)` signature, the path-return contract, the PII no-egress boundary, the three load-bearing invariants above, or the `component_set.py` palette/component contract without Architect review.
