# Recipe: Multipart Reader + Temp Staging (Traversal-Safe, Oversize-Bounded)

This task produces CODE: the `scripts/serve/multipart.py` module that reads a
multipart/form-data request body and streams each uploaded file part to a server-chosen temp
path, sanitizing the client filename so a `../` traversal cannot escape the temp dir, and
applying a byte ceiling so an oversize upload is refused before the full body is written. It
PUBLISHES the staging surface consumed by `ADR-0013-T3` (the Apple-zip extraction reuses the
staged path + the byte ceiling) and `ADR-0013-T4` (the route dispatches the staged file into
`ingest.run` / `dna.land`). The traversal-containment + the oversize ceiling are the
ADR-0013 Confirmation-3 + the ADR-0012 `07f6` mitigations. The TDD Steps follow the standard
RED/GREEN/REFACTOR/REGRESSION cycle.

## Risk Pre-Check

Active. Each gate maps to a concrete `pytest` test. A placeholder (`assert True`) fails each gate.

- **Risk ADR-0013 Confirmation-3 / Negative-1** (a path-traversal filename must not escape the temp path). Mitigation: criterion 2 — the traversal-containment assertion. **Gate (traversal-containment, falsifiable):** a RED test must upload a part with `filename=../../x` (and `..\\..\\x`, and an absolute `/etc/x`) and assert `Path(staged).resolve()` is STILL within the server-chosen temp root AND the traversal target path does not exist. **Falsifiable RED:** the assertion turns RED if the filename is used un-sanitized (the staged path escapes the temp root). **Negative-control failing-capability proof:** the RED includes a one-time negative-control — temporarily stage with the raw (un-sanitized) client filename, confirm the containment assertion FAILS for `../../x`, then restore the sanitization and confirm it passes. This proves the traversal gate is failing-capable.
- **Risk ADR-0012 `07f6`** (an unbounded copy can OOM / amplify; the Apple export can be hundreds of MB). Mitigation: criteria 3-4 — the byte ceiling + the chunked streamed copy. **Gate (oversize-bounded, falsifiable):** a RED test must upload a body exceeding the configured byte ceiling and assert the reader refuses it (raises / truncates-and-raises) BEFORE the full body is written, and the partial temp file is removed (0 residual oversize temp file). **Falsifiable RED:** the assertion turns RED if the ceiling is removed (the over-ceiling body writes fully). A separate assertion confirms the copy is chunked (`rg` finds the chunked-copy loop, 0 single-shot full-body file-part reads).

## Interface Contracts

This task PUBLISHES the staging surface consumed by `ADR-0013-T3`/`T4`, so the contract is load-bearing.

- **Function:** `stage_uploads(content_type, body_stream, temp_root)` (or equivalent) in `scripts/serve/multipart.py` — **NAMED CONTRACT (frozen at this task):** parses the multipart body, streams each file part to a sanitized path under `temp_root`, applies the byte ceiling, and returns the staged path(s) + form fields. **Invariant (load-bearing for criterion 2):** the staged path ALWAYS resolves within `temp_root`; the client filename contributes ONLY a basename. **Breaks if:** a later task uses the raw client filename or removes the ceiling — then `ADR-0013-T2` criterion 2 (traversal containment) or criterion 3 (oversize) fails.
- **Dependent tasks:** `ADR-0013-T3` (the Apple-zip extraction reuses the staged path + the byte ceiling for the inner-xml copy), `ADR-0013-T4` (the route dispatches the staged file into `ingest.run` / `dna.land`). **Change control:** downstream tasks MUST NOT change the staging signature or weaken the traversal/ceiling guards without Architect + Security review.
