## Risk Pre-Check

Risk **ADR-0001 N2** from the spec (mis-routed PII / no enforcement mechanism built): the split-path design means a mis-routed dispatch could send operator PII to a training-eligible path, and prior to this task no enforcement was built. The spec assigns criteria 1 and 3 to convert N2 from unmitigated to a covered, test-backed check.

- Before proceeding to GREEN, the RED phase MUST include the **failing-capable floor** tests that make the guard genuinely able to turn red. The floor is specified HERE — it is NOT deferred to the ADR-0001-T0 spike (the spike selects the mechanism; this recipe pins what the mechanism must be able to fail on):
  - **Crit-1 in-process fail path:** a test that wraps `callable` so it makes ≥1 outbound network call in-process (opens an outbound socket / issues an HTTP request) and asserts `egress_guard.run` returns a **fail** (falsy) result.
  - **Crit-1 out-of-process fail path (Security HIGH-1):** a test that wraps `callable` so it spawns a CHILD process that connects out (e.g. via `subprocess` spawning `curl` or a child that opens an outbound socket) and asserts `egress_guard.run` returns a **fail** (falsy) result. An in-process-only capture that passes when a subprocess egresses is a hole the trust boundary cannot have — the out-of-process direction is a first-class RED target, not the in-process socket case alone.
  - **Crit-1 fail-closed-on-unavailable path (Security HIGH-1):** a test that forces the egress-capture mechanism to be unestablishable or to error during setup, and asserts `egress_guard.run` returns a **fail** (falsy / default-deny) result — never a pass. A guard that passes when it could not actually observe egress is a silent no-op.
  - **Crit-3 plant path / token-class completeness floor (Security HIGH-2):** a test that plants an operator-PII token **from EACH declared operator-PII CLASS** — at minimum **identity** (name / DOB), **contact** (email / phone / address), and **health-identifier** (MRN / health-ID), parameterized over the ADR-0001-T0-selected token set — into a tracked file, and asserts `pii_scan.scan(tracked_files)` returns a hit count **≥1** for each planted class AND that the failing path **names the offending file**. A single-token scanner (one that finds only the one token the test plants) fails this floor: the scan must be demonstrably class-complete. A companion assertion checks the IMPLEMENTED token set EQUALS the ADR-0001-T0-declared set (not a subset), so the scanner cannot ship a narrower set than the spike fixed.
- Gate condition: a placeholder test (`assert True`, or a test that asserts only the pass-direction and never the fail-direction, or a plant test that exercises only one PII class) FAILS this Risk Pre-Check. The trust boundary requires the guard to be demonstrably failing-capable across BOTH egress directions (in-process + out-of-process) and across ALL declared PII classes, not merely pass-capable on a single token. This is the build-plan Wave 2→3 "enforcement-first guard" cross-spec check (build plan line 229): "the guard is genuinely failing-capable, not a no-op."
- These failing-capable RED targets are first-class, scheduled in Step 1 (Cycle 1) and Step 5 (Cycle 2) below — not optional add-ons.

## Interface Contracts

This task **publishes** two interfaces in the `scripts/guard/` package consumed across both specs. These are load-bearing — the downstream tasks plan against these exact signatures.

- **Function:** `run(callable)` in `scripts/guard/egress_guard.py`
  - **Signature:** `run(callable)` — accepts a zero-argument callable (the operation to observe).
  - **Unit of observation (Architect F1):** the callable is the COMPLETE operation-under-observation. Callers wrap a multi-step sequence (e.g. ADR-0002-T1's `store.append`→`store.read`) in ONE zero-arg closure, and `run` observes egress across the ENTIRE callable invocation, returning **fail** if ≥1 outbound call occurs anywhere within it (in-process or from a child/subprocess) — not per-call.
  - **Return shape (Architect F2):** `run` returns a value that is **truthy on pass, falsy on fail** — a `bool` or a result object whose `__bool__` is truthy only on pass. This is the single truthiness convention; an "exit-code int" (0=pass) is NOT an offered shape (it is falsy-on-pass and inverts under the consumer idiom). The shape must satisfy the pinned consumer idiom `sys.exit(0 if run(lambda: open('/dev/null').read()) else 1)` (build plan line 25) — the same idiom the 8 data-out 0-egress consumers use.
  - **Behavioral contract:** executes `callable` under the ADR-0001-T0-selected egress-capture mechanism; returns a **pass** result (truthy) when 0 outbound network calls carrying store content are observed across the whole invocation, and a **fail** result (falsy) when ≥1 is observed. Never silently passes an operation that made an outbound call — failing-capable by construction. **If the capture mechanism cannot be established or errors, `run` returns FAIL, never pass** (fail-closed / default-deny — Security HIGH-1).
  - **Dependent tasks (consume `run`):** ADR-0002-T1 (criterion 4: egress check over `store.append`→`store.read`), ADR-0003-T1 (criterion 5: egress over `ingest.run`), ADR-0003-T3 (scheduler egress), and every data-out 0-egress task — ADR-0004-T1, ADR-0004-T2, ADR-0005-T1, ADR-0005-T2, ADR-0006-T1, ADR-0006-T2, ADR-0007-T1, ADR-0007-T2 (build-plan cross-spec edge, line 371: `ADR-0001-T1 → {…}`).

- **Function:** `scan(tracked_files) -> int` in `scripts/guard/pii_scan.py`
  - **Signature:** `scan(tracked_files) -> int` — accepts an iterable of tracked file paths; returns the integer operator-PII hit count across them. The `-> int` return type is preserved exactly (the SEC-01(a) build-plan assertion `isinstance(scan([]), int)` depends on it); the offending-file path is out-of-band, NOT on the return.
  - **Token-class completeness floor (Security HIGH-2):** the implemented token set covers every declared operator-PII class — identity, contact, health-identifier — and EQUALS the ADR-0001-T0-declared set (not a subset). The scanner cannot ship a narrower set than the spike fixed.
  - **Offending-file channel (Security MED):** when the count is ≥1, the offending file path is exposed via ONE documented channel — a `PII-HIT: <path>` line emitted to **stderr** per offending file. This is the single channel the ADR-0005-T1 hook reads; it is NOT duplicated on the return value or any second mechanism (so the hook cannot fork).
  - **`tracked_files` capture semantics (Security LOW-1 / TOCTOU):** `tracked_files` is the caller's CURRENT staged/tracked set captured at invocation; `scan` does not re-enumerate. The ADR-0005-T1 hook passes its exact `--staged` set, closing the add-after-enumeration TOCTOU window.
  - **Behavioral contract:** returns `0` when no operator-PII token (from the ADR-0001-T0 token set) appears in any supplied file, and a count `≥1` otherwise; `scan([]) == 0`. The file list is a parameter (not discovered internally), so any caller can route its own file set through the one shared scanner.
  - **SEC-01(a) reuse contract (CRUCIAL):** **ADR-0005-T1's pre-commit hook (`block-pii-commit.sh`) calls this exact `scan(tracked_files)` function — it MUST NOT reimplement the token scan in bash.** The hook passes its staged-file set as `tracked_files`. The build plan asserts this at the Wave 2→3 boundary (line 230): `python3 -c "from scripts.guard.pii_scan import scan; assert callable(scan); n = scan([]); assert isinstance(n, int)"` exits 0 — a positive assertion that the published surface exists with the right shape. The Wave 2→3 SEC-01(b) adversarial check (line 231) further verifies the hook's block decision flips when `scan` is stubbed to return 0, proving the hook routes through this function rather than a parallel bash reimplementation. Therefore `scan` must keep a stable `(iterable[str]) -> int` signature and accept an empty list (`scan([]) == 0`).
  - **Dependent tasks (consume `scan`):** ADR-0005-T1 (the pre-commit hook — REUSES `scan` verbatim, criteria 2 and 5); the same function backs the tracked-file scan in this task's own criteria 2-3.

- **Change control:** Dependent tasks MUST NOT change either signature without Architect review. ADR-0005-T1 in particular depends on `scan(tracked_files) -> int` being importable and accepting an arbitrary file-path iterable.
