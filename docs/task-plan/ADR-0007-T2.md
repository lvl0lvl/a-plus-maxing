# Recipe: Biomarker-Matrix + Projection Render-Time Views

This task is the **terminal sink of the V1 DAG** — the cross-boundary integration that maps the `ADR-0007-T1` store-schema states (pending / not-yet-answered / no-prior) to rendered views, recomputing the biomarker matrix and naive projections from stored timepoints at render time and keeping each artifact under the `ADR-0004-T0` cap. It CONSUMES three published interfaces (the `ADR-0007-T1` store-state contract, the `ADR-0004-T1` render engine + component library, the `ADR-0004-T0` cap) plus the cross-spec store read model (`ADR-0002-T1`) and egress guard (`ADR-0001-T1`); it does **not** publish a new broadly-reused interface.

## Risk Pre-Check

The spec's `### ADR-0007-T2` Risk Mitigations field is non-empty; each mitigation below maps to a failing-capable gate that MUST have a covering RED test before GREEN. A placeholder (`assert True`) fails every gate.

- **Risk R1 — store-schema-vs-render-view 2-decision contract surface (ADR-0007 Negative).** A state the `ADR-0007-T1` store records but the view misreads is a defect spanning two decisions. **Gate (criterion 4):** a RED test (Step 9) reads the `ADR-0007-T1` `pending` + `not-yet-answered` + `no-prior` store states and asserts the rendered view maps each 1:1 to its rendered state — a pending panel rendered AS a result, an unanswered check-in rendered as a cleared/absent result, or a `no-prior` single-timepoint biomarker rendered with a fabricated trend/delta/projection FAILS the test. This is the cross-boundary integration check that closes the contract; it must be able to turn red when the mapping is wrong.
- **Risk R2 — matrix/projection strain the <500KB budget (ADR-0007 Negative).** The richest matrix + projection render pressures the inline-everything per-file ceiling. **Gate (criterion 6):** a RED test (Step 11) renders the worst-case view, applies the `ADR-0004-T0` cap to paginate/split, and asserts every rendered artifact is `wc -c` < 500000 bytes — a single over-cap unpaginated file FAILS.
- **Risk R3 — ≥3-timepoint projection guardrail → projections absent early, trend-only (ADR-0007 Negative, accepted documented limitation).** **Gate (criterion 2):** a RED test (Step 7) asserts a projection is PRESENT at ≥3 timepoints and ABSENT at exactly 2 (trend-only). A projection rendered at <3 timepoints FAILS — the honest-absence contract is the guardrail, not a bug.
- **Risk R4 — no labs/answers to model (Constraint D1→ADR-0007).** **Gate (criterion 5):** a RED test (Step 5) wraps a `render_views` recompute in the `ADR-0001-T1` egress guard and asserts 0 outbound + 0 model-bound dispatch of any lab value / symptom answer, plus `rg` for external asset references == 0; the **SEC-03** leg injects a synthetic outbound call into a recompute and asserts the guard returns FAIL (falsy) — proving the guard intercepts this new render-view code path (subprocess/async included), not merely that a clean recompute happens to make 0 calls.

These four gates (criteria 4, 6, 2, 5) plus criteria 1 and 3 are first-class RED targets below — each is falsifiable (it turns red when the behavior is wrong).
