# Recipe: Multi-Domain Plan Assembly — Routing, Composition, Attribution, Sourcing, Coverage Gaps

> **This is the multi-domain plan composer — the one task that reasons over the
> operator-derived router summary.** It reasons ONLY over the `ADR-0006-T1`
> name-addressable router summary (PII-bounded; 0 raw-PII), routes each in-scope
> goal-domain to its roster specialist, composes the specialist outputs into one
> attributable document, attaches source / confidence-tier / reversibility to
> every recommendation, flags every animal/in-vitro-grounded recommendation with a
> population-mismatch flag, emits coverage-gap disclosures (thin-library AND
> no-specialist), personalizes each section from the router summary, and — the
> load-bearing safety behavior — applies the **HALT filter**: no recommendation in
> the assembled plan may contradict a stated operator hard limit. Two safety
> controls are asserted ADVERSARIALLY (failing-capable, parallel to each other):
> **crit 3** plants an animal-grounded recommendation with NO population-mismatch
> flag and asserts the plan FAILS, and **crit 9** plants TWO hard-limit-violating
> recommendations (a literal contradiction AND a prohibited-class member in
> different terms) and asserts the FAIL-CLOSED, CLASS-AWARE HALT filter SUPPRESSES
> each rec's actionable content (default OMIT-with-disclosure; the FLAG branch
> strikes the actionable regimen, never ships it actionable) or FAILS. The Wave 5 →
> Wave 6 boundary gates this assembly GREEN with Security sign-off on the crit-7 PII
> boundary (interface + egress + negative-content) and the crit-9 HALT/hard-limit
> safety filter.

## Risk Pre-Check

The spec task block carries six risk mitigations (spec line 261); every one gates this task's GREEN and is a first-class RED target — not an optional add-on. Two of them (population-mismatch and HALT) are asserted ADVERSARIALLY: the test must turn RED when a plan FAILS to flag/omit a planted bad recommendation, not merely confirm a flag appears on an already-flagged input. A test that checks "a population-mismatch flag appears on an already-flagged animal rec" or "the plan renders when no hard limit is violated" passes for a no-op composer and FAILS this gate.

- **Risk ADR-0006 Negative (composition adds an orchestration layer; a composition bug can drop a section's attribution OR fabricate a cross-domain claim no single specialist sourced).** Implemented by crit 1, 6. Gate: before GREEN, the RED phase MUST include (a) a test asserting exactly one ATTRIBUTED section per in-scope goal-domain with 0 unattributable sections (crit 1 — the 1:1 attributed-section mapping), and (b) a test asserting every claim in the composed document traces to exactly ONE section's specialist, planting a fabricated cross-domain claim sourced by NO single specialist and asserting the composition FAILS (crit 6 — the composition-attribution integrity check). A crit-6 test that only checks attributed claims trace correctly, without planting a fabricated cross-domain claim that must break the assertion, fails this gate. A placeholder test (`assert True`) fails this gate.

- **Single-claim-set transit invariant (Security MED-3) — REFACTOR-GATED, TESTED PROPERTY.** A composition-introduced cross-domain claim (the crit-6 failure mode) could be introduced AFTER the Cycle-1 attribution check and BYPASS the HALT filter (Cycle 3) and population-mismatch (Cycle 2) if those filters operate over different claim sets at different stages. Gate: HALT, population-mismatch, sourcing-completeness, and composition-integrity (attribution) MUST all operate over the SAME canonical final "emitted recommendations" claim set — every claim, INCLUDING any composition-introduced one, TRANSITS all four filters. Make it a tested property: the RED/REFACTOR MUST assert that every claim in the returned document has transited HALT + population-mismatch + sourcing + attribution (the "single composition pass" guarantee — one canonical claim set, no claim added downstream of a filter it skips). A composer that runs HALT before a later composition step that can introduce a new claim FAILS this property.

- **Population-mismatch (crit 3) — ADVERSARIAL, FAILING-CAPABLE.** Gate: before GREEN, the RED phase MUST plant an ANIMAL/IN-VITRO-grounded recommendation that carries NO population-mismatch flag into a section and assert the assembled plan FAILS (the missing-flag case turns the test RED). The complementary direction — an animal-grounded rec WITH the flag passes — is belt-and-suspenders, not the gate. A test that only asserts "the flag is present on an already-flagged animal rec" (it would pass for a composer that never adds flags, because the input was pre-flagged) FAILS this gate. The failing-capable target is: an unflagged animal→human extrapolation breaks the test (build plan line 261). **(Security LOW-1 — metadata-keyed detection.)** The population-mismatch flag enforcement keys off the recommendation's EVIDENCE-GROUNDING METADATA (carried from the specialist output — e.g. the grounding category: animal / in-vitro / human), NOT a string heuristic over the rec text; exercise more than one grounding expression if feasible (e.g. an animal-grounding and an in-vitro-grounding metadata value), parallel to the class-aware HALT detection (Fix 2). A flagger that pattern-matches on the word "rat" in the rec prose rather than reading the grounding metadata is the anti-target.

- **Thin-library coverage gap (crit 4) — FAILING-CAPABLE.** Implemented by crit 4 (accepted, documented limitation — plan richness is bounded by the library). Promoted to FAILING-CAPABLE no-fabrication parity with crit 5 (Security MED-1): the under-specified "0 fabricated regimens" is given the SAME falsifiable mechanism crit 5 uses. Gate: before GREEN, the RED phase MUST route a thin-library in-scope domain (a domain with no vetted library coverage in the fixture) and assert the section (a) contains the SHARED gap-disclosure SHAPE (the one definition crit 5 also uses), AND (b) contains ZERO recommendation-shaped entries — a planted/leaked regimen in that section FAILS the test. The shared gap-disclosure shape extends to the no-fabrication ASSERTION, not just the disclosure string: a fabricated regimen in that section turns the test RED, exactly as in crit 5. A test that accepts an empty section, a silently-dropped domain, or that checks only that a gap string appears (without asserting 0 recommendation-shaped entries) fails this gate.

- **No-specialist coverage-gap-by-absence (crit 5) — FAILING-CAPABLE.** Gate: before GREEN, the RED phase MUST supply an in-scope goal-domain ABSENT from the stubbed roster (no matching deployed specialist) and assert (a) the domain IS PRESENT in the plan (not silently dropped), (b) it renders a coverage-gap-BY-ABSENCE disclosure (same shape as a thin-library gap), and (c) 0 fabricated regimens appear for it. A composer that silently drops the no-specialist domain, OR fabricates a regimen for it, OR renders it identically to a covered domain, FAILS this test. A test that only checks "a gap string appears somewhere" without asserting the specific no-specialist domain is present-and-gapped fails this gate.

- **Per-section operator input (crit 8) — FAILING-CAPABLE.** ADR-0006 Decision (per-section personalization from the operator's profile/goals/current state). Gate: before GREEN, the RED phase MUST plant a DISTINGUISHING operator input (a stated goal, the January-2026 issue, or a hard limit) into the router summary and assert the CORRESPONDING section SURFACES it; AND assert that a section reflecting 0 operator inputs FAILS the test. A test that asserts personalization only by checking the summary was passed in (without asserting a section surfaces a specific planted input) fails this gate — the failing-capable target is a 0-operator-input section breaks the test.

- **HALT / hard-limit safety (crit 9) — ADVERSARIAL, FAILING-CAPABLE.** ADR-0006 Positive (HALT rules: no recommendation contradicts a stated hard limit — PRD FR-2 / US-1). Gate: before GREEN, the RED phase MUST plant a hard limit in the router summary PLUS an otherwise-routable recommendation that CONTRADICTS it, and assert the HALT filter holds FAIL-CLOSED — the violating recommendation's ACTIONABLE content does not reach the operator actionable. **OMIT-with-disclosure is the DEFAULT HALT posture; FLAG is a constrained exception, NOT a free disjunction.** Two adversarial requirements, both load-bearing:
  - **(Security HIGH-1 — constrain the FLAG branch; default OMIT.)** The "OMITS or FLAGS" disjunction must NOT let a hard-limit-violating recommendation remain physician-facing flagged-but-emitted. The RED MUST distinguish OMIT from flag-but-emit: when the FLAG branch is taken, the test asserts (i) the violating regimen's ACTIONABLE content is SUPPRESSED / STRUCK (not merely annotated), AND (ii) the section carries an explicit contradiction disposition NAMING the violated hard limit; AND a plan that emits the violating rec's ACTIONABLE REGIMEN (even with a flag attached) FAILS. A flag-but-emit implementation — which ships an actively-contraindicated rec with an annotation — MUST turn the test RED. GREEN behavior is fail-closed: an un-cleared hard-limit conflict SUPPRESSES the actionable content (default OMIT-with-disclosure), never ships it actionable.
  - **(Security HIGH-2 — two-plant, class-aware HALT detection.)** Mirroring the `ADR-0006-T1` crit-4 two-plant whitelist pattern, the RED MUST plant AT LEAST TWO contradiction forms and assert HALT fires on BOTH: **(i)** a DIRECT/literal contradiction of the stated limit (a string restatement), AND **(ii) — the falsifying target —** a contradiction that is NOT a literal restatement: a member of the limit's PROHIBITED CLASS expressed in DIFFERENT TERMS (hard limit "no stimulants" vs a rec for a named stimulant compound). A string/exact-match HALT passes (i) but FAILS (ii); a class-aware HALT passes both. GREEN behavior: contradiction-detection is CLASS-AWARE — keyed off the recommendation's evidence/category metadata (the prohibited-class membership), NOT string-equality against the limit text.
  A test that does not plant a violating recommendation (it only checks the plan renders when nothing is violated) passes for a composer with no HALT filter and FAILS this gate; a test that plants ONE literal contradiction and checks only that a flag appears (not that actionable content is suppressed) FAILS this gate. The failing-capable targets are: a contradicting recommendation emitted with its actionable regimen intact breaks the test, AND a class-level (non-literal) contradiction that escapes a string-match HALT breaks the test.

- **Constraint D1→ADR-0006 (no-train summaries — crit 7) — the PII boundary.** Gate: before GREEN, the RED phase MUST assert (a) `assemble` consumes the `ADR-0006-T1` `router.summarize` summary as its operator-state source and NO raw-PII / raw-store source (a fake/spy summary is the source of every operator input that appears in the plan; `assemble` invokes no `store.read` and reads no `vault/store/*.ndjson` directly), (b) the cross-spec `egress_guard.run` over a REAL `assemble` invocation observes 0 raw-PII sends (truthy-on-pass; a `run`-falsy result fails the assertion), and (c) — the NEGATIVE CONTENT assertion (Security MED-2; project mandate: assert placement, not just existence, with negative assertions) — plant a raw-PII token into the store/source layer that is NOT present in the router summary, run `assemble`, and assert that token is ABSENT from the returned plan document AND from the rendered output. The interface assertion (no `store.read`) alone is insufficient: a raw-PII value could reach the plan through a roster fixture / goal-set arg seam, so the boundary must also be asserted by CONTENT, not only by interface + egress. A test that asserts 0 egress over a no-op rather than over a real `assemble` invocation, or that checks only the interface (no `store.read`) without the negative-content absence assertion, fails this gate.
