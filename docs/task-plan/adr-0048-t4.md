# ADR-0048-T4 — Onboarding credential UI (SPA screen-wizard step 9 + My Info Connections & Keys)

## Goal

Extend the SERVED SPA (`vault/design/templates/app_view.html`, rendered by `app_shell.render` →
`generate.run('app')`) with the two credential-onboarding surfaces faithful to the operator-signed-off
mockup `prototype/credential-onboarding-mockup.html`: **Surface A** — extend the `screen-wizard`
**step 9** (currently "API key", `app_view.html:751-768`) into "Connect your data & keys"; **Surface B** —
extend `screen-profile` (`app_view.html:607-628`) with a "Connections & Keys" panel. Both are static
render shells whose "Connect"/PAT/OAuth affordances POST to the already-merged ADR-0048-T2 connect-start
route + ADR-0048-T3 per-source write/status handlers; Surface B's live per-source connection status is
delivered CLIENT-SIDE via `fetch('/settings/trackers')` (mirroring the existing `/settings/key` pill).
This task RENDERS + wires the client-side status fetch; it does NOT re-implement the routes, and does NOT
touch `app_shell.py` (no server render-state seam). Skippable, secret-free (no `client_id`/`client_secret`
field), Garmin manual-path, inline-only, frozen-six untouched.

## PF-S142-01 retarget — read this first (why the served SPA, not `intake.py`)

The spec was AMENDED S143 (PF-S142-01, bead `a-plus-maxing-2awb`): the prior Surface-A target `intake.py`
is an UNSERVED CLI-only 6-step artifact — `server.py` serves ONLY `generate.run('app')` (the SPA) at
`GET /` and 404s every other GET (`server.py:133/:139`); `generate.py` maps `'app'→app_shell` and
`'intake'→intake` as INDEPENDENT templates (`:27`); `app_shell.py` references `intake.py` nowhere. The
LIVE intake surface is the SPA's `screen-wizard` (`app_view.html:631`), ALREADY a 9-step flow whose
**step 9 is "API key"** (`:649` stepper label, `:751` the `wstep`, header "Step 1 of 9" `:634`). So the
mockup's "Step 9 of 9 — Connect your data & keys" maps DIRECTLY onto the existing step 9 — **extend it,
do NOT renumber or rebuild.** A recipe premise "modify surface S" grounds against the SERVED path to S
(which route renders it), never S's mere file-existence (the PF-S142-01 guard).

## The served-render seam + the client-side status (grounding both surfaces)

`app_shell.render(store_read=None, *, status=None, _today=None, _root=None)` (`app_shell.py:546`) reads
`app_view.html` (`:575`) and fills `<!--MARKER-->` placeholders. The completeness gate decides WHICH
surface renders:
- **Surface A (`screen-wizard` step 9)** is PRESERVED in every render — `_lock_to_create_profile`
  (`:407`) strips only the four `_PLATFORM_SCREENS` (`:80`), NOT `screen-wizard` (`:79` comment). So
  step 9's markup is present in `app_shell.render([])`; the Surface-A test renders that.
- **Surface B (`screen-profile`)** is one of the four PLATFORM screens — STRIPPED when the profile is
  INCOMPLETE (`_intake_complete([])` False → `_lock_to_create_profile` removes it). So the Surface-B test
  MUST render a COMPLETENESS-COMPLETE store (seed via `_seed_complete_profile`/`_complete_profile_readings`,
  `tests/serve/test_app_shell.py:1452/:1444`), or `screen-profile` is absent and the assertion falsely
  REDs (QA-M2).

**Connection status is CLIENT-SIDE, not a server render-state seam (Arch F1 / QA M1).** Per-source
"connected" is keychain-derived (`server.py:1009` `_tracker_status` = `GET /settings/trackers`, returns
`{"sources": {source: _read_oauth_credential(source) is not None for source in oauth_pull._MANIFESTS}}`).
That is a JSON HTTP endpoint, NOT a `render`-time source — a `connections=` server-inject param would be a
DEAD extension point (no task threads it through `generate.run('app')`). So Surface B renders STATIC rows
with a "Checking…"-style status placeholder server-side (mirroring the `pf-key-status` pill,
`app_view.html:621`), and the SPA JS does `fetch('/settings/trackers')` on load + sets each source's
status + affordance (Connect vs Reconnect/Disconnect) CLIENT-SIDE (mirroring the `/settings/key` pill
fetch at `app_view.html:1003/:1464` + the mockup's `setAct`/connection state machine). This honors the
keychain-derived truth via an ALREADY-ROUTED endpoint with no dead seam and no `app_shell.py` change.
- **Apple Health is NOT in `_MANIFESTS`** (`oauth_pull.py:165` = `{whoop, oura, garmin, google-health}`):
  Apple is a watched-folder/ingest signal, not an OAuth credential. Surface B's Apple row's status is a
  SEPARATE client-side signal (a static "Shortcut" affordance / ingest-presence), NOT from
  `/settings/trackers` — do NOT drive Apple's row off the OAuth sources map.

## Consumer-contract grounding (the merged routes this UI renders against — PF-S141-02)

- The manifest is `app_view.html` + the test — NO route, NO `scripts/serve/*.py`, NO `app_shell.py`, NO
  credential written. AC-4 (no secret field) + render-only scope keep it off the Security roster.
