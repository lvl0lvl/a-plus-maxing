# Recipe: Composed `gate_dispatch` Adapter (quality_judge + review_plan → 3-key disposition)

Build the composed `gate_dispatch` adapter (`scripts/plan/gate_dispatch.py`, Create): over the
assembled `run_generation` result, run the built `quality_judge(assembled_plan, judge_client) ->
{verdict, dimensions, deductions}` ([quality_judge.py:206-253]) AND `review_plan(assembled_plan,
dispatch, *, lenses) -> {findings, passed, lenses}` ([safety_review.py:110-169]), and emit EXACTLY
the 3-key disposition `{accept: verdict == ACCEPT, safety_passed: review["passed"], revise_domains:
[<domains derived from the REVISE deductions / findings>]}` that the ADR-0026-T1 shared driver
consumes. The 3 keys are FIXED (OQ-2 NOTE); the one-pass-vs-two internal ordering is the build
decision. FAIL-CLOSED: a raised / missing / non-dict judge or review result → a disposition whose
`safety_passed` is NOT boolean-True (so the driver routes it to `SAFETY_BLOCKED`).

This task is Create-only over the built gate callables — it consumes them, it re-authors nothing.
The inner engine + `quality_judge.py` + `safety_review.py` stay BYTE-UNCHANGED (numstat = 0).
`scripts/plan/gate_dispatch.py` + `tests/plan/test_gate_dispatch.py` are the only new files. Every
test runs against fixture judge/review results, 0 live spend.

## Interface Contracts

This task CREATES the `gate_dispatch` composer that EMITS into the ADR-0026-T1 shared driver's
`gate_dispatch=` seam — a contract consumed by the driver (and by ADR-0026-T3/T4, which drive the
driver). It does NOT modify the gate callables or the driver.

- **`gate_dispatch` composer 3-key disposition contract (the composer's OUTPUT — consumed by
  `plan_driver`).** The composer runs `quality_judge` + `review_plan` over the assembled
  `run_generation` result and EMITS EXACTLY `{accept: bool, safety_passed: bool, revise_domains:
  list}`:
  - `accept` = (`quality_judge`'s `verdict == ACCEPT`).
  - `safety_passed` = (`review_plan`'s `passed`, a bool) — `True` ONLY when `review_plan` returned a
    dict with `passed is True`; every malformed composite (raised / non-dict / missing key) yields a
    `safety_passed` that is NOT boolean-True (fail-closed → the driver's `SAFETY_BLOCKED`).
  - `revise_domains` = the run-set domains per the derivation rule (Step-2 GREEN): STRUCTURAL
    deductions localize to a domain via the assembled result's `results[domain].section["domain"]`;
    DIMENSION-level below-band deductions (which do NOT localize — `quality_judge` deductions key on
    rubric dimensions, not plan domains) map to ALL run-set domains (conservative re-author, never a
    silent `[]`); the result is INTERSECTED with the run's `domains` (⊆ run-set — never an
    out-of-run-set target).
  - The disposition is EXACTLY these 3 keys — no more, no fewer (`set(keys) == {"accept",
    "safety_passed", "revise_domains"}`). A richer shape breaks `plan_driver`'s single-disposition
    read (OQ-2 NOTE).
  - The composer runs BOTH gates (judge ≥1 dispatch + review ≥2 lenses) — never a vacuous single-lens
    PASS.
  - **Change control:** ADR-0026-T1's driver READS this 3-key shape; ADR-0026-T3/T4 drive the driver
    over this composer. The 3-key shape MUST NOT change without Architect review (Core Rule 10) — it
    is the fixed contract the driver's loop consumes.
