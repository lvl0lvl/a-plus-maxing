# Recipe: [Spike] D4↔D7 Render-Size Measurement + Cap Parameter

This is a **spike**. The deliverable is a markdown measurement report
(`docs/spec/.pipeline/spike-ADR-0004-T0-render-size.md`), not code. The
adapted non-code TDD cycle from `tdd-planning.md` applies: RED-equiv defines
section-presence + measured-value + single-selection assertions; GREEN-equiv
builds a realistic dataset, renders it through the inline-SVG / no-chart-library
path, measures the rendered bytes with `wc -c`, and authors the report;
REFACTOR-equiv is a consistency review; REGRESSION-equiv re-runs all checks.
`/write-tests` is NOT called — a markdown report is not unit-tested.

The AC4 measurement is an **empirically recorded byte number** produced by
`wc -c` over an actually-rendered fixture. The recipe forbids asserting a
boolean "fits" / "does not fit" in place of the number, and forbids
back-filling the number from estimate rather than from a real render.

## Risk Pre-Check

This task carries risk mitigations (spec `### ADR-0004-T0` → "Risk
Mitigations"). The Risk Pre-Check is therefore active and gates the report on
the measured-number + cap before the report is accepted.

- **Risk R-D4a — ADR-0004 Negative (render-richness cap):** the <500KB /
  self-contained budget caps interactivity and render-richness (inline SVG, no
  chart library). **Gate:** the GREEN-equiv render MUST go through an
  inline-SVG / no-chart-library path with **0 external asset references**, and
  the report's "Render Method" section MUST assert this. A render that pulls a
  CDN chart library or an external font/image fails the gate (it would not be
  the artifact ADR-0004 actually ships).
- **Risk R-D4b — ADR-0004 Negative (per-file size pressure, 1+ yr):**
  inline-everything raises per-file byte pressure as a multi-year constraint and
  may need capping/pagination. **Gate:** the report MUST carry a **recorded byte
  number** (AC4, from `wc -c` over a real render of the worst-case dataset) AND
  an **explicit numeric cap or stated split rule** (AC5) that bounds a
  worst-case downstream view < 500000 bytes. A "fits" / "as needed" verdict
  with no number fails the gate.
- **Risk R-D7a — ADR-0007 Negative (matrix/projection strain the budget):**
  the matrix/projection views are the artifacts most likely to strain <500KB.
  **Gate:** the dataset (AC2) MUST be the worst case — ≥8 biomarkers × ≥3
  timepoints, so ≥1 projection passes the ≥3-timepoint guardrail and the matrix
  carries multiple series — and the render measured (AC4) MUST be the combined
  matrix + projection view, not a trivial single-series render.

Because this is a non-code spike, the "gate condition references a test"
requirement is satisfied by the RED-equiv assertion battery in TDD Step 1 (the
section-presence + recorded-number + numeric-cap + single-mitigation
assertions), which is the spike's analog of a failing test and turns red when
the report omits the number or the cap.

### Step 2: GREEN-equiv — Build the dataset, render, measure, author the report

Perform the work, then author each section so the Step-1 battery turns green.
Each item below is a change description, not code.

1. **Build the worst-case dataset (satisfies AC2 / Risk R-D7a):** construct a
   realistic biomarker dataset of **at least 8 biomarkers**, each with **at
   least 3 timepoints** (e.g., 10 biomarkers × 4 timepoints), with values in
   plausible clinical ranges and reference bands. At least one biomarker series
   must clear the ≥3-timepoint projection guardrail and the matrix must carry
   multiple series. This dataset is a throwaway in-spike fixture (scratch path,
   not `vault/store/`); record its exact biomarker count and timepoint count in
   the report's "Dataset" section. Choose the larger end of "realistic" — the
   measurement is a worst-case bound, so over-provision rather than under.

2. **Render through the inline-SVG / no-chart-library path (satisfies AC3 /
   Risk R-D4a):** because `vault/design/templates/` does not exist at Wave 1
   (Deviation 1), build a throwaway in-spike render harness that emits ONE
   self-contained HTML file with **all CSS and all chart geometry inlined as
   SVG**, **0 external asset references** (no `<link>`/`<script src>`/`<img
   src>` to any URL, no CDN, no external font). The harness renders the
   combined worst-case view: the multi-series biomarker matrix PLUS the
   ≥3-timepoint projection. Its markup density (inline SVG path data, inline
   style) must be representative of what `ADR-0004-T1`'s real template will emit
   so the byte measurement is a faithful worst-case bound. State in "Render
   Method" that the render is inline-SVG / no-chart-library, self-contained,
   0 external references.

3. **Measure with `wc -c` (satisfies AC4 / Risk R-D4b):** run `wc -c` over the
   rendered HTML fixture and record the **exact byte number** it outputs.
   Author "Measured Size" with that number and an explicit **under/over**
   verdict against the 500000-byte ceiling. The number is the recorded `wc -c`
   output — never a boolean "fits", never an estimate substituted for a real
   measurement.

4. **Derive and state the cap (satisfies AC5):** from the measured bytes,
   compute and state an explicit cap — a **max rendered-timepoints-per-view
   number** AND a **max series-per-view number**, OR a concrete pagination/split
   rule — that keeps a worst-case downstream view **< 500000 bytes**. Derive the
   cap with an explicit **safety margin / headroom** below the 500000-byte
   ceiling, not at it: the harness measures a *lower bound* on real density
   (Deviation 1 — `ADR-0004-T1`'s real `component_set.py` may inline richer SVG
   defs, the WCAG-AA contrast styling from `ADR-0004-T1` criterion 3, and an
   `@media print` block the harness omits), so size the cap so a worst-case view
   lands below the ceiling *with* room for that template-density growth. State
   the margin (e.g., a fraction of the ceiling held in reserve) and the
   reasoning, and show the per-series / per-timepoint byte cost the cap is
   derived from, so the number is defensible, not asserted at the ceiling.
   Author "Cap / Pagination Parameter" with the number(s) or rule. Not "as
   needed".

5. **Select exactly one mitigation (satisfies AC7):** author "Mitigation If
   Over Budget" selecting **one** concrete mitigation to apply if the measured
   size exceeds 500000 bytes — one of: (a) cap rendered timepoints/series, (b)
   paginate/split the matrix across artifacts, or (c) share component-set markup
   across views. State the single choice and one sentence of rationale. Not a
   list of options.

6. **Name the consumers (satisfies AC6):** author "Follow-up Tasks" naming
   BOTH `ADR-0004-T2` (the generation task rendering matrix/projection views)
   and `ADR-0007-T2` (the matrix/projection render-view task) as the tasks
   whose size-budget acceptance criteria consume this cap.

Write the report to `docs/spec/.pipeline/spike-ADR-0004-T0-render-size.md` with
exactly the six `## ` headings from AC1, spelled verbatim (the AC1 set and the
build-plan Wave-1→2 `rg "^## "` checkpoint are order-independent; spelling, not
order, is asserted).

Run: the Step-1 battery again (see Verification Checklist).
Expected: PASS — all seven checks green.

## Interface Contracts

This task does not create or modify a code interface (no function/class
signature). It does produce a **design contract** consumed by two downstream
tasks: the **cap / pagination parameter** and the **selected mitigation**.

- **Contract:** the "Cap / Pagination Parameter" value (max timepoints-per-view
  + max series-per-view, or the stated pagination/split rule) plus the
  "Mitigation If Over Budget" selection.
- **Behavioral contract:** any downstream render of the biomarker matrix or
  projection MUST keep a worst-case rendered view < 500000 bytes by applying
  this cap; the cap is the size-budget bound their acceptance criteria assert
  against.
- **Dependent tasks (per spec Dependencies — "Blocks: ADR-0004-T2,
  ADR-0007-T2"):** `ADR-0004-T2` (generation task rendering matrix/projection
  views) and `ADR-0007-T2` (matrix/projection render-view task). Build plan
  W4→5 and W6→7 boundaries assert each applies this cap (build-plan lines on
  ADR-0004-T2 criterion 1/2 and ADR-0007-T2 criterion 6).
- **Re-validation trigger (`ADR-0004-T1`):** the cap derived here rests on a
  harness that *under*-estimates real density (Deviation 1). Once `ADR-0004-T1`
  builds the real `vault/design/templates/component_set.py` template, it MUST
  re-run this measurement against the real render — which carries the richer SVG
  defs, the `ADR-0004-T1` criterion-3 WCAG-AA contrast styling, and the
  `@media print` block the harness omits — and reconcile the cap (re-derive with
  the same headroom, or confirm the harness bound still holds) BEFORE
  `ADR-0004-T2` / `ADR-0007-T2` consume it. `ADR-0004-T1` is the first real
  render; `ADR-0004-T2` / `ADR-0007-T2` remain the downstream consumers.
- **Change control:** `ADR-0004-T2` / `ADR-0007-T2` MUST NOT change the cap
  parameter without Architect review (re-running this spike's measurement).
