# Spec: DNA-Aware Planning via De-Associated Current-Science Variant Research

## Component Overview

This spec implements ADR-0032, which makes the now-live plan-generation engine DNA-aware on CURRENT science WITHOUT crossing the operator's raw genotypes to the no-train planner. ADR-0031 already lands the genotypes as durable FACTS: a genetics report extracts to `dna-report` store readings keyed `item` = gene + rsID (e.g. `"MTNR1B rs10830963"`), `timepoint` = sample date, `source` = `"dna-report"`, `value` = the alleles (e.g. `"(C;G)"`), storing the fact and explicitly NOT the report's dated interpretation ([`scripts/model/client.py:311-317`](../../../../scripts/model/client.py) [VERIFIED]; the cross-item read precedent [`scripts/ingest/status.py:69`](../../../../scripts/ingest/status.py) [VERIFIED]). But the de-identified summary `router.summarize` builds for the planner carries no genetics token — the field-set has training-age, recovery, issue-class, BPMH, and chat-sourced diet/supplement/peptide/volume tokens, none genetic ([`scripts/plan/router.py:20-47`](../../../../scripts/plan/router.py) [VERIFIED]) — so the plan ignores the genome on file.

ADR-0032 closes that gap with four new surfaces and ONE additive engine edit. **T1** stands up a NEW variant-keyed `vault/library/genetics/` section: a schema (a `### library/genetics/` entity template in `vault/WIKI.md` + a `_template.md`), the operator's OQ-3 curated planning-relevant variant set, and the ingestion-gate extension that mechanically enforces the genetics schema (a `genetics` entity type in `scripts/lib/wiki-helpers.sh` + a `check_genetics` battery in `scripts/wiki-ingest-lint.sh`). **T2** adds the LOCAL genotype↔library matcher (`scripts/genetics/match.py`, NEW): reads each curated variant's `dna-report` genotype fact via the per-item `store_read` surface, finds its `vault/library/genetics/` page, and selects the per-genotype finding by the operator's LOCAL allele — pure, 0 egress, honest no-match (a variant with no page is reported as an unfilled research gap, never fabricated). **T3** is the ONE additive plan-path edit (`scripts/plan/router.py`, the ADR-0019 `SUMMARY_FIELD_SET`-extension precedent): a de-identified `genetic-trait-classes` token + its local deriver, so the existing `summarize`/`ModelClient.author` seam carries coarse trait classes and the raw rsID+allele genotypes never reach the planner. **T4** builds the care-assistant→DNA-research-agent hookup as a STUB (`scripts/genetics/research_query.py`, NEW): a GENERIC, operator-de-associated, ALLELE-AGNOSTIC per-variant query (gene+rsID, never the operator's allele) plus a fail-closed de-association guard and a stubbed dispatch — the real `aplus-research` run is the operator-gated OQ-1. **T5** is the end-to-end proof plus the five ADR-0032 falsification probes as tests.

The research engine `aplus-research` runs as a Claude Code agent dispatch on the subscription/agent research lane the project's existing library work already uses — NOT the no-train `ModelClient` backend ([`.claude/skills/aplus-research/SKILL.md`](../../../../.claude/skills/aplus-research/SKILL.md) [VERIFIED]). The build wires UP TO that dispatch only: T4 stubs the dispatch and the live, metered variant research is OQ-1 (0 live spend). The de-identified token reaches the planner over the swappable no-train author seam (`ModelClient.author(domain, summary)`, [`scripts/model/client.py:62-76`](../../../../scripts/model/client.py) [VERIFIED]), mock-tested at the ADR-0015 `_FakeAnthropic`/backend seam.

### The crown-jewel PII boundary (NFR-1, load-bearing)

ADR-0032 is an operator-approved crown-jewel EXTENSION of ADR-0001: it adds ONE new named egress class — **generic, operator-de-associated, allele-agnostic genetic-variant literature queries** — and nothing else leaves the machine. The bound this spec enforces is threefold: (a) **0 raw genotypes (rsID+allele pairs) AND 0 operator-identity tokens in any outbound variant query** — the query carries the variant (gene+rsID) but never the operator's allele call; (b) **0 raw genotypes reaching the no-train planner** — the planner's de-identified summary carries only coarse `genetic-trait-classes` tokens, the rsID+allele NEVER crosses; (c) **0 operator-identifying tokens in any `vault/library/genetics/` page** — the cache is keyed to the VARIANT, reusable, operator-free. The operator's identity, the raw genotypes, AND the genotype↔operator link stay 100% local; the allele is applied LOCALLY against the variant-keyed library to select which per-genotype finding applies.

### EXTEND-NOT-REBUILD (NFR-2)

The inner plan ENGINE (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`), `dispatch`'s gate logic, and the store (`scripts/store/keying.py`, `scripts/store/store.py`) stay byte-frozen. The ONLY plan-path edit is the ADDITIVE `SUMMARY_FIELD_SET` `genetic-trait-classes` token + its local deriver + an optional `genetics_library_root` param in `scripts/plan/router.py` — the ADR-0019 precedent ([`docs/adr/ADR-0019-summary-field-set-extension-chat-facts.md`](../../../../docs/adr/ADR-0019-summary-field-set-extension-chat-facts.md) [VERIFIED]). `summarize`'s existing callers (`scripts/serve/chat.py:363-365`, `scripts/plan/generate_plan.py:356`, `scripts/plan/orchestrate.py:537` [VERIFIED]) pass no `genetics_library_root`, so the default applies and no caller changes — the ADR-0015 consumer-direction claim. The genetics matcher + query stub live in a NEW `scripts/genetics/` package (mirroring how ADR-0031's local-extract front module lives in `scripts/ingest/`), not an engine edit.
