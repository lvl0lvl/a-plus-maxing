## 2. Binding contract decision (5-part arbitration)

**Position A (plan-integrity / this Architect):** Closing PF-S63-02/PF-S87-01 requires threading a real `ModelClient` through `generate_plans`/`run_generation` (the front-door orchestrator), because that is the production caller the operator runs; proving the loop only at the `generate_plan` direct seam proves a path production does not use.

**Position B (a literal reading of Wave A + ADR-0015 `:88`):** The `generate_plan` direct seam already runs programmatically through the client end-to-end (the `--self-test` passes), and ADR-0015's success criterion is the self-test — so Wave A already closed it; the orchestrator is a legacy/batch path out of scope.

### Decision: **Position A — thread an optional `client=` through `orchestrate.generate_plans` and `pipeline.run_generation` (a THIN backward-compatible forward), and re-point the ADR-0017-T2 headline E2E to assert THROUGH `run_generation`, not the bare `generate_plan` seam.**

### Technical rationale (evidence, not preference)

1. The operator's actual front door is `run_generation` (SKILL.md:29,90), and `run_generation`→`generate_plans` is the documented production caller of the multi-domain terminal (`pipeline.py:8-10`: "`run_generation` is `generate_plans` + `collate`'s [production caller]"). A proof that does not exercise it is a proof of the wrong path (the CLAUDE.md "Verification Means Running the Production Path" + "E2E Tests Must Assert Placement" mandates: the test must run the production entry, not a manually-configured seam).
2. ADR-0015 `:88/:93` require the programmatic client end-to-end and explicitly block on a residual captured-data feed. Today `generate_plans:530` and `:551` are exactly that residual feed — `_FixedEnvelopeClient(author_output)` — on the front-door path. The criterion is not met for the path the operator runs.
3. The change is genuinely thin (§4): `compute_plan`/`generate_plan` already accept `client=`; threading an optional `client=` through the two outer callers is the same backward-compatible forward Wave A applied one layer down. It introduces no new interface shape and leaves the four safety filters, the clearance gate, the translators, and `record_plan` byte-unchanged (ADR-0006 untouched, ADR-0015 `:81`).

### Why Position B was not chosen (its strongest argument addressed)

B's strongest point is that ADR-0015's literal success criterion is the `--self-test`, which passes. But the `--self-test` injects the client at the `generate_plan(...)` seam (`generate_plan.py:518-522`) — the SAME direct seam, not the front door. The self-test passing is necessary but not sufficient: it proves the mechanism works when manually wired, not that the production caller (`run_generation`) wires it. ADR-0015 `:88` says "end-to-end," and the operator's end-to-end is `run_generation`. A criterion that greenlights an unwired front door is a tautological criterion (CLAUDE.md "No Tautological Tests"). B also strands the `/generate-plan` skill: its Phase 2 would call a path that cannot reach a real model author, leaving the skill's whole reason-for-being (a real conversation → a real model-authored plan) unbuildable. Position B does not close the gap; it relocates it.

### "Breaks if" conditions

- **Breaks if** the runtime-A interactive-Agent-dispatch model is the intended production author for the cross-domain path AND a programmatic `ModelClient.author` is NOT wanted there. In that case the captured-envelope `authors` IS the production mechanism, and the contract becomes "the captured envelope must originate from a live dispatch," with NO `ModelClient` in `generate_plans`. **Resolution:** ADR-0015 `:81/:88/:93` settle this — the programmatic client REPLACES the captured-data dispatch as the production mechanism; runtime-A's "interactively dispatched agent" language in the design doc + author-dispatch-process + SKILL.md is **stale relative to ADR-0015** and is flagged for reconciliation (§5). If the operator instead RE-AFFIRMS runtime-A interactive dispatch as canonical and DEMOTES ADR-0015's programmatic mandate, this decision reopens (a one-way-door, operator-owned; see §5 escalation).
- **Breaks if** the energy-bounce re-author (`generate_plans:550-551`) and the held-finding adjudicator (`:576-616`) are left on captured envelopes while only the first-pass author goes programmatic — a half-wired orchestrator. The forward MUST cover the bounce re-author's `compute_plan` call too (§3), or the re-authored workout silently rides `_FixedEnvelopeClient`.

### Conditions for revisiting

Revisit if (a) the operator re-affirms runtime-A interactive dispatch as the canonical production author mechanism over ADR-0015's programmatic client (reopens the whole decision), or (b) a fifth cross-domain behavior or a second model-touching plan path is added (re-trace the entry).

## 3. Minimal correct interface change (WHAT, not HOW)

This is the THIN forward. It threads an OPTIONAL `client=` keyword through the two outer callers so the production caller injects a real `ModelClient` while every existing caller (passing captured `authors`) keeps working unchanged.

### 3a. `orchestrate.generate_plans` — signature + forward

- **Contract change:** add an optional keyword `client=None` (or, since `generate_plans` runs MANY domains, an optional `client` that is the ONE `ModelClient` used for every domain's author leg — a single client, not a per-domain map; a per-domain map is an unneeded extension point, Architect Core Rule 8). Preconditions: `client` is either `None` (the captured-envelope back-compat path — every existing caller) or an object exposing `author(domain, summary) -> envelope`. Postcondition: when `client is not None`, EVERY domain's `compute_plan` call (the first-pass loop at `:530` AND the energy-bounce re-author at `:551`) forwards that `client`; when `None`, behavior is byte-identical to today.
- **The two forward sites (both MUST be covered — the §2 half-wired "breaks if"):**
  - `:530` first-pass loop: `compute_plan(domain, author_output, store_read, gates=gates, client=client)`.
  - `:551` bounce re-author: `compute_plan("workout", new_output, store_read, gates=gates, client=client)`.
- **Error contract:** unchanged. A failed author call still raises `ModelCallError` INSIDE `compute_plan`, which already converts it to the honest no-plan state (`generate_plan.py:361-367`, `reason == AUTHOR_CALL_FAILED`). The orchestrator's hold/record logic is untouched.
- **Out of scope:** when `client` is injected, the `authors` dict's per-domain `author_output` values become IGNORED for the author leg (the same back-compat semantics `compute_plan` already documents at `:319-320`). The `authors` keys still select WHICH domains run; their envelope VALUES are the captured-path input only. The SE must NOT remove `authors` (it is the domain selector + the back-compat path) — only ADD the `client` forward. **Whether `reauthor`/`adjudicator` themselves become programmatic-client calls is a SEPARATE question out of THIS amendment's scope** (they are orchestrator-supplied hooks; the bounce re-author's `new_output` still comes from the `reauthor` hook, and only the resulting `compute_plan` author leg is what `client` governs). Reconciling the hooks to the programmatic client is a follow-on, not part of closing NOTE-T3-1.

### 3b. `pipeline.run_generation` — signature + forward

- **Contract change:** add the same optional `client=None` keyword and forward it verbatim to `generate_plans(..., client=client)` at `pipeline.py:60`. No other change (`run_generation` is REUSE-only by its own docstring, `pipeline.py:20-23`).

### 3c. Byte-unchanged constraints (load-bearing — the SE attests these)

- `scripts/plan/assemble.py` — byte-unchanged (the four safety filters). ADR-0006 architecture untouched (ADR-0015 `:81`).
- The clearance gate (`generate_plan.py:141-153`), the per-domain translators (`:123-257`), `_DOMAIN_GATES`/`_PLAN_TRANSLATORS` (`:286-300`), and `plan_schema.record_plan` — byte-unchanged.
- `router.summarize` and the PII boundary — byte-unchanged.
- The reconciler (`reconcile`, the holds/adjudication/collation logic) — byte-unchanged; only the `compute_plan` CALL gains a forwarded kwarg.
- **The only mechanism that extends is the dispatch source of the author envelope** (captured → programmatic), exactly as ADR-0015 `:81` scoped it.

### 3d. Who builds what

- **ADR-0017-T2 (the test-only integration task) does NOT author this production change.** Its recipe forbids production code (`docs/task-plan/ADR-0017-T2.md:14,64,216`). The §3a/§3b forward is a PRODUCTION change → it belongs to **ADR-0015-T3** (the author re-wire task that owns the programmatic-client author leg) OR a new thin production task (e.g. `ADR-0015-T3a` / `NOTE-T3-1-wiring`). The orchestrator decides the task home; this amendment specifies the contract. ADR-0017-T2 then ASSERTS through the wired front door (§3e).
- If ADR-0017-T2's E2E goes RED because `run_generation` does not forward `client`, that is a real mechanism gap → ADR-0017-T2's own halt protocol (`:96,130,208`) routes it to the owning production task. This amendment pre-resolves WHERE: the `generate_plans`/`run_generation` forward.

### 3e. How ADR-0017-T2 MUST assert THROUGH the production entry (non-tautological, mock-backed, no live API)

The recipe's Step-1 driver MUST be amended from "drive … → `generate_plan`/`compute_plan`" to drive the **front-door production entry**:

- **Drive `pipeline.run_generation(authors, store_read, root, plan_date=…, gates=…, client=<ModelClient(mock backend)>)`** (the operator's actual front door), NOT a bare `generate_plan(client=…)` call. The mock `ModelClient` backend's `author(domain, summary)` returns the scripted rich-domain envelope; its `converse` returns the scripted intake turns. ONE mock client, injected at the ADR-0015 seam, drives BOTH the `/chat` conversation lane AND the plan-author leg through the front door — no live API, deterministic, CI-runnable.
- **Non-tautological assertion (load-bearing):** assert (a) `result["results"][<domain>]["recorded"] == True` (NOT the honest no-plan state); (b) ≥1 domain plan recorded + rendered; (c) the rendered plan CONTENT traces to a specific fact the fixture conversation supplied (a de-identified value from the conversation appears in the rendered plan). NEVER "a plan object is non-None."
- **The placement assertion that closes NOTE-T3-1 (the anti-tautology that proves the FRONT DOOR reached the real client, not the captured default):** the mock `ModelClient.author` MUST be observed to have been CALLED through `run_generation` — e.g. a spy backend whose `author` records its `(domain, summary)` invocations, asserted non-empty AND asserted the recorded plan's content derives from the spy's RETURN value, not from any `authors[domain]` captured envelope. Equivalently: pass `authors` whose captured envelopes would produce a DIFFERENT (or no) plan than the injected `client.author`, and assert the recorded plan matches the CLIENT's output — proving the front door used the programmatic client, not the captured default. **This is the assertion that fails if `generate_plans`/`run_generation` do not forward `client` — it is the mechanical proof NOTE-T3-1 is closed.**
- **Negative control (failing-capable):** drive the SAME front door with a mock `client.author` that raises `ModelCallError` (or returns the thin-library sentinel) and assert `recorded == False` + the honest reason (`AUTHOR_CALL_FAILED` / coverage-gap) — proving the usable-plan assertion distinguishes a real plan from the no-plan state through the production entry.
- The `--self-test` (`generate_plan.py:454`) and `core-capability-audit.sh` may STAY on the direct `generate_plan` seam (they prove the shared infrastructure); the NEW E2E is what proves the FRONT-DOOR wiring. Both coexist.

## 4. Scope verdict — THIN vs. large

**THIN.** The production change is an optional `client=None` kwarg threaded through two outer callers (`generate_plans`, `run_generation`) and forwarded to the TWO existing `compute_plan` call sites inside `generate_plans` (`:530`, `:551`). It is the identical backward-compatible forward Wave A already applied to `compute_plan`→`generate_plan` one layer down. No new interface shape, no new module, no change to any safety filter / translator / store write. Every existing caller (passing captured `authors`, `client` defaulted `None`) is byte-behavior-identical. The ADR-0017-T2 change is a test-file re-point (drive `run_generation`, add the spy-backed placement assertion) — also thin.

**One honest caveat the orchestrator should weigh (not a blocker, surfaced per Architect Core Rule 2/10):** the THIN forward closes the wiring, but it surfaces a DOCUMENTATION contradiction that is larger than code — the `/generate-plan` SKILL.md, `vault/design/plan-generation-pipeline-v1.md`, and `docs/plan-generation/author-dispatch-process.md` all still describe runtime-A interactive Agent dispatch ("`scripts/` holds no model client by design") as the production author mechanism, which ADR-0015 superseded. The CODE forward is thin; the DOC reconciliation (which mechanism is canonical for the cross-domain path) is an operator-visible design question (§5). The forward does not REQUIRE the doc reconciliation to land (the optional `client=` leaves the captured-`authors` path intact, so runtime-A interactive dispatch still works for anyone passing captured envelopes) — but shipping the forward without the doc reconciliation leaves two documented production mechanisms for the same path. Flag for the orchestrator; do not silently pick one in code.

## 5. Cross-boundary / operator-owned items (orchestrator routes)

- **DESIGN-ESCALATION (operator-owned, one-way-door):** ADR-0015 (`:81/:88/:93`) makes the programmatic `ModelClient.author` the production author mechanism; the design doc + author-dispatch-process + `/generate-plan` SKILL.md still say runtime-A interactive Agent dispatch with "no model client by design." These cannot BOTH be the canonical production author for the cross-domain path. The THIN forward assumes ADR-0015 wins (the ADRs are the authority). If the operator intends runtime-A interactive dispatch to remain canonical for `/generate-plan`, this decision reopens. **Recommend the orchestrator surface this to the operator before the §3 forward merges** — it is the §2 "breaks if (a)."
- **The `/generate-plan` SKILL.md Phase-2 amendment** (note that `run_generation` now accepts `client=` and the front-door author leg can run programmatically) is part of the same reconciliation and should land WITH the forward, or the skill's documented call omits the new kwarg.
