# Spec: Local Scheduled Headless Subscription Runner — the Plan-Loop Cadence Runtime (ADR-0039)

## Component Overview

This spec implements ADR-0039: a LOCAL scheduled headless Claude-Code SUBSCRIPTION runner, **disabled by default**, that hosts the plan-evolution loop's CADENCE trigger. It delivers a NEW driver layer under `scripts/runner/` that, on the cadence, reads the operator's local gitignored store, de-identifies the raw intake in the Python driver, builds a subscription-sub-agent `dispatch`, supplies the ADR-0027 `deid_client` (the sole metered egress) plus an optional `tailor_client`, and calls the already-built `plan_loop.signal(root, trigger=plan_loop.CADENCE_TRIGGER, dispatch=..., deid_client=..., tailor_client=...)` ([plan_loop.py:457](../../scripts/serve/plan_loop.py)) as its SINGLE entry into the loop. The runner supplies the three seams the standalone Python server cannot ([__main__.py:69-83](../../scripts/serve/__main__.py); the server's `/plan-loop` degrades `loop-dispatch-unavailable`, [server.py:857-859](../../scripts/serve/server.py)); it re-hosts nothing — the debounce (`MIN_REGEN_INTERVAL_DAYS=7` + the sustained-signal window, [plan_loop.py:383-455](../../scripts/serve/plan_loop.py)), the fail-closed composition, and the cross-domain holds all stay inside the built loop.

The architectural rationale is fixed by ADR-0039. The cadence trigger is the ONE loop trigger with no in-process host: the data-event and free-text triggers fire from the running server's route/care_chat/confirm sites, but the weekly cadence has no natural firing site (ADR-0039 Context). A cloud runtime was eliminated outright (Alternative B) because the loop re-reads the operator's LOCAL gitignored store every re-gen (`store.read_all(root)`, [plan_loop.py:127](../../scripts/serve/plan_loop.py); [store.py:263](../../scripts/store/store.py)) — a cloud runtime cannot see that store without EXPORTING raw local PII, the exact new-egress class ADR-0001 forbids. So the runtime must run LOCALLY, and only a local runtime can be BOTH a real Claude-Code subscription session (satisfying ADR-0026's not-metered dispatch) AND local-store-adjacent (satisfying the crown-jewel). **Binding raw-PII containment on the top-level session:** the raw `store.read_all` intake read and the ADR-0027 `deid_in` de-identification MUST execute in the Python DRIVER layer — exactly as they do on the `/generate-plan` A′ path (`plan_loop.regenerate` → `_read_raw_intake(root)` → `plan_orchestrator.run_orchestrated` → `deid_in`, [plan_loop.py:174-177](../../scripts/serve/plan_loop.py); [plan_orchestrator.py:127](../../scripts/plan/plan_orchestrator.py); [deid_in.py:39](../../scripts/plan/deid_in.py)) — so raw store content NEVER enters the top-level subscription session's transmitted context; the subscription lane carries ONLY PII-free orchestration plus the de-identified summary. A naïve `claude -p "read the store and run the loop"` is DISQUALIFIED.

How it fits: the runner is a pure NEW consumer of built infrastructure — the ONLY tracked-file Modify in the whole spec is `.gitignore` (every other file is a Create under the greenfield `scripts/runner/` tree). The **EXTEND-NOT-REBUILD** constraint is a hard governance floor: the frozen inner plan engine (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`) and `scripts/store/*` stay byte-frozen (`git diff --numstat origin/main` over that glob returns empty), and the runner touches NEITHER the frozen engine NOR the `scripts/serve/` server package. The runner's store lock lives in a new `scripts/runner/store_lock.py` and its lock FILE lives under the already-gitignored `vault/store/` — so `scripts/store/*` is not edited. Activation is operator-owned and disabled by default: NO build, provisioning, or `init_instance` step may load the launchd/cron entry (`scripts/clone/init_instance.py` carries 0 schedule tokens today, [init_instance.py](../../scripts/clone/init_instance.py) — a premise this spec preserves with a mechanical guard).

Every task is mock/fixture-satisfiable at 0 live spend: the subscription-session harness, the `dispatch` seam, and the `deid_client`/`tailor_client` are injectable, so no task binds a real subscription session or makes a metered call. The runner ships DISABLED BY DEFAULT. The operator-present LIVE run — real setup-token subscription + real key + real data + spend — is the downstream operator-gated attestation AFTER this build; the not-metered LIVE probe (exactly the de-id-IN call metered, 0 metered dispatch), the OQ-6 acceptable-use decision, and the live sub-agent-dispatch confirmation are recorded in the Unresolved Concerns table, not tasks.

Informing artifacts (downstream workers load on demand): the source ADR (`docs/adr/ADR-0039-scheduled-agent-runner.md`); its upstreams (`ADR-0036-automated-plan-evolution-loop.md`, `ADR-0026-v1-subscription-runtime-driver.md`, `ADR-0027-live-no-train-deid-backend.md`, `ADR-0001-pii-trust-boundary-no-train-routing.md`, `ADR-0005-operator-agnostic-clonable-pii-free-trunk.md`); the store-adversarial mandate (`docs/checklists/store-adversarial-tests.md`); and the format-exemplar spec (`docs/spec/adr-0036-0038-dynamic-plan-loop-spec.md`).
