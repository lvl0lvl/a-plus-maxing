# Spec: Gate-Dispatch Control-Inversion — Completing the A′ Subscription Driver (ADR-0028)

## Component Overview

This spec implements ADR-0028 — it completes the A′ control-inversion the S93 build left PARTIAL. Today `plan_driver.drive` inverts only the AUTHOR dispatch: it yields a bare author-tuple `(domains, summary, gates)` ([plan_driver.py:122](../../../scripts/plan/plan_driver.py)) and the consumer `.send()`s author envelopes back, but the GATE is still a SYNCHRONOUS Python call in `drive`'s own frame (`_safe_gate(gate_dispatch, result)`, [plan_driver.py:129](../../../scripts/plan/plan_driver.py)) and the `reauthor`/`adjudicator` hooks are still synchronous callables threaded DEEP INSIDE the byte-frozen `orchestrate.generate_plans` (`reauthor("workout", {...})` at [orchestrate.py:550](../../../scripts/plan/orchestrate.py), `_adjudicate_with_band(safety_finding, adjudicator)` at [orchestrate.py:578,595,613](../../../scripts/plan/orchestrate.py)). Under the operator's binding runtime split — "API for the PII de-id call ONLY, subscription for everything else" — those four dispatches must run as SUBSCRIPTION agents, which only the `/generate-plan` skill can dispatch (via the Agent tool), never a Python function. So the live A′ run halts at `_safe_gate`: there is no Python judge/lens backend and no inverted yield the skill can fulfil. This is the PF-S63-02 / PF-S87-01 "plumbing wired, end-to-end capability not" gap.

The deliverable is FIVE tasks that invert the remaining classes by TWO mechanisms keyed to call-stack position, exactly as ADR-0028's Decision resolves it. **T1** extends `drive`'s yield protocol from the bare author-tuple to a typed discriminated-union of dispatch-requests and inverts AUTHOR + GATE by DIRECT YIELD (both fire in `drive`'s frame); the GATE becomes a yielded request carrying the assembled plan + the judge + the lens roster, the consumer `.send()`s the RAW verdicts, and `drive` still calls `compose_gate_dispatch` + applies `safety_passed is True` — composition stays in ONE definition. **T2** inverts REAUTHOR + ADJUDICATOR by THROW/REPLAY-MEMOIZATION (they fire inside the byte-frozen engine and cannot yield without editing it): the consumer supplies memo-cache-backed `reauthor`/`adjudicator` callables that raise a `BaseException`-subclass sentinel on a cache-miss, unwinding to `drive`, which yields the typed request, caches the `.send()` envelope, and re-drives the pass over a FRESH scratch store. **T3** builds the step-harness `plan_step.py` (the skill's per-round drive) and pins the memo-cache serialization format + a determinism audit (OQ-5). **T4** reconciles `/generate-plan` SKILL.md to drive via `plan_step.py` and adds the NEW value-scan over the GATE/ADJUDICATOR yield payloads (the first-ever such scan over those DERIVED artifacts). **T5** extends the self-test / E2E to NON-TAUTOLOGICALLY exercise the REAUTHOR + ADJUDICATOR replay paths (the current `_sustaining_authors` fixtures trigger neither).

How it fits the architecture: ADR-0028 REFINES ADR-0026 (which control-inverted the author dispatch and bought the no-fork single-definition disposition composition + fail-closed loop) and depends on ADR-0027 (the live de-id backend — the one metered egress, already built). The runtime sequence one plan runs is de-id IN → AUTHOR yield → GATE yield → (REAUTHOR / ADJUDICATOR replay rounds, throw/yield/`.send()`/replay) → (revise → second AUTHOR → second GATE) → promote → render. The byte-frozen INNER ENGINE (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track,router}.py`) stays numstat=0; the change is confined to `plan_driver.py` + `plan_orchestrator.py` + (only at the raw-verdict boundary, if at all) `gate_dispatch.py` + the new `plan_step.py` + the SKILL.md + tests + new test files. The adjudication-RELEASE decision (`outcome == "cleared"` + the CRITICAL/H1-H2 non-overridable check, [orchestrate.py:579,597,615](../../../scripts/plan/orchestrate.py)) stays in the inner engine's `adjudicate`, NOT re-derived in the consumer/harness/skill.

Informing artifacts: the source ADR (`docs/adr/ADR-0028-gate-dispatch-control-inversion.md`), the dispositions (`docs/spec/.pipeline/adr-0028/dispositions.md`), and the predecessor live-wiring spec (`docs/spec/live-wiring-spec.md`, the format exemplar + the prior A′ task set). The LIVE subscription run — real key + real data + spend — is the operator-present S94 attestation AFTER this build, NOT a task here (a downstream dependency, recorded in the Unresolved Concerns table).
