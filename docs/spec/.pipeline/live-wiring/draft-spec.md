# Spec: Plan-Generation Engine LIVE-WIRING (Live No-Train De-Id Backend + Subscription-Runtime Driver A′)

## Component Overview

This spec wires the two approved live-wiring ADRs (ADR-0026, ADR-0027) that turn the already-built, mock-tested S92 plan-generation engine into a LIVE, subscription-driven runtime. It delivers the two halves of the one S93 runtime split: the PII-API half (ADR-0027 — the live `_ClaudeNoTrainBackend.deidentify` no-train call that produces the de-identified summary the whole pipeline consumes) and the subscription half (ADR-0026 — the A′ skill-as-orchestrator driver model that dispatches every plan-domain specialist + safety lens as a subscription agent over that summary and drives the fail-closed revise loop through ONE shared control-inversion driver).

The deliverable is five tasks: (1) fill the de-id backend stub with a real no-train API call (the crown-jewel raw-PII egress); (2) EXTRACT the inline revise-loop control flow that today lives in `run_orchestrated`'s `while True:` into ONE shared control-inversion driver and re-point `run_orchestrated` at it (the keystone, behavior-preserving refactor of the S92-authored wrapper — the byte-frozen inner engine is untouched); (3) build the composed `gate_dispatch` adapter that maps the built `quality_judge` verdict + `review_plan` result into the 3-key `{accept, safety_passed, revise_domains}` disposition the loop consumes; (4) reconcile the superseded `/generate-plan` runtime-A skill to drive the A′ path; (5) repoint `core-capability-audit.sh` onto the A′ spine with a non-tautological `--self-test`. The crown-jewel obligation is 0-leak: no raw operator PII past the de-id-IN boundary, into any dispatch payload, or into any committed file; and a single, un-forked fail-closed safety loop (`safety_passed is True` the only surface path).

The engine already exists and is wired against fixtures. Per the live tree at `main @ e3d5789`: `run_orchestrated` ([plan_orchestrator.py:136-305](../../../scripts/plan/plan_orchestrator.py)) already owns the full revise loop INLINE — the `while True:` gate→branch→re-dispatch, the `safety_passed is True` terminal gate, scratch-and-promote, the `revise_domains` re-dispatch, the de-id sentinel halt, and the `dispatch_cap` — driven today by a programmatic/fixture `dispatch`. The built gate callables `quality_judge(plan, judge_client) -> {verdict}` ([quality_judge.py:206-253](../../../scripts/plan/quality_judge.py)) and `review_plan(assembled_plan, dispatch, *, lenses) -> {passed, findings, lenses}` ([safety_review.py:110-169](../../../scripts/plan/safety_review.py)) exist but are NOT yet composed into the loop's disposition (their own docstrings defer that to "ADR-0022-T2 / the gate_dispatch composer" — the genuine gap ADR-0026-T2 fills). The de-id seam `ModelClient.deidentify` + `deid_in` exist and are fail-closed; only `_ClaudeNoTrainBackend.deidentify` is still a `NotImplementedError` stub ([client.py:156-160](../../../scripts/model/client.py)). Per the hard EXTEND-NOT-REBUILD grounding fact (context.md §"EXTEND-NOT-REBUILD"), every task WRAPS or REFACTORS-WITHIN-THE-WRAPPER; the byte-frozen INNER ENGINE (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track,router}.py`) stays numstat=0, and `run_orchestrated` (the S92-authored WRAPPER) takes the bounded control-inversion refactor under the protection of the 1611-test suite staying green.

How it fits the architecture: the DEPENDENCY tiers (DAG §4) are Tier 1 = ADR-0027 (the de-id backend, dependency sink) and Tier 2 = ADR-0026 (the driver, depends-on ADR-0027 by the de-identified-summary INPUT CONTRACT). The RUNTIME stage order DIFFERS from the dependency tiers and is the control-flow sequence one plan runs through (DAG §7): **(1) de-id IN (ADR-0027 live backend) → (2) subscription specialist dispatch + orchestrate/assemble (ADR-0026 driver + inner engine) → (3) {quality judge ∥ safety review} composed via gate_dispatch (ADR-0026) → (4) bounded revise loop (the shared driver) → (5) de-id OUT re-insertion (ADR-0021, deterministic, already built) → (6) maintained render (ADR-0025, already built)**. The load-bearing BUILD-vs-RUNTIME divergence: ADR-0026-T1 (the shared-driver extraction) is the keystone and runs the loop at runtime, but its BUILD dependency on ADR-0027-T1 is NONE — the control-flow extraction uses the existing `dispatch`/`gate_dispatch`/`deid_client` seams (a fixture `dispatch` drives it in tests), so it is a build entry point even though de-id IN is the FIRST runtime stage. The dependency is stated from the BUILD perspective, not the runtime order.

The resolved tensions are documented trade-offs, not open items. ADR-0027↔ADR-0001 (raw plan-intake PII transits the no-train API before de-id) is accepted under bounded no-train retention reusing ADR-0020/0016's already-adopted second-raw-egress-class posture, mitigated by the fail-closed `ModelCallError` contract + the retained `SUMMARY_FIELD_SET` whitelist in `deid_in`. ADR-0027↔ADR-0005 (no committed/tracked PII + the API key) is held by the raw-intake-in-memory-only AC (disposition #7), the runtime-injected key (`key_source.resolve` — never tracked/printed/committed; the agent never reads the keychain), and the `block-pii-commit.sh` + `pre-push-pii-scan.sh` backstop. ADR-0026's no-fork tension (the safety loop must stay one source of truth) is resolved by the single shared-driver extraction proven by 0 duplicated loop copies + the 1611-test suite staying green.

Informing artifacts: the Phase-3 DAG (`docs/adr/.pipeline/live-wiring/dag.md`), the cross-ADR context (`docs/spec/.pipeline/live-wiring/context.md`), the dispositions (`docs/spec/.pipeline/live-wiring/dispositions.md`), and the format exemplar (`docs/spec/adr-0020-0025-plan-gen-engine-spec.md`) — downstream workers load them on demand.
