# Spec: First-Run Intake Gate + Comprehensive Intake De-Identification + Care-Agent Review

## Component Overview

This spec implements the three-ADR intake/onboarding set against the now-live served SPA. The served front-end is the single-file `app_view.html`, rendered by `vault/design/templates/app_shell.render(store_read, *, status, _today)` and returned as the GET `/` body by the loopback server's `_render_intake` -> `generate.run('app')` seam ([app_shell.py:258-288](../../../vault/design/templates/app_shell.py) [VERIFIED]; [server.py:142-149](../../../scripts/serve/server.py) [VERIFIED]). Today that render is UNCONDITIONAL (every surface reachable on first run), the intake is a four-field demographic form hosted in a `Build Plan` tab ([app_view.html:455-469](../../../vault/design/templates/app_view.html) [VERIFIED]), five `SUMMARY_FIELD_SET` planner tokens fall to no-signal defaults because no rich-domain surface feeds them, raw medications have no curation surface, and there is no exercise-safety / PHQ-2 / apnea screen. This set closes all of that: ADR-0034 sets the comprehensive field->destination contract (the rich-domain wiring + the amended actual-value age/weight mapping + the safety routing), ADR-0033 gates the platform behind a derived store-grounded completeness predicate and renames/reshapes the unlocked shell, and ADR-0035 fires the care-agent review (clarifying questions + de-associated meds curation) at the unlock transition.

The build is a NEW gated Create-Profile intake UI + an EXTENDED capture/serve/render layer onto the frozen engine, in nine dependency-ordered tasks. **T1** extends `capture.persist_capture` to route the 9-step wizard's fields by data class — wiring the four serve-fillable default-fed tokens (`dietary-pattern-class` / `supplement-stack-class` / `peptide-use-class` / `training-volume-band`) through the EXISTING `_CHAT_RAW_SOURCE_FIELDS` raw-source -> deriver path, keeping raw meds + smoker/alcohol/race record-only, and pinning each bounded select's values onto the router derivers' keyword buckets (OQ-1). **T2** lands the OQ-5 actual-value age/weight token mechanism — a SCOPED additive `router.py` deriver edit (`training-age-band` carries the de-associated EXACT AGE from the locally-stored full DOB; `bodyweight-band` carries the de-associated current weight + trend from a local weight time-series) with the `SUMMARY_FIELD_SET` tuple + `dispatch` whitelist byte-unchanged. **T3** routes the three safety screens (exercise-safety / PHQ-2 / apnea) to a NEW intake-referral surface + the safety-screen-answered markers, and food/drug allergies to `hard-limits`, NEVER to a planner token. **T4** builds the 9-step Create-Profile wizard markup (incl. the existing-seam document uploads + the API-key save), **T5** the equipment access-gated 29-item checklist, both matching the operator-signed-off `prototype/intake-onboarding-mockup.html`. **T6** lands the derived completeness gate + unlock render branch in `app_shell.render` (no new route). **T7** reshapes the unlocked shell (the `My Plan | My Info | Generate Plan` tabs, opens-on-My-Info, the editable My-Info re-de-identify path, the Generate Plan tab roster). **T8** fires the care-agent review-on-final-save + the de-associated meds curation. **T9** is the headline E2E plus the ADR-0033/0034/0035 falsification probes as tests.

The model backend is the swappable no-train `ModelClient` (ADR-0015), so every model call — the chat turn, the care-agent clarifying review (`client.converse`), and the de-associated meds curation — is mock/fixture-tested at 0 live spend at the `_FakeAnthropic`/`_patch_backend_client` seam. The operator-present LIVE care-agent run (real key + real spend) is ADR-0035 OQ-1, deferred. The gate, the capture routing, the safety markers, and the care-agent trigger all read/write through the EXISTING `store.append` / `router.summarize` / `client.converse` / `key_source` seams; the build adds NO new server route (the route table stays the seven existing entries, [server.py:110-166](../../../scripts/serve/server.py) [VERIFIED]).

### The crown-jewel PII boundary (NFR-1, load-bearing)

The operator's IDENTITY (legal name, the full DOB) and the name<->fact (name<->med) linkage stay 100% LOCAL; only de-identified tokens + DE-ASSOCIATED facts reach the no-train model. The bound this spec enforces: (a) **0 full-DOB strings and 0 raw-PII tokens (legal name, a raw drug name, a PHQ-2 free-text answer, a race string) in any `router.summarize` output or any model request** — the planner receives the EXACT AGE (a de-associated integer computed from the local DOB) and the actual current weight + trend (de-associated), which are EXPECTED de-associated facts, not a raw crossing; (b) **0 `rx-interaction-classes` store writes originating from the serve capture path** (raw meds route record-only; only the care-agent's curated de-identified class token persists as a planner input); (c) **0 operator-identity tokens + 0 name<->med linkage in the de-associated meds-curation request** (drug names only — the named, operator-signed-off ADR-0035 egress class on the ADR-0032 de-association principle); (d) **0 safety-screen answers (exercise-safety / PHQ-2 / apnea) as a `SUMMARY_FIELD_SET` token or in any dispatched payload** (they are referral/gate signals, rejected by the `dispatch` whitelist if injected). An edit through the editable My-Info re-runs the SAME `persist_capture` -> `summarize` path, so no edit bypasses the boundary.

### EXTEND-NOT-REBUILD (NFR-2)

The inner plan ENGINE (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`), the `dispatch` whitelist gate logic, and the store (`scripts/store/*.py`, the `store.append` sink) stay BYTE-FROZEN (numstat=0). The build EXTENDS capture/serve/render. The ONLY plan-path edit is the SCOPED, ADDITIVE OQ-5 demographic-deriver change in `scripts/plan/router.py` — the ADR-0019 / ADR-0032-T3 precedent (ADR-0032-T3 made a scoped additive `router.py` edit despite the general router freeze). That edit REPURPOSES two existing tokens' DERIVERS, leaving the `SUMMARY_FIELD_SET` tuple, the `EXCLUDED_RAW_PII`-disjointness asserts, the `dispatch` whitelist, and `capture.WIRED_TOKENS`'s `<= SUMMARY_FIELD_SET` tripwire all valid by construction. The gate is a render BRANCH inside the existing `app_shell.render` / `generate.run('app')` seam, NOT a route; the care-agent review REUSES `client.converse` (a new trigger, not a new client); the referral surface writes via the UNCHANGED `store.append`.

### The OQ-5 token mechanism decision (DECIDED — repurpose, not add)

ADR-0034's amendment supersedes the coarse `training-age-band` (born-decade) and `bodyweight-band` (weight band) with the de-associated EXACT AGE and the actual current weight + trend. OQ-5 ("add new tokens vs. repurpose the band tokens — spec decides") is RESOLVED as **REPURPOSE** (T2): keep the `SUMMARY_FIELD_SET` tuple ([router.py:23-56](../../../scripts/plan/router.py) [VERIFIED]) BYTE-IDENTICAL — no token added, none removed — and change only the two tokens' derivation. `training-age-band`'s deriver (`_age_band`, the born-decade bucketer) is repurposed to emit the EXACT AGE (an integer-years scalar) computed at summarize-time from the locally-stored full `date-of-birth` (still a named-excluded raw-PII source, never crossing); the `date-of-birth -> training-age-band` `_RAW_TO_FIELD` mapping is unchanged. `bodyweight-band` changes from a pass-through `WIRED_TOKEN`/`_BOUNDED_ENUMS` band select to a `_RAW_TO_FIELD`-derived token sourced from a NEW local `bodyweight-kg` dated time-series (named-excluded raw-PII — the per-day weight log stays local + feeds the dashboard chart); its deriver emits the de-associated current weight + trend. Rationale for repurpose over add: it keeps `SUMMARY_FIELD_SET`, the `dispatch` whitelist, the disjointness asserts, and `capture.WIRED_TOKENS`'s tripwire byte-valid (minimal blast radius), leaves no dead band token, and matches the ADR's "superseding ... for the age/weight signal" framing literally. Accepted residual: the token NAMES (`...-band`) now carry a more-precise value than a band — a no-train specialist reading the token name sees a slight misnomer; the value is self-describing and the ADR sanctioned the supersede, so the residual is accepted (a rename would be a non-additive field-set churn, rejected).
