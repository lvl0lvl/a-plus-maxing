## ADR-0032: DNA-Aware Planning via De-Associated Current-Science Variant Research

> **Y-Statement:** In the context of the now-live plan-generation engine, where the operator's genotype is a durable stored FACT (ADR-0031 lands it as `dna-report` readings) but its report INTERPRETATION is stale (the report predates current science) and the de-identified `router.summarize` summary the plan author sees carries no genetics token, so the plan is not DNA-aware, facing the tension that making it DNA-aware naively would either freeze the stale, dated read OR cross sensitive raw genetic PII to the no-train model, we decided that the care assistant, while planning, requests CURRENT-science research on planning-relevant variants via the EXISTING `aplus-research` skill using GENERIC, operator-de-associated per-variant queries → vetted findings cache in a NEW variant-keyed, ingestion-gated `vault/library/genetics/` section → the operator's LOCAL `dna-report` genotypes are matched to those library findings LOCALLY → the no-train planner consumes only a locally-derived de-identified genetic-trait/implication token set, to achieve a current-science DNA-aware plan while the operator's identity, raw genotypes, AND the genotype↔operator link never leave the machine (a deliberate, operator-approved crown-jewel EXTENSION of ADR-0001), accepting a NEW named egress class whose variant SELECTION weakly correlates to the operator's genome, a genetics library that needs maintenance as science evolves, and a new local genotype↔library matching component.

### Context

The plan-generation engine reasons over a de-identified summary, never raw operator data: `router.summarize` derives a name-addressable summary whose keys are drawn ONLY from the closed `SUMMARY_FIELD_SET`, and `dispatch` rejects any field outside that set before the model send ([router.py:20-47](../../scripts/plan/router.py), [router.py:633-693](../../scripts/plan/router.py) [VERIFIED]). The plan author (`ModelClient.author(domain, summary)`) receives that summary and nothing else ([client.py:62-76](../../scripts/model/client.py) [VERIFIED]). The field-set carries training-age, recovery, issue-class, BPMH-class, and chat-sourced diet/supplement/peptide/volume tokens — but NO genetics token. The plan is therefore not DNA-aware by construction: the operator's genotypes never reach the planner.

ADR-0031 now lands the genotypes as durable FACTS: a genetics report extracts to `dna-report` store readings keyed `item` = gene+rsID, `timepoint` = sample date, `value` = the alleles, storing the fact and explicitly NOT the report's interpretation, which is "dated and re-derivable at plan time" ([client.py:290-319](../../scripts/model/client.py) [VERIFIED]; [ADR-0031 Decision](ADR-0031-local-extraction-first-pdf-ingestion.md) [VERIFIED]). The operator's report is an older artifact whose interpretations predate current science [UNVERIFIED: operator-held artifact — the ingested sample-date metadata reads 2019-12-13 (ADR-0031), while the operator recalls the report as older; the report itself is operator-held PII, not in the repo], and a dated read of a variant can be obsolete — the genotype is a stable fact, but its clinical/performance MEANING is time-varying as new science accumulates. The operator's directive is explicit: "the report is old and new science has come out since then which may update the read" ([ADR-0031 Context](ADR-0031-local-extraction-first-pdf-ingestion.md) [VERIFIED]).

Three forces pull across more than one stakeholder. The operator needs a plan that REFLECTS current-science variant implications (e.g. a caffeine-metabolism genotype informing pre-workout timing) rather than ignoring the genome it has on file. The data subject's crown-jewel containment binds the second force: raw genotypes are among the most sensitive PII the system holds, and sending the raw rsID+allele set to the no-train model for interpretation crosses that sensitive PII on the model lane — the operator explicitly rejected doing so. The maintainer's honest-data force binds the third: a stale or fabricated genetic read is a clinical-safety risk, so the read must rest on the stored FACT re-interpreted by current, cited, vetted evidence, never on the frozen, dated report narrative ([ADR-0009 Decision](ADR-0009-dashboard-visual-shell-seven-zones.md) [VERIFIED]). Against all three stands the boundary itself: ADR-0001 keeps store, ingestion, and generation local and routes only de-identified summaries to the plan model, with raw-egress carve-outs named one at a time and never silently widened ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]; [ADR-0016 Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). Because this redraws WHAT informs the plan (a genetics axis the field-set never carried) and WHAT new information-flow leaves the machine to obtain it, it is a decision, not a code comment beside the summarizer.

### Decision

While planning, the care assistant requests current-science research on the operator's planning-relevant genetic variants; a DNA research agent answers via the EXISTING `aplus-research` skill — which runs as a Claude Code agent dispatch on the subscription/agent research lane the project's existing library research already uses, NOT the no-train `ModelClient` backend — using a GENERIC, operator-de-associated, ALLELE-AGNOSTIC per-variant query that carries the variant (gene+rsID) but NOT the operator's allele (e.g. "current 2026 evidence on ACTN3 rs1815739 — the implications of each genotype for strength training" — NEVER "the operator has X" and NEVER the operator's own allele call); the vetted findings cache in a NEW, variant-keyed, ingestion-gated `vault/library/genetics/` section that is reusable and NOT operator-associated; the care assistant matches the operator's LOCAL `dna-report` genotypes to those library findings LOCALLY; and the no-train planner consumes only a LOCALLY-derived, de-identified genetic-trait/implication token set through the existing `router.summarize` / `ModelClient.author` seam — the raw rsID+allele genotypes NEVER cross to the planner.

This adds a NEW, deliberately-named egress class — **generic, operator-de-associated genetic-variant literature queries** — as an operator-approved crown-jewel EXTENSION of ADR-0001. What LEAVES the machine is only generic gene/variant questions anyone could ask. What stays 100% LOCAL is the operator's identity, the raw genotypes (including the operator's specific allele call), AND the genotype↔operator link; the operator's allele is applied LOCALLY against the variant-keyed library to select which per-genotype finding applies. The operator gave informed sign-off naming the new egress class and its weak correlation residual (the PF-S63-02 guard-loosening corollary is satisfied: the loosened-boundary failure class is named and signed off, not default-accepted). The decision is EXTEND-NOT-REBUILD: the inner plan ENGINE logic (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`) and the store (`scripts/store/*`) stay byte-frozen; the ONLY plan-path edit is the ADDITIVE `SUMMARY_FIELD_SET` genetic-trait token + its local deriver in `router.py` (the additive-`SUMMARY_FIELD_SET`-extension precedent is ADR-0019), which the planner consumes through the existing summary/author seam alongside the new library section, the research hookup, and a local matching read-surface.

### Rationale

Four options were evaluated against four criteria the governing decisions make load-bearing: **read currency** (is the genetic read CURRENT science or a frozen, dated interpretation?), **raw-genotype egress** (do the raw rsID+allele facts ever leave the device or reach the planner?), **engine reuse** (does it edit the frozen plan engine or the store?), and **V1-fit** (does it work now, without an offline interpretation model and at zero forced spend?).

On **read currency**, only re-deriving the read from current evidence keeps it honest. Freezing the report's dated interpretation (Alternative A) bakes in obsolete science the operator explicitly flagged; the de-associated-research path re-asks the literature at plan time, and the variant-keyed library refreshes as science evolves without re-ingesting the report — the same fact/interpretation separation ADR-0031 stores the fact for ([ADR-0031 Decision](ADR-0031-local-extraction-first-pdf-ingestion.md) [VERIFIED]). On **raw-genotype egress**, the chosen path is the only one that re-interprets variants WITHOUT crossing the raw genotype: the queries that leave are generic and allele-agnostic ("current evidence on ACTN3 rs1815739 — the implications of each genotype for strength training"), de-associated from the operator, and the operator's actual genotype↔implication match happens LOCALLY against the cached library. Sending the raw genotypes to the no-train model for interpretation (Alternative B) crosses sensitive raw genetic PII on the model lane — the surface ADR-0001's summaries-not-raw falsification names as a breach ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]) — which the operator rejected. On **engine reuse**, the research hookup, the genetics library, and the local match are NEW surfaces; the planner consumes the genetic implications through the EXISTING de-identified summary/author seam (a `SUMMARY_FIELD_SET`-shaped trait token, spec-detail in OQ-2), so `dispatch`'s gate logic / `ModelClient.author` and `store.append`/`read` stay byte-unchanged, and `router.summarize`'s whitelist/contract is unchanged save the one additive genetic-trait deriver ([router.py:633-693](../../scripts/plan/router.py), [store.py:134](../../scripts/store/store.py) [VERIFIED]). On **V1-fit**, the research engine already exists, is gated, and runs on the subscription/agent research lane (runtime A) the project's other PII-free library work already uses — NOT the no-train `ModelClient` plan lane: `aplus-research` enforces six blocking gates (scope 2.75, judge 3.5, integrity 4.75, critique 6, risk-floor 7.5, layers 8.5) plus three health-specific gates (population-mismatch, risk-floor, concentration-audit), so variant findings are vetted to wiki-canonical quality by the same machinery the rest of the library uses ([.claude/skills/aplus-research/SKILL.md](../../.claude/skills/aplus-research/SKILL.md) [VERIFIED]). A bundled offline interpretation database (Alternative C) is heavy and goes stale without updates — a North-Star concern, not V1.

The genetics findings are goal-agnostic, variant-keyed library entries — vetted current science about a variant, the same canonical form the compounds and biomarkers library carries, just a section that does not exist yet ([vault/library/](../../vault/library/) holds `biomarkers/`, `peptides/`, `methodology/` only [VERIFIED]). Keying the cache to the VARIANT (not to the operator) makes it reusable and keeps it on the right side of the crown jewel: the library is the same whether or not the operator carries the variant, so it leaks nothing about the operator. The new genetics section is ingestion-gated like every other library section — `INV-WIKI-INGESTION-GATED` (`scripts/wiki-ingest-lint.sh`, the `block-ungated-vault-write.sh` PreToolUse hook) refuses a `vault/library/` page that lacks passing research provenance ([vault/WIKI.md Ingest](../../vault/WIKI.md) [VERIFIED]).

### Consequences

**Positive:**
- DNA-aware planning on CURRENT science: the plan reflects a present-day variant implication (e.g. a fast-caffeine-metabolizer genotype informing pre-workout caffeine timing [UNVERIFIED — illustrative; the live implication is whatever the gated `aplus-research` run establishes]) instead of ignoring the genome or freezing the report's dated read.
- The raw genotypes never leave the machine and never reach the planner: only generic, de-associated variant queries egress, and the operator's genotype↔implication match is local — a strictly smaller and lower-sensitivity egress than ADR-0016/0027's raw-PII carve-outs ([ADR-0016 Decision](ADR-0016-intake-conversation-egress-relaxation.md), [ADR-0027 Decision](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]).
- Fact/interpretation separation future-proofs the read: as new science lands in the variant-keyed library, the operator's genetic read refreshes without re-ingesting the report — the durable-fact half ADR-0031 stores finally has a current-interpretation half ([ADR-0031 Decision](ADR-0031-local-extraction-first-pdf-ingestion.md) [VERIFIED]).
- Reusable, goal-agnostic library: variant findings are vetted by the existing `aplus-research` gates and cached for any future specialist dispatch, not re-researched per plan, and ingestion-gated like the rest of the library (`INV-WIKI-INGESTION-GATED`).
- Engine and store unchanged: the inner plan engine (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`) and store (`scripts/store/*`) are byte-frozen, the one exception being the additive `SUMMARY_FIELD_SET` token + deriver in `router.py`; the planner consumes genetics through the existing de-identified summary/author seam, so ADR-0001's persisted-side discipline holds.

**Negative:**
- A weak correlation vector: even a generic, de-associated variant query reveals WHICH variants are being researched, and the variant SELECTION traces to the operator's genome — so an adversary holding the operator's identity AND the query timing could infer the variant set of interest. Mitigated (not eliminated) by the variant set being common/curated, the queries de-associated, and the findings cached-and-reusable so a query need fire at most once per variant — but it is a residual the operator signed off on, not a zero.
- The genetics library needs ongoing maintenance: a variant read is current only as of its research date, so the section accrues a re-rotation obligation as science evolves (the same staleness ADR-0031's fact/interpretation split exists to absorb, now an explicit library upkeep cost).
- A new local component to build and keep correct: the genotype↔library matching read-surface (operator `dna-report` readings → library variant findings → de-identified trait token) is new code with its own failure modes — a mis-match could feed the planner a wrong-variant implication, so it carries a correctness burden the frozen engine does not.
- A new named egress class redraws ADR-0001: future readers must not silently widen "generic de-associated variant query" into "operator-associated variant query" or "raw genotype to model" — the carve-out is bounded and must stay bounded.

**Neutral:**
- The de-associated variant queries run on the subscription/agent research lane (runtime A) the project's existing library/research path already uses — the same `aplus-research` dispatch lane, NOT the no-train `ModelClient` backend (which carries the operator's de-identified summary on the planner side). The payload is a generic, PII-free, allele-agnostic literature question anyone could ask, so it fits ADR-0001's existing "PII-free library and research work" category and opens no new egress lane; the only operator-derived signal is the variant SELECTION (the weak correlation owned in Consequences-Negative), never operator-identifying content ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- A new `vault/library/genetics/` section joins `biomarkers/`/`peptides/` under the same ingestion gate and templates; the `dna/` vault folder for raw 23andMe-derived variant pages is a separate, pre-existing surface ([vault/WIKI.md Entity Types](../../vault/WIKI.md) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Freeze the report's dated interpretation
Store and surface the variant interpretations as the older report stated them, with no re-research.
- **Supporting evidence:** Simplest possible path — the report already contains an interpretation per variant, so no research engine, no library section, and no new egress is needed; the read is internally consistent with the source document.
- **Trade-offs:** The interpretation is stale by construction — the operator explicitly flagged that "new science has come out since then which may update the read" ([ADR-0031 Context](ADR-0031-local-extraction-first-pdf-ingestion.md) [VERIFIED]) — and a stale genetic read is a clinical-safety risk against the honest-data principle ([ADR-0009 Decision](ADR-0009-dashboard-visual-shell-seven-zones.md) [VERIFIED]). ADR-0031 already declined to store the report's interpretation for exactly this reason. Rejected: it bakes obsolete science into the plan.
- **When this becomes the right choice:** Never for a years-old report; it would be defensible only for a freshly-issued report whose interpretation IS current science, and even then the variant-keyed library is the more durable home for that read.

#### Alternative B: Send the raw genotypes to the no-train model for interpretation
Pass the operator's raw rsID+allele genotypes to `ModelClient.author`/a model call and let the model interpret them in context.
- **Supporting evidence:** Maximally capable — the model interprets the operator's actual genotypes directly, with no library section, no local matching, and no de-association step; the read is as rich as the model's genetics knowledge. It reuses the already-authorized no-train lane.
- **Trade-offs:** It crosses sensitive RAW genetic PII to the model — the exact summaries-not-raw surface ADR-0001's falsification names as a breach ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]) — on the system's most sensitive data class. The operator EXPLICITLY rejected this even on the no-train lane: the de-id-IN and intake carve-outs (ADR-0016/0020/0027) egress raw PII transiently, but raw genotypes are a step the operator drew the line at. Rejected on operator instruction and crown-jewel containment.
- **When this becomes the right choice:** Only if the model lane became a fully-local model (ADR-0015's North-Star swap), at which point "egress" is moot because nothing leaves the device — then local raw-genotype interpretation is the simpler path.

#### Alternative C: Bundle an offline genetics-interpretation model/database
Ship a local genetics-interpretation database or model with the clone, so variant reads are computed on-device with zero egress.
- **Supporting evidence:** Zero egress of any kind — the strongest privacy posture, no query leaves the machine, and the read is reproducible offline; aligned with the North-Star fully-local direction.
- **Trade-offs:** Heavy to bundle and provision, and it goes STALE without an update channel — reproducing exactly the dated-interpretation problem Alternative A has, just locally. Curating and versioning a genetics knowledge base is a substantial effort that is a North-Star concern, not a V1 deliverable. Rejected/deferred: the cost and staleness dominate for V1; the de-associated-research path reuses the already-gated `aplus-research` engine instead.
- **When this becomes the right choice:** When the North-Star transition to local models happens AND a maintainable offline variant knowledge base with an update cadence exists — then on-device interpretation supersedes the egress path entirely.

#### Alternative D: De-associated current-science variant research (Chosen)
The care assistant dispatches generic, de-associated per-variant queries through `aplus-research`, caches vetted findings in a variant-keyed library, matches the operator's local genotypes to the library LOCALLY, and feeds the planner a de-identified trait token.
- **Supporting evidence:** Current-science read (re-asked at plan time, refreshable), no raw-genotype egress and none reaching the planner, reuses the gated `aplus-research` engine and the frozen plan engine/store, and produces a reusable goal-agnostic library. It is the only option satisfying read-currency AND raw-genotype-containment AND engine-reuse at V1.
- **Trade-offs:** Adds the weak variant-selection correlation vector, a library-maintenance obligation, and a new local matching component (all owned in Consequences). Accepted because current-science + zero raw-genotype egress dominate.
- **When this becomes the right choice:** It is, for V1, while the model lane is remote and no maintainable offline genetics base exists.

#### Dissent: The no-genetics-egress purist position (inherited from ADR-0001 / 0016)
**Source:** ADR-0001's crown-jewel anchor and the "never silently widen the carve-out" review trigger ([ADR-0001 Y-Statement](ADR-0001-pii-trust-boundary-no-train-routing.md), [ADR-0016 Review triggers](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). A purist holds that ANY egress whose CONTENT is derived from the operator's genome — even a generic, de-associated variant query — is a new information-flow about the data subject, and that Alternative C (fully offline) is the only posture that truly honors the crown jewel; the weak correlation vector is a real, if small, leak.
**Conditions under which this becomes the right choice:** If the no-train provider's no-train / retention terms degrade (queries becoming training-eligible or long-retained), OR if a maintainable offline genetics knowledge base reaches usable coverage of the planning-relevant variants — then the de-associated-query egress should be retracted and the read computed on-device (the Alternative-C / North-Star direction), at which point this decision's egress class closes.

### Validation Approach

**Confirmation criteria:**
- Egress is de-associated: scan every outbound variant query in the `aplus-research` run log. Expected — each query contains a generic gene/variant string only; **0 operator-identifying tokens and 0 statements of the genotype↔operator link** (never "the operator has X"). The query is one anyone could ask about the variant.
- The planner input is genotype-free: scan the de-identified summary `router.summarize` builds for the plan. Expected — it carries only de-identified genetic-trait/implication tokens (the OQ-2 token set), **0 raw rsID+allele genotypes**, and `dispatch`'s whitelist still rejects any field outside the (extended) `SUMMARY_FIELD_SET` ([router.py:633-693](../../scripts/plan/router.py) [VERIFIED]).
- The library is variant-keyed and operator-free: scan every `vault/library/genetics/` page. Expected — keyed by gene+rsID, reusable, **0 operator-identifying tokens**, and each page passes `scripts/wiki-ingest-lint.sh` (provenance + structure, `INV-WIKI-INGESTION-GATED`).
- A plan reflects a current-science trait: with a fixture genotype matched to a fixture library finding, the rendered plan carries the current-science implication (e.g. caffeine-metabolism genotype → pre-workout timing), derived from the library finding, not the report's dated interpretation.
- Extend-not-rebuild: `git diff --numstat` shows **0 changed lines** on the inner plan ENGINE (`scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py`), `scripts/store/keying.py` / `store.append`, and `dispatch`'s gate logic; the ONLY plan-path change is the ADDITIVE `SUMMARY_FIELD_SET` genetic-trait token + its local deriver in `scripts/plan/router.py` (OQ-2; the additive-`SUMMARY_FIELD_SET`-extension precedent is ADR-0019), reviewed against this floor.

**Falsification criteria (quantitative; the crown-jewel probe is load-bearing):**
- De-association probe (the crown-jewel test): seed a known operator-identifying token and the operator's genotype↔operator link into the fixtures, run the variant-research dispatch under the egress guard. Threshold — **0 operator-identifying tokens AND 0 raw genotypes (rsID+allele pairs) in any outbound variant query**; ≥1 occurrence reds the boundary → halt and repair before release.
- Raw-genotype-to-planner probe: run the local match + summary build and inspect the planner's input. Threshold — **0 raw genotypes reaching the no-train planner** (the planner sees only de-identified trait tokens); ≥1 raw rsID+allele reaching the planner reds the boundary → halt and repair before release.
- Library-association probe: scan `vault/library/genetics/` for any operator-identifying token or the genotype↔operator link. Threshold — **0 hits**; ≥1 means the cache became operator-associated → halt and re-key to the variant before release.
- Zero-live-spend probe: the design/build wires UP TO the live lookup only. Threshold — **0 live `aplus-research` variant API calls (0 spend)** during design/build; ≥1 metered live call before the operator-present run (OQ-1) is a scope breach → halt.
- Time horizon: run the de-association probe, the raw-genotype-to-planner probe, the library-association probe, and the extend-not-rebuild diff at the first build of the variant-research hookup, at the operator-present LIVE run, and at every release thereafter, and before the July-2026 physician-visit deliverable.

**Review triggers:**
