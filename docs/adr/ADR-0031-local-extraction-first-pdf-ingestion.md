## ADR-0031: Local-Extraction-First PDF Ingestion + Genetics Genotype-Fact Capture

> **Y-Statement:** In the context of the now-live ADR-0030 model-based universal-ingestion path — which sends an unrecognized-format upload to the no-train model as a raw base64 `document` content block — facing the tension between needing to ingest dense documents (the operator's real 42-page genetics/SNP report) completely and the twin facts that (a) a raw document block truncated the model's structured OUTPUT (`stop_reason=max_tokens`) so the operator saw "no new data" and (b) shipping the whole raw binary off-device is more egress than the crown-jewel boundary wants, we decided to AMEND ADR-0030's file→model mechanism so an unrecognized-format PDF is text-extracted LOCALLY first — `pdftotext` (poppler) as the deterministic primary, `marker`/`marker_single` as the fallback when pdftotext yields no/low text — and only the extracted TEXT (not the raw binary) is sent to the no-train model for structuring over the existing `text` content-block path, CHUNKED so the structured output never truncates and every finding is captured, aggregated and deduped through the UNCHANGED `keying.is_conformant` / `store.append` sink, AND to capture genetics findings as DURABLE GENOTYPE FACTS in that same Line-Field-Set store (`item` = gene + rsID, `timepoint` = the genome sample date, `source` = `dna-report`, `value` = the alleles) so the read can be refreshed by current science rather than frozen to the report's dated interpretation, to achieve complete dense-document ingestion with strictly LESS egress (the raw binary stays local; only scopeable text crosses the authorized no-train lane), no API PDF size/page limits, and a future-proof fact/interpretation separation, accepting a local poppler/marker provisioning cost, chunking latency + multiple model calls, pdftotext's layout/table loss (mitigated by the marker fallback), and a genetics value that packs the genotype into one Line-Field-Set `value` field.

### Context

ADR-0030 made any-format upload ingestible by routing an unrecognized-format file through the no-train model: the website's router catches the `_detect_source` `SystemExit` for an unmapped extension and calls the injected client over the staged file ([route.py:109-117](../../scripts/serve/route.py) [VERIFIED]), and `_extract_unrecognized` reads the raw bytes, derives a media type, and hands BOTH to `client.extract_readings` ([route.py:143-145](../../scripts/serve/route.py) [VERIFIED]). The backend's pinned file→model mechanism is `_extract_content_block`: for `application/pdf` it base64-encodes the raw PDF into a `document` source block and sends that whole binary to the model ([client.py:303-320](../../scripts/model/client.py) [VERIFIED]); only a text media type takes the lightweight `text` block ([client.py:330-331](../../scripts/model/client.py) [VERIFIED]). ADR-0030 itself recorded `pdftotext` (present, local, mechanistic) and `marker` (installed, heavy) as its rejected zero-egress Alternatives A/B, deferred behind V1 coverage ([ADR-0030 Alternatives A/B](ADR-0030-model-based-universal-ingestion.md) [VERIFIED]).

Two operator-present live-run failures (S99) make the raw-document-block mechanism the wrong default for a dense file. First, the structured-output schema was rooted as a top-level array, which the GA structured-outputs API rejects, so every extract call 400'd and `/upload` degraded to "no new data" — fixed by object-rooting the schema (`{"readings": [...]}`) (commit `0ee9a5d` [VERIFIED], now [client.py:334-360](../../scripts/model/client.py) [VERIFIED]). Second, with the schema fixed, a real multi-page report emits dozens of readings and the JSON array truncated mid-object at `max_tokens=2048` (`stop_reason="max_tokens"`) → `json.loads` failed → fail-closed `ModelCallError` → again "no new data"; the ceiling was raised to `_EXTRACT_MAX_TOKENS = 16384` (commit `e7461ab` [VERIFIED], now [client.py:279](../../scripts/model/client.py) [VERIFIED]). That commit's own note names the residual: a document dense enough to still truncate at 16384 — "a 42-page genetics/SNP report yielding thousands of gene→trait findings, ADR-0030's noted out-of-sweet-spot format" — is a format-fit limit, not a ceiling to keep raising (commit `e7461ab` message [VERIFIED]).

The motivating file is exactly that residual: the operator's real upload is a 42-page genetics/SNP narrative report (~346 KB, 107 rsIDs, genome sample date 2019-12-13) [operator-reported; the file is operator-held PII, not in the repo, so the specific counts are UNVERIFIED against source]. Sent as one raw `document` block it is too large for a single bounded-output call to structure completely. Run through `pdftotext` it yields clean text locally with zero egress ([VERIFIED: poppler 26.02.0 at /opt/homebrew/bin/pdftotext]), and that text can be chunked so each model call's output stays inside the ceiling and ALL findings are captured.

Three forces pull across more than one stakeholder. The operator needs the dense document ingested COMPLETELY — "pull everything … the report is old and new science has come out since then which may update the read" — not a silently-truncated subset. The data subject's crown-jewel containment binds the second force: shipping the whole raw binary to the model is more file content off-device than necessary, where ADR-0001's no-egress boundary governs every file byte that crosses ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]; [ADR-0016 Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). The third force is honest data: a misread genotype is a clinical-safety risk, so the read must rest on the stored FACT (the alleles), re-interpreted by current evidence, not on the report's 2019 interpretation frozen as truth ([ADR-0009 D2](ADR-0009-dashboard-visual-shell-seven-zones.md) [VERIFIED]). Against all three stands the frozen seam ADR-0030 preserved: confirmed readings carry the Line-Field-Set shape (`item`, `timepoint`, `source`, `value`) and land via the single `store.append` sink, deduped by the one key definition ([keying.py:11](../../scripts/store/keying.py), [keying.py:35](../../scripts/store/keying.py), [store.py:134](../../scripts/store/store.py) [VERIFIED]). Because this changes WHERE extraction happens (local vs. model), what crosses the boundary (text vs. raw binary), and how genetics maps into the store — not a code comment beside the router — it is a decision.

### Decision

For an unrecognized-format PDF upload, extract the text LOCALLY before any model call, then send only the extracted TEXT to the no-train model for structuring over the existing `text` content-block path — never the raw `document` block — chunking large text so the structured OUTPUT never truncates and every finding is captured, aggregating and deduping the per-chunk readings through the UNCHANGED `keying.is_conformant` / `store.append` sink. Local extraction is two-tier: `pdftotext` (poppler) is the deterministic primary; `marker` / `marker_single` is the fallback invoked only when `pdftotext` yields no or low text (a scanned / no-text-layer / table-heavy PDF). Both are deterministic local subprocesses making zero network calls. This AMENDS ADR-0030's pinned file→model mechanism ("send the raw uploaded PDF to the no-train model as a base64 `document` content block"): the raw binary now stays on the device, and only scopeable extracted text egresses on the SAME authorized no-train lane (ADR-0016 / ADR-0027). Every other ADR-0030 contract is unchanged — extraction is still operator-confirm-before-land, still bounded to the no-train lane, still retractable to a local model at the ADR-0015 seam, and confirmed readings still land through the unchanged sink.

Additionally, capture genetics findings as DURABLE GENOTYPE FACTS in the existing Line-Field-Set store: `item` = the gene plus rsID (e.g. `MTNR1B rs10830963`), `timepoint` = the genome sample date (e.g. `2019-12-13`), `source` = `dna-report`, `value` = the genotype / alleles (e.g. `(C;G)`) — the durable fact. ALL SNP findings the report states are captured (not a "Noteworthy" subset). The report's dated interpretation is NOT stored as truth; the Genetics specialist re-derives the read from current wiki / `aplus-research` evidence at plan time. This genetics path is the unrecognized-format extract lane (a narrative PDF), distinct from the existing `dna.land` 23andMe genotype-table path (a `.txt` / `.zip` raw table); it does not change `dna.land` ([dna.py:71-105](../../scripts/ingest/dna.py) [VERIFIED]).

### Rationale

Four options were evaluated against four criteria the governing decisions make load-bearing: **completeness** (does a dense document land ALL its findings, not a truncated subset?), **egress posture** (how much file content leaves the device, and which lane?), **coverage** (can it read the document's layouts, including scanned / table-heavy?), and **seam reuse** (does it edit the frozen ingestion engine?).

On **completeness**, only local extraction with chunking lands a dense document whole. A single raw `document` block is bounded by one call's output ceiling — the exact `max_tokens` truncation the S99 run hit (commit `e7461ab` [VERIFIED]); raising the ceiling defers the wall, it does not remove it. Extracting text locally first makes the input chunkable, so each model call's output stays inside `_EXTRACT_MAX_TOKENS` and the per-chunk readings aggregate into the complete set, deduped by the unchanged key ([keying.py:35](../../scripts/store/keying.py) [VERIFIED]). On **egress posture**, sending only extracted text is strictly LESS egress than the raw binary: the raw PDF — which may carry images, embedded metadata, and layout the readings do not need — never leaves the device; only the scopeable text crosses, on the same no-train lane ADR-0016 / ADR-0027 already authorize ([ADR-0016 Decision](ADR-0016-intake-conversation-egress-relaxation.md), [ADR-0027 Decision](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). This is a move TOWARD ADR-0001's crown-jewel ideal, not away from it. It also escapes the API's PDF size / page limits, because the model now sees text, not a base64 document. On **coverage**, `pdftotext` recovers a text-layer PDF deterministically and instantly but loses table layout and recovers nothing from a scanned image; `marker` reconstructs scanned / table-heavy layouts but is a heavy (~GB) local dependency — so the decision uses `pdftotext` as the fast default and triggers `marker` only on the low-text signal, paying the heavy cost only when the cheap path fails. The model still does the structuring step, because a narrative-prose genetics report is not reliably parsed by deterministic rules. On **seam reuse**, the local-extract step is a NEW FRONT STEP at the route seam ([route.py:143-145](../../scripts/serve/route.py) [VERIFIED]), exactly as ADR-0030's extraction was a new front door onto the unchanged sink: the frozen `scripts/ingest/{ingest,adapter}.py`, `scripts/plan/*`, and `scripts/store/keying.py` / `store.append` stay byte-unchanged, so ADR-0003's 0-shared-routine-edit invariant holds ([ADR-0003 Decision](ADR-0003-source-extensible-ingestion-interface.md), [keying.py:11](../../scripts/store/keying.py), [store.py:134](../../scripts/store/store.py) [VERIFIED]).

The genetics genotype-fact model is the honest data-model choice for "pull everything." ADR-0030 noted that a DNA *report* PDF carries the lab's stated interpretations, not the raw genotype table `dna.land` validates ([ADR-0030 Rationale](ADR-0030-model-based-universal-ingestion.md) [VERIFIED]) — but the report DOES state the genotype per rsID (the alleles), and the allele call is the durable fact; the interpretation is the dated, refreshable read. Storing the fact (`item` = gene + rsID, `value` = alleles, `timepoint` = sample date, `source` = `dna-report`) and re-deriving the read at plan time means new science updates the operator's genetics read without re-ingesting the report — the fact/interpretation separation. It maps genetics INTO the existing Line-Field-Set store rather than forking a second data model, honoring the single-sink invariant; the cost (a genotype packed into one `value`, since genetics is not time-series) is owned in Consequences.

### Consequences

**Positive:**
- DNA / genetics ingestion works as a core feature: the operator's dense genetics report lands ALL its genotype findings instead of degrading to "no new data," because local extraction + chunking removes the single-call output ceiling that truncated it (commit `e7461ab` [VERIFIED]).
- Strictly less egress: the raw PDF binary never leaves the device; only the extracted, scopeable text crosses the no-train lane — a move toward ADR-0001's crown-jewel ideal, not a new relaxation ([ADR-0001 Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- No API PDF size / page limits: the model receives text, so a 42-page document is ingestible where a base64 `document` block of it was not.
- Completeness via chunking: per-chunk readings aggregate and dedupe through the unchanged `keying.is_conformant` / `store.append` sink, so a dense document lands its full reading set ([keying.py:35](../../scripts/store/keying.py), [store.py:134](../../scripts/store/store.py) [VERIFIED]).
- Fact/interpretation separation future-proofs against stale science: the stored genotype fact is re-interpreted by current evidence at plan time, so a 2019 report's read refreshes without re-ingestion.
- New front step, 0 engine edit: the frozen `scripts/ingest/{ingest,adapter}.py`, `scripts/plan/*`, and `scripts/store/keying.py` / `store.append` are byte-unchanged, so ADR-0003's 0-shared-routine-edit invariant holds and genetics readings land via the unchanged sink ([ADR-0003 Decision](ADR-0003-source-extensible-ingestion-interface.md) [VERIFIED]).

**Negative:**
- A local poppler / marker dependency to provision: the clone now needs `pdftotext` (poppler) present, and `marker` (~GB) for the fallback — a clonability cost the pure-model-document path did not carry ([VERIFIED: /opt/homebrew/bin/pdftotext, ~/.local/bin/marker_single]). A clone without them cannot run the local-extract path.
- Chunking adds latency and multiple model calls: a dense document is now several bounded `extract_readings` calls instead of one, each on the no-train lane — more wall-clock and more metered spend per upload than a single (truncating) call.
- `pdftotext` loses layout and tables: a table-heavy or columnar PDF can extract as garbled text, mitigated by the `marker` fallback but only when the low-text trigger fires — and `marker` is the heavy (~GB) dependency, slower to run.
- The genetics value packs the genotype into one Line-Field-Set `value` field: genetics is not time-series, so a single `value` (alleles) at a single `timepoint` (sample date) is a mapping compromise, not a natural fit for the store's reading shape — accepted to keep the single sink.
- The `marker` fallback's ~GB weight is paid whenever a scanned / no-text-layer / table-heavy PDF triggers it — a real runtime and disk cost when the cheap path cannot read the document.

**Neutral:**
- The no-train lane now carries extracted TEXT for novel-format ingestion where ADR-0030 carried a raw `document` block — the same lane, a smaller and more scopeable payload, so the ADR-0016 / ADR-0027 egress bound is preserved, not widened ([ADR-0016 Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).
- The existing `dna.land` 23andMe genotype-table path is untouched; the genetics-report path is the unrecognized-format extract lane, a sibling, not a replacement ([dna.py:71-105](../../scripts/ingest/dna.py) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Status quo — raw PDF as a model `document` block (ADR-0030's pinned mechanism)
Keep sending the unrecognized-format PDF to the no-train model as a base64 `document` content block ([client.py:303-320](../../scripts/model/client.py) [VERIFIED]).
- **Supporting evidence:** Zero local extraction dependency, one model call, and the model sees the document's full visual content (images, layout) the text-only path drops — the maximally capable input for an arbitrary layout [VENDOR-CLAIM: model document-extraction capability].
- **Trade-offs:** No control over completeness — a dense document's structured OUTPUT truncates against a single call's `max_tokens` ceiling, the exact `stop_reason="max_tokens"` → "no new data" failure the S99 run hit on the genetics report (commit `e7461ab` [VERIFIED]); raising the ceiling defers the wall but does not remove it. It also ships the whole raw binary off-device (more egress than the readings need) and is bound by the API's PDF size / page limits. Rejected because it cannot land a dense document completely and egresses more than necessary.
- **When this becomes the right choice:** For a small, single-page, image-heavy PDF whose layout the model must SEE and whose readings fit one bounded call — the document block is the simpler path there, and remains available as a media-type branch.

#### Alternative B: Local `pdftotext` → text → model-structure, chunked (Chosen)
Extract the text locally with `pdftotext`, chunk it so each model call's output stays inside `_EXTRACT_MAX_TOKENS`, send only text to the model for structuring, and aggregate + dedupe the per-chunk readings through the unchanged sink.
- **Supporting evidence:** Zero raw-binary egress (only scopeable text crosses); chunkable, so a dense document lands ALL findings with no truncation; no API PDF size / page limits; reuses the existing `text` content-block path ([client.py:330-331](../../scripts/model/client.py) [VERIFIED]) and the unchanged sink. `pdftotext` is present and deterministic ([VERIFIED: poppler 26.02.0 at /opt/homebrew/bin/pdftotext]).
- **Trade-offs:** A local poppler dependency to provision (already present, [VERIFIED]); chunking adds latency + multiple metered calls; `pdftotext` loses table / column layout (mitigated by the Alternative-C fallback). Accepted because completeness on dense documents + reduced egress dominate for the operator's real files.
- **When this becomes the right choice:** It is, for V1, for any text-layer PDF — the common case (lab panels, narrative reports, the genetics report).

#### Alternative C: Local `marker` / `marker_single` → markdown → model-structure
Run the heavy local document model (`marker`, installed at `~/.local/bin/marker_single`) to reconstruct the PDF as markdown, then send that to the model to structure.
- **Supporting evidence:** Reconstructs scanned, columnar, and table-heavy layouts `pdftotext` mangles or cannot read, still zero raw-binary egress, and is installed locally ([VERIFIED: ~/.local/bin/marker_single → marker-pdf]).
- **Trade-offs:** Heavy (~GB) and slow relative to `pdftotext`, so making it the DEFAULT pays that cost on every upload including the common text-layer case. Rejected as the default; ADOPTED as the FALLBACK invoked only when `pdftotext` yields no / low text (the low-text trigger), so the heavy cost is paid only when the cheap path fails.
- **When this becomes the right choice:** Whenever `pdftotext` yields no or low text — a scanned, image-only, or table-heavy PDF — which is precisely the fallback condition.

#### Alternative D: Fully deterministic parse, no model
Parse the extracted text into Line-Field-Set readings with deterministic rules (regex / table parsers), no model call at all.
- **Supporting evidence:** Zero egress on the structuring step too (nothing leaves the device beyond local extraction), zero per-call cost, no network dependency — the strongest privacy posture, and the same family as the existing deterministic adapters and `dna.land`'s shape-validator ([dna.py:30-46](../../scripts/ingest/dna.py) [VERIFIED]).
- **Trade-offs:** Brittle on narrative-prose genetics reports — a 42-page free-text report stating genotypes inline across varied phrasing is exactly what deterministic rules cannot reliably structure; it reproduces the keyword-bucketer lossiness the model step exists to overcome. Rejected because the model is needed to structure free-form findings; the deterministic step is retained only as the LOCAL TEXT EXTRACTION (Alternatives B/C), not as the structuring step.
- **When this becomes the right choice:** For a rigidly-structured tabular export (already covered by the deterministic adapters / `dna.land`), or if a future privacy constraint forbids ANY text egress — then the deterministic structuring is restored as the sole path at the cost of free-form coverage.

#### Dissent: The file-content-never-egresses purist position (inherited from ADR-0001 / 0016 / 0027)
**Source:** ADR-0001's crown-jewel anchor and ADR-0027's recorded summaries-not-raw dissent ([ADR-0001 Y-Statement](ADR-0001-pii-trust-boundary-no-train-routing.md), [ADR-0027 Dissent](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). A purist holds that ANY file content crossing to a model — even extracted text — is a privacy cost, and that Alternative D (deterministic structuring, zero text egress) is the correct posture even at the cost of free-form coverage. This ADR moves TOWARD that position (the raw binary no longer egresses), but does not reach it: the structuring step still sends text.
**Conditions under which this becomes the right choice:** If the no-train provider's no-train / retention terms degrade (extracted text becoming training-eligible or indefinitely retained), OR if deterministic structuring plus a local model (Alternatives C/D) cover the operator's real document shapes — then the text egress should be retracted (the backend swapped at the ADR-0015 seam, or the structuring made deterministic) and the zero-egress path restored.

### Validation Approach

**Confirmation criteria:**
- Local-extraction-first is testable at 0 live spend: a fixture PDF runs through `pdftotext` (and the `marker` fallback on a low-text fixture) and the model-structuring step is mock-tested with an injected backend returning canned readings — the test asserts (a) the model receives the `text` content block, never a raw `document` block, and (b) each extracted reading carries the full Line-Field-Set ([client.py:330-331](../../scripts/model/client.py), [keying.py:11](../../scripts/store/keying.py) [VERIFIED]).
- Chunk-and-aggregate is complete: a large fixture text chunked into N parts yields the UNION of all parts' readings, deduped by the unchanged key — expected: 0 findings dropped across chunk boundaries, 0 duplicates from overlap ([keying.py:35](../../scripts/store/keying.py) [VERIFIED]).
- Genetics genotype-fact mapping: a fixture genetics report yields readings with `item` = gene+rsID, `timepoint` = the sample date, `source` = `dna-report`, `value` = the alleles — expected: the durable genotype fact stored, the report's interpretation NOT stored as a reading.
- New front step, 0 engine edit: a structural diff confirms `scripts/ingest/{ingest,adapter}.py`, `scripts/plan/*`, and `scripts/store/keying.py` / `store.append` are byte-unchanged — expected: `git diff --numstat` = 0 on the frozen set ([ADR-0003 Decision](ADR-0003-source-extensible-ingestion-interface.md) [VERIFIED]).

**Falsification criteria (quantitative; the crown-jewel probe is load-bearing):**
- Raw-binary-egress probe (the crown-jewel test): seed a known token into an uploaded PDF, run the ingestion path under the OS-level egress guard. Threshold: **0 raw-binary bytes egress to ANY endpoint (including the no-train lane — the lane receives extracted TEXT only), AND 0 text bytes to any non-no-train endpoint**; any raw PDF byte leaving the device, or any extracted text on a non-no-train lane, reds the boundary → halt and repair before release.
- Local-extractor-network probe: run `pdftotext` and the `marker` fallback under the egress guard. Threshold: **0 network calls from the local extractor**; ≥1 outbound connection from the extraction subprocess reds the boundary → halt and repair before release.
- Extend-not-rebuild: diff the frozen set after the change. Threshold: **`git diff --numstat` = 0 on `scripts/ingest/{ingest,adapter}.py` + `scripts/plan/*` + `scripts/store/keying.py`** (and 0 edits to `store.append`); ≥1 changed line on the frozen set means the front step leaked into the engine → repair the seam before release.
- Completeness / no-silent-truncation: extract a document too large for one bounded call and assert the chunk-aggregate path captures every finding; inject a document so large even chunking cannot complete and assert an HONEST partial / too-large signal reaches the operator. Threshold: **0 findings silently dropped with no operator-visible signal**; ≥1 truncated extraction that lands a silent subset (the exact prior "no new data" failure) is a breach → halt and restore the honest-partial signal before release.
- Confirm-gate probe (inherited from ADR-0030): run extraction and scan the store before the operator confirms. Threshold: **0 model-extracted readings land in the store without an operator-confirm step**; ≥1 unconfirmed reading is a breach → restore the confirm gate before release.
- Key-never-committed scan: grep every tracked file and git history on a fresh clone for the API-key value. Threshold: **0 API-key hits**; ≥1 is release-blocking.
- Time horizon: run the raw-binary-egress probe, the local-extractor-network probe, the extend-not-rebuild diff, the completeness check, the confirm-gate probe, and the key scan at the first build of the local-extract route, at the operator-present LIVE run, and at every release thereafter, and before the July-2026 physician-visit deliverable.

**Review triggers:**
- A change to the no-train provider's no-train or retention terms — re-verify the text-egress class this decision carries.
- A local structuring model reaching parity on the operator's document shapes — swap the backend (Dissent / Alternative D direction); the text egress retracts to zero at the ADR-0015 seam.
- A change to the `store.append` / Line-Field-Set sink or the ADR-0013 upload front door — re-confirm the local-extract front step still routes without editing the frozen engine.
- A genetics report whose layout `pdftotext` mangles and `marker` cannot reconstruct — re-evaluate the extraction-tier strategy and the low-text trigger threshold.
