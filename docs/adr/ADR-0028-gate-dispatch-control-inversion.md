## ADR-0028: Gate-Dispatch Control-Inversion — Completing the A′ Subscription Driver

> **Y-Statement:** In the context of the S93 A′ driver `plan_driver.drive`, which control-inverts only the author dispatch while the GATE (in `drive`'s frame, [plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]) and the `reauthor`/`adjudicator` hooks (DEEP INSIDE the byte-frozen `orchestrate.generate_plans`, [orchestrate.py:550,578,595,613](../../scripts/plan/orchestrate.py) [VERIFIED]) stay synchronous callables the `/generate-plan` skill cannot fulfil with the Agent tool — leaving the live A′ run non-executable under the operator's API-PII-only / subscription-everything-else split — we decided to invert the remaining classes by TWO mechanisms keyed to call-stack position: AUTHOR and GATE by DIRECT YIELD; REAUTHOR/ADJUDICATOR (which cannot yield without editing the frozen engine) by THROW/REPLAY-MEMO — consumer-supplied memo-cache callables raise a `BaseException` sentinel on a cache-miss, unwinding to `drive`, which yields the typed request and re-drives the pass over a fresh scratch store with the fulfilled envelope cached — so the consumer fulfils every dispatch with a subscription agent while `compose_gate_dispatch` + `drive` keep the disposition composition + fail-closed `safety_passed is True` loop in ONE definition, to achieve an executable live subscription run with no metered backend and no forked safety loop, accepting a tagged-union protocol the consumer handles exhaustively, a NEW value-scan over the derived GATE/ADJUDICATOR payloads, and a path mock-tested only until the S94 operator-present attestation.

### Context

ADR-0026 selected the A′ driver model and the S93 build landed it: `plan_driver.drive` is a control-inversion generator-coroutine, `compose_gate_dispatch` composes the quality + safety gates into the fixed 3-key disposition, and `run_orchestrated` drives the generator. But the inversion is PARTIAL, and the remaining dispatches split into TWO call-stack positions that determine how each can invert:

- **In `drive`'s own frame.** `drive` yields exactly ONE request shape — the author-request `(tuple(domains), summary, gates)` ([plan_driver.py:122](../../scripts/plan/plan_driver.py) [VERIFIED], re-yielded for the revise pass at [plan_driver.py:162](../../scripts/plan/plan_driver.py) [VERIFIED]) — and the consumer reads back `{domain: envelope}` author fragments ([plan_orchestrator.py:251-258](../../scripts/plan/plan_orchestrator.py) [VERIFIED]). The GATE is then called synchronously in `drive`'s OWN frame, AFTER `run_generation` returns: `_safe_gate(gate_dispatch, result)` ([plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]), where `gate_dispatch` calls `_quality_judge(assembled_plan, judge_client)` + `_review(assembled_plan, review_dispatch, lenses=...)` ([gate_dispatch.py:133-135](../../scripts/plan/gate_dispatch.py) [VERIFIED]). Both AUTHOR and GATE are at the driver frame.
- **DEEP INSIDE the byte-frozen inner engine.** The `reauthor`/`adjudicator` hooks are threaded verbatim into `pipeline.run_generation` ([plan_driver.py:125-127,165-168](../../scripts/plan/plan_driver.py) [VERIFIED]) and `generate_plans` ([pipeline.py:60-63](../../scripts/plan/pipeline.py) [VERIFIED]), then invoked from inside `orchestrate.generate_plans`: `reauthor("workout", {"sustainable_training_kcal": ceiling})` on an energy bounce ([orchestrate.py:550](../../scripts/plan/orchestrate.py) [VERIFIED]) and `adjudicator(safety_finding)` via `_adjudicate_with_band` at the additive-AE, conflict, and Rx-BPMH held-finding sites ([orchestrate.py:329,578,595,613](../../scripts/plan/orchestrate.py) [VERIFIED]). These fire NESTED below `drive` → `run_generation` → `generate_plans`, NOT at the driver frame.

This split is the crux: a dispatch at the driver frame can become a direct yield, but a dispatch nested inside `generate_plans` cannot — turning `generate_plans` into a generator would edit the byte-frozen engine, which is forbidden.

Two forces pull against each other. The operator's binding runtime split is "API for the PII de-id call ONLY, subscription for everything else" (ADR-0026 Decision; the no-train de-id backend is the one metered egress, [ADR-0027, Decision](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). Under that split the judge, the safety lenses, the energy-bounce re-author, and the medical-liaison adjudication must run as SUBSCRIPTION agents — dispatched via the Agent tool, which only the `/generate-plan` skill-orchestrator holds, never a Python function. Against that stands the built seam shape: a Python callable cannot synchronously spawn a subscription Task agent and pull its reasoning back into a return value (the same impossibility ADR-0026 named for the author seam, [ADR-0026, Context](ADR-0026-v1-subscription-runtime-driver.md) [VERIFIED]). So the gate/judge/lens/reauthor/adjudicator dispatches are, today, only fulfillable by a Python backend — and no such backend exists: `ModelClient` exposes `converse`/`author`/`deidentify` and no `.judge` or `.review` ([client.py:33-95](../../scripts/model/client.py) [VERIFIED]), and `author`/`converse` are `NotImplementedError` stubs ([client.py:203-211](../../scripts/model/client.py) [VERIFIED]); `deidentify` alone is live ([client.py:213-250](../../scripts/model/client.py) [VERIFIED]). The only production code that constructs `compose_gate_dispatch` or calls `run_orchestrated` is the fixture-only `_a_prime_self_test.py` ([_a_prime_self_test.py:234,273,299](../../scripts/plan/_a_prime_self_test.py) [VERIFIED]).

The consequence affects the data subject, not only the operator. The `/generate-plan` skill PROSE already CLAIMS it dispatches each safety lens "as a SUBSCRIPTION agent" and supplies `reauthor`/`adjudicator` as "live subscription dispatches" ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED]) — but the seams those values feed (`gate_dispatch=`, and the hooks threaded into `run_generation`) are synchronous Python callables the skill cannot fulfill with an Agent-tool dispatch. A 0-spend dry-run surfaces the gap: de-id runs (live backend present), the author yield is fulfillable, then the driver reaches `_safe_gate` and there is no Python `gate_dispatch` to call (no judge/lens backend) and no inverted yield to hand the skill. This is the PF-S87-01 "plumbing wired, end-to-end capability not" pattern — the `core-capability-audit` proves the deterministic spine but the live subscription dispatch of the gate/hooks was never built, only deferred as the S94 operator-present attestation. The decision must clear: invert the REMAINING dispatch classes so the skill can fulfil them with subscription agents, WITHOUT moving the disposition composition or the fail-closed loop out of their single definition (the no-fork crown jewel ADR-0026 bought), WITHOUT editing the byte-frozen inner engine, and keeping `run_orchestrated` + the full test suite green.

### Decision

Extend `plan_driver.drive`'s yield protocol from the bare author-tuple to a DISCRIMINATED-UNION of typed dispatch-requests, one per agent-dispatch CLASS: AUTHOR (the existing author fan-out / revise re-author), GATE (the assembled plan plus the judge and safety-lens roster to dispatch), REAUTHOR (the energy-bounce second-personal-trainer request), and ADJUDICATOR (the held-finding medical-liaison request). The consumer fulfils each yielded request — dispatching a subscription agent (skill mode) or calling a programmatic callable (`run_orchestrated`/test mode) — and `.send()`s the RAW result back; the driver composes the disposition (via `compose_gate_dispatch`) and runs the fail-closed `safety_passed is True` revise loop, both kept in their existing single definition.

The four classes invert by TWO mechanisms, chosen by WHERE in the call stack each fires:

- **AUTHOR and GATE invert by DIRECT YIELD.** Both fire in `drive`'s own frame (AUTHOR before `run_generation`, GATE after it returns), so `drive` simply yields the typed request and resumes on `.send()`. The GATE — today the synchronous `_safe_gate(gate_dispatch, result)` ([plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]) — becomes a yielded GATE request carrying the assembled plan + the judge + the lens roster; the consumer dispatches the judge and each lens and `.send()`s the RAW verdicts back, and the driver still calls `compose_gate_dispatch` to map them into the 3-key disposition and applies the fail-closed `safety_passed is True` gate ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py), [plan_driver.py:133](../../scripts/plan/plan_driver.py) [VERIFIED]). Composition stays in ONE place.

- **REAUTHOR and ADJUDICATOR invert by THROW/REPLAY-MEMOIZATION.** Both fire DEEP INSIDE `orchestrate.generate_plans` ([orchestrate.py:550,578,595,613](../../scripts/plan/orchestrate.py) [VERIFIED]); they CANNOT become direct yields without turning `generate_plans` into a generator — i.e. editing the byte-frozen engine, forbidden. Instead the consumer supplies `reauthor`/`adjudicator` callables backed by a MEMO CACHE keyed by the call's identity — `reauthor:(domain, constraint)` (e.g. `("workout", {"sustainable_training_kcal": ceiling})`, [orchestrate.py:550](../../scripts/plan/orchestrate.py) [VERIFIED]); `adjudicator:(held-domain, hold-class, finding_id)` (the `finding_id` distilled at each held site, [orchestrate.py:222,255,301](../../scripts/plan/orchestrate.py) [VERIFIED]). On a cache HIT the callable returns the cached envelope and the inner engine proceeds UNCHANGED. On a cache MISS the callable raises a sentinel that is a **`BaseException` subclass — NOT `Exception`**, so it cannot be confused with or swallowed by the engine's narrow domain catch (`except ModelCallError`, [generate_plan.py:363](../../scripts/plan/generate_plan.py) [VERIFIED]) and is robust against ANY future broad `except Exception` were one added. The inner engine TODAY has NO broad `except Exception` (verified: zero across the 8 byte-frozen modules; the only catches are the narrow `except ModelCallError` and a CLI-path `except (OSError, ValueError)`), so a plain `Exception` subclass would also unwind cleanly — `BaseException` removes the dependency on that fact staying true. It unwinds cleanly to `drive`. `drive` catches the sentinel, YIELDS the corresponding REAUTHOR or ADJUDICATOR request, receives the fulfilled envelope on `.send()`, stores it in the memo cache, and RE-DRIVES the pass from the top over a FRESH scratch store. Because the inner engine is a deterministic pure function of (authors, summary, gates, cached-hook-responses), each replay reproduces the same calls up to the next cache-miss, advancing exactly one dispatch per round until no miss remains and the pass completes. The engine stays BYTE-FROZEN (numstat=0): it still only calls plain callables — the memo/replay logic lives entirely in the consumer + `drive`.

This asymmetry — direct-yield for AUTHOR/GATE, throw/replay-memo for REAUTHOR/ADJUDICATOR — is the honest consequence of the frozen-engine constraint, not a flaw: the only inversion of a deeply-nested hook that does NOT edit the engine is a throw-and-replay over a pure function.

ADJUDICATOR is yielded ONCE PER HELD DOMAIN PER PASS, not once per pass: a single `generate_plans` call invokes the adjudicator independently at the additive-AE-held supplement ([orchestrate.py:578](../../scripts/plan/orchestrate.py) [VERIFIED]), each conflict-held domain ([orchestrate.py:595](../../scripts/plan/orchestrate.py) [VERIFIED]), and each Rx-BPMH-held domain ([orchestrate.py:613](../../scripts/plan/orchestrate.py) [VERIFIED]) — a single pass can fire 3+. Each is independently memo-keyed (by held-domain + hold-class + finding_id), independently charged on its own cache-miss, and independently fail-closed. The yield protocol therefore models a SEQUENCE of ADJUDICATOR requests across the replay rounds of one pass, not a single one.

One driver, three layers (the driver `drive`; the programmatic consumer `run_orchestrated`; the skill consumer, realized via the step-harness `plan_step.py`), no fork; the byte-frozen inner engine stays byte-frozen.

### Rationale

The extension was evaluated across the four criteria ADR-0026 made load-bearing — **no-fork fidelity** (the disposition composition + the fail-closed loop in one definition), **subscription-vs-metered cost** under the operator's split, **executability of the live A′ run**, and **buildability under extend-not-rebuild** — against the chosen tagged-union inversion, Alternative B (build API judge/lens/author backends), Alternative C (hybrid), and Alternative D (keep the synchronous gate).

On **executability** the chosen option is decisive and the others split. The gate/judge/lens/reauthor/adjudicator are agent dispatches, and only the skill holds the Agent tool; a synchronous Python `gate_dispatch` (Alternative D) is unfulfillable by the skill, so the live run halts at `_safe_gate` ([plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]) — the run is non-executable, which is the present state. Inverting the remaining classes makes every agent-touching dispatch a yield the skill can fulfil with a subscription agent, mirroring the author seam that already works ([plan_orchestrator.py:251-258](../../scripts/plan/plan_orchestrator.py) [VERIFIED]).

On **no-fork fidelity** the resolution of OQ-2 is the crux: the GATE yield carries the RAW INPUTS (the assembled plan + the judge + the lens roster); the consumer dispatches the judge and each lens and returns the RAW verdicts; the driver hands those to `compose_gate_dispatch`, which keeps the `accept`/`safety_passed`/`revise_domains` mapping AND the fail-closed `safety_passed is True` default in its one definition ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py) [VERIFIED]). The alternative — the consumer composes the disposition and `.send()`s the finished 3-key dict — would move the `safety_passed` surface logic into the agent-driven skill consumer, re-creating exactly the forked-safety-loop failure class ADR-0026 rejected (a skill-prose copy of "a non-True disposition surfaces 0 plans" that can drift, [ADR-0026, Alternative A-naive](ADR-0026-v1-subscription-runtime-driver.md) [VERIFIED]). So the inversion deliberately stops at the RAW inputs/results boundary; composition stays in code.

On **cost**, the chosen option keeps every agent dispatch on the subscription session (the judge, lenses, reauthor, adjudicator are subscription agents; the de-id call is the one metered egress, [ADR-0027, Consequences](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]), matching the operator split. Alternative B (build API judge/lens/author backends) is rejected on this axis: it routes non-PII work through the metered API, contradicting "subscription for everything else" and paying per-token for every judge/lens/reauthor/adjudicate dispatch the revise loop multiplies. On **buildability**, the change is confined to `plan_driver.py` (the yield protocol, the per-class request handling, the BaseException-sentinel catch + memo cache + fresh-scratch replay for the throw/replay classes), `plan_orchestrator.py` (the consumer drive loop gains a per-class fulfilment switch + the memo-cache-backed `reauthor`/`adjudicator` callables; the existing programmatic callables stay the test-mode fulfilment), the step-harness (`plan_step.py`, the skill's per-round drive mechanism), and tests; `gate_dispatch.py` MAY change only at the boundary where it now receives raw verdicts instead of bound clients. The inner engine (`pipeline`/`orchestrate`/`assemble`/`generate_plan`/`adjudicate`/`adjust`/`track`/`router`) stays byte-frozen (numstat=0) — OQ-4 — because the memo-cache callable preserves the engine's plain-callable contract: `generate_plans` still calls `reauthor(...)`/`adjudicator(...)` exactly as today, oblivious to whether the call hits the cache or unwinds. Critically, the adjudication-RELEASE decision (the `outcome == "cleared"` test + the CRITICAL/H1-H2 non-overridable auto-block) stays where it is — composed by the inner engine's `adjudicate` over the consumer-returned raw liaison envelope ([orchestrate.py:579,597,615](../../scripts/plan/orchestrate.py) [VERIFIED]) — and is NOT re-derived in the consumer or the harness. The consumer returns only the raw envelope; the engine composes the release. Long-term, the cost the decision accepts permanently for V1 is a richer driver protocol (a tagged union the consumer must exhaustively handle, plus the replay machinery) that the future all-API cutover retires only partway — the all-API path still drives the same union, just fulfilling each yield with a programmatic backend rather than an agent.

### Consequences

**Positive:**
- The live A′ run becomes genuinely executable end-to-end on the subscription session: every agent-touching dispatch (author, judge, each lens, reauthor, adjudicator) is a yield the skill fulfils with a subscription agent, so `/generate-plan` can drive de-id → author → gate → revise → promote without a synchronous Python gate it cannot satisfy ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED] is then truthful, not aspirational).
- The disposition composition + the fail-closed `safety_passed is True` loop stay in EXACTLY ONE definition (`compose_gate_dispatch` + `plan_driver.drive`); the GATE yield carries raw inputs/results and the driver composes — verifiable as 0 second composition sites by grep ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py) [VERIFIED]). The no-fork crown jewel ADR-0026 bought is preserved across the wider inversion.
- Subscription-cost posture is honored unchanged: no judge/lens/author API backend is built, so the only metered egress stays the single ADR-0027 de-id call per plan-gen.

**Negative:**
- The yield protocol becomes a DISCRIMINATED UNION the consumer must handle EXHAUSTIVELY: both consumers (the skill, via the step-harness, and `run_orchestrated`) gain a per-class fulfilment switch, and a consumer that mis-handles or omits a request kind is a new failure surface the bare author-tuple did not have. The fail-closed mitigation (OQ-3) — every malformed/absent/raised `.send()`-back fails closed, in one of the two distinct shapes below — bounds the blast radius but does not erase the added protocol complexity, a permanent (1+ year) cost the all-API cutover does not remove.
- **The PII value-scan over the GATE/ADJUDICATOR payloads is NEW, not restored.** The AUTHOR-seam 0-raw-PII property is STRUCTURAL: the orchestrator only ever holds the de-identified summary ([plan_orchestrator.py:101-124](../../scripts/plan/plan_orchestrator.py) [VERIFIED]) and there is NO value-scan on the author seam — the seam is clean by construction. The GATE yield carries the ASSEMBLED PLAN and the ADJUDICATOR yield carries a safety finding; both are DERIVED artifacts whose PII-freeness is transitive-but-unverified (they are built from the de-identified summary, but nothing asserts that derivation introduced no operator value). So they require a NEW value-scan — the FIRST one ever over those payloads — before the dispatch leaves the process. This ADDS a scan to a previously-unscanned surface; it does not "restore" one. The REAUTHOR constraint (`{sustainable_training_kcal: ...}`) is a numeric ceiling and structurally PII-free, but is covered by the same new scan for completeness.
- The skill cannot drive a live Python generator directly (a generator cannot pause for the orchestrator's Agent tool, OQ-5): a thin step-harness (`plan_step.py`) IS the skill consumer's drive mechanism (skill → harness → driver), persisting/resuming the driver across Agent-tool round-trips — a new runnable artifact with its own correctness burden (resumable state, idempotent replay). The replay is safe ONLY because (a) each replay round runs against a FRESH scratch store (no accumulated `plan::`/`dvq::` writes — the driver already opens a per-pass scratch at [plan_driver.py:123,164](../../scripts/plan/plan_driver.py) [VERIFIED]), so re-running the engine cannot double-write the promoted store; and (b) the dispatch budget charges ONLY on a cache-MISS (a newly-issued dispatch), never on a replayed cache-HIT — the budget instrumentation moves to the consumer's fulfilment point (where `_charging` wraps the hooks today, [plan_orchestrator.py:212-214](../../scripts/plan/plan_orchestrator.py) [VERIFIED]), so a replay that re-traverses N cached hooks charges 0 for them and only the one new miss.

**Neutral:**
- `compose_gate_dispatch`'s signature shifts from bound clients (`judge_client`, `review_dispatch`) toward receiving raw verdicts at composition time; its internal mapping + fail-closed default are unchanged, only its input boundary moves (a follow-on adapter shape, not a behavior change).
- A second instance of the typed-request driver pattern joins the project alongside the build pipeline's execute-plan orchestrator — the same control shape, widened from one request kind to four.

### Alternatives Considered

#### Alternative A: Discriminated-union yield protocol, driver composes (Chosen)
`drive` yields a tagged request per dispatch class: AUTHOR/GATE by direct yield (driver frame), REAUTHOR/ADJUDICATOR by throw/replay-memo (frozen-engine frame). The consumer fulfils each with a subscription agent (skill) or a programmatic callable (`run_orchestrated`) and `.send()`s the raw result back; the driver + `compose_gate_dispatch` retain the disposition composition + the fail-closed loop.
- **Supporting evidence:** The only option that makes the live A′ run executable on the subscription session (no metered backend) while keeping the disposition composition + `safety_passed is True` loop in one definition ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py) [VERIFIED]) and the inner engine byte-frozen — the throw/replay-memo mechanism is what inverts the deeply-nested hooks without editing `generate_plans`.
- **Trade-offs:** A tagged-union protocol the consumer handles exhaustively (Negative-1) plus the replay machinery; a NEW value-scan over the derived GATE/ADJUDICATOR payloads (Negative-2); a step-harness for the live skill drive (Negative-3, OQ-5). Accepted because it is the only option that makes the live run executable while preserving the no-fork loop under the operator's subscription split.
- **When this becomes the right choice:** It is, for V1, when the gate/judge/lens/reauthor/adjudicator must run as subscription agents, the inner engine is byte-frozen, and the safety loop must stay one definition.

#### Alternative B: Build API judge/lens/author backends on `ModelClient`
Add `.judge`/`.review`/live-`author` backends to `ModelClient` so `gate_dispatch`, the lenses, and the author dispatch all run as synchronous API calls from Python — the driver stays as-is, fulfilling the existing synchronous seams with metered model calls.
- **Supporting evidence:** Genuinely viable and the smallest driver change — the yield protocol is untouched, the existing `gate_dispatch`/hook seams are filled by Python backends, and the driver loop runs entirely in-process (no step-harness, no tagged union). The model boundary (ADR-0015) already anticipates additional backend methods alongside `converse`/`author`/`deidentify`.
- **Trade-offs:** Routes all non-PII work (judge, lenses, reauthor, adjudicator, author) through the METERED API, directly contradicting the operator's "API for PII-only, subscription for everything else" split and paying per-token for every dispatch the revise loop multiplies (N specialists × revise iterations + judge + M lenses + adjudications). It is the future all-API path, not the V1 subscription path — adopting it now inverts the operator's deliberate cost posture.
- **When this becomes the right choice:** When the runtime moves to all-API (or a local model): every dispatch class becomes a programmatic backend call, the union is fulfilled in-process, and `run_orchestrated` becomes the single live driver — the ADR-0015 cutover, the V1-rejected/future-adopted form.

#### Alternative C: Hybrid — invert only the GATE class, keep reauthor/adjudicator synchronous
Invert only the GATE yield (the judge + lenses, the highest-volume agent dispatch) and leave `reauthor`/`adjudicator` as synchronous Python hooks fulfilled by small API or local backends.
- **Supporting evidence:** Smaller protocol surface than the full union — only one new request kind — while still removing the largest metered cost (the per-revise judge/lens fan-out) from the API. The reauthor/adjudicator hooks fire less often (only on an energy-bounce or a held finding), so their residual API cost is bounded.
- **Trade-offs:** Splits the dispatch model along an arbitrary line: `reauthor` is a second personal-trainer dispatch and `adjudicator` is a medical-liaison dispatch — both are exactly the "specialist/safety agent over the summary" class the operator put on subscription, so leaving them metered re-introduces the split-violation Alternative B has, just smaller. It also keeps two fulfilment mechanisms (yield-driven for GATE, synchronous-backend for the hooks), so the consumer still needs a Python backend that does not exist, and the live run is still not executable for a plan that triggers an energy bounce or a held finding. A partial inversion that leaves the live run conditionally non-executable is not a stable V1 state.
- **When this becomes the right choice:** If measurement later shows the reauthor/adjudicator dispatches are rare AND a cheap local model reaches parity for them, pinning those two to a local backend while the GATE stays subscription-yielded would cut protocol surface at no cost-posture violation.

#### Alternative D: Keep the synchronous gate; accept the skill cannot run it
Leave `drive`'s yield protocol at the bare author-tuple and the gate/hooks as synchronous Python callables; the live A′ run remains a documented future capability, fulfilled only when API backends exist.
- **Supporting evidence:** Zero code change — the S93 build, the self-test, and the full test suite stay exactly as-is; the deterministic spine is proven by `core-capability-audit` and the fixture self-test.
- **Trade-offs:** The live A′ run is NON-EXECUTABLE: the skill cannot fulfil the synchronous `gate_dispatch`/hook seams with an Agent-tool dispatch, and no Python judge/lens backend exists ([client.py:203-211](../../scripts/model/client.py) [VERIFIED]; only `_a_prime_self_test.py` composes the gate, [_a_prime_self_test.py:234](../../scripts/plan/_a_prime_self_test.py) [VERIFIED]). The skill prose claiming live subscription dispatch ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED]) stays untrue, and the core capability — a followable plan generated end-to-end — does not work (the exact PF-S63-02 / PF-S87-01 gap this ADR exists to close). Rejected because "the components each pass their own tests" while the end-to-end run cannot execute is the drift the project's mandates forbid.
- **When this becomes the right choice:** If V1 abandons live subscription generation entirely and ships only the fixture/self-test deterministic spine as a demonstrator — a scope the operator has not chosen.

### Validation Approach

**Confirmation criteria:**
- **Typed-request ordering (fixture run):** a 4-domain fixture run yields the typed requests in the right order and count — exactly 1 AUTHOR request first, then 1 GATE request per generated pass, with REAUTHOR yielded (via the throw/replay round) iff an energy-bounce fires and an ADJUDICATOR request yielded ONCE PER HELD DOMAIN (additive-AE + each conflict-held + each Rx-BPMH-held — a single pass can yield 3+, in sequence across replay rounds); a revise pass yields a second AUTHOR (the revise-targeted domains) then a second GATE. Expected: the yielded request kinds match the pass's triggers, every request tagged with exactly one kind.
- **Non-tautological reauthor/adjudicator exercise (build-blocking, AR-002):** the current `_sustaining_authors` fixtures do NOT trigger an energy bounce or a held finding, so they DO NOT exercise the REAUTHOR or ADJUDICATOR yield+replay paths at all. Before the live run is called buildable, the fixture self-test MUST be EXTENDED with (a) a non-sustaining author whose `energy_cost` exceeds the nutrition budget — forcing a real energy bounce so the REAUTHOR throw → yield → `.send()` → cache → replay round actually fires; and (b) a held finding (an additive-AE / cross-domain-conflict / Rx-BPMH hold) — forcing a real ADJUDICATOR throw/replay round. Expected: the extended self-test drives ≥1 REAUTHOR replay round AND ≥1 ADJUDICATOR replay round, each advancing exactly one dispatch, the pass completing on the final cache-all-hit replay.
- **No-fork — one composition site AND one release site:** grep the skill, `run_orchestrated`, and the step-harness for (i) a second site that builds the `{accept, safety_passed, revise_domains}` disposition or evaluates `safety_passed is True`, AND (ii) a re-derivation of the `adjudicate` override-RELEASE decision (the `outcome == "cleared"` test or the CRITICAL/H1-H2 non-overridable check). Expected: **exactly 1 composition site** (`compose_gate_dispatch`), **exactly 1 surface gate** (`plan_driver.drive`'s `safety_passed is True`), and **exactly 1 release site** (the inner engine's `adjudicate`/`generate_plans`, [orchestrate.py:579,597,615](../../scripts/plan/orchestrate.py) [VERIFIED]) — **0 duplicates** of any in a consumer or the harness; the consumer returns only the RAW liaison envelope.
- **Backward-compat green:** `run_orchestrated` plus the full existing test suite stay green across the protocol change. NOTE the discriminated-union is a CLEAN break (OQ-1): it CHANGES the yield wire shape, so `run_orchestrated`'s `req_domains, req_summary, req_gates = request` unpack ([plan_orchestrator.py:253](../../scripts/plan/plan_orchestrator.py) [VERIFIED]) AND every generator-driving test are updated in the SAME change. "Behavior-preserving" here refers to the CONTROL-FLOW contract (promotion-on-accept, 0-plans-on-not-`True`), NOT the wire shape, which changes by design. Expected: 0 control-flow regressions; the wire-shape unpack + test drives updated in-PR.
- **Skill-drive step-harness (fixture):** the step-harness drives de-id → AUTHOR → GATE → (REAUTHOR/ADJUDICATOR replay rounds) → (revise) → promote → render over fixtures to a promoted plan with **0 SYNCHRONOUS agent calls inside `drive`** — every gate/judge/lens/reauthor/adjudicator dispatch is satisfied via a yield+`.send()` (GATE) or a throw → yield → `.send()` → replay round (REAUTHOR/ADJUDICATOR), not an in-driver/in-engine synchronous agent callable. Expected: ≥1 plan promoted; count of synchronous judge/lens/reauthor/adjudicator agent calls inside `drive` = 0 (the engine's calls hit the memo cache).

**Falsification criteria:**
- **Malformed-send probe — TWO distinct fail-closed shapes (every class):** `.send()` a malformed/absent/raised result back for each yield class. The fail-closed threshold DIFFERS by class because the dispatches gate different things:
  - **GATE** (a non-dict verdict, a raised lens, a missing key) → terminal `SAFETY_BLOCKED`, **0 plans promoted** for the whole run. The GATE is the whole-plan safety surface; a bad GATE result blocks everything.
  - **REAUTHOR** (a non-fuelable / absent / raised re-author envelope) → the WORKOUT domain stays HELD (`ENERGY_BOUNCE_UNRESOLVED`, records nothing), while OTHER domains may still surface. Threshold: **the workout domain is NOT recorded** (not "0 plans promoted").
  - **ADJUDICATOR** (a malformed / absent / raised liaison envelope for a held domain) → that AFFECTED held domain stays HELD (the block stands, records nothing), while other domains may surface. Threshold: **the affected held domain is NOT recorded** (not "0 plans promoted").
  Both shapes are fail-closed (never default-allow) but they are DIFFERENT shapes — a per-domain hold for REAUTHOR/ADJUDICATOR, a terminal block for GATE. If a malformed GATE send surfaces ≥1 plan, OR a malformed REAUTHOR/ADJUDICATOR send RECORDS the affected domain, the inversion broke the fail-closed floor — halt and restore the per-class guard.
- **No-double-charge / no-double-write probe (replay safety, AR-003):** drive a fixture run that triggers ≥1 REAUTHOR dispatch + ≥2 ADJUDICATOR dispatches (so multiple replay rounds run), then assert `budget.count` AND the promoted-store row-count EQUAL those of a single in-process synchronous drive of the same fixtures (the `run_orchestrated` reference). Threshold: **exact equality** — the replay charged once per cache-MISS (no double-charge across the re-traversed cache-hits) and promoted exactly one row-set (no double-write across the fresh-scratch replays). If `budget.count` exceeds the reference (a replayed cache-hit was charged) or the row-count exceeds it (a replay double-promoted), replay safety is broken — halt and re-verify charge-on-miss-only + fresh-scratch-per-round.
- **Forked-loop probe:** if the no-fork grep finds **≥1** duplicated disposition-composition site, `safety_passed is True` surface, OR adjudication-RELEASE re-derivation (the `outcome == "cleared"` / CRITICAL-H1-H2 check) in any consumer or the step-harness, the safety loop has been forked — halt and re-route composition/release back into `compose_gate_dispatch`/`drive`/the inner engine.
- **Raw-PII-in-yield probe (ADDS the scan, AR-006):** seed a synthetic raw-PII token (a legal name + a lab value) into the raw intake, run the fixture A′ path, and ADD a value-scan over the derived yield payloads — GATE assembled plan + ADJUDICATOR finding (+ REAUTHOR constraint for completeness). The AUTHOR summary is structurally PII-free (no scan needed; the seam only ever holds the de-identified summary), so this probe introduces the FIRST scan over the derived payloads, it does not restore a removed one. Threshold: **0 raw-PII hits** in any derived yield payload. If ≥1 hit, the de-id-OUT derivation leaked a value past the boundary — halt and harden the new value-scan.
- **Frozen-engine probe:** if the build edits any of `pipeline`/`orchestrate`/`assemble`/`generate_plan`/`adjudicate`/`adjust`/`track`/`router` (numstat > 0 on any inner-engine module), the extend-not-rebuild constraint is breached — halt and re-route the inversion into `plan_driver`/`plan_orchestrator`/`gate_dispatch`/`plan_step`, not the engine. (The throw/replay-memo mechanism is precisely what keeps this probe green: the engine still only calls plain callables.)
- **Time horizon:** run the malformed-send, no-double-charge/no-double-write, forked-loop, raw-PII-in-yield, and frozen-engine probes at the first build of the wider inversion, at the S94 operator-present LIVE test, and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- The subscription session's rate/concurrency ceiling blocks the per-plan aggregate yield volume (author + gate + per-lens + reauthor + adjudicator, × revise iterations) — re-open Alternative B (the all-API path) against the cost trade-off.
- The North-Star transition to all-API / local-model is initiated — each yield class becomes a programmatic backend call, `run_orchestrated` becomes the single live driver; re-validate the union fulfilment against the new execution model.
- A change to `compose_gate_dispatch`'s input boundary (raw verdicts vs bound clients) is proposed — re-verify the composition + fail-closed default stay in one definition.
