## ADR-0028: Gate-Dispatch Control-Inversion — Completing the A′ Subscription Driver

> **Y-Statement:** In the context of the S93-built A′ shared driver `plan_driver.drive`, which control-inverts ONLY the author dispatch — it `yield`s a single `(tuple(domains), summary, gates)` author-request ([plan_driver.py:122,162](../../scripts/plan/plan_driver.py) [VERIFIED]) and the consumer feeds back captured author envelopes via `.send()` ([plan_orchestrator.py:251,256](../../scripts/plan/plan_orchestrator.py) [VERIFIED]) — while the GATE (`gate_dispatch`, calling `quality_judge` + `review_plan` synchronously, [gate_dispatch.py:133-135](../../scripts/plan/gate_dispatch.py) [VERIFIED]) and the `reauthor`/`adjudicator` hooks are SYNCHRONOUS Python callables invoked from inside the driver/inner-engine call stack ([plan_driver.py:129,125-127,165-168](../../scripts/plan/plan_driver.py) [VERIFIED]), facing the tension that the Agent tool belongs to the `/generate-plan` skill-orchestrator and not to a Python frame — so the skill cannot fulfill the gate/judge/lens/reauthor/adjudicator dispatches with subscription agents (the only production caller of `compose_gate_dispatch`/`run_orchestrated` is the fixture self-test, [_a_prime_self_test.py:234,273](../../scripts/plan/_a_prime_self_test.py) [VERIFIED]; `ModelClient` has no `.judge`/`.review` and its `author`/`converse` backends are `NotImplementedError` stubs, [client.py:203-211](../../scripts/model/client.py) [VERIFIED]) and the live A′ run is therefore NOT executable under the operator's "API for PII-only, subscription for everything else" runtime split, we decided to extend `plan_driver.drive`'s yield protocol from the bare author-tuple to a DISCRIMINATED-UNION of typed dispatch-requests — one per agent-dispatch CLASS (AUTHOR, GATE, REAUTHOR, ADJUDICATOR) — so the consumer fulfils each yield with a subscription agent and `.send()`s the raw result back while the driver/`compose_gate_dispatch` retains the disposition composition + the fail-closed `safety_passed is True` loop in ONE definition, with ONE driver and two consumers (the skill, subscription mode; `run_orchestrated`, programmatic/test mode), to achieve a genuinely executable live subscription run without a metered backend and without forking the safety loop, accepting that the yield protocol becomes a tagged union the consumer must exhaustively handle, that the de-id-OUT-before-dispatch obligation now applies to the assembled plan handed to the GATE yield (not only the author summary), and that the live skill-driven path remains non-deterministic and mock-tested only until the S94 operator-present attestation.

### Context

ADR-0026 selected the A′ driver model and the S93 build landed it: `plan_driver.drive` is a control-inversion generator-coroutine, `compose_gate_dispatch` composes the quality + safety gates into the fixed 3-key disposition, and `run_orchestrated` drives the generator. But the inversion is PARTIAL. `drive` yields exactly ONE request shape — the author-request `(tuple(domains), summary, gates)` ([plan_driver.py:122](../../scripts/plan/plan_driver.py) [VERIFIED], re-yielded for the revise pass at [plan_driver.py:162](../../scripts/plan/plan_driver.py) [VERIFIED]) — and the consumer's drive loop reads back only `{domain: envelope}` author fragments ([plan_orchestrator.py:251-258](../../scripts/plan/plan_orchestrator.py) [VERIFIED]). Every OTHER agent-touching dispatch stays a SYNCHRONOUS Python callable invoked from inside the call stack: the gate is called at `_safe_gate(gate_dispatch, result)` ([plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]), where `gate_dispatch` itself synchronously calls `_quality_judge(assembled_plan, judge_client)` and `_review(assembled_plan, review_dispatch, lenses=...)` ([gate_dispatch.py:133-135](../../scripts/plan/gate_dispatch.py) [VERIFIED]); the `reauthor`/`adjudicator` hooks are threaded verbatim into `pipeline.run_generation` ([plan_driver.py:125-127,165-168](../../scripts/plan/plan_driver.py) [VERIFIED]) and fire from inside the inner engine.

Two forces pull against each other. The operator's binding runtime split is "API for the PII de-id call ONLY, subscription for everything else" (ADR-0026 Decision; the no-train de-id backend is the one metered egress, [ADR-0027, Decision](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). Under that split the judge, the safety lenses, the energy-bounce re-author, and the medical-liaison adjudication must run as SUBSCRIPTION agents — dispatched via the Agent tool, which only the `/generate-plan` skill-orchestrator holds, never a Python function. Against that stands the built seam shape: a Python callable cannot synchronously spawn a subscription Task agent and pull its reasoning back into a return value (the same impossibility ADR-0026 named for the author seam, [ADR-0026, Context](ADR-0026-v1-subscription-runtime-driver.md) [VERIFIED]). So the gate/judge/lens/reauthor/adjudicator dispatches are, today, only fulfillable by a Python backend — and no such backend exists: `ModelClient` exposes `converse`/`author`/`deidentify` and no `.judge` or `.review` ([client.py:33-95](../../scripts/model/client.py) [VERIFIED]), and `author`/`converse` are `NotImplementedError` stubs ([client.py:203-211](../../scripts/model/client.py) [VERIFIED]); `deidentify` alone is live ([client.py:213-250](../../scripts/model/client.py) [VERIFIED]). The only production code that constructs `compose_gate_dispatch` or calls `run_orchestrated` is the fixture-only `_a_prime_self_test.py` ([_a_prime_self_test.py:234,273,299](../../scripts/plan/_a_prime_self_test.py) [VERIFIED]).

The consequence affects the data subject, not only the operator. The `/generate-plan` skill PROSE already CLAIMS it dispatches each safety lens "as a SUBSCRIPTION agent" and supplies `reauthor`/`adjudicator` as "live subscription dispatches" ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED]) — but the seams those values feed (`gate_dispatch=`, and the hooks threaded into `run_generation`) are synchronous Python callables the skill cannot fulfill with an Agent-tool dispatch. A 0-spend dry-run surfaces the gap: de-id runs (live backend present), the author yield is fulfillable, then the driver reaches `_safe_gate` and there is no Python `gate_dispatch` to call (no judge/lens backend) and no inverted yield to hand the skill. This is the PF-S87-01 "plumbing wired, end-to-end capability not" pattern — the `core-capability-audit` proves the deterministic spine but the live subscription dispatch of the gate/hooks was never built, only deferred as the S94 operator-present attestation. The decision must clear: invert the REMAINING dispatch classes so the skill can fulfil them with subscription agents, WITHOUT moving the disposition composition or the fail-closed loop out of their single definition (the no-fork crown jewel ADR-0026 bought), WITHOUT editing the byte-frozen inner engine, and keeping `run_orchestrated` + the full test suite green.

### Decision

Extend `plan_driver.drive`'s yield protocol from the bare author-tuple to a DISCRIMINATED-UNION of typed dispatch-requests, one per agent-dispatch CLASS: AUTHOR (the existing author fan-out / revise re-author), GATE (the assembled plan plus the judge and safety-lens roster to dispatch), REAUTHOR (the energy-bounce second-personal-trainer request), and ADJUDICATOR (the held-finding medical-liaison request). The consumer fulfils each yielded request — dispatching a subscription agent (skill mode) or calling a programmatic callable (`run_orchestrated`/test mode) — and `.send()`s the RAW result back; the driver composes the disposition (via `compose_gate_dispatch`) and runs the fail-closed `safety_passed is True` revise loop, both kept in their existing single definition. One driver, two consumers, no fork; the byte-frozen inner engine stays byte-frozen.

### Rationale

The extension was evaluated across the four criteria ADR-0026 made load-bearing — **no-fork fidelity** (the disposition composition + the fail-closed loop in one definition), **subscription-vs-metered cost** under the operator's split, **executability of the live A′ run**, and **buildability under extend-not-rebuild** — against the chosen tagged-union inversion, Alternative B (build API judge/lens/author backends), Alternative C (hybrid), and Alternative D (keep the synchronous gate).

On **executability** the chosen option is decisive and the others split. The gate/judge/lens/reauthor/adjudicator are agent dispatches, and only the skill holds the Agent tool; a synchronous Python `gate_dispatch` (Alternative D) is unfulfillable by the skill, so the live run halts at `_safe_gate` ([plan_driver.py:129](../../scripts/plan/plan_driver.py) [VERIFIED]) — the run is non-executable, which is the present state. Inverting the remaining classes makes every agent-touching dispatch a yield the skill can fulfil with a subscription agent, mirroring the author seam that already works ([plan_orchestrator.py:251-258](../../scripts/plan/plan_orchestrator.py) [VERIFIED]).

On **no-fork fidelity** the resolution of OQ-2 is the crux: the GATE yield carries the RAW INPUTS (the assembled plan + the judge + the lens roster); the consumer dispatches the judge and each lens and returns the RAW verdicts; the driver hands those to `compose_gate_dispatch`, which keeps the `accept`/`safety_passed`/`revise_domains` mapping AND the fail-closed `safety_passed is True` default in its one definition ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py) [VERIFIED]). The alternative — the consumer composes the disposition and `.send()`s the finished 3-key dict — would move the `safety_passed` surface logic into the agent-driven skill consumer, re-creating exactly the forked-safety-loop failure class ADR-0026 rejected (a skill-prose copy of "a non-True disposition surfaces 0 plans" that can drift, [ADR-0026, Alternative A-naive](ADR-0026-v1-subscription-runtime-driver.md) [VERIFIED]). So the inversion deliberately stops at the RAW inputs/results boundary; composition stays in code.

On **cost**, the chosen option keeps every agent dispatch on the subscription session (the judge, lenses, reauthor, adjudicator are subscription agents; the de-id call is the one metered egress, [ADR-0027, Consequences](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]), matching the operator split. Alternative B (build API judge/lens/author backends) is rejected on this axis: it routes non-PII work through the metered API, contradicting "subscription for everything else" and paying per-token for every judge/lens/reauthor/adjudicate dispatch the revise loop multiplies. On **buildability**, the change is confined to `plan_driver.py` (the yield protocol + the per-class request handling), `plan_orchestrator.py` (the consumer drive loop gains a per-class fulfilment switch + the existing programmatic callables become the API-mode fulfilment), the skill (the drive mechanism), and tests; `gate_dispatch.py` MAY change only at the boundary where it now receives raw verdicts instead of bound clients, and the inner engine (`pipeline`/`orchestrate`/`assemble`/`generate_plan`/`adjudicate`/`adjust`/`track`/`router`) stays byte-frozen (numstat=0) — OQ-4. Long-term, the cost the decision accepts permanently for V1 is a richer driver protocol (a tagged union the consumer must exhaustively handle) that the future all-API cutover retires only partway — the all-API path still drives the same union, just fulfilling each yield with a programmatic backend rather than an agent.

### Consequences

**Positive:**
- The live A′ run becomes genuinely executable end-to-end on the subscription session: every agent-touching dispatch (author, judge, each lens, reauthor, adjudicator) is a yield the skill fulfils with a subscription agent, so `/generate-plan` can drive de-id → author → gate → revise → promote without a synchronous Python gate it cannot satisfy ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED] is then truthful, not aspirational).
- The disposition composition + the fail-closed `safety_passed is True` loop stay in EXACTLY ONE definition (`compose_gate_dispatch` + `plan_driver.drive`); the GATE yield carries raw inputs/results and the driver composes — verifiable as 0 second composition sites by grep ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py) [VERIFIED]). The no-fork crown jewel ADR-0026 bought is preserved across the wider inversion.
- Subscription-cost posture is honored unchanged: no judge/lens/author API backend is built, so the only metered egress stays the single ADR-0027 de-id call per plan-gen.

**Negative:**
- The yield protocol becomes a DISCRIMINATED UNION the consumer must handle EXHAUSTIVELY: both consumers (the skill and `run_orchestrated`) gain a per-class fulfilment switch, and a consumer that mis-handles or omits a request kind is a new failure surface the bare author-tuple did not have. The fail-closed mitigation (OQ-3) — any malformed/absent/raised `.send()`-back for ANY class routes to `SAFETY_BLOCKED`/honest-no-plan — bounds the blast radius but does not erase the added protocol complexity, which is a permanent (1+ year) cost of the wider inversion that the all-API cutover does not remove.
- The de-id-OUT-before-dispatch obligation now extends to the GATE/REAUTHOR/ADJUDICATOR yields: where the AUTHOR yield carries only the de-identified summary ([plan_orchestrator.py:101-124](../../scripts/plan/plan_orchestrator.py) [VERIFIED]), the GATE yield carries the ASSEMBLED PLAN and the ADJUDICATOR yield carries a safety finding — payloads the existing author-seam value-scan does not cover. Every newly-yielded payload must carry only de-identified content (0 raw PII), and the test floor must add a value-scan over the new yield payloads, or the wider inversion widens the PII surface.
- The skill cannot drive a live Python generator directly (a generator cannot pause for the orchestrator's Agent tool, OQ-5): a thin step-harness must persist/resume the driver across Agent-tool round-trips, a new runnable artifact (`scripts/plan/<x>.py`) with its own correctness burden (resumable state, idempotent replay) that did not exist when the loop was a single in-process `.send()` cycle.

**Neutral:**
- `compose_gate_dispatch`'s signature shifts from bound clients (`judge_client`, `review_dispatch`) toward receiving raw verdicts at composition time; its internal mapping + fail-closed default are unchanged, only its input boundary moves (a follow-on adapter shape, not a behavior change).
- A second instance of the typed-request driver pattern joins the project alongside the build pipeline's execute-plan orchestrator — the same control shape, widened from one request kind to four.

### Alternatives Considered

#### Alternative A: Discriminated-union yield protocol, driver composes (Chosen)
`drive` yields a tagged request per dispatch class (AUTHOR/GATE/REAUTHOR/ADJUDICATOR); the consumer fulfils each with a subscription agent (skill) or a programmatic callable (`run_orchestrated`) and `.send()`s the raw result back; the driver + `compose_gate_dispatch` retain the disposition composition + the fail-closed loop.
- **Supporting evidence:** Makes the live A′ run executable on the subscription session (no metered judge/lens backend); keeps the disposition composition + `safety_passed is True` loop in one definition ([gate_dispatch.py:137-147](../../scripts/plan/gate_dispatch.py), [plan_driver.py:133](../../scripts/plan/plan_driver.py) [VERIFIED]); extends the author-seam inversion that already drives green ([plan_orchestrator.py:251-258](../../scripts/plan/plan_orchestrator.py) [VERIFIED]); confines edits to `plan_driver`/`plan_orchestrator`/the skill/tests with the inner engine byte-frozen.
- **Trade-offs:** A tagged-union protocol the consumer must handle exhaustively (Negative-1); the de-id-OUT obligation widens to the new yield payloads (Negative-2); a step-harness is required for the live skill drive (Negative-3, OQ-5). Accepted because it is the only option that makes the live run executable while preserving the no-fork loop under the operator's subscription split.
- **When this becomes the right choice:** It is, for V1, when the gate/judge/lens/reauthor/adjudicator must run as subscription agents, the inner engine is byte-frozen, and the safety loop must stay one definition.

#### Alternative B: Build API judge/lens/author backends on `ModelClient`
Add `.judge`/`.review`/live-`author` backends to `ModelClient` so `gate_dispatch`, the lenses, and the author dispatch all run as synchronous API calls from Python — the driver stays as-is, fulfilling the existing synchronous seams with metered model calls.
- **Supporting evidence:** Genuinely viable and the smallest driver change — the yield protocol is untouched, the existing `gate_dispatch`/hook seams are filled by Python backends, and the driver loop runs entirely in-process (no step-harness, no tagged union). The model boundary (ADR-0015) already anticipates additional backend methods alongside `converse`/`author`/`deidentify`.
- **Trade-offs:** Routes all non-PII work (judge, lenses, reauthor, adjudicator, author) through the METERED API, directly contradicting the operator's "API for PII-only, subscription for everything else" split and paying per-token for every dispatch the revise loop multiplies (N specialists × revise iterations + judge + M lenses + adjudications). It is the future all-API path, not the V1 subscription path — adopting it now inverts the operator's deliberate cost posture.
- **When this becomes the right choice:** When the runtime moves to all-API (or a local model): every dispatch class becomes a programmatic backend call, the union is fulfilled in-process, and `run_orchestrated` becomes the single live driver — the ADR-0015 cutover, the V1-rejected/future-adopted form.

#### Alternative C: Hybrid — invert only the GATE class, keep reauthor/adjudicator synchronous
Invert only the GATE yield (the judge + lenses, the highest-volume agent dispatch) and leave `reauthor`/`adjudicator` as synchronous Python hooks fulfilled by small API or local backends.
- **Supporting evidence:** Smaller protocol surface than the full union — only one new request kind — while still removing the largest metered cost (the per-revise judge/lens fan-out) from the API. The reauthor/adjudicator hooks fire less often (only on an energy-bounce or a held finding), so their residual API cost is bounded.
- **Trade-offs:** Splits the dispatch model along an arbitrary line: `reauthor` is a second personal-trainer dispatch and `adjudicator` is a medical-liaison dispatch — both are exactly the "specialist/safety agent over the summary" class the operator put on subscription, so leaving them metered re-introduces the split-violation Alternative B has, just smaller. It also keeps two fulfilment mechanisms (yield-driven for GATE, synchronous-backend for the hooks), so the consumer still needs a Python backend that does not exist, and the live run is still not executable for a plan that triggers an energy bounce or a held finding. A partial inversion that leaves the live run conditionally non-executable is not a stable V1 state.
- **When this becomes the right choice:** If measurement later shows the reauthor/adjudicator dispatches are rare AND a cheap local model reaches parity for them, pinning those two to a local backend while the GATE stays subscription-yielded would cut protocol surface at no cost-posture violation.

#### Alternative D: Keep the synchronous gate; accept the skill cannot run it
Leave `drive`'s yield protocol at the bare author-tuple and the gate/hooks as synchronous Python callables; the live A′ run remains a documented future capability, fulfilled only when API backends exist.
- **Supporting evidence:** Zero code change — the S93 build, the self-test, and the full test suite stay exactly as-is; the deterministic spine is proven by `core-capability-audit` and the fixture self-test.
- **Trade-offs:** The live A′ run is NON-EXECUTABLE: the skill cannot fulfil the synchronous `gate_dispatch`/hook seams with an Agent-tool dispatch, and no Python judge/lens backend exists ([client.py:203-211](../../scripts/model/client.py) [VERIFIED]; only `_a_prime_self_test.py` composes the gate, [_a_prime_self_test.py:234](../../scripts/plan/_a_prime_self_test.py) [VERIFIED]). The skill prose claiming live subscription dispatch ([generate-plan/SKILL.md:124-138](../../.claude/skills/generate-plan/SKILL.md) [VERIFIED]) stays untrue, and the core capability — a followable plan generated end-to-end — does not work (the exact PF-S63-02 / PF-S87-01 gap this ADR exists to close). Rejected because "the components each pass their own tests" while the end-to-end run cannot execute is the drift the project's mandates forbid.
- **When this becomes the right choice:** If V1 abandons live subscription generation entirely and ships only the fixture/self-test deterministic spine as a demonstrator — a scope the operator has not chosen.

### Validation Approach

**Confirmation criteria:**
- **Typed-request ordering (fixture run):** a 4-domain fixture run yields the typed requests in the right order and count — exactly 1 AUTHOR request first, then 1 GATE request per generated pass, with REAUTHOR yielded iff an energy-bounce fires and ADJUDICATOR yielded iff a finding is held; a revise pass yields a second AUTHOR (the revise-targeted domains) then a second GATE. Expected: the yielded request kinds match the pass's triggers, every request tagged with exactly one kind.
- **No-fork — one composition site:** grep the skill, `run_orchestrated`, and the step-harness for a second site that builds the `{accept, safety_passed, revise_domains}` disposition or evaluates `safety_passed is True`. Expected: **exactly 1 composition site** (`compose_gate_dispatch`) and **exactly 1 surface gate** (`plan_driver.drive`'s `safety_passed is True`), **0 duplicates** in any consumer or the harness.
- **Backward-compat green:** `run_orchestrated` plus the full existing test suite stay green across the protocol change (the per-class fulfilment is a behavior-preserving extension of the existing `next()`/`.send()` drive). Expected: 0 previously-passing tests fail.
- **Skill-drive step-harness (fixture):** the step-harness drives de-id → AUTHOR → GATE → (revise) → promote → render over fixtures to a promoted plan with **0 SYNCHRONOUS gate calls** — every gate/judge/lens/reauthor/adjudicator dispatch is satisfied via a yield+`.send()`, not an in-driver synchronous callable. Expected: ≥1 plan promoted; count of synchronous `gate_dispatch`/judge/lens calls inside `drive` = 0.

**Falsification criteria:**
- **Malformed-gate-send probe (fail-closed, every class):** `.send()` a malformed/absent/raised result back for the GATE yield (a non-dict verdict, a raised lens, a missing key) — and separately for the REAUTHOR and ADJUDICATOR yields. Threshold: **0 plans promoted** (terminal `SAFETY_BLOCKED`/honest-no-plan) for each. If ≥1 plan surfaces on any malformed class send, the wider inversion broke the fail-closed floor — halt and restore the disposition gate ([plan_driver.py:133](../../scripts/plan/plan_driver.py) [VERIFIED]).
- **Forked-loop probe:** if the no-fork grep finds **≥1** duplicated disposition-composition site OR `safety_passed is True` surface in any consumer or the step-harness, the safety loop has been forked — halt and re-route composition back into `compose_gate_dispatch`/`drive`.
- **Raw-PII-in-yield probe:** seed a synthetic raw-PII token (a legal name + a lab value) into the raw intake, run the fixture A′ path, and scan EVERY yielded request payload (AUTHOR summary, GATE assembled plan, REAUTHOR constraint, ADJUDICATOR finding). Threshold: **0 raw-PII hits** in any yielded payload. If ≥1 hit, a yield leaked raw PII past the de-id-OUT boundary — halt and restore the de-id-OUT scan over the new payloads.
- **Frozen-engine probe:** if the build edits any of `pipeline`/`orchestrate`/`assemble`/`generate_plan`/`adjudicate`/`adjust`/`track`/`router` (numstat > 0 on any inner-engine module), the extend-not-rebuild constraint is breached — halt and re-route the inversion into `plan_driver`/`plan_orchestrator`/`gate_dispatch`, not the engine.
- **Time horizon:** run the malformed-send, forked-loop, raw-PII-in-yield, and frozen-engine probes at the first build of the wider inversion, at the S94 operator-present LIVE test, and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- The subscription session's rate/concurrency ceiling blocks the per-plan aggregate yield volume (author + gate + per-lens + reauthor + adjudicator, × revise iterations) — re-open Alternative B (the all-API path) against the cost trade-off.
- The North-Star transition to all-API / local-model is initiated — each yield class becomes a programmatic backend call, `run_orchestrated` becomes the single live driver; re-validate the union fulfilment against the new execution model.
- A change to `compose_gate_dispatch`'s input boundary (raw verdicts vs bound clients) is proposed — re-verify the composition + fail-closed default stay in one definition.

| OQ-3 | Does a malformed/absent/raised `.send()`-back for the GATE/REAUTHOR/ADJUDICATOR classes route to a fail-closed terminal state, never default-allow? | Walter McGivney | Resolved here (Decision) | RESOLVED: every malformed yield-back mirrors the existing `_safe_gate` + malformed-disposition guard ([plan_driver.py:131-134,171-193](../../scripts/plan/plan_driver.py) [VERIFIED]) — a non-dict/absent/raised result for ANY class yields a disposition that is NOT `safety_passed is True`, routing to `SAFETY_BLOCKED`/honest-no-plan with 0 plans.
