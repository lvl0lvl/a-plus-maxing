## ADR-0019: Extend the Closed SUMMARY_FIELD_SET so the Planner Consumes De-Identified Chat-Sourced Nutrition/Supplement/Peptide/Training Facts

> **Y-Statement:** In the context of the conversational-intake pivot, where the chat now captures the rich nutrition/supplement/peptide/training-detail dialogue the form lost but those domains carry no de-identified token in the closed `SUMMARY_FIELD_SET`, so ADR-0017 routes them record-only and they never reach the planner (the deferred ADR-0014 OQ-1, and the exact PF-S87-01 gap — rich capture that never feeds the plan), facing the tension between the planner coverage the pivot needs (these domains MUST feed the plan for it to be usable) and the de-identification discipline that bounds what crosses to the plan-reasoning model (each new token enlarges the de-identified surface the model sees), we decided to extend the closed `SUMMARY_FIELD_SET` with de-identified nutrition/supplement/peptide/training-detail tokens, each a band/class derivation under the existing change-control tripwire discipline, so chat-extracted facts for those domains reach the plan roster, to achieve a usable multi-domain plan personalized from the operator's own dialogue, accepting that each new token expands the de-identified crossing surface, that each needs a de-identification derivation plus a maintained change-control tripwire, and that the closed-set's small-audited-vocabulary safety dilutes as the vocabulary grows.

### Context

The conversational-intake pivot has the chat capture the rich sections the rigid form lost — nutrition, the supplement/peptide stack, and training detail — but the planner reads only the closed `SUMMARY_FIELD_SET`, a 12-token allowlist whose members are goal/training-age/recovery/Rx-class tokens and which carries no dietary, supplement-stack, or peptide token ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]). ADR-0017's extraction contract therefore routes those domains record-only to the gitignored scaffold: a chat-extracted nutrition fact "lands on the gitignored scaffold as record-only exactly as ADR-0014 does" and does "not reach the planner until the field-set is extended" ([ADR-0017, Consequences-Negative](ADR-0017-conversation-to-deidentified-store-extraction.md) [VERIFIED]). This recreates the exact PF-S87-01 gap the operator caught in session 87 — only 6 signals reach the planner while "everything else routes record-only and never reaches the planner (training specifics… all of nutrition)," a feature reviewed for plumbing but never for whether the capture produces a usable plan ([session-87.md, items 3 and PF-S87-01](../../vault/sessions/session-87.md) [VERIFIED]). The plan roster's domain translators already exist and already reason over a summary that lacks these tokens: `_to_nutrition_plan`, `_to_supplements_plan`, and `_to_peptides_plan` translate surviving recommendations into domain plans, and `compute_plan` feeds them `router.summarize(store_read)` — a summary keyed only by the closed field-set ([generate_plan.py L130-228, L314](../../scripts/plan/generate_plan.py) [VERIFIED]).

Two forces pull against each other, across the operator and the data subject. The pivot's whole point is the rich-section interplay reaching the plan: the operator's own read is that "a plan's value is the interplay (peptide ⟷ goal ⟷ recovery ⟷ bloodwork ⟷ DNA)," so nutrition/supplement/peptide MUST feed the planner for the plan to be usable ([session-87.md, item 4](../../vault/sessions/session-87.md) [VERIFIED]). Against that stands the de-identification discipline that bounds what crosses to the plan-reasoning model: the `SUMMARY_FIELD_SET` is a deliberately small audited vocabulary, every member of which is a de-identified band/class, and each token added enlarges the de-identified surface the model sees ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]; [ADR-0016, Consequences-Negative tension-with-0019](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). The closed-set safety the system rests on — a whitelist that `dispatch` enforces by rejecting any field outside it, and disjointness tripwires that fail at module load if a token is added wrong ([router.py L307-313, L329-349, L435-475](../../scripts/plan/router.py) [VERIFIED]) — is exactly the coverage the pivot now needs to widen. Because extending a closed, change-controlled trust-boundary vocabulary redraws what de-identified facts may cross to the model rather than implementing an existing rule, it is a decision, not a code comment.

### Decision

Extend the closed `SUMMARY_FIELD_SET` with de-identified nutrition, supplement, peptide, and training-detail tokens — each a band/class derivation honoring the existing change-control discipline (the `_RAW_TO_FIELD` / `_FIELD_DERIVATION` derivation pattern and the disjointness tripwires) — so the chat-extracted facts for those domains, produced via ADR-0017's extraction contract, reach the plan roster's nutrition/supplement/peptide/training authors. The exact token vocabulary — which tokens, their band/class buckets — is fixed at spec stage, not in this ADR. The training-detail tokens this ADR mints are the CHAT-SOURCED training-VOLUME/detail tokens (training split, weekly volume, modality) — distinct from ADR-0018's already-activated demographic `training-age-band`, which is a `date-of-birth` derivation owned by the demographic form's Step-1 activation, not a chat-extracted fact; the two "training" token families do not overlap.

### Rationale

The extension was evaluated against keeping those domains record-only (A), sending raw nutrition/supplement free-text to the planner (B), and a phased per-domain rollout (C), across four criteria the pivot and the existing boundary make load-bearing: planner coverage / usable-plan, de-identification preserved, closed-set audit-ability, and the change-control discipline.

On **planner coverage / usable-plan**, only an extension delivers it. The record-only status quo (Alternative A) is the precise mechanism by which the chat would capture rich dialogue the planner never sees — the PF-S87-01 gap, where a feature passes plumbing review yet produces no usable plan because the captured facts never reach the roster ([session-87.md, PF-S87-01](../../vault/sessions/session-87.md) [VERIFIED]; [ADR-0017, Consequences-Negative](ADR-0017-conversation-to-deidentified-store-extraction.md) [VERIFIED]). The translators that would consume these facts already exist and already render the honest no-plan state when no token feeds them, so the gap is structural, not a missing translator ([generate_plan.py L130-228](../../scripts/plan/generate_plan.py) [VERIFIED]). On **de-identification preserved**, the extension stays inside the discipline rather than breaking it: each new token is a band/class derived from a raw-PII source item through the same `_RAW_TO_FIELD` → `_FIELD_DERIVATION` pattern the existing raw-backed tokens use (`training-age-band` from `date-of-birth`, `active-issue-class` from raw symptom text), so the raw value never appears in the token and the `summarize` 8j6 gate still raises on any pass-through PII at the boundary ([router.py L80-85, L298-305, L405-430](../../scripts/plan/router.py) [VERIFIED]) — which is why letting the planner see raw nutrition/supplement free-text (Alternative B) is rejected: raw operator PII to the plan-reasoning model is a direct ADR-0001/ADR-0016 violation, the boundary those decisions exist to hold ([ADR-0016, Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). On **change-control discipline**, each new token is pinned by the existing disjointness tripwires — `SUMMARY_FIELD_SET` must stay disjoint from the named-excluded raw-PII set, and every raw source item must be a named-excluded field — so a token added wrong reds the module-load assert rather than leaking silently ([router.py L307-313, L329-349](../../scripts/plan/router.py) [VERIFIED]). On **closed-set audit-ability**, the extension is the one place this criterion is conceded rather than won: a larger vocabulary is a larger audited surface (see Consequences-Negative), which is why the phased rollout (Alternative C) is a real option for sequencing the audit cost.

Long-term, the extension closes a standing 1+ year constraint in place: ADR-0014 and ADR-0017 both record nutrition/supplement/peptide as record-only "until the field-set is extended," and this ADR is that extension — once the tokens exist, the same routing/translation path produces richer plans with no re-decision of the assembly architecture ([ADR-0014, Consequences-Negative + OQ-1](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]; [ADR-0017, OQ-1](ADR-0017-conversation-to-deidentified-store-extraction.md) [VERIFIED]). The cost it accepts permanently is that the crossing surface grows in de-identified vocabulary, auditable token-by-token but no longer the minimal 12-token set the boundary started from.

### Consequences

**Positive:**
- Chat-extracted nutrition/supplement/peptide/training-detail facts reach the plan roster as de-identified tokens, so `_to_nutrition_plan` / `_to_supplements_plan` / `_to_peptides_plan` personalize their sections from the operator's own dialogue rather than rendering the honest no-plan state for un-tokenized domains — closing the PF-S87-01 "rich capture that never reaches the planner" gap ([generate_plan.py L130-228, L314](../../scripts/plan/generate_plan.py) [VERIFIED]; [session-87.md, PF-S87-01](../../vault/sessions/session-87.md) [VERIFIED]).
- Resolves the deferred ADR-0014 OQ-1 / ADR-0017 OQ-1 in place: the standing "these domains route record-only until the field-set is extended" constraint closes, and the same assembly path produces richer plans without re-deciding the architecture ([ADR-0014, OQ-1](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]; [ADR-0017, OQ-1](ADR-0017-conversation-to-deidentified-store-extraction.md) [VERIFIED]).
- Each new token honors ADR-0016's persisted-side-de-identified half: it crosses as a band/class, never raw, so the field-set expands in de-identified vocabulary while the raw-egress class stays conversation-only ([ADR-0016, Decision + tension-with-0019](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).

**Negative:**
- Each new token EXPANDS the de-identified surface the plan-reasoning model sees — more tokens crossing the relaxed-but-still-de-identified boundary ADR-0016 draws, a boundary-surface expansion that pulls against the "keep the crossing surface minimal" instinct; accepted only because every token stays de-identified (the tensions-with ADR-0016, resolved as de-identified-only) ([ADR-0016, Consequences-Negative tension-with-0019](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).
- Each new token needs a de-identification derivation plus a change-control tripwire kept correct: a mis-derivation could leak more granularity than intended (a too-fine dietary band that reconstructs a raw dietary detail), and a token added to neither structure would read through `summarize`'s else-branch under its own name. The risk is mitigated by the derivation's COARSENESS (the band/class discards the raw value) plus the disjointness asserts failing at module load plus a per-token output scan proving non-reversibility, NOT by the `summarize` 8j6 per-value gate — the 8j6 `scan_text` raise runs only on the pass-through (else) path (`router.py` L416-430), NOT on the raw-backed DERIVED path (the `source_items`/`_FIELD_DERIVATION` branch, `router.py` L406-412, which runs no per-value scan), and every new token here is raw-backed-derived. This is real machinery that must be authored and maintained per token — a standing 1+ year discipline cost ([router.py L307-313, L329-349, L405-432](../../scripts/plan/router.py) [VERIFIED]).
- The closed-set's small-audited-vocabulary safety dilutes as the vocabulary grows: the 12-token set was small enough to read at a glance; every domain added enlarges the surface a PII-boundary review must cover, so the audit cost per review grows with the token count ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]).

**Neutral:**
- The de-identified band/class buckets for nutrition/supplement/peptide/training detail become a shared vocabulary the extraction step (ADR-0017), the field-set, and the domain translators must all agree on — the same classification discipline already imposed on each existing field-set token.

### Alternatives Considered

#### Alternative A: Keep nutrition/supplement/peptide RECORD-ONLY (the ADR-0014 status quo)
Leave the closed field-set unextended; ADR-0017 continues routing those domains to the gitignored scaffold as record-only, as ADR-0014 does today.
- **Supporting evidence:** Zero change to the trust boundary — the closed 12-token set stays minimal and maximally auditable, no new derivation or tripwire to maintain, and the record-only path already exists and is gate-protected ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]; [ADR-0014, Consequences-Negative](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]).
- **Trade-offs:** It recreates the exact PF-S87-01 gap the operator caught — the chat captures rich nutrition/supplement/peptide dialogue the planner never sees, so the plan is not usable for those domains; the operator's pivot rationale is precisely that the interplay across these domains must reach the plan ([session-87.md, item 4 + PF-S87-01](../../vault/sessions/session-87.md) [VERIFIED]). Rejected for any domain the operator wants planned.
- **When this becomes the right choice:** Never, for domains the operator wants planned. It remains correct only for a domain genuinely out of plan scope — captured for the record but with no plan section to feed.

#### Alternative B: Let the planner see RAW nutrition/supplement free-text (no de-identification)
Pass the chat-extracted nutrition/supplement free-text to the plan-reasoning model verbatim, skipping any band/class derivation.
- **Supporting evidence:** Maximal fidelity — no information lost to bucketing, so the planner reasons over the operator's exact dietary and stack detail, and it needs no new derivation logic.
- **Trade-offs:** It breaks the de-identification discipline outright — raw operator PII to the plan-reasoning model is the boundary ADR-0001 fixed and ADR-0016 deliberately kept on the persisted/crossing side, so this is a direct ADR-0001/ADR-0016 violation that `dispatch`'s whitelist and the `summarize` 8j6 gate exist to prevent ([ADR-0016, Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]; [router.py L405-430, L435-475](../../scripts/plan/router.py) [VERIFIED]). Rejected because it moves raw PII across the one boundary the system is built to hold.
- **When this becomes the right choice:** Only under the North-Star local model, where nothing leaves the machine and the de-identification-before-egress requirement is moot — the same condition ADR-0016's Alternative B names; until then, raw free-text to the plan model is forbidden.

#### Alternative C: PHASED per-domain extension (mint a domain's token only when its plan author is ready)
Extend the field-set one domain at a time — mint nutrition's tokens when the nutrition author is ready, then supplements, then peptides, then training detail — rather than all four at once.
- **Supporting evidence:** Spreads the audit and derivation cost over time, so each PII-boundary review covers one domain's tokens at a time, and a domain ships its planner coverage the moment its tokens and author are ready rather than waiting on the slowest domain. It is a genuine, reasonable build-sequencing option.
- **Trade-offs:** It leaves the un-minted domains in the record-only PF-S87-01 gap longer — a partially-usable plan during the rollout, where some rich-section dialogue still never reaches the planner — and it spreads the change-control churn (tripwire edits, disjointness re-checks) across multiple changes rather than one reviewed batch. Not rejected on principle: this is a sequencing choice the spec can take, deferred to Open Questions.
- **When this becomes the right choice:** When one domain's plan author is materially ahead of the others and the operator wants that domain's planner coverage sooner — a phased rollout shipping the ready domain first, accepting a temporarily partial plan, is the right call there.

### Validation Approach

**Confirmation criteria:**
- After the extension, every chat-extracted nutrition/supplement/peptide/training fact that the operator stated and the extractor mapped appears in the `summarize` summary as a de-identified token AND reaches the roster: a round-trip test per new token confirms the fact lands as a `SUMMARY_FIELD_SET` store item, is read by `summarize`, and is consumed by its domain translator — expected: ≥1 round-trip test per new token, 0 new tokens missing from the summary ([generate_plan.py L130-228, L314](../../scripts/plan/generate_plan.py) [VERIFIED]; [router.py L390-432](../../scripts/plan/router.py) [VERIFIED]).
- Every new token is de-identified — a band/class, never raw: a scan of each new token's emitted value finds 0 raw operator values, and a crafted raw value seeded at the token's source item is de-identified by its DERIVATION (the band/class discards the raw value), proven by a per-token output scan — expected: 0 raw values in the new tokens. NOTE: for these raw-backed DERIVED tokens the `summarize` 8j6 gate does NOT run (it covers the pass-through else-path only, `router.py` L416-430), so the per-token output scan — not the 8j6 gate — is the de-identification proof ([router.py L298-305, L406-412](../../scripts/plan/router.py) [VERIFIED]).
- The change-control tripwires stay green with the new tokens present: the module-load disjointness asserts (field-set disjoint from named-excluded raw-PII; every raw source item named-excluded) pass with the extended set — expected: clean module load, 0 tripwire reds ([router.py L307-313, L329-349](../../scripts/plan/router.py) [VERIFIED]).

**Falsification criteria:**
- If a new token is found carrying raw PII in a post-conversation scan (≥1 hit), its DERIVATION is leaky or too-fine — for a raw-backed derived token the `summarize` 8j6 gate does NOT run on its path (`router.py` L406-412 runs no per-value scan), so it would NOT have raised; the failure is the derivation, and the catch is the per-token output scan (a crafted raw value at the source item → 0 raw value in the emitted token). Halt extraction, treat the derivation as broken, and repair its coarseness before the next intake run ([router.py L406-412](../../scripts/plan/router.py) [VERIFIED]).
- If a chat-captured nutrition/supplement/peptide/training fact still never reaches the planner after the extension (≥1 stated, extractor-mapped fact absent from the summary and its translator), the extension did not close the PF-S87-01 gap for that domain — re-open this decision against the un-fed domain before the plan ships ([generate_plan.py L130-228](../../scripts/plan/generate_plan.py) [VERIFIED]; [session-87.md, PF-S87-01](../../vault/sessions/session-87.md) [VERIFIED]).
- If a closed-set disjointness tripwire reds at module load after the extension (≥1 failing assert), a token was added wrong (into neither structure, or overlapping the excluded set) — fix the token placement before ship; a red tripwire is a release blocker ([router.py L307-313, L329-349](../../scripts/plan/router.py) [VERIFIED]).
- Time horizon: run the round-trip, de-identification, and tripwire checks at the first build of each new token and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- A new plan domain is added to the chat surface — decide whether it needs its own field-set token(s) and re-run the round-trip + de-identification checks for them.
- A token's de-identification derivation changes (its band/class buckets are re-cut) — re-verify it still emits a de-identified value and the disjointness tripwires stay green.
- The field-set audit is run (the periodic PII-boundary review of `SUMMARY_FIELD_SET`) — re-confirm every new token is a band/class, is backed by a named-excluded raw source item where raw-derived, and that the audited surface is still readable.
