## ADR-0050: Wire the Context Assembler into Front-Door Authoring with Contract-Driven, Genetics-Aware Specialist Prompts

> **Y-Statement:** In the context of the `/generate-plan` front door — which computes ADR-0042's Context Assembler on the plan path (`generate_plan.py:560`) but discards it, because `orchestrate.generate_plans` calls `compute_plan` with no `client` (`orchestrate.py:794`) so `_FixedEnvelopeClient` replays a thin `router.summarize`-authored envelope and ignores the assembled record (`generate_plan.py:87-88`), and authors that thin envelope through a generic scaffold prompt carrying none of `specialist-plan-contracts.md`'s per-specialist intent and no directive to personalize ### Context

The `/generate-plan` front door produces a plan that ignores the operator's real record. Three forces, each verified against the live tree on `feature/plan-personalization`, make the fix a decision rather than a code comment.

First, **the Context Assembler is computed on the front-door path and then thrown away.** `_do_generate_plan` derives the thin band `summary = router.summarize(store_read)` ([server.py:815](../../scripts/serve/server.py) [VERIFIED]), pre-authors it through the model at `authors[domain] = normalize_author_output(self.client.author(domain, summary))` ([server.py:832](../../scripts/serve/server.py) [VERIFIED]), and hands the resulting envelopes to `orchestrate.generate_plans(authors, …)` ([server.py:843](../../scripts/serve/server.py) [VERIFIED]). `generate_plans` calls `compute_plan(domain, author_output, store_read, gates=gates)` with **no `client=` argument** ([orchestrate.py:794](../../scripts/plan/orchestrate.py) [VERIFIED]). Inside `compute_plan`, `client = client if client is not None else _FixedEnvelopeClient(author_output)` ([generate_plan.py:555](../../scripts/plan/generate_plan.py) [VERIFIED]) wraps the pre-authored envelope; `summary = context_assembler.assemble_context(store_read)` computes the rich identity-stripped record ([generate_plan.py:560](../../scripts/plan/generate_plan.py) [VERIFIED]); but `envelope = _author_callable(client)(domain, summary)` ([generate_plan.py:566](../../scripts/plan/generate_plan.py) [VERIFIED]) runs against `_FixedEnvelopeClient.author(self, domain, summary): return self.author_output` ([generate_plan.py:87-88](../../scripts/plan/generate_plan.py) [VERIFIED]), which discards `summary` entirely and replays the thin envelope. The assembler ADR-0042 built to end DATA-COLLAPSE runs on the front door and reaches no model.

Second, **the author prompt is a generic scaffold with no per-specialist intent and no directive to personalize.** `_author_system_prompt(domain)` ([client.py:510](../../scripts/model/client.py) [VERIFIED]) names a persona and the output schema — "You are a {specialist}… You receive ONLY a de-identified band/class summary of the operator (no names, no raw values) and must produce {domain} recommendations grounded in that summary" ([client.py:515-518](../../scripts/model/client.py) [VERIFIED]). It carries none of the per-specialist Inputs/Monitoring/Tracking/Analysis→plan content designed in [specialist-plan-contracts.md](../../design/specialist-plan-contracts.md) [VERIFIED], which was consumed only for the activation roster and never turned into an authoring input ([plan-grounding §3](/private/tmp/claude-501/-Users-waltermcgivney-Documents-Projects-a-plus-maxing/cbb44fe9-48f8-4a9b-bc4a-c6bd4052b2e1/scratchpad/plan-grounding.md) [VERIFIED]). The real author call feeds this scaffold and `json.dumps(summary)` to the model ([client.py:769,772-773](../../scripts/model/client.py) [VERIFIED]).

Third, **the model is not the constraint.** The author backend runs `MODEL = "claude-opus-4-8"` ([client.py:687](../../scripts/model/client.py) [VERIFIED]) — a strong model receiving a coarse band it is never instructed to personalize from. These forces pull across stakeholders: the operator (and the physician who will read the plan) needs specialists reasoning over the real program, symptoms, and traits; the maintainer must not disturb the ADR-0032 frozen spine; and the data subject's crown-jewel boundary (no raw genotype or lab value to the model) must hold unchanged. No prior gate ever verified real plan quality — all six ADR-0041–0046 "LIVE run" checks were deferred by construction ([plan-grounding §4](/private/tmp/claude-501/-Users-waltermcgivney-Documents-Projects-a-plus-maxing/cbb44fe9-48f8-4a9b-bc4a-c6bd4052b2e1/scratchpad/plan-grounding.md) [VERIFIED]).

### Decision

On the `/generate-plan` path, author each specialist from `assemble_context`'s identity-stripped record by injecting a real model client into `compute_plan` (`client=` non-`None`), so the author reads the assembled free-text record instead of the `_FixedEnvelopeClient` thin replay. Make `_author_system_prompt` contract-driven — carrying each specialist's `specialist-plan-contracts.md` Inputs/Analysis→plan authoring contract — and genetics-aware, with an explicit directive to personalize off the de-identified genetic signal and free-text the author receives (the derived trait-classes today, and — once ADR-0051 surfaces the raw panel — raw rsID+allele genotype calls the prompt must instruct the specialist to interpret). This ADR decides HOW the author consumes whatever the assembler carries; WHAT signal reaches it is not this ADR's — the genetic representation specifically is ADR-0051's decision (it reverses the ADR-0032/0042 carve-out so raw genotypes flow identity-stripped), while labs, medications, and free-text already flow identity-stripped as the assembler's built behavior under the operator's identity-stripping-only de-id standard. The invariant this wiring must preserve is the assembler's identity-strip (no name/DOB/contact/health-identifier to the model, via `pii_scan`), not a raw-value carve-out.

### Rationale

The choice was weighed against keeping the thin `router.summarize` authoring (Alternative A), a fully conversational care-agent-only plan (Alternative B), and hardcoding richer per-domain prompts without the contract file (Alternative C), across four criteria the plan goal makes load-bearing: **personalization fidelity** (does the plan reflect the operator's real record?), **single-sourced authoring intent** (is the per-specialist content one canonical source?), **blast radius** (does the change stay outside the ADR-0032 frozen spine?), and **verifiability** (can real quality be confirmed?).

On **fidelity**, only injecting the real client fixes the root cause: the front door already computes `assemble_context` ([generate_plan.py:560](../../scripts/plan/generate_plan.py) [VERIFIED]); consuming it is the minimum change that lets the author reason over the real program, the shoulder symptom, and the trait-classes rather than the coarse band that `router.summarize` derives. Keeping the thin authoring (A) is the verified cause of the generic plan and cannot deliver fidelity by definition. On **single-sourced intent**, sourcing the prompt from `specialist-plan-contracts.md` makes that file the one place the per-specialist authoring content lives — the same file the roster is already built from — so the authoring intent and the activation partition do not drift; hardcoding (C) would fork it. On **blast radius**, the change lands in `generate_plan.py` / `client.py` / `orchestrate.py` / `server.py`, none of which is one of the ADR-0032 six frozen files (`store.py` / `keying.py` / `pipeline.py` / `adjudicate.py` / `adjust.py` / `router.py`), which stay byte-frozen; `compute_plan` already exposes a keyword-only `client` parameter for exactly this injection ([generate_plan.py:503,534-535](../../scripts/plan/generate_plan.py) [VERIFIED]), so the wiring extends an existing seam rather than reopening the frozen surface. On **verifiability**, wiring a real client makes the plan's dependence on the record testable — a revert of the wiring must change the plan output, which is the falsification hook the thin path structurally lacked.

The two facets — wire the assembler, upgrade the prompt — are one decision, not two. Wiring the assembler without a directive to personalize gives the model a richer input it is not told to use; upgrading the prompt without wiring the assembler gives an instruction with nothing rich to consume. Both are required for the single outcome "the front-door plan personalizes off the operator's real record," which is why they ship as one ADR. Long-term, this authoring contract is what ADR-0051's richer de-identified signal will be consumed through: widening what reaches the author is inert until the author is wired to read it and instructed to personalize from it.

### Consequences

**Positive:**
- The `/generate-plan` plan personalizes off the operator's real identity-stripped record: a section reflects the actual training split, the shoulder symptom, and the operator's trait-classes rather than a `low`/`moderate`/`high`-derived generic ([generate_plan.py:560,566](../../scripts/plan/generate_plan.py) [VERIFIED]).
- The per-specialist authoring content is single-sourced from [specialist-plan-contracts.md](../../design/specialist-plan-contracts.md) [VERIFIED] — the same artifact the activation roster is built from — so authoring intent and activation partition cannot silently diverge.
- The change lands entirely outside the ADR-0032 frozen spine and reuses `compute_plan`'s existing `client` parameter ([generate_plan.py:503](../../scripts/plan/generate_plan.py) [VERIFIED]), so it neither reopens the frozen surface nor adds a new model-boundary egress class.

**Negative:**
- **The author prompt grows per specialist, so per-call token cost rises.** Folding each specialist's contract content into `_author_system_prompt` enlarges every author call, and the effect scales with the ADR-0046 roster — a standing per-generation operational cost, not a one-time hit.
- **Plan quality now depends on the quality of the contract content.** A thin or stale entry in `specialist-plan-contracts.md` yields a thin plan for that domain; the file becomes a load-bearing quality input that must be maintained, not a design artifact.
- **The deferred operator-present LIVE run becomes a hard new dependency.** Real plan quality was never verified — every prior gate checked fixture shape at 0 spend ([plan-grounding §4](/private/tmp/claude-501/-Users-waltermcgivney-Documents-Projects-a-plus-maxing/cbb44fe9-48f8-4a9b-bc4a-c6bd4052b2e1/scratchpad/plan-grounding.md) [VERIFIED]). This ADR can only be confirmed by the operator-present run that spends model budget on real data; that run is now on the critical path to "done," not deferrable.
- **A wiring regression can silently reintroduce the thin replay.** If a future change drops `client=` on the `generate_plans`→`compute_plan` call, the path falls back to `_FixedEnvelopeClient` ([generate_plan.py:555,87-88](../../scripts/plan/generate_plan.py) [VERIFIED]) and re-thins the plan with no error. This requires a test that REDs when the front door authors thin, or the failure is invisible until an operator reads a generic plan.
- **The genetics-aware prompt must interpret raw rsID+allele genotype calls, not just a trait-class token.** Once ADR-0051 surfaces the raw panel, specialists receive genotype-shaped data (e.g. `MTNR1B rs10830963 = (C;C)`), so the prompt must carry genotype-interpretation guidance; a thin genetics directive yields uninterpreted or mis-read calls. This is a new authoring-content burden and correctness risk that ADR-0050 owns (flagged as a consequence in ADR-0051), dependent on ADR-0051's raw-genotype representation.

**Neutral:**
- `router.summarize` persists in its other roles (the care-profile identity-safe base, the de-id-IN summary contract); this ADR changes only the front-door specialist-author input, not the summarizer's other consumers.
- **The assembler carries the operator's raw health data to the model IDENTITY-STRIPPED — the operator-accepted de-id posture (identity-stripping only).** Under that standard the author receives raw labs, medications, and free-text stripped of identity (no name/DOB/contact/health-identifier, via `pii_scan`), which is the assembler's already-built behavior ([context_assembler.py:54-65](../../scripts/plan/context_assembler.py) [VERIFIED]); ADR-0050 consumes this, it does not define it. ADR-0050's "genetics-aware" directive tells the author to personalize off whatever genetic signal the assembler carries — today the derived `genetic-trait-classes` token, and once ADR-0051 supersedes the ADR-0032/0042 carve-out, raw genotypes. Recorded tradeoff: raw genotypes are inherently re-identifying even identity-stripped — an accepted residual of ADR-0051's signal decision that ADR-0050 inherits, not a blocker for this wiring.

### Alternatives Considered

#### Alternative A: Keep the thin `router.summarize` authoring
Leave the front door authoring the pre-authored `_FixedEnvelopeClient` envelope over `router.summarize`'s ~18-token band, and improve the plan by widening the band's field-set instead.
- **Supporting evidence:** Zero change to the authoring wiring; the closed band keeps a mechanically small, auditable model-boundary payload; the field-set has a precedent for additive widening under change control.
- **Trade-offs:** It is the verified cause of the generic plan — the author never sees the operator's free-text program or symptoms ([generate_plan.py:87-88](../../scripts/plan/generate_plan.py) [VERIFIED]), and a coarse band cannot carry a followable, physician-ready section. Widening the band chases fidelity token-by-token against a closed allowlist and, in the limit, reconstructs the assembler with extra ceremony.
- **When this becomes the right choice:** If the set of details a specialist ever needs were small, bounded, and stable, and the operator-present full-record run proved unacceptable on privacy or cost grounds.

#### Alternative B: A fully conversational care-agent-only plan
Drop the pipeline front door as the plan producer and have the care agent synthesize the entire plan conversationally from its full-record view.
- **Supporting evidence:** The care agent already holds full-record access, so it can reason over the real detail without new wiring; a conversation adapts to operator follow-ups that a one-shot plan cannot.
- **Trade-offs:** The plan is a pipeline product — cross-domain reconciliation, safety gates, and the DOMAIN PROGRAM schema (ADR-0041) live in `generate_plans`/`compute_plan`, not in a chat turn; routing all authoring through conversation would bypass those gates or force re-implementing them in the care agent. The operator's entry point is the front-door button, not a chat prompt.
- **When this becomes the right choice:** If the product pivoted so the primary plan surface were the conversation and the pipeline gates were re-homed behind it.

#### Alternative C: Hardcode richer per-domain prompts without the contract file
Wire the real client into `compute_plan`, but write richer per-domain authoring instructions directly in `_author_system_prompt` rather than sourcing them from `specialist-plan-contracts.md`.
- **Supporting evidence:** Delivers the fidelity gain (the author still reads the assembled record) with no dependency on the design file's format; the prompt author controls the wording directly.
- **Trade-offs:** It forks the per-specialist authoring intent away from `specialist-plan-contracts.md`, which is the single source the activation roster is already built from ([plan-grounding §3](/private/tmp/claude-501/-Users-waltermcgivney-Documents-Projects-a-plus-maxing/cbb44fe9-48f8-4a9b-bc4a-c6bd4052b2e1/scratchpad/plan-grounding.md) [VERIFIED]); the two representations of "what this specialist does" then drift, and a contract change no longer propagates to authoring. It trades single-sourcing for short-term prompt-authoring convenience.
- **When this becomes the right choice:** If `specialist-plan-contracts.md` were retired as the roster source, so there were no single-source invariant left to protect.

### Validation Approach

**Confirmation criteria:**
- **The front-door author call receives the assembled record (executable):** on the `/generate-plan` path, assert the model author call's `summary` argument carries `assemble_context`'s free-text fields (`raw-training-detail-free-text`, `raw-symptom-free-text`, `raw-supplement-free-text`) — not `router.summarize`'s ~18-token band. Threshold: ≥3 free-text fields present in the author payload; 0 if the client-wiring is inert. If the author payload is byte-identical to `router.summarize`'s output, the wiring did not take — halt.
- **The prompt carries the specialist's contract (executable):** assert `_author_system_prompt(domain)` for ≥1 domain contains that specialist's `specialist-plan-contracts.md` Inputs/Analysis→plan content and the personalize directive. Threshold: the contract-derived content and the genetics-aware directive are both present; the generic-scaffold-only string fails.
- **The real plan cites operator-specific detail (operator-present):** the operator-present LIVE run produces a plan that cites ≥1 operator-specific detail the coarse band would have erased — the actual training split, the shoulder symptom, and ≥1 genetic signal (a trait-class today; a genotype-derived recommendation once ADR-0051 surfaces the raw panel). Threshold: ≥1 such detail per active domain; a plan expressible from the band alone fails.

**Falsification criteria:**
- **Reverting the client-wiring leaves the plan unchanged → the wiring is inert:** run the plan path with and without the real client injected. Threshold: the two plans must differ on ≥1 operator-specific detail. If reverting `client=` produces a byte-identical plan, the assembler is not being consumed — the wiring is a no-op; halt and repair before release. This is the RED-capable guard against the silent thin-replay regression.
- **The real plan still ignores the free-text/traits after the fix → the directive is ineffective:** at the operator-present run, if the plan cites none of the operator's free-text detail or trait-classes despite the author receiving them, the prompt directive is not steering the model. Threshold: 0 operator-specific details in the plan while ≥3 free-text fields were in the author payload → the prompt directive, not the wiring, is the defect.
- **An identity token reaches the author payload → the wiring broke the load-bearing safety invariant:** scan the front-door author payload for pure-identity tokens (name / DOB / contact / health-identifier — the `pii_scan` strip the assembler enforces, [context_assembler.py:54-65](../../scripts/plan/context_assembler.py) [VERIFIED]). Threshold: **0 identity tokens** in any author payload; ≥1 means the wiring is passing something other than the assembler's stripped output — halt and repair before release. This is the invariant ADR-0050's wiring must preserve (identity-strip), distinct from any raw-value carve-out, which the operator's identity-stripping-only standard does not require.
- **Time horizon:** run the payload-content, prompt-content, and identity-strip assertions at the first build; run the plan-difference falsification at every release; run the operator-specific-detail check at the operator-present LIVE run before the July-2026 physician-visit deliverable.

**Review triggers:**
- A new plan-path author consumer is added (the ADR-0046 roster scale-up) — verify it reads the injected client, not a residual `_FixedEnvelopeClient` replay.
- `specialist-plan-contracts.md` changes — re-verify the author prompt still sources from it (the single-source invariant).
- Per-generation token cost or latency crosses an operational threshold — re-evaluate the full-contract prompt against a per-specialist relevant slice.
- ADR-0051 lands richer de-identified signal — re-verify the author both receives and is instructed to personalize from the new fields.
