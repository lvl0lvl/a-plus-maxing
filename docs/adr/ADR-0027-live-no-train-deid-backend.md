## ADR-0027: Wire the Live No-Train API De-Identification Backend (`_ClaudeNoTrainBackend.deidentify`)

> **Y-Statement:** In the context of the S92 plan-generation engine, where the de-id-IN boundary ADR-0020 decided is live-callable through `deid_in(raw_intake, client)` but its default backend method `_ClaudeNoTrainBackend.deidentify` is still a `NotImplementedError` stub, facing the tension between needing a real model-backed de-id call that ingests raw operator plan-intake PII and the crown-jewel requirement that no raw PII ever returns past the boundary or persists, we decided to wire the live backend as a single `claude-opus-4-8` no-train API call — model id kept as the swappable `MODEL` class attribute (ADR-0015), emitting only a `SUMMARY_FIELD_SET`-bounded de-identified summary, fail-closed to `ModelCallError` on any failure or out-of-set response — to achieve the highest-recall de-id of rich free-form intake while the deterministic `deid_in` whitelist backstops every miss, accepting that raw plan-intake PII now actually transits the no-train API (the live form of ADR-0020's crown-jewel relaxation), that the no-train property is a contractual requirement on the injected key rather than a per-request flag the SDK exposes, and that a model failure halts plan-generation to honest-no-plan.

### Context

The plan path's de-id-IN boundary is decided (ADR-0020) and live-callable in shape, but not live. `deid_in(raw_intake, client)` is the sole de-id-IN on the plan path: it routes the de-id call through `client.deidentify(raw_intake)`, enforces that the returned summary's keys are a subset of `SUMMARY_FIELD_SET`, and fails closed to the honest no-plan sentinel `{"deidentified": False, "reason": DEID_CALL_FAILED, "error_type": ...}` on any exception or out-of-set field ([deid_in.py:30-73](../../scripts/plan/deid_in.py) [VERIFIED]). The `ModelClient.deidentify(raw_intake)` seam already validates the backend result is a mapping and raises `ModelCallError` otherwise ([client.py:78-95](../../scripts/model/client.py) [VERIFIED]). What is missing is the backend itself: `_ClaudeNoTrainBackend.deidentify` still raises `NotImplementedError("live deidentify is wired at the Wave-B operator checkpoint; tests inject a backend")` ([client.py:156-160](../../scripts/model/client.py) [VERIFIED]). No plan-generation front door constructs a live de-id client today; the only `ModelClient()` constructions are the intake server and a test fixture ([.pipeline/live-wiring/discovery.md](.pipeline/live-wiring/discovery.md) [VERIFIED]).

Two forces pull against each other. The boundary exists to de-identify rich free-form plan-intake faithfully, which only a capable model can do — the deterministic `router.summarize` derivers collapse a paragraph to one closed-vocabulary token, the lossiness the conversational pivot exists to overcome ([ADR-0020, Context](ADR-0020-model-backed-api-deid-boundary-in.md) [VERIFIED]). Against that stands the crown-jewel containment: this is the ONE model call that ingests raw operator PII, and a missed PII token in the model's emitted summary is a leak past the de-id-IN boundary into every downstream specialist dispatch. The mitigation is structural — `deid_in` rejects any summary carrying a field outside `SUMMARY_FIELD_SET` ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]) — so a non-faithful de-id call that smuggles a raw-PII field under a novel key fails closed rather than crossing. But the whitelist gates field NAMES, not the de-identified-ness of values under an in-set key; the model's de-id fidelity still carries weight.

The decision binds the data subject, not only the operator. The raw plan-intake may name medications, labs, the January-2026 issue, and identity; routing it to an API before de-identification is the surface ADR-0001's "Only plan reasoning touches the model, over summaries rather than raw PII" falsification named as a breach ([ADR-0001, Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]), and ADR-0005 keeps that PII out of committed history, where a leak cannot be cleanly scrubbed ([ADR-0005, Decision](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]). The no-train lane this runs on is the bounded second raw-egress class ADR-0020 added to ADR-0016's carve-out ([ADR-0016, Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). The key the backend uses is resolved at call time from the `ANTHROPIC_API_KEY` env var (or the `a-plus-maxing-api-key` macOS-keychain item), never captured at module load and never read from a tracked file ([key_source.py:64-90](../../scripts/model/key_source.py) [VERIFIED]). Because wiring the live backend fixes the model id, the prompt→summary contract, and the fail-closed posture that the whole boundary's containment rests on — not just a code comment — it is a decision, not implementation.

### Decision

Wire `_ClaudeNoTrainBackend.deidentify` as a single live `claude-opus-4-8` no-train API call that ingests the raw operator plan-intake and returns ONLY a de-identified summary whose fields are a subset of `SUMMARY_FIELD_SET`. The model id is the existing swappable `MODEL` class attribute, not a literal buried in the call. The backend raises `ModelCallError` on any API failure or malformed/out-of-set response; the no-train property is a contractual requirement on the injected key, not a per-request SDK flag. The persisted-side `router.summarize` gate is unchanged (the same `SUMMARY_FIELD_SET` shape `router.summarize` emits persisted-side — `deid_in` enforces the subset, so the live IN summary and the persisted summary share ONE contract, not two distinct summaries).

### Rationale

The model id was evaluated across three criteria the crown-jewel boundary makes load-bearing — **PII-recall safety** (the probability the emitted summary leaks no raw token), **cost-per-call**, and **latency** — against the four available models (`claude-fable-5`, `claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5`) [VENDOR-CLAIM: claude-api model catalog, cached 2026-06-04].

On **PII-recall safety**, the asymmetry is decisive: a missed raw token is a crown-jewel leak (irreversible if it then persists), while the downstream cost of a spuriously-conservative de-id is only a slightly coarser plan — so the decision weights recall over thrift. `claude-opus-4-8` is the most capable widely-released production model below the Fable tier and is the project's standing default for model calls (it is already the pinned `MODEL`, [client.py:135](../../scripts/model/client.py) [VERIFIED]) [VENDOR-CLAIM]. The deterministic `SUMMARY_FIELD_SET` whitelist in `deid_in` is the second line — a non-faithful summary carrying an out-of-set field fails closed ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]) — but it gates field NAMES only, so it cannot catch raw PII smuggled inside an in-set field's value; the model's recall still carries real weight, which is why the cheaper tiers are not chosen for a one-call-per-plan-gen crown-jewel step.

On **cost-per-call**, this is one de-id call per plan-generation (not a per-turn loop), so the per-call delta between tiers is small in absolute terms: `claude-opus-4-8` is $5/$25 per MTok input/output vs `claude-sonnet-4-6` at $3/$15, `claude-haiku-4-5` at $1/$5, and `claude-fable-5` at $10/$50 [VENDOR-CLAIM: claude-api model catalog]. The intake is a bounded summary-sized payload, so Opus-tier cost on a single call is acceptable against the leak risk the cheaper tiers raise; Fable's 2× premium buys recall headroom not justified for a structured-extraction task with a deterministic backstop. On **latency**, all four are single-call latencies on a synchronous de-id step that gates the whole run; none is fast enough to change the run's UX character, so latency does not separate them and is not the deciding axis.

The model id is held as the `MODEL` class attribute so the choice stays a one-line swap at the ADR-0015 seam, not a re-plumb — the local-model North Star (ADR-0001 Alternative C) retracts the raw egress to zero by swapping the backend, callers unchanged ([ADR-0015, Decision L22](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]). Long-term, the cost the decision accepts permanently for V1 is the standing no-train API + network dependency on the de-id-IN step and the bounded raw-PII egress; the mitigation that keeps it falsifiable is the fail-closed `ModelCallError` contract plus the retained `SUMMARY_FIELD_SET` whitelist, both made testable below.

### Consequences

**Positive:**
- The de-id-IN boundary becomes live end-to-end: a real `claude-opus-4-8` call de-identifies rich free-form plan-intake into the `SUMMARY_FIELD_SET`-shaped summary the orchestrator consumes, replacing the `NotImplementedError` stub ([client.py:156-160](../../scripts/model/client.py) [VERIFIED]) — the last missing piece of the de-id-IN seam ADR-0020 decided.
- Containment is double-gated and unchanged at the persisted side: the model emits only de-identified fields, AND `deid_in` rejects any summary with an out-of-`SUMMARY_FIELD_SET` field, failing closed to the honest no-plan sentinel rather than returning a contaminated dict ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]); `router.summarize` still gates the persisted store, so the store stays de-identified regardless of the live IN call ([ADR-0020, Consequences](ADR-0020-model-backed-api-deid-boundary-in.md) [VERIFIED]).
- The model id stays a one-line swap at the ADR-0015 `MODEL` attribute, keeping the local-model North-Star retraction a backend swap rather than a re-plumb ([ADR-0015, Consequences L37](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]).

**Negative:**
- Raw operator plan-intake PII now ACTUALLY transits the no-train API before de-identification — the live form of ADR-0020's crown-jewel relaxation. Where the stub never sent anything, the live call sends raw intake (medications, labs, the January-2026 issue, identity) to the no-train API, a real and permanent (1+ year) expansion of the plan-path egress surface, under the no-train lane's bounded retention ([ADR-0001, Falsification L105](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- The no-train property is NOT enforced per-request by the SDK: there is no per-request no-train / zero-data-retention flag on `messages.create` — ZDR/no-train is an org/account property of the KEY (confirmed by the inverse: an org set to zero-data-retention makes some models 400) [VENDOR-CLAIM: claude-api SDK reference]. So the boundary's no-train guarantee rests on the operator injecting a no-train key, a contractual precondition this ADR documents rather than a mechanism it can assert in code [UNVERIFIED: the specific no-train terms of the `a-plus-maxing-api-key` key are operator-asserted, not verified against published policy — OQ-2].
- The de-id-IN step gains a hard runtime dependency on the no-train API and network: a model error, timeout, or malformed response raises `ModelCallError`, which `deid_in` turns into DEID_HALTED honest-no-plan, so a de-id outage yields 0 plans rather than a degraded plan — correct, but it means plan-generation is offline-incapable at the de-id-IN step ([client.py:105-123](../../scripts/model/client.py), [deid_in.py:61-72](../../scripts/plan/deid_in.py) [VERIFIED]).
- A new live raw-input surface is introduced: the raw plan-intake handed to the call must never reach a tracked file. The mitigation is that raw residue lands only on the gitignored `vault/scaffold/filled/` / `vault/store/` surfaces and the `block-pii-commit.sh` + `pre-push-pii-scan.sh` hooks deny a committed raw/PII path, but the discipline of keeping raw plan-intake off the tracked tree is now exercised against a real call, not a stub ([ADR-0005, Decision](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]).

**Neutral:**
- The no-train API becomes a runtime dependency for plan-intake de-id specifically, alongside its ADR-0015 roles for intake conversation and plan-author dispatch; the store, ingestion, and dashboard generation stay model-independent per ADR-0001 ([ADR-0001, Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- `claude-opus-4-8` becomes the recorded de-id model behind the `MODEL` attribute; a future provider/model change is a backend-attribute edit, not a caller change.

### Alternatives Considered

#### Alternative A: Live `claude-opus-4-8` no-train call behind the swappable `MODEL` attribute (Chosen)
Wire `_ClaudeNoTrainBackend.deidentify` to call `claude-opus-4-8` over the no-train lane, model id held as the existing `MODEL` class attribute, emitting a `SUMMARY_FIELD_SET`-subset summary and raising `ModelCallError` on any failure.
- **Supporting evidence:** Highest PII-recall of the production-tier models on the crown-jewel miss, and already the project's pinned default ([client.py:135](../../scripts/model/client.py) [VERIFIED]) [VENDOR-CLAIM]. One call per plan-gen makes the Opus-tier per-call cost ($5/$25 per MTok) acceptable against the leak risk [VENDOR-CLAIM: claude-api model catalog]. The deterministic `deid_in` whitelist backstops every field-name miss ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]). Runs through the existing ADR-0015 seam, so the local-model swap stays a backend edit.
- **Trade-offs:** Pays the Opus-tier per-call cost and a network/latency dependency the cheaper tiers would reduce, and routes raw PII across the API under bounded no-train retention. Accepted because the crown-jewel recall asymmetry dominates the per-call cost on a single call, and the egress reuses ADR-0020's already-adopted posture.
- **When this becomes the right choice:** It is, for V1, when the de-id-IN boundary must be live, the no-train commercial lane is the model surface, and the local-model North Star has not reached parity.

#### Alternative B: Cheaper-tier model (`claude-sonnet-4-6` or `claude-haiku-4-5`) for the de-id call
Wire the same live no-train call but pin a lower-cost model for the de-id extraction, relying more heavily on the deterministic `SUMMARY_FIELD_SET` whitelist as the safety net.
- **Supporting evidence:** Genuinely lower per-call cost — `claude-sonnet-4-6` at $3/$15 and `claude-haiku-4-5` at $1/$5 per MTok vs Opus-tier $5/$25 [VENDOR-CLAIM: claude-api model catalog] — and de-id is structured extraction over a bounded payload, a task class where smaller models are often adequate. The `deid_in` whitelist catches any out-of-set field a weaker de-id emits, so a field-NAME miss still fails closed rather than crossing ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]).
- **Trade-offs:** The whitelist gates field NAMES, not the de-identified-ness of a value under an in-set key — a weaker model that leaves a raw token inside an allowed field's value passes the whitelist, so lower model recall directly raises crown-jewel leak risk on the one call that ingests raw PII. The per-call saving is small in absolute terms (one call per plan-gen) and does not justify trading recall on the boundary the whole containment rests on.
- **When this becomes the right choice:** If the intake payload grows so large or plan-gen so frequent that de-id cost becomes material AND independent measurement shows a cheaper tier's de-id recall is at parity on the operator's intake shape — then the cheaper tier is the right pin behind the same `MODEL` attribute.

#### Alternative C: Deterministic regex / NER de-identification, no model call
Replace the model-backed de-id with a deterministic named-entity-recognition / regex pipeline that strips identity, contact, and clinical tokens from the raw intake locally, keeping the de-id-IN step model-free and offline.
- **Supporting evidence:** Zero raw-PII egress on the de-id-IN step (nothing leaves the device), zero per-call cost, no network dependency, and no no-train-key precondition — the strongest IN-side privacy posture. It is the same family as the existing deterministic `router.summarize` derivers, which already strip named-excluded raw-PII fields locally ([router.py SUMMARY_FIELD_SET](../../scripts/plan/router.py) [VERIFIED]).
- **Trade-offs:** Brittle on free-form intake — regex/NER misses novel PII forms (an unusual identifier, an embedded address, a misspelled drug name) and cannot de-identify the rich conversational detail the pivot exists to surface; it reproduces the keyword-bucketer lossiness ADR-0020 rejected, and a missed novel form is exactly the crown-jewel leak the model-backed boundary was chosen to reduce ([ADR-0020, Alternative B](ADR-0020-model-backed-api-deid-boundary-in.md) [VERIFIED]). ADR-0020 already adjudicated the deterministic-only posture as too lossy for the rich-intake target; this ADR wires the boundary that decision settled, it does not re-open it.
- **When this becomes the right choice:** If a future privacy constraint forbids ANY raw plan-intake egress, the deterministic gate is restored as the sole de-id-IN — ADR-0020's Alternative-B / dissent condition, not a V1 wiring option.

#### Dissent: The summaries-not-raw purist position (inherited from ADR-0020)
**Source:** ADR-0020's recorded dissent — ADR-0001's anchor that the plan path's de-id-IN should never be a model boundary, so raw plan-intake reaching an API before de-id is a genuine weakening of the system's most load-bearing privacy guarantee ([ADR-0020, Dissent](ADR-0020-model-backed-api-deid-boundary-in.md) [VERIFIED]; [ADR-0001, Falsification L105](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]). A reviewer can reasonably hold that turning the stub into a real call is the moment the relaxation becomes concrete, and the deterministic gate (Alternative C) is the correct posture even at the cost of de-id fidelity.
**Conditions under which this becomes the right choice:** If the no-train provider's no-train or retention terms degrade (raw plan-intake becoming training-eligible or indefinitely retained), OR if a local open-weight model reaches intake-de-id parity on the operator's hardware (ADR-0001 Alternative C's condition) — in either case the live model-backed de-id-IN should be retracted (the backend swapped) and the deterministic gate restored as the sole de-id-IN.

### Validation Approach

**Confirmation criteria:**
- The backend is mock-testable at 0 live spend: a patched `anthropic` SDK / injected fake backend returns a canned envelope, and the test asserts (a) the prompt passed to the call carries the raw intake, (b) the parsed summary's keys are a subset of `SUMMARY_FIELD_SET`, and (c) the de-id runs on the no-train lane only — expected: parsed summary ⊆ `SUMMARY_FIELD_SET`, count of de-id calls on any non-no-train lane = 0 ([deid_in.py:71-72](../../scripts/plan/deid_in.py) [VERIFIED]).
- The model id resolves from the `MODEL` class attribute, not a buried literal: a scan of the backend confirms the de-id call reads `MODEL` and that swapping `MODEL` requires no caller-side edit — expected: 1 `MODEL` reference at the call, 0 caller-side edits to change the de-id model ([client.py:135](../../scripts/model/client.py) [VERIFIED]).
- The persisted side stays de-identified after a live-wired plan-intake run: scan the post-run store and `router.summarize` output for raw operator PII — expected: 0 raw-PII hits ([ADR-0020, Confirmation](ADR-0020-model-backed-api-deid-boundary-in.md) [VERIFIED]).

**Falsification criteria (including the raw-PII-leak probe):**
- Raw-PII-leak probe (the crown-jewel test): seed a known raw-PII token (a synthetic legal name + a synthetic lab value) into the raw plan-intake, run the live-wired de-id backend, and scan (a) the de-identified summary the pipeline consumes and (b) every committed/persisted file on a fresh-clone scan. Threshold: **0 raw-PII hits past the boundary AND 0 raw-PII hits in any committed/persisted file**. If ≥1 hit in either, the live backend leaked — halt and repair the de-id call / restore the gitignore boundary before release.
- Fail-closed-on-error: inject an API failure / timeout / a malformed (non-mapping) response / a response carrying a field outside `SUMMARY_FIELD_SET`, and assert the backend raises `ModelCallError` and `deid_in` returns the DEID_HALTED sentinel → 0 plans. Threshold: ≥1 plan produced over a fabricated, partial, or out-of-set summary = breach — halt and restore the fail-closed degrade before release ([client.py:105-123](../../scripts/model/client.py), [deid_in.py:61-72](../../scripts/plan/deid_in.py) [VERIFIED]).
- Key-never-committed scan: grep every tracked file and git history on a fresh clone for the API key value. Threshold: **0 API-key hits**; ≥1 hit is release-blocking — revert the leaking path ([key_source.py:64-90](../../scripts/model/key_source.py) [VERIFIED]).
- Lane bound: if any de-id call is observed on a training-eligible / general lane (≥1 such call), the no-train bound has failed — halt and restore the no-train routing before release.
- Time horizon: run the raw-PII-leak probe, the fail-closed check, the key-never-committed scan, and the lane check at the first build of the live backend, at the operator-present LIVE test (S94), and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- A change to the no-train provider's commercial no-train terms or retention policy — re-verify the no-train claim now extended to raw plan-intake (OQ-2).
- A change to the available model set or pricing that shifts the recall-vs-cost trade-off — re-evaluate the `MODEL` pin against the three criteria.
- The North-Star transition to a local model is initiated — swap the backend; the raw plan-intake egress retracts to zero and this relaxation closes.
- Any proposal to add a THIRD raw-egress class (beyond the conversation and plan-intake de-id) — re-open this decision and ADR-0016 against the bound.
