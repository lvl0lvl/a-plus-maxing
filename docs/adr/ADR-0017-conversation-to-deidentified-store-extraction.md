## ADR-0017: Adopt a Conversation→De-Identified-Store Extraction Contract That Writes Only SUMMARY_FIELD_SET-Class Facts the Planner Reads

> **Y-Statement:** In the context of the conversational-intake pivot, where the raw intake dialogue egresses to the no-train model under ADR-0016 but the planner's input must stay de-identified (the `SUMMARY_FIELD_SET` discipline), facing the tension between the convenience of trusting the model to emit clean structured facts and the crown-jewel posture of never trusting the model to self-de-identify, we decided that chat-extracted facts are written through the SAME two-surface, gate-enforced routing as the structured form — de-identified facts to `store.append` under the token name, raw to the gitignored scaffold — with de-identification enforced at the extraction boundary by the deterministic `capture` value gates BEFORE any store write, to achieve a dialogue-sourced planner input that cannot carry raw operator PII into a model-bound token, accepting that the extractor is the first consumer of model output through the `capture` de-identification gate (the structured form's gate was fed named form fields, never model output) — a mis-classified fact could route raw detail toward a token if the gate has a gap — that free dialogue is lossy-to-structure, and that domains lacking a de-identified token route record-only until the field-set is extended.

### Context

The conversational-intake pivot makes the raw dialogue the one layer that egresses raw to the no-train model: ADR-0016 scoped ADR-0001's zero-egress boundary so the live conversation may cross, while "every persisted fact — the time-series store and the plan-reasoning summary — stays de-identified" ([ADR-0016, Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). That leaves an unsolved seam: the conversation is unstructured free text that may carry raw operator PII anywhere — a medication name, the January-2026 issue, a lab specific, an address — yet the planner reads only the closed de-identified `SUMMARY_FIELD_SET` ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]). Something must turn the dialogue into the field-set-class facts the planner consumes without letting raw detail reach a model-bound token.

Two forces pull against each other. The convenient path is to trust the model to emit clean structured facts — the dialogue model already holds the conversation, so asking it to return de-identified `SUMMARY_FIELD_SET` values is one prompt away and needs no post-parse gate. Against that stands the crown-jewel posture the system is built on: ADR-0001 fixed "sending zero operator PII to any model," realized mechanically as `summarize()` being the 0-raw-PII boundary that raises on any pass-through value carrying raw PII ([router.py L352-432](../../scripts/plan/router.py) [VERIFIED]), and ADR-0014 already established that captured input is routed by data class through deterministic gates, never trusting the producer — a raw value mis-routed into a `SUMMARY_FIELD_SET` store item must be caught by the `summarize` 8j6 gate, not prevented only by the producer's good behavior ([capture.py L189-244](../../scripts/serve/capture.py) [VERIFIED]; [ADR-0014, Consequences-Negative L40](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]). A model that self-de-identifies is exactly the producer the de-identification gate exists not to trust. A second tension is that ADR-0014 routes NAMED form fields through `capture.persist_capture` by data class ([capture.py L213-239](../../scripts/serve/capture.py) [VERIFIED]); free dialogue has no named fields, so the conversation→named-facts step is a genuinely new contract, not a reuse of the existing form routing as-is. Because this redraws WHERE and HOW de-identification is enforced for unstructured dialogue rather than implementing an existing rule, it is a decision, not a code comment.

### Decision

Chat-extracted facts are written through the SAME two-surface, gate-enforced routing the structured form already uses — de-identified facts to `store.append` under the `SUMMARY_FIELD_SET` token name tagged `source: "intake"`, raw or record-only context to the gitignored `vault/scaffold/filled/` scaffold. De-identification is enforced at the extraction boundary: the model's extraction output passes through the same deterministic `capture` value gates (the bounded-enum gate, the full-value PII scan, and the by-data-class routing) BEFORE any `store.append`, and the `router.summarize` 8j6 PII gate remains the runtime backstop. The model proposes facts; the deterministic gate disposes — a model-emitted fact carrying raw PII routes record-only or is rejected, never silently into a model-bound token.

### Rationale

The extraction contract was evaluated against three alternatives across three criteria this architecture makes load-bearing: where de-identification is enforced, trust-the-model versus gate-enforced disposal, and reuse of the existing capture routing versus a new mechanism.

On **where de-identification is enforced**, the decision places it at the same boundary `capture.persist_capture` already enforces it for the form: the `_bounded_value_ok` enum gate routes a crafted out-of-set value record-only rather than into the model-bound token, and `_value_has_pii` scans a free-text value in full (via `scan_text_full`, which has no window boundary a long postal can straddle) and routes a positive hit record-only ([capture.py L125-147, L98-122, L216-225](../../scripts/serve/capture.py) [VERIFIED]). Letting the de-identification happen only inside the model (Alternative A) moves the boundary off the deterministic substrate entirely, so the only enforcement left would be the `summarize` 8j6 backstop firing after a raw value already landed in the store — a fail-AFTER, not a fail-BEFORE. On **trust-the-model versus gate-enforced**, the model is structurally the wrong place to vest the de-identification guarantee: it is a probabilistic producer, and ADR-0014 already adjudicated that a capture path must route raw values through gates that the producer cannot bypass ([ADR-0014, Decision L22](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]); the extractor is a strictly less-trusted producer than a named form field, so it needs the gate at least as much. "Model proposes, gate disposes" keeps the trust boundary deterministic — the same posture `dispatch`'s whitelist takes, rejecting any field outside the closed set before the send ([router.py L435-440](../../scripts/plan/router.py) [VERIFIED]). On **reuse versus new mechanism**, writing through `store.append` unchanged ([store.py L134-162](../../scripts/store/store.py) [VERIFIED]) and the `vault/scaffold/filled/` record-only surface ([capture.py L168-186](../../scripts/serve/capture.py) [VERIFIED]) means the extractor inherits the store-adversarial battery and the same two-surface PII guard the form already passes, rather than minting a parallel persistence path a second consumer would have to bridge — the extractor adds only the dialogue→facts producer in front of the existing gates.

Long-term, the contract's value is that the de-identification boundary does not move when the producer changes: the structured form and the chat extractor are two producers feeding one gate-at-write surface, so a future producer (a richer model, a different provider behind the ADR-0015 seam) lands behind the same gates. The cost the decision accepts permanently is that the extractor is the first consumer of model output through the `capture` de-identification gate (the structured form's gate was fed named form fields, never model output), so the gate's coverage — not the model's good behavior — is what stands between a mis-classified fact and a model-bound token. (The plan-author dispatch under ADR-0015 is also model output, but it flows through `assemble`'s filters, not this `capture`/`persist_capture` de-identification gate.)

### Consequences

**Positive:**
- A dialogue-sourced fact reaches the planner only as a de-identified `SUMMARY_FIELD_SET`-class value: the extraction output passes the same `_bounded_value_ok` / `_value_has_pii` gates and by-data-class routing the form uses before any `store.append`, so the planner's input contract is unchanged and no new consumer is introduced ([capture.py L189-244](../../scripts/serve/capture.py) [VERIFIED]; [router.py L352-432](../../scripts/plan/router.py) [VERIFIED]).
- The extractor reuses the unchanged `store.append` write and the gitignored `vault/scaffold/filled/` record-only surface, so it inherits the store-adversarial battery and the two-surface PII guard rather than forking a parallel persistence path ([store.py L134-162](../../scripts/store/store.py) [VERIFIED]; [capture.py L168-186](../../scripts/serve/capture.py) [VERIFIED]).
- The de-identification boundary is producer-agnostic: the structured form and the chat extractor feed one gate-at-write surface, so the persisted side stays de-identified exactly as ADR-0016 requires, honoring its "store stays de-identified" half without a second mechanism ([ADR-0016, Decision](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).

**Negative:**
- The extractor is a NEW model-output-trusting surface — the first consumer of model output through the `capture` de-identification gate (the structured form's gate was fed named form fields, never model output), rather than named form fields. A model-emitted fact mis-classified by the extraction step could route raw detail toward a token if the deterministic gate has a coverage gap; the risk is mitigated by the same gates the form uses plus the `summarize` 8j6 backstop, but a documented residual already exists at the form's free-text gate (a diagnosis deliberately typed into a goals field is not caught — the model path is no-train and a clinical-PHI detector is out of scope), and that residual now applies to model-emitted free-text too ([capture.py L88-95](../../scripts/serve/capture.py) [VERIFIED]; [router.py L425-430](../../scripts/plan/router.py) [VERIFIED]). The gate's coverage, not the model's behavior, is the load-bearing guarantee — a standing 1+ year discipline cost.
- Free dialogue is lossy-to-structure: the extraction step maps unstructured turns to a closed set of named facts, so nuance the operator stated that has no field-set home is dropped or mis-bucketed — a real fidelity loss the form did not have (its fields were named) and the conversation's richness exists to surface.
- Domains lacking a de-identified `SUMMARY_FIELD_SET` token route record-only and never reach the planner until the field-set is extended: nutrition, the supplement/peptide stack, and peptides carry no dietary or supplement token today ([router.py L18-36](../../scripts/plan/router.py) [VERIFIED]), so a chat-extracted nutrition fact lands on the gitignored scaffold as record-only exactly as ADR-0014 does — the standing ADR-0014-OQ-1 constraint, now inherited by the chat path ([ADR-0014, OQ-1 L99](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]).

**Neutral:**
- The conversation transcript and any raw extraction residue become another value class that must stay off the tracked tree — held transiently for the live session, any persisted residue landing only on gitignored surfaces (ADR-0005), the no-committed-transcript guarantee resting on the `block-pii-commit` / pre-push backstop ([ADR-0016, OQ-2 L114](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).
- The dialogue→named-facts extraction step becomes a producer the system must classify against the `SUMMARY_FIELD_SET` / record-only split for every domain the chat covers, the same classification discipline ADR-0014 imposed on each wired form field ([capture.py L50-56](../../scripts/serve/capture.py) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Let the model write the store directly
Have the dialogue model emit de-identified `SUMMARY_FIELD_SET` values and write them to `store.append` itself, with no deterministic post-parse gate at the extraction boundary.
- **Supporting evidence:** Fewest moving parts — the model already holds the conversation, so a single structured-output prompt produces store-ready facts with no intermediate gate to design or maintain; it is the fastest path to a chat-sourced store write.
- **Trade-offs:** It trusts the model to self-de-identify, which is precisely the producer the de-identification gate exists not to trust — a probabilistic model that returns a raw drug name or address under a token name would write it straight into a model-bound item, and the only thing left to catch it is the `summarize` 8j6 backstop firing AFTER the raw value already landed in the store ([router.py L425-430](../../scripts/plan/router.py) [VERIFIED]). It defeats the gate-enforced boundary ADR-0014 established for the form ([ADR-0014, Decision L22](ADR-0014-web-form-capture-operator-input-persistence.md) [VERIFIED]). Rejected because it moves the de-identification guarantee off the deterministic substrate into the least-trusted producer.
- **When this becomes the right choice:** If the model were a locally-run, fully-audited de-identifier whose output were independently verifiable per call (the North-Star local model with a proven de-identification contract), the post-parse gate would be redundant overhead rather than the trust boundary.

#### Alternative B: Extract to a raw structured form first, then de-identify in a second pass
Have the extractor write the dialogue into a raw structured intermediate (named fields holding raw values), then run a separate de-identification pass over that intermediate before the store write.
- **Supporting evidence:** A two-pass split is auditable — the raw intermediate is a complete record of what the extractor parsed, so a de-identification regression can be diagnosed against the raw structure, and the de-identification logic is testable in isolation against a fixed intermediate.
- **Trade-offs:** It persists a raw structured intermediate, which is a NEW PII-at-rest surface: a structured file of raw operator values that must itself be kept off the tracked tree and scrubbed, whereas the one-pass gate-at-write never materializes a raw structured record at all — raw values route to the gitignored scaffold or are rejected at the boundary, the same single-surface discipline the form uses ([capture.py L216-239](../../scripts/serve/capture.py) [VERIFIED]). Rejected because it pays a second PII-at-rest surface to buy an audit trail the one-pass path does not need for V1.
- **When this becomes the right choice:** If a raw audit trail of the extractor's parse were a hard requirement — e.g. a replay/debug stream of exactly what each dialogue turn produced before de-identification — the two-pass split wins, accepting the extra raw surface as the cost of the audit record (the same condition ADR-0014's Alternative C named for a keystroke audit stream).

#### Alternative C: Reuse `capture.persist_capture` unchanged
Route the dialogue through the existing `persist_capture` by-data-class routing with no new contract — treat the chat's output as if it were form fields.
- **Supporting evidence:** Zero new code on the persistence side — `persist_capture` already routes named fields by data class through the gates, so if the dialogue could be presented as named fields it would inherit the entire two-surface guard with nothing added ([capture.py L189-244](../../scripts/serve/capture.py) [VERIFIED]).
- **Trade-offs:** It is insufficient, not wrong: `persist_capture` routes NAMED form fields keyed by the form's field names ([capture.py L213-239](../../scripts/serve/capture.py) [VERIFIED]), but free dialogue has no named fields — the missing piece is exactly the dialogue→named-facts mapping step, which is the new contract this ADR decides. Reusing `persist_capture` is correct for the routing-and-gate half and is what this decision does; it is insufficient ALONE because the producer in front of it (the extraction step that maps unstructured turns to named facts) does not exist for the chat. Rejected as a complete answer; adopted as the routing substrate the new producer writes through.
- **When this becomes the right choice:** It IS the chosen substrate — this ADR reuses `capture`'s gates and routing unchanged and adds only the dialogue→facts producer in front; the "unchanged, nothing added" reading is the right choice only if the chat surface produced named form fields rather than free dialogue, which the pivot's conversational intake does not.

### Validation Approach

**Confirmation criteria:**
- Every chat-extracted fact passes through the deterministic gate before `store.append`: a round-trip test per extracted token confirms the extraction output reaches the store only via `persist_capture`'s `_bounded_value_ok` / `_value_has_pii` / by-data-class routing — expected: 100% of chat-extracted facts pass through the gate before the store write, 0 reaching `store.append` another way ([capture.py L189-244](../../scripts/serve/capture.py) [VERIFIED]).
- No model-emitted fact reaches a `SUMMARY_FIELD_SET` store item without passing the gate: a crafted extraction output carrying a raw value under a token name routes record-only or is rejected, never into the token item — expected: 0 model-emitted facts in a `SUMMARY_FIELD_SET` store item that did not pass `_bounded_value_ok` / `_value_has_pii` ([capture.py L216-225](../../scripts/serve/capture.py) [VERIFIED]).
- The persisted side stays de-identified after a conversation: a post-conversation scan of the store and the `summarize` output finds 0 raw-PII hits, the boundary `summarize` already enforces — expected: 0 raw-PII hits ([router.py L352-432](../../scripts/plan/router.py) [VERIFIED]).

**Falsification criteria:**
- If any chat-extracted raw PII lands in a `SUMMARY_FIELD_SET` store item (≥1 hit on a post-conversation scan), the gate-at-extraction has failed — halt extraction, treat the de-identification path as broken, and repair the gate routing before the next intake run. NOTE on the 8j6 backstop's scope: for a PASS-THROUGH token (a store item of its own name) the `summarize` 8j6 gate would have raised at the boundary (`router.py` L416-430, the else-path); for a DERIVED token (e.g. `active-issue-class` from the raw-symptom item) the 8j6 gate does NOT run (`router.py` L406-412 runs no per-value scan), so a raw value reaching a derived token is caught by the derivation's coarseness + its per-token output scan, not by the 8j6 backstop ([router.py L406-430](../../scripts/plan/router.py) [VERIFIED]).
- If a model-emitted fact bypasses the gate path (an extraction-to-`store.append` route that does not pass through `persist_capture`'s gates, ≥1 occurrence), the extraction boundary has been breached — re-route the producer through the gate before release.
- If any raw conversation or extraction residue appears in a COMMITTED file on a fresh-clone scan (≥1 hit), the trunk has leaked beyond ADR-0005's scope — because history cannot be cleanly scrubbed, treat as a release-blocking incident and scrub-or-rewrite before release.
- Time horizon: run the gate-coverage and persisted-side checks at the first build of the extractor and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- The `SUMMARY_FIELD_SET` field-set extension lands (the deferred ADR-0014 OQ-1 / a future field-set-extension decision) — re-validate that the newly de-identified tokens flow through the extraction gate and that their raw inputs still land on the gitignored surface only.
- A new domain is added to the chat surface — re-classify it against the `SUMMARY_FIELD_SET` / record-only split before the extractor writes it, and re-run the gate-coverage check.
- The gate logic changes (`_bounded_value_ok`, `_value_has_pii`, or the by-data-class routing) — re-verify the extraction output still routes raw detail record-only and only de-identified facts reach a token item.
- ADR-0001's `SUMMARY_FIELD_SET` or `summarize` summary contract changes — re-validate the extractor's emitted facts still map to current tokens.
