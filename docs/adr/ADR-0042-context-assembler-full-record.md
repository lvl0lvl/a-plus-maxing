## ADR-0042: Context Assembler Feeds Specialists the Full Identity-Stripped Record on the Plan Path

> **Y-Statement:** In the context of the plan path, where `compute_plan` feeds each specialist a de-identified summary that `router.summarize` collapses from the operator's rich free-text record into a closed 18-token band/class allowlist (`SUMMARY_FIELD_SET`) — a full training program flattened to one of `low`/`moderate`/`high`, a peptide regimen to `none`/`peptide-in-use` — while `dispatch` RAISES on any field outside that set, so a specialist structurally cannot receive anything richer than the coarse bands ([router.py:23-60,584-623,893-897](../../scripts/plan/router.py); [generate_plan.py:356](../../scripts/plan/generate_plan.py) [VERIFIED]), facing the tension that a followable, physician-ready plan needs specialists reasoning over the operator's REAL detail while the closed field-set is simultaneously the plan path's load-bearing PII containment, we decided to adopt a Context Assembler that feeds each specialist the operator's FULL record with pure identity stripped only (the operator's standing parked-de-id assumption — legal name, exact DOB, contact, address removed; all health substance flows), replacing `router.summarize`'s collapse as the specialist/plan input and generalizing the full-record access the care agent already holds ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]), to achieve specialists that reason over real detail instead of coarse bands, accepting that this redraws the crown-jewel PII boundary (what crosses the model boundary on the plan path changes from a closed coarse field-set to full health substance minus identity), breaks the EXTEND-NOT-REBUILD freeze ADR-0032 held on the `router.summarize` plan-path surface (classified HARD, operator sign-off OBTAINED at the Phase-1 gate), and enlarges every specialist prompt — while this ADR only GROUNDS and NAMES that boundary change and does NOT design, re-open, or widen any de-identification scheme.

### Context

The plan path collapses the operator's real record before any specialist sees it. `router.summarize` derives a name-addressable summary whose keys are drawn ONLY from the closed 18-token `SUMMARY_FIELD_SET` ([router.py:23-60](../../scripts/plan/router.py) [VERIFIED]), mapping every raw free-text source through a band/class transformation: `_RAW_TO_FIELD` routes `raw-training-detail-free-text` → `training-volume-band` (one of `low`/`moderate`/`high`, [router.py:584-623](../../scripts/plan/router.py) [VERIFIED]), `raw-peptide-free-text` → `peptide-use-class` (one of `not-discussed`/`none`/`peptide-in-use`, [router.py:561-581](../../scripts/plan/router.py) [VERIFIED]), and `raw-nutrition-free-text` / `raw-supplement-free-text` likewise to coarse class tokens ([router.py:128-143](../../scripts/plan/router.py) [VERIFIED]). `dispatch` then enforces `set(payload) ⊆ SUMMARY_FIELD_SET` and RAISES on any field outside the set ([router.py:893-897](../../scripts/plan/router.py) [VERIFIED]). The plan-path consumer is `compute_plan`, which does `summary = router.summarize(store_read)` and hands that summary to `assemble([domain], summary, roster)` for every specialist ([generate_plan.py:356,372](../../scripts/plan/generate_plan.py) [VERIFIED]); the cross-domain `orchestrate` rides that same `compute_plan` per domain ([orchestrate.py:530](../../scripts/plan/orchestrate.py) [VERIFIED]). The `plan_driver` loop path arrives at the same coarse shape one step earlier: `run_orchestrated` computes `summary = deid_in(raw_intake, deid_client)` and passes it into `drive(summary, …)` → `pipeline.run_generation`, the ADR-0027 de-id-IN summary keyed to the same closed `⊆ SUMMARY_FIELD_SET` band/class allowlist ([plan_orchestrator.py:223](../../scripts/plan/plan_orchestrator.py); [plan_driver.py:144,412](../../scripts/plan/plan_driver.py); [deid_in.py:90](../../scripts/plan/deid_in.py) [VERIFIED]). A specialist author therefore structurally cannot receive anything richer than the coarse tokens — the "rich real program → one coarse band" DATA-COLLAPSE.

One boundary treatment is a standing GIVEN this ADR does not decide: the parked-de-id assumption. The de-identification boundary is the care → specialist / plan hand-off, NOT the operator → care-agent link; only PURE identity (legal name, exact DOB, contact, address — the identity members of `EXCLUDED_RAW_PII`, [router.py:65-108](../../scripts/plan/router.py) [VERIFIED]) is stripped, and all health SUBSTANCE flows. That posture is already realized in the tree: the care agent's `_care_profile` reads `router.summarize`'s identity-safe base PLUS the operator's raw `health_detail` free-text (nutrition, supplement, peptide, training, injury) PLUS the scaffold medications, because "the care agent is the operator's OWN private agent, so it reads the operator's ACTUAL detail ... instead of the coarse specialist-facing bands" ([care_chat.py:122-200](../../scripts/serve/care_chat.py) [VERIFIED]). The full record minus identity is thus already assembled on the machine; it simply does not reach the specialist/plan hand-off today.

Three forces pull against each other across more than one stakeholder. The operator and the physician need specialists reasoning over the real detail — a followable, physician-ready plan cannot be authored from `low`/`moderate`/`high`; ADR-0001 itself records that "summaries-not-raw ... constrains how rich and operator-specific the model's input can be" ([ADR-0001, Negative](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]), and ADR-0006 depends on that same summaries lane, capping section richness ([ADR-0006, Negative](ADR-0006-multi-domain-plan-assembly-via-roster.md) [VERIFIED]). Against that, the data subject's crown-jewel containment is realized precisely BY the closed field-set: `dispatch`'s `⊆ SUMMARY_FIELD_SET` gate is what mechanically bounds what crosses the model boundary on the plan path ([router.py:893-897](../../scripts/plan/router.py) [VERIFIED]). And the maintainer's freeze binds the third: ADR-0032 held `router.summarize` / `SUMMARY_FIELD_SET` and the inner plan engine byte-frozen under EXTEND-NOT-REBUILD, allowing only ADDITIVE field-set extension ([ADR-0032, Decision + Validation](ADR-0032-dna-aware-planning.md) [VERIFIED]). Because this redraws WHAT crosses the model boundary on the plan path — an information-flow + PII-boundary change touching the boundary ADR-0001/0006/0027 fixed and the surface ADR-0032 froze, both one-way doors — it is a decision, not a code comment beside the summarizer.

### Decision

Adopt a Context Assembler as the specialist/plan input on the plan path: it feeds each dispatched specialist the operator's FULL record with pure identity stripped only, superseding `router.summarize`'s coarse-band collapse as that input.

1. **Full identity-stripped record, not the coarse field-set.** The specialist input becomes the operator's real record (the raw health detail the care agent already assembles) minus pure identity, replacing the `set(payload) ⊆ SUMMARY_FIELD_SET` collapse as the plan-path specialist/author input ([router.py:893-897](../../scripts/plan/router.py); [generate_plan.py:356](../../scripts/plan/generate_plan.py) [VERIFIED]).
2. **De-id stays PARKED — a stated assumption, not a decision here.** Only pure identity (legal name, exact DOB, contact, address) is stripped; all health substance flows. This ADR GROUNDS and NAMES the boundary change; it does NOT design, re-open, or widen a de-identification scheme, and it introduces no new de-id lane. The concrete identity-strip mechanism is a spec/build concern (OQ-1).
   - **Genetics carve-out (ADR-0032 crown-jewel preserved).** "All health substance flows" has ONE named exception: raw rsID+allele genotypes. They remain 100% LOCAL and NEVER reach the assembled record (the S102 crown-jewel invariant, [ADR-0032, Decision](ADR-0032-dna-aware-planning.md) [VERIFIED]) — genetics reaches the assembled record ONLY as ADR-0032's derived, de-id-by-construction coarse `genetic-trait-classes` token, which the assembler carries like any other health-substance field. This is CONSISTENT with "all health substance flows": the trait-classes token IS the genetic substance that flows to the specialist; only the raw-genotype REPRESENTATION stays local, via ADR-0032's EXISTING de-id-by-construction mechanism — this is NOT a new de-id lane and does NOT re-open the parked de-id scope, so the de-id-parked constraint (§2) still holds. The assembler therefore feeds full health substance EXCEPT raw genotypes; the trait-classes token re-bases onto the assembler as the genetic-substance carrier.
3. **This BREAKS the EXTEND-NOT-REBUILD freeze on the `router.summarize` plan-path surface.** ADR-0032 held that surface (and the `compute_plan` consumer line) byte-frozen; replacing the collapse is a non-additive supersession of it. Classified HARD (a one-way door — it redraws the crown-jewel boundary); operator sign-off OBTAINED at the Phase-1 gate.
4. **Generalizes existing full-record access — precedent, not a new egress class.** The assembler extends the care agent's `_care_profile` full-record access ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]) onto the specialist/plan hand-off; the record is the same one already assembled on the machine.
5. **Synthetic/mock only; the live run is operator-gated.** Built and mock/fixture-tested at 0 live spend; the operator-present LIVE run (real spend) is operator-gated (OQ-4), as with ADR-0032 OQ-1.

### Rationale

The assembler was weighed against widening the field-set incrementally (Alternative A) and a per-field named-egress carve-out (Alternative B) across four criteria the governing decisions make load-bearing — **fidelity** (does the specialist see the operator's real detail?), **boundary integrity** (is what crosses the model boundary a single, named, auditable seam?), **freeze cost**, and **buildability**.

On **fidelity**, only the assembler fixes DATA-COLLAPSE at the root: the specialist reasons over the real record instead of a band, so a plan reflects the operator's actual program rather than a `low`/`moderate`/`high`-derived generic. Widening the field-set (A) moves the ceiling but keeps a lossy CLOSED allowlist — anything a specialist needs that is not yet a token is still collapsed; the carve-out (B) admits only the specific fields carved, so fidelity is bounded by an ever-growing exception list. On **boundary integrity**, the assembler yields ONE named boundary — "full health substance minus identity" — auditable at a single seam, whereas B multiplies unbounded per-field carve-outs with no coherent boundary, and A leaves the boundary defined by whichever tokens happen to be in the set. On **buildability**, the assembler generalizes an access pattern already in the tree: `_care_profile` already reads the full identity-stripped record ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]), so this extends existing full-record access to a new consumer rather than inventing a new egress class. The cost it pays over A is the freeze break and the larger boundary; the cost it pays over B is that the whole record crosses rather than a few named fields.

Long-term, the assembler is the single input contract the rest of the plan-platform re-architecture set consumes — the DOMAIN PROGRAM specialists (ADR-0041) and the orchestrator's briefs (ADR-0043) both read the assembled record — so widening the field-set token-by-token (A) would force re-deciding the ceiling every time a domain needs more detail, while the carve-out (B) would compound the review burden per field. The decision accepts, permanently for V1, that what crosses the model boundary on the plan path is now full health substance minus identity, mitigated by the parked-de-id identity strip and made falsifiable by the identity-leak and no-collapse probes below.

### Consequences

**Positive:**
- Specialists reason over the operator's REAL detail: a plan section reflects the actual program (the specific split, the specific stack) instead of a coarse band, fixing the DATA-COLLAPSE the `low`/`moderate`/`high` and `none`/`peptide-in-use` derivers impose ([router.py:561-623](../../scripts/plan/router.py) [VERIFIED]).
- A single named boundary: what crosses the model boundary on the plan path is one auditable seam ("full health substance minus identity"), not 18 lossy coarse tokens ([router.py:23-60](../../scripts/plan/router.py) [VERIFIED]) each discarding detail — one place to review, one place to falsify.
- Generalizes existing full-record access rather than opening a new class: the record the assembler feeds is the same one `_care_profile` already assembles on the machine ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]), so this is a precedent extension, not a novel egress.

**Negative:**
- **It redraws the crown-jewel PII boundary — the highest-stakes change in the set.** What crosses the model boundary on the plan path changes from a closed coarse field-set (`dispatch`'s `⊆ SUMMARY_FIELD_SET` gate, [router.py:893-897](../../scripts/plan/router.py) [VERIFIED]) to full health substance minus identity. This must be named and signed off — it is (HARD, Phase-1 gate). It is NOT a new de-id scheme (de-id stays parked, only identity stripped), but the QUANTITY of health substance crossing the model boundary on the plan path grows from coarse tokens to the full record — a permanent (1+ year) expansion of the plan-path model-boundary surface that ADR-0001/0006/0027 must be amended to reflect.
- **It breaks the EXTEND-NOT-REBUILD freeze on the `router.summarize` plan-path surface.** ADR-0032 held `router.summarize` / `SUMMARY_FIELD_SET` and the `compute_plan` consumer byte-frozen (additive extension only, [ADR-0032, Validation](ADR-0032-dna-aware-planning.md) [VERIFIED]); replacing the collapse is a non-additive supersession of that surface — a one-way door. Classified HARD; operator sign-off obtained. ADR-0032's own de-id-by-construction `genetic-trait-classes` token must re-base onto the assembler.
- **`dispatch`'s structural containment no longer gates the specialist payload on the plan path.** Today the closed whitelist mechanically rejects anything outside the field-set ([router.py:893-897](../../scripts/plan/router.py) [VERIFIED]); once the assembler feeds the full record, the plan-path containment is no longer "reject everything but 18 tokens" but "strip pure identity, pass the rest." The correctness burden shifts onto the identity-strip being complete — the parked-de-id assumption's mechanism (out of scope here, OQ-1) becomes the plan path's load-bearing seam, an invariant to enforce in review rather than a closed enum.
- **Larger prompts, higher cost, higher latency.** The full record is a materially larger payload than the ~18 coarse tokens, so every specialist prompt grows; per-dispatch token cost and latency rise, and the effect scales with the roster (ADR-0046's 15+ specialists) — a standing operational cost, not a one-time hit.

**Neutral:**
- The de-id-parked assumption becomes the plan path's containment contract (it already is the care agent's, via `_care_profile`); the assembler makes it the specialist/plan contract too, unifying the two on one boundary.
- `router.summarize` is superseded in its plan-path SPECIALIST-INPUT role only; its other consumers (the `_care_profile` identity-safe base, [care_chat.py:180-182](../../scripts/serve/care_chat.py) [VERIFIED]; the ADR-0027 de-id-IN summary contract) are out of this ADR's scope and may persist (OQ-3).

### Alternatives Considered

#### Alternative A: Widen `SUMMARY_FIELD_SET` incrementally
Keep the closed-allowlist collapse and add richer tokens/fields to `SUMMARY_FIELD_SET` as domains need more detail, under the existing change-control tripwire.
- **Supporting evidence:** Minimal change; preserves `dispatch`'s closed-whitelist containment intact ([router.py:893-897](../../scripts/plan/router.py) [VERIFIED]); has a direct precedent — ADR-0019 already widened the field-set for de-identified chat-sourced tokens ([ADR-0006 Related, ADR-0019 rows](ADR-0006-multi-domain-plan-assembly-via-roster.md) [VERIFIED]). No freeze break beyond an additive extension, no boundary redraw.
- **Trade-offs:** It is still a lossy CLOSED allowlist — it moves the ceiling, it does not remove it. The fundamental DATA-COLLAPSE (rich real program → coarse token) persists for anything not yet added, and every new detail a specialist needs forces re-deciding the field-set. It cannot deliver "the specialist reasons over the operator's real detail" without, in the limit, widening the set to the whole record — at which point it is the assembler with extra ceremony.
- **When this becomes the right choice:** If the set of details specialists ever need were small, bounded, and stable, widening a handful of tokens is cheaper than redrawing the boundary.

#### Alternative B: A named-egress carve-out per field
Apply the project's established named-egress discipline (ADR-0016 / 0032 / 0035) field-by-field: each time a specialist needs a raw detail, add a bounded, signed-off per-field carve-out.
- **Supporting evidence:** Matches the project's proven "name the class, bound it, sign off, never silently widen" pattern that ADR-0016/0032/0035 use for intake conversation, variant queries, and med names ([ADR-0032, Decision](ADR-0032-dna-aware-planning.md) [VERIFIED]); each carve-out is individually reviewed and auditable.
- **Trade-offs:** The carve-out pattern was built for a FEW bounded classes, not wholesale full-record access. The full record is dozens of fields; carving them one at a time yields no single boundary — an ever-growing exception list with no coherent seam, and a review burden that compounds per field. It fixes DATA-COLLAPSE only for the fields carved, so plan fidelity stays bounded by the exception list rather than the record.
- **When this becomes the right choice:** If only a handful of specific raw fields were ever needed on the plan path — but the physician-ready plan goal needs the whole record.

#### Dissent: The summaries-not-raw purist position (inherited from ADR-0001 / 0027)
**Source:** ADR-0001's crown-jewel anchor that the plan path reasons over summaries, not raw, and ADR-0027's inherited dissent that raw plan-intake reaching the model is a genuine weakening of the most load-bearing privacy guarantee ([ADR-0001, Falsification](ADR-0001-pii-trust-boundary-no-train-routing.md); [ADR-0027, Dissent](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). A reviewer can reasonably hold that the closed field-set IS the crown-jewel guarantee, that feeding the full record — even identity-stripped — is the moment the plan path's structural containment (the closed whitelist) is given up, and that incremental field-set widening (Alternative A) is the correct posture even at the cost of plan fidelity.
**Conditions under which this becomes the right choice:** If the parked-de-id identity-strip cannot be made reliable enough that "full health substance minus identity" is an acceptable boundary, OR if the no-train lane's terms degrade (plan-path payloads becoming training-eligible or long-retained) — then retract to the closed field-set and widen it only incrementally.

### Validation Approach

**Confirmation criteria:**
- **A specialist on the plan path receives the full real record (executable):** seed a store with a rich free-text program (a GENERIC multi-day training split + a multi-item supplement stack) and run the plan path; assert the specialist input carries the operator's real detail (the actual program text), NOT a coarse band. Threshold: the specialist input contains the substantive free-text fields of the record; 0 rich sources collapsed to a `SUMMARY_FIELD_SET`-only band. If the specialist input is byte-identical to `router.summarize`'s output, the collapse was not replaced — halt.
- **A plan reflects real detail not a coarse band (executable):** assert the rendered plan section reflects ≥1 operator-specific detail that the coarse band would have erased (a specific split parameter, a specific stack item), not a `low`/`moderate`/`high`-derived generic ([router.py:584-623](../../scripts/plan/router.py) [VERIFIED]). Threshold: ≥1 operator-specific detail present that `router.summarize` would have discarded.
- **Identity is stripped (executable):** scan the specialist input for pure-identity tokens (legal name, exact DOB, contact, address — the `EXCLUDED_RAW_PII` identity members, [router.py:65-108](../../scripts/plan/router.py) [VERIFIED]). Threshold: 0 identity tokens in any specialist input.

**Falsification criteria:**
- **Raw legal-name / contact reaching a specialist payload → FAIL (the crown-jewel probe, load-bearing):** seed a synthetic legal name + a synthetic contact string into the store, run the plan path, and scan every specialist payload. Threshold: **0 pure-identity tokens** in any specialist payload; ≥1 (a legal name, exact DOB, contact, or address reaching a specialist) means the identity strip failed — halt and repair before release.
- **The assembler emitting a coarse-band-only summary → FAIL:** run the assembler over a rich free-text source; if the specialist receives only the coarse `SUMMARY_FIELD_SET` tokens (the old collapse), the assembler did not replace the collapse and DATA-COLLAPSE is unfixed. Threshold: the specialist input must carry richer-than-coarse-band detail for ≥1 rich source; if it equals `router.summarize`'s 18-token output, halt.
- **Time horizon:** run the identity-leak probe, the no-collapse probe, and the identity-strip scan at the first assembler build, at the operator-present LIVE run (OQ-4), and at every release thereafter, and before the July-2026 physician-visit deliverable.

**Review triggers:**
- A new plan-path specialist consumer is added (the ADR-0046 15+-specialist roster) — verify it reads the assembler, not a residual `router.summarize` collapse, or it will under-inform the specialist.
- The parked-de-id identity-strip mechanism is revisited (OQ-1) — re-confirm what counts as "pure identity" against the boundary this ADR names.
- The no-train lane's no-train / retention terms change — re-verify the full-record plan-path egress is still acceptable (the Dissent retraction condition).
- Plan-generation cost or latency crosses an operational threshold — re-evaluate the full-record payload size against a per-specialist relevant slice (OQ-2).
