## ADR-0006: Multi-Domain Plan Assembly via Roster Specialists

> **Y-Statement:** In the context of a local-first single-operator health system that holds a 20-agent specialist roster and a gated goal-agnostic library but nothing that assembles an operating plan, facing the tension between the depth a per-domain specialist gives and the single-coherent-attributable-document a physician-ready plan demands, we decided to assemble the plan by routing each in-scope goal-domain to its matching deployed roster specialist, composing their outputs into one document, attributing each section to its specialist, carrying source + confidence-tier + reversibility on every recommendation, flagging animal/in-vitro evidence with population-mismatch, personalizing from the operator's profile/goals/current-state over the no-train summaries path, and disclosing coverage gaps honestly where the library is thin, to achieve a sourced, decision-framed, clinician-legible plan, accepting that plan richness is bounded by current thin-library coverage (many domains hit coverage-gap disclosures), that composition/attribution adds an orchestration layer, and that a goal-domain with no matching specialist has no defined routing target yet.

### Context

The reasoning capacity is live but produces no assembled plan. `.claude/agents/` holds 20 deployed specialists (peptide-specialist, personal-trainer, nutritionist, plus cardiovascular/endocrine/labs/recovery/sleep/supplement/dermatology/gi/lymphatic/genetics/longevity/mental-performance/medical-liaison/two reviewers and an architect) ([.claude/agents/ directory, 20 agent profiles](../../.claude/agents/) [VERIFIED]; [PRD-v1, Finding 1 L351](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). The personalization inputs are scaffolded, not greenfield: `operator-profile.md`, `goals.md`, and `current-state.md` define complete schemas (the January-2026 issue with HALT rules, hard limits, per-domain goals, active protocols) but hold placeholder prompts only — filling them is what creates the PII surface ([PRD-v1, Finding 2 L353](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). Nothing routes a domain to a specialist, composes their outputs, or renders a plan ([PRD-v1, Finding 1 L351](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).

Several forces pull against each other across more than one stakeholder. The operator wants concrete per-domain regimens deep enough to run, which argues for routing each domain to the specialist that holds that domain's vetted evidence ([PRD-v1, US-1 L47-53, FR-1 L123](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). The physician — collaborator and validator, not author or addressee — needs a plan that meets the five-point physician-ready bar: sourced, safety-surfaced, honestly uncertain, decision-framed, clinician-legible ([vision.md, physician-ready bar L21-28](../../design/vision.md) [VERIFIED]). Those two pull against single-document coherence: a bag of disconnected specialist outputs is not a plan a time-constrained doctor can read, so the specialist outputs must compose into one coherent, attributable document ([PRD-v1, FR-1 AC L127-129](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). Every recommendation must carry source + confidence-tier + reversibility, every number units + reference range, with zero unsourced claims ([PRD-v1, NFR-5 L253-259](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]); animal/in-vitro evidence and population mismatch must be flagged — a governed project invariant, not a new ask ([PRD-v1, NFR-6 L261-265](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [INVARIANTS.md, INV-RESEARCH-POPULATION-MISMATCH L36](../../INVARIANTS.md) [VERIFIED]). The library the plan draws on is thin and gated — only bpc-157 is populated — so coverage must be disclosed honestly rather than fabricated ([PRD-v1, FR-5 L156-161, Finding 6 L361, NG-8 L284](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). And the library is goal-agnostic by settled decision: personalization happens at the specialist-dispatch step, never by biasing the library for one operator ([2026-05-23-wiki-schema.md, Decision 5 L48-50](../../vault/decisions/2026-05-23-wiki-schema.md) [VERIFIED]). Plan reasoning is THE PII-touching dispatch — it reasons over the operator's profile/goals/current-state — so it is the one dispatch that must run on the no-train summaries path ([PRD-v1, US-9 AC L115, NFR-1 L223](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).

### Decision

Assemble the multi-domain operating plan by routing each in-scope domain — every domain present in the operator's goals — to its matching deployed roster specialist, then composing the specialist outputs into one coherent document with each section attributable to the specialist that produced it. Every recommendation carries a source citation, a confidence tier, and a reversibility note; animal/in-vitro evidence is flagged with population-mismatch; each section is personalized from the operator's profile, goals, and current state; and where the gated library lacks vetted coverage for an in-scope domain, the plan states the coverage gap honestly rather than fabricating a recommendation. Plan reasoning runs on the no-train path over summaries, reads current state from the store, and the assembled plan is rendered through the single-file generation path.

### Rationale

The plan-assembly architecture was evaluated against three alternatives — a single monolithic generalist plan-writer (A), disconnected per-specialist outputs handed over separately (B), and pre-filtering the library at plan time (C) — across four criteria the PRD and vision make load-bearing: specialist depth, single-document coherence/attribution, library grounding, and the goal-agnostic-library discipline.

On **specialist depth**, routing each domain to its matching specialist puts the domain's vetted evidence behind every section — the peptide-specialist holds peptide evidence, the nutritionist holds nutrition evidence — which a single generalist writer (A) cannot match, because no one agent holds all domains' vetted library content at the physician-ready depth ([PRD-v1, FR-1 L123, US-1 AC L50](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [.claude/agents/ 20 specialists](../../.claude/agents/) [VERIFIED]). On **coherence/attribution**, composition into one document keeps the plan a single artifact a doctor reads while each section stays traceable to its producer, satisfying FR-1's "single coherent document, not a set of disconnected outputs" and "attributable to the specialist" criteria together ([PRD-v1, FR-1 AC L127-129](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]) — exactly what option B (hand the operator each specialist's output separately) fails to deliver. On **library grounding**, routing draws every recommendation from the gated goal-agnostic library, so NFR-5's zero-unsourced-claims bar and FR-5's honest-coverage-gap rule are enforceable at the section level: a thin-library domain produces a stated gap, not a fabricated regimen ([PRD-v1, NFR-5 AC L257-259, FR-5 AC L160-161](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). On **goal-agnostic-library discipline**, personalization is applied at the specialist-dispatch step (the specialist reads the operator's profile/goals/current-state and tailors), never by pre-filtering the shared library — the settled split that option C would violate and that the PF-S2-04 lesson exists to prevent ([2026-05-23-wiki-schema.md, Decision 5 L48-50, Breaks-If L77](../../vault/decisions/2026-05-23-wiki-schema.md) [VERIFIED]).

The accepted trade-off is that plan richness is bounded by current library coverage: with only bpc-157 populated, many in-scope domains will produce a coverage-gap disclosure rather than a deep regimen, and the composition/attribution step adds an orchestration layer the disconnected-outputs alternative avoids ([PRD-v1, Finding 6 L361, Dependencies row 2 L332](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). We accept this because honest thin coverage is the V1 contract — the library grows on a parallel research track and V1 does not block on it (FR-5 + NG-8), so the plan ships with stated gaps rather than waiting for a complete library ([PRD-v1, NG-8 L284, A-5 L312-315](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]). Long-term, as the library fills, the same routing/composition path produces richer plans without re-deciding the assembly architecture — coverage gaps close in place as specialists gain content to ground.

### Consequences

**Positive:**
- The assembled plan contains a distinct section per in-scope goal-domain, each attributable to the specialist that produced it — verified against FR-1's attributability and single-document criteria ([PRD-v1, FR-1 AC L127-129, US-1 AC L50](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- 100% of recommendations display a source citation, a confidence tier, and a reversibility note, and 100% of numbers display units + reference range, with 0 unsourced claims — the NFR-5 physician-ready measurement applied to the plan ([PRD-v1, NFR-5 AC L257-259](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Each domain section is personalized from the operator's profile/goals/current-state — reflecting at least one operator-specific input (the January-2026 issue, a hard limit, a stated goal) and honoring HALT rules so no recommendation contradicts a stated hard limit ([PRD-v1, FR-2 AC L135-136, US-1 AC L51](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Animal/in-vitro-grounded recommendations carry an explicit population-mismatch flag, satisfying the physician-ready honesty bar and the governed invariant ([PRD-v1, NFR-6 AC L265](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [INVARIANTS.md, INV-RESEARCH-POPULATION-MISMATCH L36](../../INVARIANTS.md) [VERIFIED]).

**Negative:**
- Plan richness is bounded by current thin-library coverage: with only bpc-157 populated, many in-scope domains will render an FR-5 coverage-gap disclosure rather than a deep regimen, so the first July plan is honestly sparse outside the populated domains — a standing 1+ year constraint that closes only as the parallel research track fills the library ([PRD-v1, Finding 6 L361, NG-8 L284, Dependencies row 2 L332](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Composition/attribution adds an orchestration layer not present in a single-writer or hand-over-separately model: the per-section provenance contract, the routing step, and the compose-into-one-document step are new machinery that must be built and kept correct, and a composition bug can drop a section's attribution or fabricate a cross-domain claim no single specialist sourced ([PRD-v1, FR-1 AC L127-129](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Routing depends on the operator's goals naming domains that have a matching deployed specialist: a goal-domain with no specialist in the 20-agent roster has no defined routing target, so the assembly has an unhandled edge until that case is resolved (see Open Questions OQ-1) ([.claude/agents/ 20 specialists](../../.claude/agents/) [VERIFIED]; [PRD-v1, OQ-3 L344](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Plan reasoning is the one PII-touching dispatch, so it is constrained upstream by the no-train summaries path (ADR-0001) and the store read model (ADR-0002): it cannot reason over raw PII and cannot read state the store does not expose, narrowing how rich and operator-specific the model's input can be ([ADR-0001, Decision + Negative consequences](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]; [ADR-0002, Decision](ADR-0002-local-first-time-series-store.md) [VERIFIED]).

**Neutral:**
- The 20-agent roster becomes a shared contract between this plan-assembly path and the library it consumes: routing depends on the roster staying the set of domains the plan can cover, and the roster's documented goal-agnostic-library / personalize-at-dispatch split governs how each specialist is dispatched ([2026-05-23-wiki-schema.md, Decision 4-6 L42-58](../../vault/decisions/2026-05-23-wiki-schema.md) [VERIFIED]).
- "Summary" is a shared contract with ADR-0001: the plan-reasoning dispatch reasons over the same summaries-not-raw-PII representation the trust boundary fixes, so the summarization step the store/profile side produces is the input the routing step consumes ([ADR-0001, Neutral consequences + Decision](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Single monolithic generalist plan-writer
One agent reads the operator's profile/goals/current-state and the whole library and writes the entire multi-domain plan itself, with no per-domain routing.
- **Supporting evidence:** Simplest to orchestrate — one dispatch, no routing or composition layer, no per-section attribution machinery, and inherently a single coherent document because one author writes it end to end. It avoids the composition-bug surface the chosen route introduces.
- **Trade-offs:** No single agent holds all 20 domains' vetted library content at physician-ready depth, so a generalist writer flattens specialist depth and loses per-section attribution to the specialist that owns the evidence — failing FR-1's specialist-routing requirement and the depth US-1 asks for ([PRD-v1, FR-1 L123, US-1 AC L50](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [.claude/agents/ 20 specialists](../../.claude/agents/) [VERIFIED]). It also weakens the goal-agnostic grounding: a generalist reasoning over the whole library at once is more likely to produce a cross-domain claim no specialist sourced. Rejected because it forfeits the specialist depth and attribution the plan exists to deliver.
- **When this becomes the right choice:** If the domain set collapsed to one or two domains a single agent could hold at full depth, the routing/composition layer would be overhead with no depth benefit.

#### Alternative B: Disconnected per-specialist outputs handed over separately
Route each domain to its specialist (as chosen) but stop there — hand the operator each specialist's output as a separate artifact, with no composition into one document.
- **Supporting evidence:** Preserves full specialist depth and per-domain attribution trivially (each output is one specialist's), and skips the composition/attribution orchestration layer the chosen route builds. Each specialist output stands alone, sourced and personalized.
- **Trade-offs:** A set of disconnected outputs is not a plan a time-constrained physician can read — FR-1 explicitly requires "a single coherent document, not a set of disconnected specialist outputs," and the physician-ready bar's clinician-legible point needs one skimmable artifact, not N ([PRD-v1, FR-1 AC L128](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [vision.md, physician-ready bar point 5 L27](../../design/vision.md) [VERIFIED]). It also cannot surface cross-domain interactions (a contraindication spanning two specialists' regimens) that only composition reconciles. Rejected because composition into one coherent document is a load-bearing FR-1 criterion.
- **When this becomes the right choice:** For an internal working pass where the operator wants each specialist's raw output for review before composition — a build-time intermediate, not the shared deliverable.

#### Alternative C: Pre-filter / personalize the library at plan time
Bias the gated library for the operator's context at plan-assembly time — filter or re-rank entries against the January-2026 issue and goals — so the routing step reads an already-personalized library.
- **Supporting evidence:** Would put operator-relevant evidence first at routing time and could make each specialist's grounding step shorter, since the library is pre-narrowed to what matters for this operator.
- **Trade-offs:** It violates the settled goal-agnostic-library split: a wiki entry is built once and used by many future queries, and pre-filtering at library time for one operator's context corrupts the entry for every other query — the exact PF-S2-04 failure the wiki-schema decision exists to prevent ([2026-05-23-wiki-schema.md, Decision 5 L48-50, Breaks-If L77](../../vault/decisions/2026-05-23-wiki-schema.md) [VERIFIED]). Personalization belongs at the specialist-dispatch step, where the specialist reads the operator's meta files and tailors without touching the shared library ([2026-05-23-wiki-schema.md, Decision 6 L52-58](../../vault/decisions/2026-05-23-wiki-schema.md) [VERIFIED]). Rejected because it relocates personalization into the wrong layer and corrupts a shared asset.
- **When this becomes the right choice:** Only if the library stopped being a shared, multi-query asset and became a single-operator private cache — which V1's operator-agnostic, clonable design explicitly forbids.

### Validation Approach

**Confirmation criteria:**
- The assembled plan has a distinct, attributable section for each in-scope goal-domain — verified by listing the domains named in the operator's goals and confirming each has a plan section naming the specialist that produced it (expected: 1 attributed section per in-scope domain, 0 unattributable sections) ([PRD-v1, FR-1 AC L127-129, US-1 AC L50](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Every recommendation shows a source citation, a confidence tier, and a reversibility note, and every number shows units + reference range — verified by scanning the plan for recommendations/numbers missing any of these (expected: 100% complete, 0 unsourced claims) ([PRD-v1, NFR-5 AC L257-259](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Coverage gaps are stated where the library is thin — verified by checking that each in-scope domain the library cannot support carries an explicit gap statement, not a regimen (expected: every uncovered in-scope domain shows a stated gap) ([PRD-v1, FR-5 AC L160-161](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- Animal/in-vitro-grounded recommendations carry a population-mismatch flag — verified by checking each such recommendation for the flag (expected: 100% flagged) ([PRD-v1, NFR-6 AC L265](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [INVARIANTS.md, INV-RESEARCH-POPULATION-MISMATCH L36](../../INVARIANTS.md) [VERIFIED]).
- Plan reasoning runs on the no-train path over summaries — verified by confirming the plan-assembly dispatch routes to the no-train lane and reasons over summaries, not raw PII (expected: 100% of PII-touching plan dispatches on the no-train path, 0 raw-PII sends) ([PRD-v1, NFR-1 AC L228, US-9 AC L115](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).

**Falsification criteria:**
- If any recommendation appears in the plan with no backing source from the vetted library, FR-5/NFR-5 has failed — block the plan from release and either source the recommendation or convert it to a coverage-gap statement ([PRD-v1, FR-5 AC L161, NFR-5 AC L259](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- If any domain section is unattributable (cannot be traced to the specialist that produced it), FR-1's attributability criterion has failed — halt and restore per-section provenance before release ([PRD-v1, FR-1 AC L129](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- If a thin-library in-scope domain produces a fabricated recommendation instead of a coverage-gap disclosure, the honest-gap contract has failed — a direct FR-5 breach; pull the fabricated section and replace it with the stated gap ([PRD-v1, FR-5 AC L160-161](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]).
- If plan reasoning sends raw operator PII to the model (rather than summaries on the no-train path), the ADR-0001 boundary has been breached — halt the dispatch and re-route per ADR-0001 before any plan ships ([PRD-v1, NFR-1 AC L228](../prd/PRD-v1-local-first-health-tracking-planning.md) [VERIFIED]; [ADR-0001, Decision](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- Time horizon: run all five checks at the first plan-assembly cycle (before the July-2026 visit, when the first plan ships) and at every plan generation thereafter.

**Review triggers:**
- A goal-domain appears with no matching deployed specialist in the roster (OQ-1) — re-evaluate the routing contract for the no-matching-specialist case before assembling a plan that includes it.
- The library crosses from thin to substantially populated for a domain — re-evaluate whether that domain's coverage-gap disclosures should become full regimens.
- The deployed roster changes (a specialist is added, removed, or merged) — re-validate that every in-scope domain still has exactly one routing target.
- ADR-0001's no-train routing path or "summary" contract changes — re-validate that the plan-assembly dispatch still runs on the correct lane over the agreed summary representation.
