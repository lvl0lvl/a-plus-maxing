## ADR-0043: Care Agent as the Plan Orchestrator

> **Y-Statement:** In the context of the plan path — where the care agent's system prompt is literally `{task:"care-conversation", profile, extractable_fields, notes}`, so its one `converse` call only converses and captures facts and returns `{"reply", "receipt"}` with NO orchestration instruction ([care_chat.py:214-219,280,304](../../scripts/serve/care_chat.py) [VERIFIED]), while the only cross-domain reconciliation the tree HAS is `orchestrate.reconcile`'s FIVE hard-coded pair-specific holds (RED-S/LEA short-circuit, energy bounce, overlap+conflict, additive-AE, Rx-BPMH) read off a bespoke `meta` side-channel ([orchestrate.py:13-47,101-124,337-456](../../scripts/plan/orchestrate.py) [VERIFIED]), and the loop's re-entry front door is the flat `run_orchestrated` composition `regenerate` re-runs — a per-domain compute-reconcile-record pass that synthesizes no single coherent plan ([plan_loop.py:130,177-180](../../scripts/serve/plan_loop.py); [orchestrate.py:621-635](../../scripts/plan/orchestrate.py) [VERIFIED]) — facing the tension that an integrated, physician-ready plan needs a component that decomposes goals into per-specialist briefs, collects the domain outputs, reconciles across domains, and synthesizes ONE coherent plan while the care agent already holds the full identity-stripped record and the operator relationship yet does none of it, we decided to adopt the care agent as the plan Orchestrator — it decomposes the operator's goals + assembled state into per-specialist briefs (each brief = that specialist's own input contract), collects the DOMAIN PROGRAMs (ADR-0041), reconciles the specialist-authored `cross_domain_seams`, and synthesizes ONE coherent plan + dated milestones, replacing the reply-only `{task:"care-conversation"}` prompt and becoming the front door ADR-0036's loop re-runs — to achieve one coherent cross-domain plan the operator can actually follow, accepting a SPLIT reversibility — MODERATE rework of the care-agent prompt + the orchestration control flow, but a HARD break on one frozen surface: generalizing the five holds means superseding the byte-frozen SAFETY-CRITICAL `orchestrate.reconcile` (a member of ADR-0032's inner-engine freeze glob), a HARD safety-surface break stated honestly and covered by the set-wide frozen-spine operator sign-off OBTAINED at the Phase-1 gate — plus a hard coupling to the two HARD one-way-door Tier-1 ADRs it consumes (ADR-0041's schema, ADR-0042's assembler), and the reconciliation-generalization risk that generalizing the five audited hard-coded holds to specialist-authored seams makes reconciliation coverage depend on what specialists declare.

### Context

The care agent's runtime responsibility today is conversation plus capture, not orchestration. `_care_messages` builds the model payload from a literal context dict — `{"task": "care-conversation", "profile": profile, "extractable_fields": _EXTRACTABLE_FIELDS, "notes": _PERSISTENCE_NOTE}` ([care_chat.py:214-219](../../scripts/serve/care_chat.py) [VERIFIED]) — carrying NO instruction to decompose, brief, collect, reconcile, or synthesize. `respond` re-reads the operator's full profile server-side, makes exactly ONE `converse` call, routes the model's proposed facts through the same capture gate the intake chat uses, and returns `{"reply", "receipt"}` ([care_chat.py:240-304](../../scripts/serve/care_chat.py) [VERIFIED]). So the care agent replies to the operator and writes captured facts back to the store — and does none of the five things a plan orchestrator does. The full identity-stripped record it would need is ALREADY in hand: `_care_profile` reads `router.summarize`'s identity-safe base plus the operator's raw health free-text plus the scaffold medications, precisely because it is the operator's own private agent ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]).

The only cross-domain reconciliation the tree HAS lives elsewhere and is fixed. `orchestrate.reconcile` implements FIVE hard-coded, pair-specific behaviors — a RED-S/LEA nutrition→workout short-circuit, a nutrition→workout energy bounce, overlap detection plus author-conflict holds, a supplement↔peptide additive-AE screen, and a supplement↔Rx BPMH screen ([orchestrate.py:13-47,337-456](../../scripts/plan/orchestrate.py) [VERIFIED]) — each bound to specific domains and each reading its cross-domain inputs not from the plan payload but from a bespoke `meta` side-channel (`_ae_profile` reads `candidate.meta.ae_profile`, [orchestrate.py:101-124](../../scripts/plan/orchestrate.py) [VERIFIED]). `generate_plans` records each surviving domain via `record_plan` and returns a per-domain `results` map ([orchestrate.py:467-479,621-635](../../scripts/plan/orchestrate.py) [VERIFIED]) — it holds and bounces pairwise, but it never authors ONE integrated program with milestones. And the loop's re-entry front door is that same flat composition: `regenerate` drives `run_orchestrated` ([plan_loop.py:130,177-180](../../scripts/serve/plan_loop.py) [VERIFIED]) — the per-domain compute-reconcile-record pass, which `.pipeline/dag.md` names the "flat `run_orchestrated` composition" the orchestrator is to replace ([.pipeline/dag.md](.pipeline/dag.md) [VERIFIED]). Decomposition-into-briefs and synthesis-into-one-plan exist nowhere in the tree.

Two stakeholders pull across this gap. The operator and the physician need one integrated, followable plan — not four disjoint per-domain outputs — that reconciles cross-domain conflicts and carries dated milestones; today no component decomposes the operator's goals into per-specialist briefs or synthesizes across domains, so what a specialist emits is composed only by the fixed reconciler and stored per-domain. The care agent is the natural home for that work: it already holds the full record (`_care_profile`, the care-agent implementation's own full identity-stripped read, [care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]; the same record the ADR-0042 assembler feeds every specialist) and owns the operator conversation. Against adopting it: this couples to two HARD, one-way-door Tier-1 decisions it must consume — ADR-0041 (the uniform DOMAIN PROGRAM shape the orchestrator collects and reconciles) and ADR-0042 (the assembled full record its briefs carry) — so it cannot be built until both land; and generalizing the five AUDITED hard-coded holds to a specialist-authored `cross_domain_seams` field is a real reconciliation-coverage risk. Because this redefines the care agent's runtime responsibility (converse+capture → decompose→brief→collect→reconcile→synthesize) and the plan control flow — a component-responsibility + control-flow decision touching multiple components — it is an architecture decision, not an implementation detail.

### Decision

**Adopt the care agent as the plan Orchestrator: it decomposes the operator's goals + assembled state into per-specialist BRIEFS (each brief carrying that specialist's own input contract), collects the returned DOMAIN PROGRAMs, reconciles the specialist-authored cross-domain seams, and synthesizes ONE coherent plan with dated milestones — replacing the reply-only `{task:"care-conversation"}` prompt that today only converses and captures.**

Stated generically (a training-domain brief, a compound-domain brief, a nutrition-domain brief — the same orchestration shape for each):

1. **Decompose → brief.** The orchestrator decomposes the operator's goals + assembled state into N per-specialist briefs; each brief IS that specialist's input contract — the ADR-0042 assembled identity-stripped record (the full record, or a per-specialist relevant slice — OQ-2, left open here), not the coarse `router.summarize` band.
2. **Collect.** It collects each dispatched specialist's DOMAIN PROGRAM (ADR-0041's uniform seven-field output — one shape across all domains).
3. **Reconcile the specialist-authored seams.** It reconciles by reading each program's `cross_domain_seams` field (ADR-0041), generalizing `orchestrate.reconcile`'s five hard-coded pair-specific holds ([orchestrate.py:337-456](../../scripts/plan/orchestrate.py) [VERIFIED]) into one uniform-field pass — the re-basing ADR-0041 hands to this decision.
4. **Synthesize.** It synthesizes ONE coherent plan plus dated milestones across the reconciled programs — an integrated program, not four disjoint per-domain plans stored side-by-side.
5. **This becomes the loop's front door.** The orchestrator replaces the flat `run_orchestrated` composition `regenerate` re-runs ([plan_loop.py:130,177-180](../../scripts/serve/plan_loop.py) [VERIFIED]); ADR-0036's re-gen re-enters decompose→brief→collect→reconcile→synthesize.
6. **Extends an existing responsibility, not a new component.** The care agent already holds the full record (`_care_profile`, [care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]) + the operator relationship; orchestration is a prompt + control-flow change on that existing agent, not a second full-record reader.
7. **Reversibility is SPLIT — MODERATE overall, HARD on one surface; synthetic/mock only.** The dominant cost is the care-agent prompt + orchestration control-flow rework — rework-costly but not a data-model migration, so MODERATE. But one surface it touches is HARD: generalizing the five holds supersedes the byte-frozen SAFETY-CRITICAL `orchestrate.reconcile` (a member of ADR-0032's inner-engine freeze glob), a one-way safety-surface break (see the Freeze-break note below). The live, metered run is operator-gated (OQ-4), as with ADR-0041/0042.

This does NOT decide the DOMAIN PROGRAM schema (ADR-0041), the assembler (ADR-0042), the stored plan model that persists the synthesized plan + milestones (ADR-0044, decided separately), or the dispatch/activation topology (ADR-0046) — it consumes the first two and its output is stored by the third.

**Freeze break (safety-critical surface — stated honestly per the set's freeze-break-honesty rule).** Generalizing `orchestrate.reconcile`'s five hard-coded pair-specific holds (RED-S/LEA, energy bounce, overlap+conflict, additive-AE, Rx-BPMH) into the uniform `cross_domain_seams` reconciliation supersedes `orchestrate.reconcile` — the FIRST member of ADR-0032's byte-frozen inner-engine glob `scripts/plan/{orchestrate,pipeline,assemble,generate_plan,adjudicate,adjust,track}.py` ([ADR-0032:26,43,107](ADR-0032-dna-aware-planning.md); [orchestrate.py:337-456](../../scripts/plan/orchestrate.py) [VERIFIED]) and a SAFETY-CRITICAL surface (its holds are the cross-domain safety screens). This is a HARD break on that surface. It is NOT re-gated here: it rides the SET-WIDE frozen-spine operator sign-off OBTAINED at the Phase-1 gate — the same sign-off that covers the ADR-0041/0042/0044 breaks, extended to the safety-reconciler because the whole-set supersession of the ADR-0032 frozen spine (record model + specialist-output + reconciler) is the load-bearing decision the operator accepted before Tier authoring proceeded ([.pipeline/discovery.md](.pipeline/discovery.md) [VERIFIED]). The safety CONTENT of the five holds is re-based, not deleted (Consequences-Neutral); the safety-critical subset is retained as always-on floors (OQ-1). The freeze-break probe for this surface is scoped to ADR-0043's OWN commit delta (the `orchestrate.py` reconciler rewrite), disjoint from ADR-0044's record-model probe and ADR-0041's `generate_plan.py`/`assemble.py` probe, so the sibling probes do not forbid each other's intended supersession ([ADR-0044, Validation](ADR-0044-comprehensive-plan-model.md) [VERIFIED]).

### Rationale

The care-agent orchestrator was weighed against keeping the fixed five-hold reconciler and incrementing it (Alternative A) and a separate orchestrator service distinct from the care agent (Alternative B), across four criteria the Context makes load-bearing — **integration** (does one component synthesize ONE coherent plan across domains?), **seam scalability** (what does reconciling a new cross-domain interaction cost?), **full-record locality** (is there ONE component holding the full record + the operator relationship, or two?), and **control-flow coherence** (is the loop's re-entry front door a real orchestrator?).

On **integration**, only an orchestrator that decomposes→briefs→collects→reconciles→synthesizes yields one coherent plan with milestones. The fixed reconciler (A) holds and bounces pairwise but returns a per-domain `results` map ([orchestrate.py:621-635](../../scripts/plan/orchestrate.py) [VERIFIED]) — it never authors an integrated program, so it leaves the synthesis gap open no matter how many holds are added. On **seam scalability**, reconciling by reading the uniform `cross_domain_seams` field costs 0 new hard-coded branches for a new cross-domain interaction, whereas A adds a bespoke branch over a new `meta` key per interaction — the same per-pair cost ADR-0041 identifies in the five current behaviors ([orchestrate.py:101-165,337-456](../../scripts/plan/orchestrate.py) [VERIFIED]). On **full-record locality**, the care agent already reads the full identity-stripped record (`_care_profile`, [care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]) and owns the operator conversation, so making IT the orchestrator adds no second full-record reader; the separate service (B) would duplicate that full-record access — a second raw-record reader is a second audit surface — and would sever the decompose/brief step from the agent that actually knows the operator's goals and history. On **control-flow coherence**, the chosen path makes the loop's re-entry front door a real orchestrator, replacing the flat composition ([.pipeline/dag.md](.pipeline/dag.md) [VERIFIED]).

Long-term, the orchestrator is the single component the re-architecture set's authoring flow runs through: it consumes ADR-0041's schema + ADR-0042's assembler and its synthesized plan feeds the ADR-0044 plan model and the ADR-0046 dispatch roster. The cost the decision accepts is real and not hidden: MODERATE rework of the care-agent prompt + the orchestration control flow, a hard coupling to two HARD one-way-door ADRs, and the reconciliation-generalization risk (Consequences-Negative). That cost is accepted because integration and mechanical seam-reconciliation are the two properties the operator's core ask — a single followable plan — requires, and neither alternative delivers both without reproducing the synthesis gap (A) or the duplicated-full-record audit surface (B).

- Mechanical seam reconciliation: the orchestrator reconciles by reading the uniform `cross_domain_seams` field (ADR-0041) in one pass, so a new cross-domain interaction adds 0 hard-coded reconciler branches and 0 bespoke `meta` keys — versus today's five pair-specific holds over a `meta` side-channel ([orchestrate.py:101-124,337-456](../../scripts/plan/orchestrate.py) [VERIFIED]).
- Extends an existing responsibility, not a new component: orchestration is a prompt + control-flow change on the care agent, which already holds the full record + the operator relationship ([care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]) — no second full-record reader, no new audit surface.

**Negative:**

Overall reversibility is MODERATE (prompt + control-flow rework), but THIS surface is a HARD safety-surface break — named honestly, riding the set-wide frozen-spine sign-off (Decision Freeze-break note), not silently absorbed into "MODERATE rework." Once shipped, reverting the reconciler to the five fixed holds is itself a migration.
- **Couples to two HARD one-way-door ADRs.** The orchestrator cannot be built until ADR-0041 (the DOMAIN PROGRAM shape it collects/reconciles) and ADR-0042 (the assembled full record its briefs carry) land, so it inherits their frozen-spine-break risk and their operator-sign-off gating ([.pipeline/dag.md](.pipeline/dag.md) [VERIFIED]) — a standing dependency, not a one-time cost.
- **Reconciliation-generalization risk vs today's five audited hard-coded holds.** Generalizing the FIVE fixed holds — RED-S/LEA, energy bounce, overlap+conflict, additive-AE, Rx-BPMH, each code that ALWAYS runs and is individually audited ([orchestrate.py:13-47,337-456](../../scripts/plan/orchestrate.py) [VERIFIED]) — to a specialist-authored `cross_domain_seams` field makes reconciliation coverage a function of what specialists DECLARE: a cross-domain interaction no specialist surfaces is un-reconciled, where today the five holds fire regardless of any author declaration. This trades a small audited fixed set for scalability to arbitrary seams; the safety-critical subset should be retained as always-on floors (OQ-1) — a long-term (1+ year) invariant to enforce in review rather than a fixed code set.
- **Longer, costlier orchestrator call.** Decompose→brief→collect→reconcile→synthesize over N specialists is materially more model work than one `converse` reply, and it scales with the ADR-0046 roster (4 → 15+) — a standing per-run cost, not a one-time hit.

**Neutral:**
- The care agent's capture responsibility is unchanged: `respond` still writes operator-stated facts through the capture gate ([care_chat.py:286-289](../../scripts/serve/care_chat.py) [VERIFIED]). Orchestration adds a responsibility; it does not remove conversation or capture.
- The five holds' safety CONTENT does not vanish: the liaison adjudication + the additive-AE / Rx-BPMH screens re-base onto the `cross_domain_seams` reconciliation surface (ADR-0041's fold of the `meta` side-channel into the uniform field) — a re-basing, not a deletion.

### Alternatives Considered

#### Alternative A: Keep the fixed five-hold reconciler and bolt on more holds
Leave `orchestrate.reconcile`'s five hard-coded pair-specific behaviors in place and add a new hard-coded branch (over a new `meta` key) each time a new cross-domain interaction arises; keep the care agent reply-only.
- **Supporting evidence:** Zero rework of the care-agent prompt and no coupling to ADR-0041/0042; the five holds are already built, audited, and always-on ([orchestrate.py:337-456](../../scripts/plan/orchestrate.py) [VERIFIED]), so reconciliation coverage for the known interactions is a fixed, inspectable code set — the lowest-risk path for the interactions that exist today.
- **Trade-offs:** REJECTED — it does not scale to specialist-authored seams and never closes the synthesis gap. Each new interaction is a new bespoke branch over a new side-channel key (the per-pair cost ADR-0041 names), and the reconciler still returns a per-domain `results` map ([orchestrate.py:621-635](../../scripts/plan/orchestrate.py) [VERIFIED]) — it holds and bounces pairwise but authors no single coherent plan with milestones. No amount of added holds decomposes goals into briefs or synthesizes across domains.
- **When this becomes the right choice:** If the domain set and its cross-domain interactions were small, fixed, and stable forever (no roster growth, no new seams) AND a single integrated plan were not a goal, the audited fixed set would beat a declaration-dependent generalization.

#### Alternative B: A separate orchestrator service distinct from the care agent
Build a new orchestrator component that decomposes→briefs→collects→reconciles→synthesizes, kept separate from the care agent, reading the assembled record independently.
- **Supporting evidence:** Clean separation of concerns — the care agent stays a pure conversation/capture surface while a dedicated service owns orchestration; the orchestration logic is isolated and independently testable.
- **Trade-offs:** REJECTED — the care agent already holds the full identity-stripped record (`_care_profile`, [care_chat.py:166-200](../../scripts/serve/care_chat.py) [VERIFIED]) and the operator relationship, so a separate service would DUPLICATE that full-record access — a second raw-record reader is a second PII audit surface to stress-test — and would sever the decompose/brief step from the agent that actually knows the operator's goals and conversation history. It adds a component and an audit surface to do work the care agent is already positioned to do.
- **When this becomes the right choice:** If the care agent's conversational role and the orchestration role diverged enough that co-locating them harmed either — or if a deployment needed orchestration without a care agent at all — a separate service's isolation could outweigh the duplicated full-record reader.

#### Dissent: Keep the care agent reply-only; the flat composition plus operator stitching IS the synthesis
**Source:** The status-quo position — the flat `run_orchestrated` composition records per-domain plans ([plan_loop.py:130,177-180](../../scripts/serve/plan_loop.py); [orchestrate.py:621-635](../../scripts/plan/orchestrate.py) [VERIFIED]) and the operator (or the ADR-0037 tailoring presentation pass) stitches them into a followable whole, so no authoring/synthesis orchestrator is needed and the care agent stays a conversation surface.
**Conditions under which this becomes the right choice:** If per-domain plans that the operator reads side-by-side were an acceptable deliverable — i.e. if cross-domain synthesis and dated milestones were not required and the fixed five holds covered every safety-relevant interaction — then adding an orchestrator would be over-engineering. The dissent loses because the operator's core ask is one integrated, physician-ready plan: presentation-layer stitching (ADR-0037) re-presents a cleared plan, it does not decompose goals into briefs or reconcile-and-synthesize across domains, so the synthesis gap stays open under the status quo.

### Validation Approach

**Confirmation criteria:**
- **The orchestrator emits N briefs from the specialist input contracts (executable, load-bearing).** Seed goals + an assembled state spanning ≥2 domains (a training-domain and a compound-domain); run the orchestrator and assert it produces exactly one brief per active specialist, each brief carrying that specialist's own input contract (the ADR-0042 assembled record — the full record or a per-specialist relevant slice, OQ-2), NOT a coarse `router.summarize` band. Threshold: brief count == active-specialist count AND each brief carries the specialist's required inputs; if a brief collapses to the coarse band or a specialist is un-briefed, the decompose step under-briefed — halt.
- **The orchestrator synthesizes a reconciled plan (executable).** Seed two specialists whose returned DOMAIN PROGRAMs declare a conflict in `cross_domain_seams`; assert the orchestrator reconciles the seam (holds / adjusts / routes the declaring side) AND emits ONE coherent plan with dated milestones, not two disjoint per-domain plans. Threshold: the declared seam is reconciled (not shipped as-is) AND the output is a single integrated plan carrying milestones; if the output is a per-domain `results` map with no synthesis, the synthesis step did not run — halt.

**Falsification criteria:**
- **A cross-domain conflict passes un-reconciled → FAIL (deterministic).** Seed two DOMAIN PROGRAMs declaring a `cross_domain_seams` conflict; if the synthesized plan ships both sides without holding, adjusting, or routing the conflict to the safety gate, the reconciliation regressed. Threshold: **0 declared-seam conflicts reach the synthesized plan un-reconciled**; ≥1 un-reconciled declared conflict → halt and repair before release. (Distinct from the confirmation probe: this asserts the NEGATIVE — a conflict must never survive into the plan un-handled.)
- **A brief missing the specialist's inputs → FAIL (deterministic).** Assert every emitted brief carries the specialist's full input contract (the ADR-0042 assembled record); a brief that omits a required input — e.g. collapses back to a coarse band or drops a domain-relevant field — means the decompose step under-briefed the specialist. Threshold: **0 briefs missing a required input**; ≥1 → halt and re-route the brief builder to the assembled record.
- **Time horizon:** run the emit-N-briefs probe, the synthesize-reconciled-plan probe, the un-reconciled-conflict probe, and the under-briefed probe at the first orchestrator build, at the operator-present LIVE run (OQ-4), at every release thereafter, and before the July-2026 physician-visit deliverable.

**Review triggers:**
- ADR-0041's DOMAIN PROGRAM schema changes (a field added/removed, or the `cross_domain_seams` shape changes) — re-verify the orchestrator collects and reconciles the new shape.
- ADR-0042's assembler changes what it feeds a specialist — re-verify each brief carries the assembled record, not a residual `router.summarize` collapse.
- ADR-0046's roster scales (4 → 15+ with progressive activation) — re-verify the orchestrator briefs only the active specialists and reconciles their declared seams in one pass.
- A new safety-critical cross-domain interaction is identified — decide whether it is an always-on reconciliation floor or a specialist-declared seam (OQ-1), so the generalization risk (Negative-3) stays bounded.
- The care-agent prompt/seam (`_care_messages` / `respond`) changes — re-confirm the orchestration responsibility and the capture responsibility both hold.
