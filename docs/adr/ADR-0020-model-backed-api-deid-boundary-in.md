## ADR-0020: Adopt a Model-Backed API De-Identification Boundary for Raw Plan-Intake (De-Id IN)

> **Y-Statement:** In the context of the operator-confirmed S91 full-target plan engine, where the de-id-IN boundary is today the deterministic `router.summarize` gate that can only emit closed-vocabulary band/class tokens and cannot faithfully de-identify the rich free-form intake the conversational pivot now captures, facing the tension between that capture fidelity and ADR-0001's "Only plan reasoning touches the model, over summaries rather than raw PII" crown-jewel boundary, we decided to adopt a model-backed no-train API de-identification boundary that ingests raw operator plan-intake PII and emits the de-identified summary the plan pipeline consumes — superseding `router.summarize` as the SOLE de-id-IN on the plan path while `summarize` survives as the persisted-side de-id — to achieve a de-id richer than the coarse derivers can produce without re-plumbing onto the deferred local-model North Star, accepting that raw plan-intake PII now transits an API boundary before de-identification (the crown-jewel relaxation on the plan path) under bounded no-train retention, and that the boundary MUST be fail-closed to honest-no-plan and the persisted/committed store MUST stay de-identified, enforced by `router.summarize` plus the `block-pii-commit.sh` + `pre-push-pii-scan.sh` hooks.

### Context

The plan path's de-identification-IN boundary is deterministic today. `router.summarize` reads operator state only through the store-read surface and derives a name-addressable summary over the closed `SUMMARY_FIELD_SET`, applying per-field band/class transformations (`_age_band`, `_issue_class`, `_dietary_pattern_class`, `_supplement_stack_class`, …) so no named-excluded raw-PII field survives, and `dispatch` rejects any payload field outside the closed field-set before the no-train send ([router.py:540-630, 633-693](../../scripts/plan/router.py) [VERIFIED]). This boundary is structurally coarse by design: it can only emit closed-vocabulary tokens — `restricted`/`plant-based`/`omnivore` for diet, `low`/`moderate`/`high` for training volume, `back-region`/`lower-limb-region` for an issue ([router.py:343-372, 422-462, 331-340](../../scripts/plan/router.py) [VERIFIED]). The raw free-text is mapped to one bucket and discarded; the unstructured detail the conversational intake exists to surface cannot pass through a keyword-bucketer.

Two forces pull against each other. The S91 target establishes that the operator's intake is now a rich, free-form conversation (the conversational-intake pivot), and the deterministic derivers cannot de-identify rich input faithfully — they reduce a paragraph of nutrition or training detail to a single band, the same lossiness ADR-0016 records for the rigid form ([ADR-0016, Context L18](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). A model-backed de-id can read the operator's actual words and emit a de-identified summary that preserves clinically meaningful structure the field-set has no token for. Against that stands ADR-0001's crown-jewel boundary: "Only plan reasoning touches the model, over summaries rather than raw PII," whose falsification names "≥1 plan-reasoning dispatch sending raw (non-summary) PII to the model" as a boundary breach ([ADR-0001, Decision L24, Falsification L105](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]). Routing raw plan-intake PII to an API *before* de-identification is exactly that surface.

The decision binds more than the operator. The data subject's assurance rests on raw labs, DNA, and health history not leaving the device to a model before de-identification, and ADR-0005 keeps that PII out of committed history — a leak that, once landed, cannot be cleanly scrubbed ([ADR-0005, Context L20, Falsification L98-100](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]). ADR-0016 already opened a scoped raw-egress carve-out (the live conversation may egress raw on the no-train lane while persisted facts stay de-identified) and mandates re-opening for any second raw-egress class ([ADR-0016, Decision L24, Review-trigger L107](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). The model client this would run through already exists and is swappable — `ModelClient.author(domain, summary)` over an injectable no-train backend, fail-closed on any failed call ([client.py:32-74, 84-99](../../scripts/model/client.py) [VERIFIED]) — but its live `_ClaudeNoTrainBackend.author` is still `NotImplementedError`, wired at the operator checkpoint ([client.py:126-130](../../scripts/model/client.py) [VERIFIED]). Because this redraws where de-identification happens on the plan path rather than implementing a settled boundary, it is a decision, not a code comment.

### Decision

Adopt a model-backed no-train API de-identification boundary that ingests raw operator plan-intake PII and emits the de-identified summary the plan-generation pipeline consumes. This boundary supersedes `router.summarize` as the SOLE de-id-IN on the plan path; `summarize` survives unchanged as the persisted-side de-id over store-read state. The boundary runs only on the no-train lane (the same lane as ADR-0016's conversation egress), is fail-closed to the honest no-plan state on any failure, and never causes raw plan-intake PII to reach a committed/tracked file.

### Rationale

The de-id-IN boundary was evaluated against the deterministic-gate-only status quo and a hybrid across three criteria the target and ADR-0001 make load-bearing: **de-id fidelity** (can the boundary faithfully de-identify rich free-form intake), **PII-exposure surface** (how much raw PII crosses the model boundary), and **reversibility** (whether the posture retracts to the North Star without re-plumbing).

On **de-id fidelity**, only the model-backed boundary delivers it: the deterministic derivers are keyword-bucketers that collapse free-form intake to one closed-vocabulary token and discard the rest ([router.py:343-372, 422-462](../../scripts/plan/router.py) [VERIFIED]), so a paragraph of training or nutrition detail de-identifies to a single band the planner then reasons over — the exact lossiness the conversational pivot exists to overcome ([ADR-0016, Context L18](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). A model can read the operator's words and emit a de-identified summary that preserves structure the field-set has no token for. On **PII-exposure surface**, this is the criterion the decision pays into rather than wins: the deterministic gate's surface is zero raw-PII to the model (`dispatch` raises on any out-of-field-set payload, [router.py:668-672](../../scripts/plan/router.py) [VERIFIED]), whereas the model-backed boundary routes raw plan-intake PII across the API before de-id — accepted because it reuses ADR-0016's already-adopted threat-model-B raw-egress posture rather than opening a new exposure class, and the persisted side stays de-identified (the boundary's output still feeds the `summarize`-gated store). On **reversibility**, the boundary runs through the existing swappable `ModelClient` seam ([client.py:32-74](../../scripts/model/client.py) [VERIFIED]; [ADR-0015, Decision L22](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]), so when the North-Star local model reaches ADR-0001's Alternative-C parity the raw-egress retracts to zero by swapping the backend, not re-plumbing the callers ([ADR-0001, Alternative C L65-69](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).

Long-term, the cost the decision accepts permanently for V1 is that the plan path's de-id-IN is no longer a 0-raw-PII in-process gate but a model-backed boundary with bounded no-train retention on raw plan-intake PII (the same exposure ADR-0016 accepted for the conversation, now extended). The mitigation that keeps this falsifiable is the fail-closed contract and the retained persisted-side `summarize` gate, both made testable in the Validation Approach.

### Consequences

**Positive:**
- The de-id-IN boundary can faithfully de-identify rich free-form plan-intake instead of collapsing it to one closed-vocabulary token, removing the keyword-bucketer ceiling the deterministic derivers impose (e.g. diet de-identifies past the 5-class `restricted`/`plant-based`/`plant-forward`/`omnivore`/`general-diet` cut, [router.py:343-372](../../scripts/plan/router.py) [VERIFIED]).
- The persisted-side PII boundary is untouched: `router.summarize` still derives a 0-raw-PII store-read summary and raises on raw-PII pass-through, and `dispatch` still rejects any out-of-field-set payload — so the persisted/committed store stays de-identified regardless of the new IN boundary ([router.py:540-630, 633-693](../../scripts/plan/router.py) [VERIFIED]).
- The boundary reuses the already-wired swappable `ModelClient.author` seam and ADR-0016's existing no-train lane, so it needs no new trust infrastructure and keeps ADR-0001's deferred local-model Alternative C reachable as a backend swap ([client.py:32-74](../../scripts/model/client.py) [VERIFIED]; [ADR-0015, Consequences L37](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]).

**Negative:**
- Raw operator plan-intake PII now transits an API boundary BEFORE de-identification on the plan path — the crown-jewel relaxation. Where ADR-0001 guaranteed the plan model saw only a de-identified summary, raw intake (which may name medications, labs, the January-2026 issue, and identity) now crosses to the no-train API first. This is a real expansion of the plan-path egress surface, not a relabeling ([ADR-0001, Falsification L105](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- Off-device bounded retention now covers raw plan-intake PII, not only summaries: the no-train lane carries bounded (not zero) retention — the project records a ~30-day no-train profile, the precise window unconfirmed against published policy ([ADR-0001, Consequences-Negative L42, OQ-2 L120](ADR-0001-pii-trust-boundary-no-train-routing.md) [VENDOR-CLAIM; window UNVERIFIED]). The exposure ADR-0016 bounded for the conversation now extends to plan-intake de-id, a standing 1+ year exposure.
- A new attack/leak surface is introduced on the plan path: the boundary's raw input must never reach a tracked file. The mitigation is that raw residue lands only on the gitignored `vault/scaffold/filled/` / `vault/store/` surfaces and the registered `block-pii-commit.sh` PreToolUse hook plus the `pre-push-pii-scan.sh` backstop deny a committed filled-value/PII path, but the discipline burden of keeping raw plan-intake off the tracked tree is new and permanent ([ADR-0005, Decision L28 amendment, Falsification L100](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]; [ADR-0016, Consequences L44](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).
- The plan path gains a hard runtime dependency on the no-train API and network for de-id-IN: a deterministic in-process gate could run offline; a model-backed boundary cannot. Each plan-intake de-id carries the no-train API's per-call cost and latency ([ADR-0015, Consequences-Negative L40, L42](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]). This ADR fixes the PER-CALL fail-closed degrade (a failed/partial de-id call → honest no-plan), but the SYSTEM-LEVEL behavior when the de-id API boundary is DOWN/unreachable for a whole run — does the engine degrade to the deterministic `router.summarize` gate, or halt entirely to honest-no-plan — is a build-planning decision carried as OQ-4.
- The zero-egress invariant is now a SCOPED carve-out with TWO raw-egress classes (the conversation and plan-intake de-id), so every future PII-bearing path must be checked against the bound, and the standing risk is a future change widening the class silently — a documentation-coherence and review cost ([ADR-0016, Consequences L45](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]).

**Neutral:**
- "Raw plan-intake" becomes a named data class distinct from "live conversation," "persisted fact," and "summary" — a second member of ADR-0016's raw-egress set the intake, de-id, and persistence sides must share.
- The no-train API becomes a runtime dependency for plan-intake de-id specifically, alongside its existing roles for intake conversation and plan-author dispatch; the store, ingestion, and dashboard generation stay model-independent per ADR-0001 ([ADR-0001, Decision L24](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Full model-backed de-id IN (Chosen)
The no-train API model ingests raw operator plan-intake PII and emits the de-identified summary the pipeline consumes, superseding `router.summarize` as the sole de-id-IN on the plan path.
- **Supporting evidence:** Only this option de-identifies rich free-form intake faithfully — the deterministic derivers are keyword-bucketers that discard everything past one band ([router.py:343-372, 422-462](../../scripts/plan/router.py) [VERIFIED]). It runs through the existing swappable `ModelClient` seam and ADR-0016's no-train lane, so the North-Star retraction is a backend swap, not a re-plumb ([client.py:32-74](../../scripts/model/client.py) [VERIFIED]).
- **Trade-offs:** Routes raw plan-intake PII across the API before de-id — the crown-jewel relaxation — under bounded no-train retention, and adds a hard network dependency and per-call cost to the de-id-IN step. Accepted because the fidelity gain is the target's load-bearing requirement and the exposure reuses ADR-0016's already-adopted threat-model-B posture.
- **When this becomes the right choice:** It is, for V1, when rich conversational intake is the capture model and the local-model North Star has not reached parity.

#### Alternative B: Keep the deterministic `summarize` gate as the SOLE de-id-IN; use a model only on the OUT side (ADR-0021)
Leave `router.summarize` as the only de-id-IN (0 raw PII to the model on intake) and introduce the model only for the OUT-side PII re-insertion (the ADR-0021 sibling).
- **Supporting evidence:** Preserves the 0-raw-PII-IN invariant entirely — `dispatch`'s whitelist still rejects every out-of-field-set field, so no raw plan-intake PII ever crosses the model boundary ([router.py:633-693](../../scripts/plan/router.py) [VERIFIED]). It is the strongest IN-side privacy posture and needs no new IN dependency. The OUT side could still re-insert from the gitignored identity config without the IN boundary changing at all.
- **Trade-offs:** It accepts that the IN side stays as lossy as today's closed field-set — a paragraph of intake de-identifies to one band, and the conversational pivot's rich capture cannot reach the planner faithfully, reproducing the form's lossiness the pivot exists to overcome ([ADR-0016, Context L18](ADR-0016-intake-conversation-egress-relaxation.md) [VERIFIED]). The coarse gate cannot faithfully de-identify free-form input because de-identification-by-keyword-bucket is a one-token projection, not a structure-preserving transform.
- **When this becomes the right choice:** If a future privacy constraint forbids any raw plan-intake egress, or if the intake reverts to a structured-form-only capture where the closed field-set is sufficient and no free-form richness needs de-identifying.

#### Alternative C: Hybrid — model proposes de-id, deterministic gate verifies/backstops
The deterministic gate strips named-excluded raw PII first; the model de-identifies only the residual free-text the field-set cannot structure, and `summarize`/`dispatch` verify the model's output before it reaches the planner — the "model proposes, gate disposes" pattern ADR-0017 already uses for extraction.
- **Supporting evidence:** Narrows what raw text the API sees (the field-set strips identity/contact/lab fields first), and keeps a deterministic backstop — the same posture as `extract.persist_extraction`, which routes a model proposal UNCHANGED through the capture gate so a model-emitted raw value never lands in a `SUMMARY_FIELD_SET` item ([extract.py:110-147](../../scripts/serve/extract.py) [VERIFIED]). It is a smaller PII-exposure surface than Alternative A while still richer than B.
- **Trade-offs:** It is materially more complex to build and reason about (two de-id stages with a verification contract between them), and the residual free-text the model must still de-identify is exactly the unstructured PII-dense detail — so the exposure reduction over Alternative A is partial, not categorical. The verification gate would have to judge whether a model-emitted summary is de-identified, which the deterministic `summarize` cannot do for free-form text (it only whitelists field NAMES, [router.py:668-672](../../scripts/plan/router.py) [VERIFIED]).
- **When this becomes the right choice:** If the accepted raw-egress exposure of Alternative A proves too large under a hardened threat model but full reversion to the coarse gate (B) is too lossy — the hybrid is the middle posture that trades build complexity for a smaller raw-text surface.

#### Dissent: The summaries-not-raw purist position
**Source:** ADR-0001's anchor — "Only plan reasoning touches the model, over summaries rather than raw PII," whose falsification names raw (non-summary) PII to the model as a boundary breach ([ADR-0001, Decision L24, Falsification L105](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]). A reviewer can reasonably hold that the plan path's de-id-IN should never be a model boundary — that the operator's raw plan-intake reaching an API before de-id is a genuine weakening of the system's most load-bearing privacy guarantee, and Alternative B (deterministic IN, model only OUT) is the correct posture even at the cost of de-id fidelity.
**Conditions under which this becomes the right choice:** If the no-train provider's no-train or retention terms degrade (raw plan-intake becoming training-eligible or indefinitely retained), OR if local open-weight models reach intake-de-id parity on the operator's hardware (ADR-0001 Alternative C's condition) — in either case the model-backed de-id-IN should be retracted and the deterministic gate restored as the sole de-id-IN, the purist position becoming correct.

### Validation Approach

**Confirmation criteria:**
- During a plan-intake de-id, the de-id-IN boundary runs only on the no-train lane and emits a de-identified summary the pipeline consumes — verified by inspecting every outbound call during a plan-intake run (expected: de-id-IN lane = no-train, count of de-id-IN calls on any training-eligible lane = 0).
- The persisted side stays de-identified: after a plan-intake run, every store-write and the `router.summarize` persisted-side output carries only de-identified field-set-class values — verified by scanning the post-run store and the `summarize` output for raw operator PII (expected: 0 raw-PII hits), the boundary `summarize`/`dispatch` already enforce ([router.py:540-630, 633-693](../../scripts/plan/router.py) [VERIFIED]).
- The boundary is fail-closed: an injected failed/empty/partial de-id call yields the honest no-plan state, never a plan over a fabricated or raw-leaking summary — verified by injecting a `ModelCallError` at the de-id boundary and asserting the no-plan outcome (expected: honest no-plan, mirroring `ModelClient`'s fail-closed contract, [client.py:84-99](../../scripts/model/client.py) [VERIFIED]).

**Falsification criteria (including the raw-PII-leak test):**
- Raw-PII-leak probe (the crown-jewel test): seed a known raw-PII token (a synthetic legal name + a synthetic lab value) into the raw plan-intake, run the de-id-IN boundary, and scan (a) the de-identified summary the pipeline consumes and (b) every committed/persisted file on a fresh-clone scan. Threshold: **0 raw-PII hits past the boundary AND 0 raw-PII hits in any committed/persisted file** (the de-identified-store invariant). If ≥1 hit in either, the boundary leaked — halt and repair the de-id boundary / restore the gitignore boundary before release.
- If a failed/timed-out/empty/partial de-id call yields a plan over a fabricated or raw-leaking summary (≥1 such result reaching the planner or the operator), the fail-closed contract is breached — halt and restore the honest-no-plan degrade before release.
- If any raw plan-intake PII is found in a COMMITTED file or git history on a fresh-clone scan (≥1 hit), the relaxation has leaked beyond its scope — because history cannot be cleanly scrubbed, treat as a release-blocking incident and revert the leaking path ([ADR-0005, Falsification L98](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]).
- If any raw egress to a TRAINING-ELIGIBLE lane is observed (≥1 de-id-IN call off the no-train lane), the lane bound has failed — halt and restore the no-train routing before release.
- Time horizon: run the raw-PII-leak probe, the fail-closed check, and the lane/tracked-file checks at the first build of the de-id-IN boundary and at every release thereafter, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- A change to the no-train provider's commercial no-train terms or retention policy — re-verify the no-train claim and the bounded-retention window now extended to raw plan-intake.
- The North-Star transition to a local model is initiated — the raw plan-intake egress retracts to zero (the backend swaps), and this relaxation is closed.
- Any proposal to add a THIRD raw-egress class (beyond the conversation and plan-intake de-id) — re-open this decision and ADR-0016 against the bound before adding it.
- The maintained-HTML / re-insertion output path (ADR-0021/0025) lands — re-verify the commit/push hooks deny raw plan-intake residue and re-inserted PII on the new output surface (the §6 Pending tension), noting the operator-NAME scan-SCOPE hole ADR-0021/0025 OQ-1 carry: `vault/artifacts/generated/` is outside the hooks' `DATA_BEARING_PREFIXES` name scan, so this needs a scan-SCOPE fix, not just a fixture.
