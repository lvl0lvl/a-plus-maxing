## ADR-0030: Model-Based Universal Ingestion — Any-Format Upload Extraction via the No-Train Lane

> **Y-Statement:** In the context of a local-first single-operator health system whose ingestion path today reads only a closed set of wearable/DNA export shapes and has no parser for an arbitrary or unstructured upload, facing the tension between an alpha tester needing to bring in a file of any format (a lab PDF, an arbitrary CSV/JSON export, a photo of a report) and the crown-jewel no-egress boundary that file content must not cross, we decided to route any-format uploads through the no-train model lane to EXTRACT structured `(item, timepoint, source, value)` readings, gate every extracted value behind operator confirmation, and land confirmed readings through the UNCHANGED `store.append` sink, to achieve universal ingestion without per-source adapter brittleness and without an engine rewrite, accepting that this is the FIRST extension of the operator's already-authorized no-train lane onto the ingestion axis — previously the import/ingestion routine ran model-independently (ADR-0001 Decision L24, ADR-0003 falsification #3) — which broadens the operator-data-to-no-train-API surface from plan-path data to whole raw uploaded FILES, and that on acceptance ADR-0030 amends the ingestion-model-independence falsification criteria of ADR-0001, ADR-0003, ADR-0013, and ADR-0029 to authorize this one extraction-egress class on the SAME remote no-train lane that already serves chat (ADR-0016) and de-id (ADR-0020/0027), bounded by operator-confirm-before-land and retractable to a zero-egress local model at the swappable ADR-0015 seam (the documented North-Star direction).

### Context

The system brings an export into the store one structured way per known source. The operator CLI's `_EXT_SOURCE` maps four extensions to named adapters, and `_detect_source` raises `SystemExit` on any other extension — a `.pdf` cannot be inferred and exits asking for a `--source` that does not exist ([__main__.py:39,42-49](../../scripts/ingest/__main__.py) [VERIFIED]). The website's router `route_upload` dispatches only the named wearable adapters plus a `.zip` content-branch and "adds NO extraction logic" by design ([route.py:58-93](../../scripts/serve/route.py), [route.py:14](../../scripts/serve/route.py) [VERIFIED]). `dna.land` fails loud on a file that is not a 23andMe genotype table ([dna.py:101-105](../../scripts/ingest/dna.py) [VERIFIED]). The labs dropzone advertises `.pdf`/`.csv`/`.txt`/`.json`, but `status.resolve` surfaces only landed-file COUNTS — there is no labs parser or adapter behind the dropzone ([status.py:51-66](../../scripts/ingest/status.py) [VERIFIED]).

Three forces pull across more than one stakeholder. The operator (and an alpha tester on arbitrary providers) wants to upload whatever a clinic or device hands them — a PDF panel, an idiosyncratic CSV, a phone photo of a printout — and a non-developer cannot author an adapter per provider. The data subject's safety binds the second force: a health reading carries a value, and a misread lab or biomarker number is a clinical-safety risk, so a value that lands must be the operator's confirmed value, not a machine's guess (ADR-0009's zone-state honesty rule forbids "an invented number… or sample content presented as data", [ADR-0009 D2](ADR-0009-dashboard-visual-shell-seven-zones.md) [VERIFIED]). The third force is the crown-jewel containment: a browser upload is operator PII the moment it arrives, governed by ADR-0001's no-egress boundary on the upload surface ([ADR-0013 Context](ADR-0013-operator-started-loopback-intake-server.md) [VERIFIED]), so routing a raw file to a model is a new egress, not a local read. Against all three stands a frozen seam worth preserving: `store.append` is the single sink and `READING_FIELDS = keying.LINE_FIELDS` is the universal reading shape every adapter already targets ([ingest.py:36](../../scripts/ingest/ingest.py), [adapter.py:20](../../scripts/ingest/adapter.py) [VERIFIED]). Because the resolution sets where raw file content may go and constrains every future ingest path, the rationale cannot live in a code comment beside the router.

### Decision

Route a browser-uploaded file of any format (PDF, arbitrary CSV/JSON, a photo of a report) through the no-train model lane to extract structured `(item, timepoint, source, value)` readings, require the operator to confirm every extracted value before anything lands, and write confirmed readings through the unchanged `store.append` sink. This is the FIRST routing of the ingestion path through a model: until now the import/ingestion routine ran model-independently (ADR-0001 Decision L24; ADR-0003 falsification #3), so this decision EXTENDS the operator's already-authorized no-train lane — the SAME remote no-train API that already serves chat (ADR-0016) and de-id (ADR-0020/0027), not a new lane and not a local model — onto the ingestion axis, and on acceptance amends the falsification criteria of ADR-0001, ADR-0003, ADR-0013, and ADR-0029 accordingly (see Related Decisions). Operator-confirmation-before-land is a hard precondition: no model-extracted reading becomes the operator's data unconfirmed. The extraction backend is the swappable no-train client (ADR-0015), so swapping it for a local model retracts the file egress to zero with callers unchanged.

### Rationale

Three options were evaluated against four criteria the governing decisions make load-bearing: **format coverage** (can it read arbitrary and unstructured input?), **egress posture** (does file content leave the device?), **extraction fidelity/safety**, and **seam reuse** (does it edit the ingestion engine?).

On **format coverage**, only a capable model reads the unstructured long tail — a scanned photo with no text layer, an idiosyncratic lab layout — that the closed extension map and the deterministic detectors cannot ([__main__.py:42-49](../../scripts/ingest/__main__.py) [VERIFIED]); a model extracts `(item, timepoint, source, value)` rows from arbitrary document shapes including images [VENDOR-CLAIM: model document-extraction capability]. On **egress posture**, the deterministic and local-model options are zero-egress while the remote no-train call adds a bounded file egress; the decision weights covering the exact arbitrary inputs the alpha exists to handle over zero-egress for V1, because the swappable ADR-0015 seam keeps a zero-egress local backend reachable as the North Star without a re-plumb ([ADR-0015 Decision](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]). On **fidelity/safety**, a model can misread a value and a misread lab or biomarker number is a clinical-safety risk, so the mitigation is structural: operator-confirm-before-land, grounded directly in that misread-is-a-clinical-safety-risk force, with ADR-0009's no-invented-number rule cited as the honest-data POSTURE it extends from the render surface to ingest (not as a render-rule applied out of domain to justify the gate) — a misread is caught at confirmation, before it is "data". On **seam reuse**, extraction is a NEW FRONT DOOR onto the unchanged sink, exactly as ADR-0013's router is a front door to `ingest.run`/`dna.land`: confirmed readings carry the Line-Field-Set shape and land via `store.append`, so ADR-0003's 0-shared-routine-edit invariant holds ([ingest.py:36](../../scripts/ingest/ingest.py), [adapter.py:20](../../scripts/ingest/adapter.py), [ADR-0003 Decision](ADR-0003-source-extensible-ingestion-interface.md) [VERIFIED]) — no engine edit. This new-front-door / 0-engine-edit precedent speaks to the SINK ONLY — confirmed readings still land the established way — and does NOT make the EGRESS boundary-safe by analogy: ADR-0013's loopback front door was boundary-safe *because* it made 0 outbound calls, whereas this front door egresses the raw file to the no-train lane. That egress is a genuine boundary extension, owned in Consequences (Negative) and amended in Related Decisions, not a precedent-covered no-op.

The honest ceiling bounds the coverage claim: extraction recovers the readings a document *states*, not data the document does not carry. A DNA *report* PDF carries the lab's stated interpretations, not the raw genotype table `dna.land` validates ([dna.py:71-105](../../scripts/ingest/dna.py) [VERIFIED]); extraction yields the report's findings, never the variants. Long-term, the bounded file egress is the cost the decision accepts for V1; the ADR-0015 swap to a local model (Alternative B) retracts it to zero at the North Star, callers unchanged, and the deterministic detectors (Alternative A, Open Questions) can ship as a zero-egress fast-path that falls back to the model only for the unstructured tail.

### Consequences

**Positive:**
- Any-format upload becomes ingestible without a per-provider adapter: the `.pdf`/arbitrary-CSV/JSON `SystemExit` dead-end closes ([__main__.py:46-49](../../scripts/ingest/__main__.py) [VERIFIED]) and the display-only labs dropzone gains a real ingest path ([status.py:65](../../scripts/ingest/status.py) [VERIFIED]).
- New front door, 0 engine edit: confirmed readings land through the unchanged `store.append` single sink in the Line-Field-Set shape, so ADR-0003's 0-shared-routine-edit invariant holds — no second sink, no second dedupe key ([ingest.py:36](../../scripts/ingest/ingest.py), [adapter.py:20](../../scripts/ingest/adapter.py) [VERIFIED]).
- The operator-confirm gate keeps the store honest: because a misread lab or biomarker value is a clinical-safety risk, no unconfirmed, possibly-misread model-extracted reading becomes the operator's data — grounded primarily in that misread-safety force, with ADR-0009's no-invented-number rule as the honest-data posture/precedent it extends to ingest ([ADR-0009 D2](ADR-0009-dashboard-visual-shell-seven-zones.md) [VERIFIED]).
- Retractable to zero egress: the ADR-0015 seam swaps remote→local with callers unchanged, so the egress this decision accepts is reversible rather than entrenched ([ADR-0015 Decision](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]).

**Negative:**
- **The FIRST extension of the no-train lane onto the ingestion axis — a real boundary extension, not a bounded instance of the existing carve-out.** Until now the import/ingestion routine ran model-independently: ADR-0001 Decision L24 names "the import/ingestion routine" as running "model-independently… sending zero operator PII to any model," and ADR-0003 falsification #3 halts ingestion if it "sends ≥1 raw operator reading to the model" ([ADR-0003 Falsification](ADR-0003-source-extensible-ingestion-interface.md) [VERIFIED]). ADR-0030 relaxes that separate ingestion guarantee for the first time. The honest negative is the broadened surface: the operator-data-to-no-train-API surface grows from plan-path data (the ADR-0016 conversation + the ADR-0020/0027 de-id summary) to **whole raw uploaded FILES** — labs, DNA reports, biomarker panels, not summaries — on the ingestion axis. There are three honest counting frames, not one: it is the FIRST class on the ingestion-model-independence axis (ADR-0001/0003), the THIRD on the no-train-model-egress axis (conversation → de-id-IN → file extraction — the reconsideration ADR-0027's own review trigger names, "any proposal to add a THIRD raw-egress class… re-open this decision and ADR-0016 against the bound", [ADR-0027 Review triggers](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]), and the SECOND outbound class on the ADR-0013 upload server (after the `/chat` turn). It is a real, permanent (1+ year) expansion that must be proven egress-bounded on every release.
- **Amendment declaration (on acceptance).** ADR-0030 amends the falsification criteria of four accepted ADRs to authorize this one ingestion-extraction egress class on the no-train lane — the SAME amendment convention the set already uses (ADR-0016 amended ADR-0013, ADR-0020 amended ADR-0016, ADR-0015 amended ADR-0001): **ADR-0001** — its ingestion clause's model-independence (Decision L24) is scoped to admit the extraction call; **ADR-0003** — falsification #3 ("halt ingestion if it sends ≥1 raw reading to the model") is scoped, the no-train-lane extraction call being the authorized, operator-confirmed exception; **ADR-0013** — its upload-server falsification ("exactly ONE outbound class, the `/chat` call; any OTHER outbound call reds the boundary", [ADR-0013 Validation L100](ADR-0013-operator-started-loopback-intake-server.md) [VERIFIED]) is scoped to admit a SECOND authorized upload-server outbound class, the extraction call, exactly as ADR-0016 added the first; **ADR-0029** — its "≥1 outbound class beyond the ADR-0016 `/chat` turn → block adoption" falsification ([ADR-0029 Falsification L95](ADR-0029-unified-spa-front-end-shell.md) [VERIFIED]) is scoped to admit the upload-extraction egress, same no-train-lane bound. The four `[AMENDED …, ADR-0030 §amends]` notes are applied to those ADR files on acceptance/build per the set's lifecycle — this PROPOSED ADR DECLARES the amendments; it does not edit those files now. Mitigations on all four: the SAME operator no-train key/lane (0 file bytes to any non-no-train endpoint), operator-confirm-before-land, and swappable-to-local at the ADR-0015 seam (North Star).
- A standing verification burden the deterministic CLI never carried: every release must prove file content egresses ONLY on the no-train lane and that 0 readings land unconfirmed — two new falsification probes (below) on every release rather than an offline local read.
- A fidelity ceiling that shifts review onto the operator: the model can misread a value; operator-confirm catches it but a long or dense upload means many confirmations, a real per-upload cost.
- A per-upload metered model call plus a network dependency for novel-format ingestion: an offline operator cannot ingest a novel-format file via this path (the wired adapters still ingest their sources offline).

**Neutral:**
- The no-train API becomes a runtime dependency for novel-format ingestion specifically, alongside its de-id/chat/author roles ([client.py:233-335](../../scripts/model/client.py) [VERIFIED]). The EXISTING wired adapters and the store stay model-independent per ADR-0001 — but the new extraction front door is, by design, NOT model-independent: that is the boundary extension owned in Negative, not an exception that leaves ADR-0001's ingestion clause intact. The model-independence guarantee now holds for the deterministic adapters, not for the universal-extraction path ([ADR-0001 Decision](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).
- Confirmed readings land only in the gitignored local store ([ADR-0005 Decision](ADR-0005-operator-agnostic-clonable-pii-free-trunk.md) [VERIFIED]) — a boundary fact inherited from the existing sink, not new behavior.

### Alternatives Considered

#### Alternative A: Deterministic-only — per-source adapters + generic format-family detectors + local `pdftotext`
Extend the existing adapter family with generic format-family detectors (genotype-table / tabular-timeseries / lab-panel) and a local `pdftotext` text-layer extraction, keeping ingestion model-free and offline.
- **Supporting evidence:** Zero raw-file egress (nothing leaves the device), zero per-call cost, no network dependency, no operator-confirm burden — the strongest privacy posture. It is the same family as the existing adapters and `dna.land`'s shape-validator ([dna.py:30-46](../../scripts/ingest/dna.py) [VERIFIED]), and `pdftotext` is a present, local, mechanistic extractor ([VERIFIED: poppler 26.02.0 at /opt/homebrew/bin/pdftotext]).
- **Trade-offs:** Brittle on the arbitrary/unstructured long tail — `pdftotext` recovers nothing from a scanned photo (no text layer), and a generic detector cannot read an idiosyncratic lab layout; it leaves unreadable exactly the inputs the alpha exists to handle. The operator-rejected path: it has genuine merit (zero-egress, deterministic) but cannot reliably handle the unstructured tail.
- **When this becomes the right choice:** If a future privacy constraint forbids ANY raw-file egress, the deterministic path is restored as the sole ingest path. Its tier-1 detectors can also ship independently, zero-egress, as a fast-path ahead of the model (Open Questions OQ-2).

#### Alternative B: Local-model extraction (`marker` / a local LLM)
Run a local document-extraction model (e.g. `marker`, present at `~/.local/bin/marker`) or a local LLM as the extraction backend, behind the same ADR-0015 seam.
- **Supporting evidence:** Zero raw-file egress while still handling arbitrary input including images, and the ADR-0015 swap makes A/B/C a backend choice, not a re-plumb ([ADR-0015 Decision](ADR-0015-swappable-no-train-model-client.md) [VERIFIED]). `marker` is already installed locally ([VERIFIED: ~/.local/bin/marker], a heavy ~GB local dependency). This IS the North-Star direction.
- **Trade-offs:** Heavier to run and less capable on the hardest layouts than the remote model today [VENDOR-CLAIM: relative local-vs-frontier extraction capability], so V1 universal coverage would regress.
- **When this becomes the right choice:** When a local extraction model reaches parity on the operator's hardware for the operator's document shapes — swap the backend at the ADR-0015 seam and the file egress retracts to zero.

#### Alternative C: Remote no-train model extraction (Chosen)
Route the raw upload to the live no-train backend ([client.py:233-249](../../scripts/model/client.py) [VERIFIED]) for extraction, gate the result behind operator-confirm, and land confirmed readings via `store.append`.
- **Supporting evidence:** Most capable on arbitrary and unstructured input today [VENDOR-CLAIM], and it reuses three live seams rather than building new ones — the ADR-0027 no-train backend, the ADR-0013 loopback upload front door, and the ADR-0015 swap seam — landing through the unchanged sink ([ingest.py:36](../../scripts/ingest/ingest.py) [VERIFIED]).
- **Trade-offs:** Adds the bounded raw-file egress class, a per-call cost/network dependency, and the operator-confirm burden — accepted because the universal-coverage need dominates for V1 and the egress is bounded to the no-train lane and reversible at the ADR-0015 seam.
- **When this becomes the right choice:** It is, for V1, when universal any-format coverage is required and the local extraction model has not reached parity.

#### Dissent: The file-content-never-egresses purist position (inherited from ADR-0001/0016/0027)
**Source:** ADR-0001's crown-jewel anchor and ADR-0027's recorded summaries-not-raw dissent ([ADR-0001 Y-Statement](ADR-0001-pii-trust-boundary-no-train-routing.md), [ADR-0027 Dissent](ADR-0027-live-no-train-deid-backend.md) [VERIFIED]). A reviewer can reasonably hold that adding a third raw-egress class — and the first carrying whole uploaded *files* — is a genuine weakening of the most load-bearing privacy guarantee, and that Alternative A (deterministic-only, zero-egress) is the correct posture even at the cost of the unstructured long tail.
**Conditions under which this becomes the right choice:** If the no-train provider's no-train or retention terms degrade (raw files becoming training-eligible or indefinitely retained), OR if the deterministic detectors plus a local model (Alternatives A/B) cover the operator's real document shapes — then the remote extraction egress should be retracted (the backend swapped or the model path disabled) and the zero-egress path restored as the sole ingest path.

### Validation Approach

**Confirmation criteria:**
- Extraction is mock-testable at 0 live spend: a patched SDK / injected fake backend returns a canned extraction, and the test asserts (a) each extracted reading carries the full Line-Field-Set, (b) a reading reaches `store.append` ONLY after the operator-confirm step, and (c) the extraction call runs on the no-train lane only — expected: extracted readings ⊆ Line-Field-Set; 0 store writes before confirm ([adapter.py:20](../../scripts/ingest/adapter.py), [ingest.py:36](../../scripts/ingest/ingest.py) [VERIFIED]).
- New front door, 0 engine edit: a structural check that the extraction path calls the unchanged `ingest.run`/`store.append` and adds no second sink and no second dedupe key — expected: 0 edits to the `ingest.py`/`adapter.py` shared routines ([ADR-0003 Decision](ADR-0003-source-extensible-ingestion-interface.md) [VERIFIED]).
- Backend swappability: the extraction model resolves from the ADR-0015 seam — expected: swapping the backend requires 0 caller-side edits ([client.py:44-45](../../scripts/model/client.py) [VERIFIED]).

**Falsification criteria (quantitative; the crown-jewel probe is load-bearing):**
- File-egress probe (the crown-jewel test): seed a known token into an uploaded file, run the extraction path under the OS-level egress guard with sockets blocked except the no-train host. Threshold: the ONLY egress of file content is the no-train lane — **0 file bytes to any non-no-train endpoint**; a non-no-train key, or any other outbound connection carrying file content, reds the boundary → halt and repair before release.
- Confirm-gate probe: run extraction and scan the store before the operator confirms. Threshold: **0 model-extracted readings land in the store without an operator-confirm step**; ≥1 unconfirmed reading in the store is a breach → halt and restore the confirm gate before release.
- Fail-closed-on-error: inject an extraction failure / timeout / malformed response and assert the call raises `ModelCallError` and that 0 fabricated readings are offered for confirmation ([client.py:105-126](../../scripts/model/client.py) [VERIFIED]). Threshold: ≥1 fabricated reading surfaced over a failed/partial extraction = breach.
- Key-never-committed scan: grep every tracked file and git history on a fresh clone for the API-key value — threshold: **0 API-key hits**; ≥1 is release-blocking ([key_source.py:65-91](../../scripts/model/key_source.py) [VERIFIED]).
- Time horizon: run the file-egress probe, the confirm-gate probe, the fail-closed check, and the key scan at the first build of the extraction route, at the operator-present LIVE run, and at every release thereafter, and before the July-2026 physician-visit deliverable.

**Review triggers:**
- A change to the no-train provider's no-train or retention terms — re-verify the file-egress class this decision adds.
- A local extraction model reaching parity on the operator's document shapes — swap the backend (Alternative B); the file egress retracts to zero.
- Any proposal to add a FOURTH raw-egress class — re-open this decision and ADR-0016 against the bound.
- A change to the `store.append`/Line-Field-Set sink or the ADR-0013 upload front door — re-confirm the new front door still routes without editing the shared routine.
