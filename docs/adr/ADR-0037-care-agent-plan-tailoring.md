## ADR-0037: Care-Agent Plan Tailoring as a Named, Mechanically-Gated Raw-Egress Carve-Out

> **Y-Statement:** In the context of the closed plan loop, where the driver records a DE-IDENTIFIED `plan::<domain>` (the specialists only ever see `router.summarize`'s closed field-set tokens, [router.py:23-60](../../scripts/plan/router.py) [VERIFIED]) yet the operator's core ask is a plan personalized against their ACTUAL peptides / supplements / meds / injuries, facing the tension that the care agent already reads that raw detail ([care_chat.py:125-131,182-198](../../scripts/serve/care_chat.py) [VERIFIED]) but v1's "tailoring stays a safety-floored, non-authoring pass" was PROSE with no code behind it (review finding D) — able to shadow-prescribe a held domain or dose an investigational compound — AND a `plan-tailor::` STORE stream is forbidden (ADR-0021/0001 keep the persisted store + every tracked render de-identified, review finding E), we decided to add a CARE-LANE tailoring pass that runs AFTER the driver records the de-identified plan, personalizes it with the operator's raw data, and renders ONLY into the gitignored, realpath-guarded, name-reinserted `maintained` artifact (ADR-0025/0021) — never a de-id store stream, never the de-id dashboard — as a NEW NAMED raw-egress carve-out that amends ADR-0001's egress list on the ADR-0016/0032/0035 discipline, floored by MECHANICS IN CODE (emit a domain ONLY when `plan::<domain>` exists AND was in NO hold set; a dosing-token reject on compound-domain output; a DETERMINISTIC drug×supplement×peptide interaction screen built on ADR-0034's curated `rx-interaction-classes` + the existing BPMH/additive-AE lenses that FAILS CLOSED to "see your doctor"; a load-time tripwire that no tailoring key is a `SUMMARY_FIELD_SET` member) — to achieve the operator's personalized plan without routing raw data around the de-id boundary or a plan around the safety composition, accepting a SECOND raw-egress surface to audit and that the tailored plan lives only in the local artifact, not the shareable dashboard.

### Context

The care agent is the operator's OWN private agent: `_care_profile` reads the RAW health detail the operator entered at intake — the peptide, supplement, diet, training, and injury free-text — under `_CARE_HEALTH_DETAIL` ([care_chat.py:125-131](../../scripts/serve/care_chat.py) [VERIFIED]), plus the record-only MEDICATIONS the scaffold holds ([care_chat.py:189-198](../../scripts/serve/care_chat.py) [VERIFIED], where `record.pop("rx-interaction-classes")` surfaces the raw meds under an explicit `medications` label). That is the whole point of the care lane: the de-identification line is the care→SPECIALIST/plan hand-off (`router.dispatch`), NOT the operator→care-agent link ([care_chat.py:11-18,165-176](../../scripts/serve/care_chat.py) [VERIFIED]). The operator's core ask — a plan personalized to that real detail — is therefore natural for the care lane and structurally impossible for the specialist lane.

The forces pull hard against each other, and the six-agent design review ([design/dynamic-plan-loop-design.md §0, findings C/D/E/F](../../design/dynamic-plan-loop-design.md) [VERIFIED]) named where v1 relaxed the boundary it did not quote:

- **The de-id boundary is not one sentence but a SET, mechanically enforced.** `router.summarize` emits ONLY `SUMMARY_FIELD_SET` tokens ([router.py:752-819](../../scripts/plan/router.py) [VERIFIED]); `dispatch` fail-closes if a payload carries anything outside that set (`set(payload) ⊆ SUMMARY_FIELD_SET`, [router.py:854-855](../../scripts/plan/router.py) [VERIFIED]); load-time asserts pin the field-set disjoint from the raw-PII set (`set(SUMMARY_FIELD_SET).isdisjoint(set(EXCLUDED_RAW_PII))`, [router.py:667-668](../../scripts/plan/router.py) [VERIFIED]), and `rx-interaction-classes` is curated record-only, deliberately absent from `capture.WIRED_TOKENS` with its OWN load-time tripwire ([capture.py:95-102,283-286](../../scripts/serve/capture.py) [VERIFIED]). Raw operator detail crosses to the model ONLY as named, operator-signed-off carve-outs (ADR-0016 intake conversation; ADR-0032 de-associated variant queries; ADR-0035 de-associated meds curation — [ADR-0001:92,98,99](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]).

- **v1's tailoring "floor" was prose in unwritten code (finding D — CONFIRMED).** v1 asserted tailoring is "not an authoring authority" and observes "a safety floor," but nothing in code enforced it — so a tailoring pass could shadow-prescribe a HELD domain or hand back a dose for an investigational compound. A held domain is a code fact: `_held_result` records `recorded: False, plan: None` for a candidate a cross-domain hold suppressed ([orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]), and the hold sets (`holds` / `conflict_held` / `rx_bpmh_held`) are tracked independently ([orchestrate.py:64-69,366-367](../../scripts/plan/orchestrate.py) [VERIFIED]). A tailoring pass that emits for a domain the engine held is exactly the plan-around-the-safety-composition failure the loop exists to prevent.

- **A `plan-tailor::` store stream is forbidden (finding E — CONFIRMED).** ADR-0021 keeps the persisted store and every TRACKED render de-identified — real PII materializes ONLY on the local, gitignored artifact ([ADR-0021 Y-Statement](ADR-0021-pii-reinsertion-local-artifact-out.md) [VERIFIED]); ADR-0001's persisted-side-de-identified invariant is unamended by any of its carve-outs. A new raw store stream would put operator PII in the de-identified store — the one thing every prior decision forbids.

- **This IS a new named raw-egress purpose (finding F — CONFIRMED).** v1 waved tailoring through as "the care lane already exists." But every raw egress in this system is a SEPARATELY ADR-named, operator-signed-off carve-out amending ADR-0001's list — that is the established discipline (ADR-0016/0032/0035, [ADR-0001:92,98,99](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]). Tailoring reads raw meds/peptides/supplements/injuries into a model presentation call; it is a distinct purpose from the meds-curation egress ADR-0035 already named, and it must be named on its own terms.

The decision must give the operator the personalized plan they asked for WITHOUT (a) routing raw data around the de-id boundary into a store stream or the shareable dashboard, (b) letting the presentation pass alter the safety-cleared prescription, or (c) leaving the floor as prose. Every clause of the floor must be a mechanism in code, not a sentence in a prompt.

### Decision

After the driver records the de-identified `plan::<domain>`, a CARE-LANE tailoring pass personalizes the plan with the operator's RAW data (the same `_care_profile` raw detail the care agent already reads, [care_chat.py:182-198](../../scripts/serve/care_chat.py) [VERIFIED]) and renders the result ONLY into the gitignored `maintained` artifact — the ADR-0025 living artifact `reinsert_out` re-inserts the real operator name onto, written under the realpath-containment guard `_assert_contained` and the atomic temp-then-rename ([maintained.py:61-107,312-325](../../scripts/generate/maintained.py) [VERIFIED]). It is NEVER written to a de-identified store stream (ADR-0021/0001 forbid) and NEVER to the de-identified dashboard. Tailoring is a NEW NAMED raw-egress carve-out that AMENDS ADR-0001's egress list, per the ADR-0016/0032/0035 discipline.

The floor is a set of MECHANICS IN CODE, not prompt prose:

1. **Emit-gate on recorded, non-held domains.** Tailoring emits for a domain ONLY when `plan::<domain>` EXISTS in the promoted store AND that domain was in NO hold set for the pass that produced it (`holds` / `conflict_held` / `rx_bpmh_held`, [orchestrate.py:64-69,366-367](../../scripts/plan/orchestrate.py) [VERIFIED]; a held candidate carries `recorded: False, plan: None`, [orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]). A held domain has no recorded plan to tailor; the gate reads the recorded state, it does not re-derive the safety decision. This is the mechanical form of "tailoring is not an authoring authority" — it can only re-present a plan the safety composition already cleared and recorded, never conjure one for a domain the engine suppressed.

2. **Dosing-token reject on compound-domain output.** The tailoring pass's output for a compound domain (supplements, peptides) is scanned for a dosing token; a hit is REJECTED (the domain degrades to its un-tailored recorded plan). Tailoring re-presents the cleared prescription; it does not introduce or alter a dose. This closes the "dose an investigational compound" shadow-prescribe path in code.

3. **A deterministic drug×supplement×peptide interaction screen that FAILS CLOSED.** Before a compound domain's tailored presentation is emitted, a DETERMINISTIC RULE (not a model call) screens the operator's raw meds × raw supplements × raw peptides for an interaction, built ON ADR-0034's curated `rx-interaction-classes` ([ADR-0034 Y-Statement](ADR-0034-intake-content-deid-safety-mapping.md) [VERIFIED]; the curated class tokens, [router.py:44,219-239](../../scripts/plan/router.py) [VERIFIED]) plus the existing BPMH / additive-AE lenses the reconciler already runs ([orchestrate.py:168-193 additive-AE lens, 262-280 rx-BPMH screen](../../scripts/plan/orchestrate.py) [VERIFIED]). On a match the screen SURFACES "see your doctor" — it never silently drops the concern. The screen is a rule over curated class data; it does NOT ride the presentation model call (§4), so a model failure cannot suppress it.

4. **Presentation failure degrades to the un-tailored (safe) plan; the safety screen is split off the model call.** The tailoring PRESENTATION is a model call; the SAFETY SCREEN (§3) and the emit-gate (§1) are deterministic code that runs independently. If the presentation model call fails or returns empty, the domain degrades to its un-tailored, de-identified, safety-cleared recorded plan — the same fail-closed posture the care turn already takes on `ModelCallError` ([care_chat.py:277-288](../../scripts/serve/care_chat.py) [VERIFIED]). The safety screen never fails open on a presentation failure because it does not depend on the presentation call.

5. **A load-time tripwire that no tailoring key is a `SUMMARY_FIELD_SET` member.** Mirroring the `capture.WIRED_TOKENS ⊆ SUMMARY_FIELD_SET` and `router` disjointness asserts ([capture.py:283-286](../../scripts/serve/capture.py), [router.py:667-668,688-689](../../scripts/plan/router.py) [VERIFIED]), an import-time assert reds if any tailoring-artifact key is a `SUMMARY_FIELD_SET` member — so a tailoring key can never masquerade as a planner token that `summarize`/`dispatch` would carry across the de-id boundary.

The tailoring pass reuses the `reemit_maintained` writer and its guards; it opens no store stream, defines no store key, and adds no second name-bearing writer ([maintained.py:37-40 module contract](../../scripts/generate/maintained.py) [VERIFIED]).

### Rationale

The design was evaluated against the crown-jewel boundary taken as the full SET (the five clauses the review enumerated, [design/dynamic-plan-loop-design.md §3](../../design/dynamic-plan-loop-design.md) [VERIFIED]): (1) every recorded plan passed `gate_dispatch`; (2) store + tracked renders stay de-identified; (3) specialists see only field-set tokens; (4) each raw egress is a named ADR carve-out; (5) the maintained artifact is name-reinserted under the realpath guard. The chosen design satisfies each MECHANICALLY. Clause 1 holds because the emit-gate reads the recorded/held state and can only re-present a cleared plan (§1) — tailoring never re-enters or bypasses `gate_dispatch`, it renders a plan that already survived it. Clause 2 holds because the output lands ONLY in the gitignored artifact via `reemit_maintained`, never a store stream or the de-id dashboard (§Decision), enforced by the no-`SUMMARY_FIELD_SET`-key tripwire (§5). Clause 3 is untouched — the tailoring pass runs in the care lane, downstream of `router.dispatch`, and reads raw detail the care agent already holds; no new token reaches the specialist path. Clause 4 holds because tailoring is named here and amends ADR-0001's list on the ADR-0016/0032/0035 discipline. Clause 5 holds because tailoring reuses `_assert_contained` + `reinsert_out` rather than adding a second writer.

The safety FLOOR is deliberately split from the PRESENTATION so a model failure cannot unlatch a safety guard: the emit-gate (§1), the dosing-token reject (§2), and the interaction screen (§3) are deterministic code; only the prose personalization is a model call, and its failure degrades to the safe un-tailored plan (§4). A deterministic interaction rule is chosen over a model-judged one precisely so its firing is falsifiable in CI (fires on a known combo, does NOT fire on a safe combo — a paired control, §Validation) and cannot be talked out of a referral by a persuasive prompt.

### Consequences

**Positive:**
- The operator gets the personalized plan they asked for — the maintained artifact presents each cleared domain against their ACTUAL peptides / supplements / meds / injuries — WITHOUT any raw data reaching a store stream, the de-id dashboard, or the specialist path. The personalization rides the care lane's existing raw access ([care_chat.py:182-198](../../scripts/serve/care_chat.py) [VERIFIED]), not a new boundary crossing.
- The tailoring floor is MECHANICAL, not prose: a held domain cannot be tailored (§1, verifiable against `_held_result`'s `recorded: False`, [orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]); a compound dose cannot be introduced by presentation (§2); a raw drug×supplement×peptide interaction surfaces "see your doctor" deterministically and fails closed (§3); a presentation failure degrades safe (§4). Each clause has a red-on-violation test (§Validation).
- No new store stream, no second name-bearing writer, no new de-id-boundary token: the pass reuses `reemit_maintained`'s realpath-guarded atomic write ([maintained.py:61-107,312-325](../../scripts/generate/maintained.py) [VERIFIED]) and the load-time tripwire (§5) keeps tailoring keys out of `SUMMARY_FIELD_SET`.

**Negative:**
- **A SECOND raw-egress surface to audit.** Before this decision, the ONLY raw egresses were the named intake-conversation (ADR-0016), variant-query (ADR-0032), and meds-curation (ADR-0035) classes. Tailoring adds a distinct one — a raw-detail model PRESENTATION call whose non-leak now also depends on the gitignore boundary + the commit/push PII hooks holding, exactly the standing dependency ADR-0021 accepted ([ADR-0021 Y-Statement](ADR-0021-pii-reinsertion-local-artifact-out.md) [VERIFIED]). Every future review of the egress set must now stress-test one more surface; the audit surface grew, permanently.
- **The tailored plan lives ONLY in the local artifact, not the shareable dashboard.** By construction (clause 2), the personalized presentation cannot be rendered into the de-identified dashboard or any tracked surface — so the operator cannot share the tailored plan the way they can share a de-identified dashboard view. Sharing the tailored plan means sharing the gitignored local file directly, outside the system's tracked-render path. This is the deliberate cost of keeping raw PII off every tracked surface.

**Neutral:**
- The interaction screen's class coverage is only as complete as ADR-0034's curated `rx-interaction-classes` ([ADR-0034 Y-Statement](ADR-0034-intake-content-deid-safety-mapping.md) [VERIFIED]); a med whose class is uncurated is not screened by the rule (it still routes through the care agent's own reasoning). The screen strengthens as the curated class set grows; it does not weaken any existing lens.
- Under ADR-0036's loop, the tailoring pass re-runs on each re-generation; it is idempotent per `(plan, date)` and degrades to the un-tailored plan on failure, so a re-run produces no duplicate/stale artifact (the ADR-0036 constraint, [.pipeline/dag.md §constraint propagation](.pipeline/dag.md) [VERIFIED]).

### Alternatives Considered

#### Alternative A: Care-lane tailoring, artifact-only, mechanically floored (Chosen)
Tailoring runs after the recorded de-id plan, personalizes with raw care-lane data, renders ONLY into the gitignored maintained artifact, and is floored by the five code mechanics (emit-gate, dosing-reject, deterministic fail-closed interaction screen, presentation-failure degrade, no-`SUMMARY_FIELD_SET`-key tripwire).
- **Supporting evidence:** The only option that gives the operator personalization while satisfying every clause of the crown-jewel set mechanically ([design §3](../../design/dynamic-plan-loop-design.md) [VERIFIED]): the floor is red-on-violation code, the output never leaves the gitignored artifact, and the pass reuses the ADR-0021/0025 realpath-guarded writer ([maintained.py:61-107](../../scripts/generate/maintained.py) [VERIFIED]) rather than a new surface.
- **Trade-offs:** A second raw-egress surface to audit (Negative-1); the tailored plan is local-artifact-only, not dashboard-shareable (Negative-2). Accepted because both are the deliberate price of keeping raw PII off every tracked surface while still answering the operator's core ask.
- **When this becomes the right choice:** When the operator needs a plan personalized to raw detail, the store/dashboard must stay de-identified, and the floor must be enforceable code rather than prompt prose — the present state.

#### Alternative B: A new `plan-tailor::` STORE stream
Persist the tailored, raw-personalized plan as a new `plan-tailor::<domain>` store stream, rendered from the store like any other domain.
- **Supporting evidence:** Symmetric with the existing `plan::`/`dvq::` streams; the tailored plan would be a first-class, queryable, re-renderable store object with the store's dedupe/namespacing guarantees for free.
- **Trade-offs:** FORBIDDEN by ADR-0021/0001/0005 (review finding E — CONFIRMED, [design §0](../../design/dynamic-plan-loop-design.md) [VERIFIED]): the persisted store and every tracked render stay de-identified; a raw-personalized store stream puts operator PII in the de-identified store, violating the persisted-side-de-identified invariant every carve-out leaves intact ([ADR-0001:24-26](ADR-0001-pii-trust-boundary-no-train-routing.md) [VERIFIED]) and the `block-pii-commit` / disjointness posture ([router.py:667-668](../../scripts/plan/router.py) [VERIFIED]). Rejected outright — no benefit justifies raw PII in the store.
- **When this becomes the right choice:** Never under the local-first/public-repo threat model; only a fundamentally different deployment (a HIPAA/BAA-covered private store) could reconsider it, which V1 explicitly is not.

#### Alternative C: Let tailoring ALTER the safety-cleared prescription
Give the tailoring pass authoring authority — allow it to adjust doses, add or drop a compound, or re-present a held domain, on the reasoning that the care agent "knows the operator best."
- **Supporting evidence:** Maximally personalized; the care agent holds the fullest picture of the operator's raw detail, so letting it author would in principle produce the most tailored plan.
- **Trade-offs:** This IS the shadow-prescribe risk (review finding D — CONFIRMED). A pass with authoring authority can emit a plan for a domain the engine HELD (`_held_result`'s `recorded: False`, [orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]) or dose an investigational compound — routing a plan around the `gate_dispatch` safety composition and the cross-domain holds, the exact failure the loop exists to prevent. Rejected: tailoring is a PRESENTATION authority, never an AUTHORING one, and the emit-gate (§1) + dosing-reject (§2) enforce that in code.
- **When this becomes the right choice:** Never for an automated pass; a human clinician adjusting the prescription is a different actor entirely, outside this decision's scope.

#### Alternative D: A prompt-only "please refuse to prescribe" floor
Keep tailoring an ungated model call and instruct the model, in its prompt, to refuse to prescribe, respect holds, and defer doses to a doctor.
- **Supporting evidence:** Zero new code; the smallest possible change — just prompt text.
- **Trade-offs:** This is precisely v1's floor that the review CONFIRMED as unenforced prose ("'not an authoring authority' + 'safety-floor' are prose with no mechanism," finding D, [design §0](../../design/dynamic-plan-loop-design.md) [VERIFIED]). A prompt instruction has NO enforcement: a model that ignores it shadow-prescribes with nothing to catch it, and the safety screen would ride the same model call that could fail. Rejected — the whole point of the decision is to replace prose with mechanism; the floor must be code that reds on violation, split off the presentation model call (§4).
- **When this becomes the right choice:** Never as the sole floor; prompt guidance is a complement to the mechanical floor, not a substitute for it.

### Validation Approach

**Confirmation criteria:**
- **Personalized output asserted (executable):** run the tailoring pass over a fixture with a recorded, non-held `plan::<domain>` and raw care-lane detail (a peptide + a supplement); assert the maintained artifact's tailored section for that domain references the operator's ACTUAL raw specifics (not a coarse band). Expected: the artifact carries the personalization; the domain's tailored section is present.
- **Held domain NOT emitted (executable, paired with the falsification below):** seed a domain HELD (an additive-AE / conflict / Rx-BPMH hold so `_held_result` records `recorded: False, plan: None`, [orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]); run tailoring; assert NO tailored content is emitted for the held domain. Expected: 0 tailored output for a held domain; other domains may still tailor.
- **Interaction screen fires on a known combo (executable):** feed raw meds × supplements × peptides that intersect a curated `rx-interaction-class`; assert the tailored output for the affected compound domain SURFACES "see your doctor" and does NOT silently drop the concern. Expected: the referral text is present, fail-closed.
- **Fail-closed on model error (executable):** inject a `ModelCallError` / empty return on the presentation call; assert the affected domain degrades to its un-tailored, de-identified, safety-cleared recorded plan, and the deterministic safety screen still ran. Expected: the un-tailored plan renders; the screen's verdict is unchanged by the presentation failure.

**Falsification criteria:**
- **Emit-gate probe:** if a tailored plan is emitted for a domain whose recorded state is `recorded: False` (a held domain), clause §1 is broken — halt and re-route the emit-gate to read the recorded/held state ([orchestrate.py:459-465](../../scripts/plan/orchestrate.py) [VERIFIED]). Threshold: 0 tailored output for any held domain.
- **Dosing-token reject probe:** feed a dosing token in the tailoring output for a compound domain (supplements / peptides); assert it is REJECTED and the domain degrades to the un-tailored recorded plan. Threshold: 0 compound-domain tailored output carrying a dosing token. If a dose survives, §2 is broken — halt.
- **Interaction-screen PAIRED control (deterministic rule):** the screen must fire on a KNOWN interacting combo AND must NOT fire on a SAFE combo (a med × supplement × peptide set with no curated-class intersection). Threshold: fires-on-known == True AND fires-on-safe == False. A rule that fires on both (or neither) is not the deterministic screen §3 specifies — halt and re-ground the rule against ADR-0034's curated classes ([ADR-0034 Y-Statement](ADR-0034-intake-content-deid-safety-mapping.md) [VERIFIED]).
- **Fail-closed-on-model-error probe:** if a presentation model failure produces a crash, a silently dropped concern, OR a fail-OPEN (the domain emitted with the safety screen skipped), §4 is broken — halt and re-split the safety screen off the presentation model call. Threshold: presentation failure → un-tailored safe plan rendered AND the deterministic screen's verdict intact.
- **Wire-scan non-egress probe (crown-jewel):** seed a synthetic raw-PII token (a legal name + a raw drug name) into the raw intake; run the full tailoring path; dump BOTH the store streams and the de-identified dashboard payload; assert the raw tokens AND every tailoring-artifact key are ABSENT from both (the `test_care_chat` wire-scan pattern, [design §4](../../design/dynamic-plan-loop-design.md) [VERIFIED]). Threshold: 0 raw-PII hits and 0 tailoring keys in any store stream or the dashboard. A hit means tailoring content reached a tracked/de-id surface — halt and restore the artifact-only boundary.
- **Load-time tripwire probe:** if any tailoring-artifact key is added to `SUMMARY_FIELD_SET`, the import-time assert (§5) must RED — mirroring `capture.WIRED_TOKENS ⊆ SUMMARY_FIELD_SET` ([capture.py:283-286](../../scripts/serve/capture.py) [VERIFIED]). Threshold: import reds on any tailoring key that is a `SUMMARY_FIELD_SET` member.
- **Time horizon:** run the emit-gate, dosing-reject, paired-interaction, fail-closed, wire-scan, and tripwire probes at the first build of tailoring, at every ADR-0036 loop-re-run integration test, and before the July-2026 physician-visit deliverable ships.

**Review triggers:**
- ADR-0034's curated `rx-interaction-class` set changes — re-verify the deterministic screen's coverage and re-run the paired control.
- A proposal to render any tailored content into a tracked surface (the dashboard, a committed report) — re-verify against clause 2 + the wire-scan probe before it lands.
- ADR-0036's loop changes the re-generation cadence — re-verify tailoring idempotency per `(plan, date)` and the degrade-to-safe path.
