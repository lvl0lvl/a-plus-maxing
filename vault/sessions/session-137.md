# Session 137 — tracker-ingestion API-pull adapters (mechanical wearable data ingestion)

## What happened
With the ADR-0041–0046 comprehensive-plan build complete + kn29 cleared (S136), the operator directed the tracker→system data ingestion to be **mechanical** — "make the export and ingestion mechanical so it doesn't require manual updates or manual sorting" — specifying API-pull adapters for **Whoop + Oura + Garmin**, Apple Health via a **Shortcut**, and (after a look-up: Fitbit Air runs on the new Google Health API `health.googleapis.com/v4/`, Google OAuth 2.0) **Google-Health**. This session built it end-to-end through the rigor pipeline: architect design note (operator-approved) → two SE builds → Tier-2 whole-change review → 7-finding remediation → Tier-3 FULL `/review-pr` → `/merge`. **PR #344 squash-merged to `main` (`72d73699`).** Wearable data now ingests mechanically from the operator's own vendor clouds + Apple, no manual export/sorting.

## The problem it solved
Getting tracker data into the local store meant manual export + manual sorting. The operator wanted the bridge to be automatic. The existing ADR-0003 adapter seam was already pluggable/idempotent/schedulable but had only ever had *file-reading* adapters (a human drops an export file); it had never had a *network producer* feeding its `exports` map.

## Deliverable (on `main` via #344, Option A)
A shared OAuth/fetch layer (`scripts/ingest/oauth_pull.py`) authenticates + pulls each source's delta into a gitignored **staged file** in a file-reading adapter's `{item,timepoint,value}` shape; the **UNCHANGED** `ingest.run`→`store.append` lands it. Option B (an adapter `fetch` mode) was rejected because it would edit the frozen routine.
- **Four `*_cloud` adapters** (whoop/oura/garmin/google-health), pure `read_readings` parsers (a shared `read_staged_rows` helper, four dedicated adapters kept). OAuth-2.0 refresh→access for Whoop/Oura/Google; a **Garmin OAuth-1.0a request-signing strategy** (CSPRNG nonce, verified against the canonical X/Twitter known-answer vector). Per-source keychain refresh tokens `a-plus-maxing-<source>-oauth`.
- **`pull.py`** — the disabled-by-default scheduled caller of the UNCHANGED `scheduler.run` under `store_lock.cadence_lock`; per-source landing isolation; the Apple watched-folder scan (via the byte-unchanged `healthkit` adapter). The three legacy file-drop stubs retired `UNWIRED`.
- **ADR-0001 ruling (Architect):** the inbound pull is **not a new egress class** — only an OAuth token + a date cursor leaves, to the vendor that already holds the operator's data; 0 store bytes outbound, 0 model-lane calls; `oauth_pull` imports stdlib-only, so it *structurally* can't reach the model lane. No ADR-0001 amendment (the mirror image of ADR-0030). The frozen ADR-0032 six + `ingest.run`/`scheduler.run`/`adapter.py` byte-frozen numstat=0.
- Design note `docs/design/tracker-ingestion-api-adapters.md` (amended F1 retire-not-reuse / F3 credential_* seam-naming post-Tier-2).

## The review earned its keep — a real unattended-crash bug caught before merge
Tier-2 (QA/Security/Architect, each executed) caught 7 findings — incl. **M1** (the land-loop wasn't per-source-isolated → a malformed watched export crashed the tick) and **SEC-01** (`_http` followed 3xx with the default urllib opener → a cross-host 302 leaked `Authorization: Bearer` to the redirect host on the LIVE run, proven with two local servers). Tier-3 FULL `/review-pr` (6-agent → blind triage → 4 fix commits → blind verify 6/6 revert-RED) caught 6 more — headlined by **BUG-1** (Critical): the **fetch-loop twin of M1**. The fetch loop caught only `TrackerPullError` while the land loop caught `Exception`; an off-shape-but-HTTP-200 vendor envelope (`{"records": null}` — the common "no data in the window" steady state — → `TypeError`; a non-dict element → `AttributeError`) escaped uncaught and **crashed the whole unattended tick, blocking every other source AND the Apple watched folder**. Bug-Hunter ran it end-to-end (Whoop `{"records":null}` + a staged Apple export → uncaught `TypeError`, healthkit landed 0). Fixed (reader coercion: null→empty-delta, malformed→`TrackerPullError`; fetch `except`→`Exception`; watched-scan wrapped) + blind-verified revert-RED. Plus three proven-vacuous coverage gaps (honest-absence, degraded-200 token, JSON-blob rotation — each left the suite GREEN under a guard-mute) + two Suggestions (4× adapter duplication, stale docstring). All fixed, none suppressed. pytest 2 env-floor / 2827 passed / 8 skipped on the merged head.
