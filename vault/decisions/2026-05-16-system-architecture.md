## Context
Initial scoping conversation for a-plus-maxing. The fork in the road: build as SaaS-style tracker, build as LLM-driven agent, or hybrid. Walter explicitly chose "LLM-driven personal health agent, not a tracker."

## Decisions

### 1. Markdown substrate + HTML artifacts on demand
- All canonical state lives in markdown in the vault
- HTML is generated by the agent on demand for rich, layout-dependent consumption (weekly reviews, doctor handouts, genetic report)
- Rationale: markdown is LLM-native (low token overhead), version-controllable, doctor-shareable; HTML wins for layout-rich outputs (per Thariq Shihipar's HTML-effectiveness argument). The two compose cleanly — no need to pick one.
- Reference: https://thariqs.github.io/html-effectiveness/

### 2. No diet app
- Walter's eat-the-same-thing weekday pattern + LLM-driven micronutrient computation removes the need for MacroFactor / Cronometer
- `protocols/meal-template.md` is the source; agent computes macros + micros via USDA FoodData
- Deviations logged conversationally in one sentence; agent estimates impact
- Revisit if weight-trend math becomes a friction point in practice (track via `interactions/`)

### 3. Phased interface: A → B → C
- **A (now):** Conversational use of Claude with vault access — zero new infra
- **B (next):** Scheduled jobs (daily/weekly/monthly) produce artifacts in the vault
- **C (later):** Custom phone-friendly interface, designed from `interactions/` friction-log evidence

Walter's reasoning for the phasing: "collecting data on how I'm interacting with it will inform the C layer and be more useful, because we'll use it to solve friction points that arise through the process." Evidence-driven product design over speculation.

### 4. Near-term goal: July 2026 doctor visit baseline
- Walter has a new doctor appointment in July 2026 (sports-nutrition / exercise-oriented)
- Goal: arrive with a structured baseline — current protocols, training log, dietary template, genetic-actionable summary, target biomarker order list
- This shapes priorities for May–July 2026 (system setup phase)

## Consequences
- No SaaS to build; nothing to deploy
- Vault grows over time as the agent's memory
- Friction logging is a first-class concern (`vault/interactions/`)
- Doctor-visit artifact is the first major HTML output that needs to look polished
- HTML design protocol (`vault/design/artifact-design-protocol.md`) must be filled in before the first doctor-visit handout is generated
